# 访问权限——岗位、共享与权限集

面向管理员和实施人员。本篇讲的是 HotCRM 里点来点去看不出来的那部分：**谁能看到谁的数据**，以及原因。

## 岗位

岗位是分发记录访问权的群体。**设置 → 人员与组织 → 岗位持有人**列出了全部岗位及各自的任职人：销售、服务和市场营销各有总监、经理和一线三级，另有一个**高管**岗位，以及两个区域分组（**北美销售团队**和**欧洲销售团队**）。

岗位是**扁平的**——没有任何上卷。销售总监不会继承销售经理的访问权；每一级需要看到某条记录，都由一条专门的共享规则点名，所以下面的管理层规则都是成对出现的。

审批和升级自动化也使用同样的岗位：大额商机送交**销售经理** / **销售总监**审批；升级的工单交给名下未结工单最少的**服务经理**。注意扁平意味着什么：移交的目标是*岗位*，而不是"负责人的经理"——根本没有汇报线可循——该岗位无人时，工单保留原负责人。

## 记录可见性（共享规则）

基于所有权的访问由以下规则扩大（规则名保持产品内的英文原名）：

| 规则 | 对象 | 访问 | 用途 |
|---|---|---|---|
| Account Team | 客户 | **编辑** | 销售经理可编辑活跃的客户。名字如此，实际按条件匹配——并没有"客户团队"名册对象。 |
| Territory — North America / Europe | 客户 | **编辑** | 区域团队可编辑本区域内的客户。 |
| Sales Sharing | 商机 | **只读** | 销售总监可查看进行中的大额商机。 |
| Large Open Deals — Executive | 商机 | **只读** | 高管一级查看同样的商机。 |
| Case Escalation | 工单 | **编辑** | 已升级的工单可由升级处理人编辑。 |
| Escalated Cases — Service Director | 工单 | **只读** | 服务总监可看到服务经理被呼叫处理的工单。 |
| Escalated Cases — Previous Owner | 工单 | **只读** | 工单被升级拿走后，原客服在工单关闭前仍能看到它。 |
| Live Campaigns — Marketing Manager / Director | 营销活动 | **编辑** | 市场管理层可处理任何进行中的营销活动。 |
| Forecasts — Sales Manager Edit | 销售预测 | **编辑** | 销售经理可调整任何销售代表的预测。编辑共享从不授予删除权，因此销售经理仍无法删除预测。 |

## 队列——还没有负责人的记录

到达时没有负责人的新工单或新线索会进入队列，而不是靠共享规则。HotCRM 自带两个队列：**Support Intake**（支持受理，`case_intake`，成员是所有持有*客服专员*岗位的人）和 **Lead Intake**（线索受理，`lead_intake`，成员是所有持有*销售代表*岗位的人）。分配规则把每一条新到的无主记录交给手头未结工作最少的成员。队列里没有成员时，记录就在队列里无主等待：每一位成员都可以打开它并点击**认领**成为负责人，记录上的其他内容都不变。

要把某个人加进队列而不给他岗位，到**系统设置 → 访问控制 → 队列成员**里新增一行，队列填队列名（`case_intake` 或 `lead_intake`），成员选这个人。这两个队列随应用声明，所以**系统设置 → 访问控制 → 队列**的列表里看不到它们。

明细对象——商机产品明细、报价明细、营销活动成员和联系人——按设计**不带**共享规则：它们的记录访问权来自其父记录（`controlled_by_parent`，ADR-0055），所以扩大它们访问范围的是父记录上的共享。写入它们需要对父记录有编辑权。

**一条规则只扩大一个对象，而不是它下面的记录。** 上面的客户规则交出的是客户本身，以及——通过 `controlled_by_parent`——它的联系人。该客户下的报价单、合同和任务都是 `private`，没有自己的规则；商机只在 ≥ $100k 的管理层规则下扩大。因此对区域规则的接收者来说，这些相关列表仍只显示自己的记录。是否应当改变，是一个尚未决定的产品问题（#549）；在决定之前，文档描述的是"只看自己"的行为，而不承诺 360° 视图。

## 权限集

权限集为标准角色提供：**系统管理员**、**销售经理**、**销售代表**、**客服专员**、**服务经理**、**市场专员**，以及用于未登录网页转线索的**访客（公开表单）**。

权限集**只做显式允许**：任何权限集都没有点名的对象，对所有用户都拒绝，管理员也不例外——对象级 CRUD 闸门会在组织范围默认值、共享规则或*查看所有数据*被考虑之前就拒绝请求。因此给应用新增一个对象，必然要同时为它新增授权；缺失时 `test/authorization-coverage.test.ts` 会让构建失败。

导出是**授予的，而不是默认具备的**。平台自带的管理员访问权不含导出，所以管理员（包括搭建部署的那个账号）只有在被分配了一个授予导出的权限集之后才能导出列表：**系统管理员**在线索、客户、联系人、商机和工单上授予导出。在本地演示环境里，`pnpm demo:staff` 会把这个权限集分配给开发管理员。管理员的权限集也是打开这本**管理员手册**的钥匙：它只发布给**系统管理员**的持有人（多组织部署上是 **Tenant Administrator**），其他人在**帮助**下看不到它。

在对象授权之上还有两条记录级规则：

- `crm_opportunity.is_private`——标记为私密的商机只有其负责人能看到，持有组织范围商机读取权的权限集（销售经理、市场专员）也看不到。
- 字段级安全屏蔽 `crm_account.health_score`（销售经理以下只读）、`crm_case.internal_notes`（仅服务人员可见；对销售代表隐藏）、`crm_account.annual_revenue` 以及计算出的工单 SLA 字段。

## 禁用模块

HotCRM 由核心应用加三个模块组成——**HotCRM Service**、**HotCRM Revenue** 和 **HotCRM Marketing**。用不到的模块可以在**系统设置 → 已安装应用**里关掉：选*显示全部*，打开该模块，选择**禁用**；选择**启用**即可重新打开。

模块禁用期间，所有人都看不到它，管理员也不例外：

- 它的入口从侧边栏消失——服务模块是"服务"分组和*我的工单*，收入模块是*报价*、*产品*和*价格表*，营销模块是*营销活动*——它的记录也无法打开。
- 核心应用不再提供通往它的按钮：营销模块禁用时，线索和联系人上没有**加入营销活动**；收入模块禁用时，商机上没有**生成报价单**。收入模块禁用时，CRM Overview 仪表板不显示 **List Price by Category** 磁贴。
- 指向该模块的字段（例如商机的*营销活动*、任务关联的工单）在记录页上保留已有的值，但选择器里选不到新的值。该模块的相关列表显示为空。

禁用模块不会删除任何东西：它的记录仍留在数据库里，重新启用后，记录、侧边栏入口和按钮都会回来。
