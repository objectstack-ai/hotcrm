# 常見問題

## 🔒 存取與可見性

### 為什麼我看不到一筆我確定存在的記錄？

最有可能是某條[共享規則](/zh-Hant/docs/administration/sharing-and-security)沒有授予你存取權限。按以下順序檢查：

1. 你是**擁有者**嗎？如果不是……
2. 這筆記錄是否**從你能看到的父記錄衍生**（你客戶下的聯絡人、你報價上的行項）？如果不是……
3. 是否有**共享規則**同時符合該記錄和你的某個**職位**（例如，地區、層級）？如果不是……
4. 這筆記錄是否被**手動共用**給了你？如果不是……
5. 你的設定檔是否擁有 **View All**？如果不是……

→ 你將看不到它。請擁有者把記錄共用給你，或請管理員擴展共享規則。

注意：共用一個**客戶**只會帶上它的聯絡人；該客戶底下的報價、合約、任務、案件與商機仍歸各自的所有人。

### 為什麼某個欄位是灰色 / 唯讀的？

三種可能：

- **欄位級安全**限制了你設定檔的編輯權限 → 請管理員處理。
- 該記錄**在審批流程中被鎖定** → 等待或撤回。
- 某條**驗證規則**阻止了變更 → 查找內嵌錯誤訊息。

### 我在另一個租戶中擁有管理員權限 —— 為什麼這裡沒有？

設定檔和權限是**按租戶**劃分的。你需要管理員在此租戶中授予你*系統管理員*設定檔。

### 為什麼 AI Copilot 說「我找不到那筆記錄」？

Copilot 遵守你的共享設定 —— 如果你看不到它，它也看不到。請確認記錄存在並檢查共享設定。

## 📈 記錄與資料

### 我建立了一筆線索，但它被指派給了別人 —— 為什麼？

是自動指派跑了。**不存在「Setup → Lead Settings」這個畫面，也沒有任何指派規則可查** —— 一筆到達時沒有擁有者的線索，會在插入時交給持有 `sales_rep` 職位的人中未結線索最少的那一位（`src/objects/lead.hook.ts`）。它做的是負載平衡，不匹配地區或區域。所以你看到的擁有者是負載最輕的銷售代表，而不是離得最近的那一位。

### 我的商機無法移動到 Closed Won。

三個阻礙因素，按順序：

1. **必填欄位**缺失（Close Date、Amount、Won Reason）。
2. **需要審批** —— 金額 > $500K 會觸發[折扣審批](/zh-Hant/docs/revenue/approvals)；必須先獲得批准。
3. **驗證規則** —— 例如，*「必須有一個主要聯絡人角色」*。

### 為什麼我的商機跳回到了上一個階段？

很可能是審批被拒絕了。檢查商機上的**審批歷史**部分。

### 刪除的記錄去了哪裡？

哪裡也沒去 —— **刪除是立即且永久的。** 沒有資源回收筒可供還原，設定裡也沒有對應入口：平台根本沒有軟刪除執行時。`@objectstack/spec` 已經把當年承諾資源回收筒的那個開關退役，並把理由寫得很直白 —— *「每一次刪除從來都是硬刪除，一個預設為真、承諾資源回收筒的開關是一種虛假的能力暗示」*。請把每一次刪除都當作不可逆。**Setup → Audit Logs** 裡的稽核日誌會記錄誰在何時刪了什麼；但它無法把記錄找回來。

### 我的匯入顯示「匯入 0 列」 —— 為什麼？

常見原因：

- **External ID** 欄未設為匹配鍵，但衝突模式為*僅更新*。
- CSV 中的**選擇清單值**與定義的值不匹配。
- **必填欄位**缺失。
- **擁有者信箱**與任何使用者都不匹配。

試執行報告會告訴你哪一列失敗以及原因。請始終先試執行。

## ⚙️ 自動化

### 我的流程沒有觸發 —— 為什麼？

按順序檢查：

1. 該流程是否**已啟用**？
2. 在儲存時記錄是否真的**符合起始條件**？
3. 是否有**驗證規則**在流程觸發前阻止了儲存？
4. 是否有**先前的流程**變更了記錄，導致條件不再匹配？
5. 這條流程是否在**上一次執行尚未結束時又因同一筆記錄被重入**？引擎的重入守衛會跳過這次執行並記一條警告日誌。沒有可對照的重新評估次數 —— 守衛是兜底，不是停止條件。參見[管理 › 自動化](/zh-Hant/docs/administration/automation)。

**Studio → Developer → Flow Runs** 顯示某條流程最近的執行及其狀態 —— 先選中你預期應當觸發的那條流程。

### 我的 SLA 計時器沒有執行。

本應用裡沒有任何東西在倒數 —— 不存在可以盯著看的即時 SLA 計時器。真實存在的是：給每一張工單打上的一個截止時間，加上一個每小時跑一次、事後標記違約的掃描。檢查：

- 工單處於**開啟狀態**（不是 Resolved / Closed）—— 每小時的 `case_sla_monitor` 掃描按 `status: { $nin: ['resolved', 'closed'] }` 過濾，所以已解決的工單永遠不會被撈進來。
- 工單**到底有沒有 SLA 截止時間**。現在每個優先順序都會被自動打上，取自 `src/objects/case.hook.ts` 裡的一張優先順序 × 客戶層級矩陣 —— 但矩陣裡沒有對應列的優先順序仍然會留空，而截止時間為空的工單永遠進不了掃描的候選集，所以無論它開著多久，**SLA Violated** 都保持 `false`。（手工填一個截止時間是有效的 —— 之後掃描會像對待其他工單一樣對待它。）
- 那個截止時間**已經過去**，並且此後已經跑過一次掃描。掃描每小時一次，且只標記已經逾期的工單，所以一個逾期但在下一次掃描之前就被解決的工單，根本不會被標記。

**沒有營業時間設定可查** —— 本應用裡沒有工作日日曆，沒有假日清單，也不存在「設定 → 營業時間」這個畫面。矩陣裡的每一個數字都是掛鐘小時，夜間、週末與假日一律照算。**同樣不存在「SLA 定義」這個介面**：矩陣寫死在鉤子裡而不是設定出來的，你在介面上能設的只有帳戶的**客戶層級**，它決定走哪一欄。參見 [SLA 與升級](/zh-Hant/docs/service/sla-and-escalation)。

### 自動編號跳號了（例如，從 #1234 跳到 #1267）。

正常現象。為提升效能，序列會成批預留編號；當記錄被刪除、儲存嘗試後驗證失敗或批次被放棄時會出現間隙。該序列是**單調遞增**的，而非連續的。

## 🤖 AI Copilot

### Copilot 的回答錯誤 / 過時。

三個原因：

- **知識庫陳舊** —— 在 *Setup → AI → Knowledge Bases → Refresh* 處重新索引。
- **來源文件過時** —— 被引用的文章需要更新。
- **提示詞可以更精準** —— 對於自訂技能，優化提示詞；對於內建技能，透過點踩按鈕提交回饋報告。

### Copilot 不回答關於某個特定客戶的問題。

兩種可能：

- **共享** —— 你看不到該客戶的記錄。
- **AI 去識別化規則** —— 管理員可以阻止 Copilot 引用被標記的客戶（例如 VIP、訴訟中）。Copilot 會明確說明這一點。

### 為什麼今天 AI 回應很慢？

檢查 AI 儀表板（*Setup → AI → Health*）。常見原因：上游 LLM 供應商延遲、知識庫正在重新索引，或速率限制節流。

## 📊 報表與儀表板

### 我的報表顯示的記錄比預期少。

共享問題。報表遵守記錄可見性 —— 你只能看到你能看到的內容。執行公司管道報表的銷售代表只能看到自己的商機。

### 儀表板磁貼是空的。

檢查：

- 磁貼的**篩選器** —— 是否過於嚴格？
- 底層的**分析重新整理** —— 編譯後的 cube 由分析服務重新整理，HotCRM 沒有宣告任何重新整理計畫，所以磁貼不新鮮要去問你自己的部署。
- 你對來源物件的**設定檔權限**。

### 我變更了某筆記錄上的某個欄位 —— 儀表板何時更新？

每塊儀表板按自己宣告的間隔重新查詢：Customer Service 每 **60 秒**、Sales Performance 每 **180 秒**、CRM Overview / Sales Activity / Executive Overview 每 **300 秒**（`src/dashboards/`）。底下那個 cube 多久由分析服務重新編譯一次，是部署側的問題 —— 本應用自己不組態任何重新整理計畫。HotCRM 的儀表板中繼資料也沒有宣告任何手動重新整理控制項，所以你的主控台上若有重新整理按鈕，它來自平台而不是本應用。

### 為什麼我無法將自訂欄位加入報表？

該欄位必須在欄位定義中為**報表**啟用。請管理員打開 *Available in Reports* 開關。

## 🔌 整合

### 我的郵件未被記錄。

檢查：

- **Gmail / Outlook 連接器**已連接（Settings → Email）。
- 郵件發往/來自**已知聯絡人**（透過信箱匹配）。
- 寄件人/收件人信箱不在你的**排除**清單中。

### 我的 DocuSign 信封沒有更新合約。

檢查 **DocuSign 整合日誌**（Setup → Integrations → DocuSign → Activity）。來自 DocuSign 的 Webhook 投遞可能正在重試。

### Stripe 說客戶 X 存在；HotCRM 說沒有。

Stripe 透過信箱或 external ID 匹配 HotCRM 客戶。如果兩者都不匹配，則不會建立關聯。手動加入 external ID 或使用 **Stripe Sync → Re-link** 操作。

## 🚀 效能

### 頁面載入緩慢。

檢查：

- **網路** —— 你的 VPN 是否經過較慢的地區路由？
- **清單檢視大小** —— 嘗試篩選到 &lt;500 列。
- **自訂小工具** —— 暫時停用以隔離問題。
- **瀏覽器** —— 清除快取；我們推薦最新版 Chrome / Edge / Safari / Firefox。

如果問題持續，檢查**狀態頁面**是否有事故。

### 我觸發了 API 速率限制。

參見[效能與限制](/zh-Hant/docs/reference/performance-and-limits)中的矩陣。常見原因：沒有退避機制的緊湊整合迴圈。加入指數退避並遵守 `Retry-After` 標頭。

## 👥 使用者與授權

### 我如何停用一個使用者？

**Setup → Users → [user] → Deactivate**。其記錄會按停用精靈重新指派。**不要刪除**使用者 —— 這會破壞歷史記錄。

### 一個使用者可以有兩個設定檔嗎？

不可以。使用**權限集**在基礎設定檔之上授予額外權限。

### 一個使用者可以屬於多個角色嗎？

不可以 —— 每個使用者一個角色。使用**公開群組**進行橫向共享。
