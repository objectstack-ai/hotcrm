# 工单分诊——助手如何权衡一张工单

写给部署中运行了平台助手的客服专员和服务经理。助手是平台提供的，在 ObjectOS Cloud 和 Enterprise 上可用；自行部署的开源版本没有助手，那里的每张工单都由你按下文同样的规则自己分诊。

分诊回答一个问题：这张工单有多紧急，为什么？答案由助手提出，由人决定。

## 何时启用

你打开一张工单时，分诊技能会自动就绪：请助手对这张工单做分诊、定优先级或归类即可。你也可以在任何地方提问，并说明是哪张工单。

## 它读取什么

它每次都重新读取工单，从不凭之前回答的记忆：先读取工单的结构（所以管理员新加的字段会立刻被用上），再读取这张工单本身。它以你的身份读取，看到的字段和记录与你完全相同。

## 它如何权衡

它按重要性从高到低权衡四件事：

1. **客户是谁。** 客户的**客户分层**和他们的合同金额。
2. **客户是否被卡住。** 无法工作且没有变通办法的客户，优先于只是不方便的客户。
3. **时间。** 工单已开启多久，对照它的 **SLA 到期**。
4. **语气。** 客户最近一条消息的情绪。

答案是一个**优先级**（低、中、高或严重），加上决定它的**那一个**理由，并写明工单编号和它依据的字段值。只给一个理由，而不是一串：这是你能核对、也能直接粘贴的那句话。

## 从哪一步起由人接手

助手不能修改工单。它没有任何可以写入的工具，所以之后的每一步都由你来做：

- **设定优先级。** 由你亲自编辑**优先级**。设为**严重**会立即升级工单，不等 SLA 计时：见[工单](./crm_service_cases.md)。
- **升级。** 它判断工单属于严重时会明说，引导你使用工单上的**升级工单**，并给出可以直接粘贴的原因。升级特意要求由人填写这个原因。
- **关闭。** 工单实质上已解决时，它会引导你使用**关闭工单**，并给出可以粘贴的解决说明。
- **回复客户。** 它把回复交给邮件撰写技能，由那个技能写出草稿。在你亲自发送之前，什么都不会发出。

你不同意它给的优先级时，以你的为准：它说的任何话都不会记到工单上。
