# 发票与回款——由谁录入，什么算逾期

写给销售，也写给财务（**应收会计**岗位）。发票和回款是财务在自己系统中开具和收到的记录。财务录入或导入它们；销售只查看、从不录入，所以销售看到的每个数字都是财务写的。

发票和回款属于**客户**，两者**并行**：回款不填发票。发票填它开给的订单或合同；回款填它收的**回款计划**，或它付的订单或合同。一张发票对应多个订单，或暂时对应不上任何东西的预收款，只需填客户。

应收会计岗位在所有客户上录入和导入它们。这个岗位能查看所有客户，但不能编辑任何客户：能查看客户，就足以写入它的发票和回款。

## 界面上看不出的规则

- **客户、订单与合同。** 选择订单或合同会带出它的客户。选择另一个客户的订单或合同会被拒绝，并写明是哪一个。归在合同下的订单会带出它的合同：填了另一份合同会被拒绝，订单和合同属于不同客户也会被拒绝。回款只填了回款计划、没填订单或合同时，会从回款计划带出订单和合同，这样订单和合同上的汇总与回款计划统计的是同一批回款。
- **订单的合同带到它的发票和回款上。** 订单在发票和回款保存之后才有了合同（点了**起草合同**，或选了订单的**关联合同**），其中没填合同的会带上这份合同，合同的汇总随即把它们算进去。把订单改到另一份合同下时，原来跟着旧合同的发票和回款一起改到新合同；清空订单的合同时，它们的合同也一起清空，订单下一次有了合同再把它们补上。填了其他合同的保持不变。不管是谁改的订单都会这样：销售改订单会连带改掉财务的发票和回款上的**合同**，此外什么都不改。每条记录的历史里都能看到这次修改。
- **到期日。** 留空时，保存时自动填写：**开票日期**加上合同的**付款条款**；没有合同或合同没填付款条款时，取订单的**付款条款**（Net 15、30、60 或 90 天；Due on Receipt 即开票当天）。财务填写的日期会保留。两者都没有的发票没有付款条款可用，请手工填写到期日。
- **已开票**只统计状态为**已开具**的发票。**已作废**的发票退出所有统计。
- **未回款与未开票。** 订单上的**未回款**是订单金额减去**已回款**，**未开票**是订单金额减去**已开票**，都不低于零；合同上按合同金额同样计算。超过应收的回款照样接受，无论是手工录入还是导入，未回款到零为止。客户上的这两个数是各订单、各合同自己的数之和，见回款计划手册。
- **逾期**看的是回款计划，不是发票。「订单与回款」应用的**跟进 → 逾期回款计划**列出**计划日期**早于今天且仍有**未回款**金额的回款计划。
- **一笔回款最多填一个回款计划。** 一笔收款结清多个回款计划时，每个回款计划记录一笔回款；没有分摊。

## 导入

财务使用 **Invoice Import (CSV)** 和 **Payment Import (CSV)** 导入。**ERP 编号**列是唯一键：编号已在某条记录上的行会更新这条记录，而不是新增一条。每条导入的记录**来源**为**导入**，并带有**同步时间**（导入的时刻）。客户用客户名称指定，订单用订单编号（SO-0001）或它的**外部编号**，合同用合同编号（CTR-0001），回款计划用节点名称。每行需要客户、订单或合同：订单或合同（回款还可以是回款计划）能带出客户时，**Account** 列可以留空。回款文件没有 **Invoice** 列，发票文件没有 **Billing Milestone** 列。一笔收款分到两张订单时是两行回款，各有自己的 **ERP 编号**：和导出文件的一方约定编号规则（例如收款编号加订单编号）。

**多份合同上有同名节点时，该行导入失败**（「匹配到多条记录」）：导入会在所有合同里查找这个名称。这时在该列填写节点的记录 ID，即节点页面地址的末尾。多个客户同名时，同样会失败。
