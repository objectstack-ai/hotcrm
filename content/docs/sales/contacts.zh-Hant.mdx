# 聯絡人

**聯絡人**是某個客戶處的個人——通常是決策者、影響者或最終使用者。每個聯絡人都屬於一個客戶。

## 聯絡人記錄儲存的內容

聯絡人詳情介面有 6 個可摺疊區塊：

| 區塊 | 欄位 |
| --- | --- |
| **身份** | 稱謂、名、姓、全名 |
| **客戶與角色** | 客戶、職位、部門、主要聯絡人標誌 |
| **聯絡資訊** | 郵箱、電話、手機、傳真 |
| **郵寄地址** | 完整的結構化地址 |
| **附加資訊** | 描述、生日、潛在客戶來源、匯報對象 |
| **溝通偏好** | 郵件退訂、請勿致電、傳真退訂 |

## 主要聯絡人

每個客戶有**一個主要聯絡人**——通常是主要決策者或業務發起人。將某個聯絡人設為主要會自動清除前一個聯絡人上的標誌，因此你絕不會出現兩個的情況。

主要聯絡人會被自動建議為以下情境的預設值：

- 商機（主要聯絡人欄位）
- 報價（聯絡人欄位）
- 合約（主要聯絡人欄位）

這能省去大量點擊。

## 客戶處的組織架構圖

使用**匯報對象**來建模客戶內部的組織結構：

```
CEO
├── VP Sales
│   └── Sales Director
└── VP Engineering
```

客戶詳情頁將其渲染為一棵可點擊的樹，因此你能一眼看出誰向誰匯報。AI Copilot 在總結客戶時會用到它——它能告訴你哪些人是決策者、哪些是影響者。

## 溝通偏好（GDPR / CCPA）

三個退訂標誌告訴系統此人不希望被聯絡。每個標誌都以**紅色徽章**顯示在聯絡人介面頂部，讓人不可能錯過：

| 標誌 | 會發生什麼 |
| --- | --- |
| **郵件退訂** | Sales Copilot 拒絕為此人起草外發郵件；行銷活動會將其排除。 |
| **請勿致電** | 系統會阻止你向此聯絡人記錄*電話*任務。 |
| **傳真退訂** | 基於傳真的行銷活動會跳過此聯絡人。 |

銷售代表可以請求更改標誌，但不能自行移除——這是僅限管理員的操作。

## 內建規則

- **郵箱地址在你所屬的組織內必須唯一**。同一個地址不能同時用於兩個聯絡人，即使這兩個聯絡人隸屬於不同的客戶——第二次儲存會被拒絕，並提示 *"Another contact … with email … already exists."*。同一平台上的其他組織可以有自己使用該地址的聯絡人——這條規則只作用於你自己的資料，而不是整個平台。郵箱在儲存與比較前會統一轉為小寫，因此 `Ada@Example.com` 與 `ada@example.com` 視為同一個地址。因此，若同一個人同時在兩家公司與你往來，兩筆聯絡人記錄需要各自使用不同的郵箱地址。
- **歡迎郵件**——當建立一個聯絡人時，系統會自動向其發送 *contact_welcome* 郵件範本。

## 共享——誰能看到哪個聯絡人

聯絡人可見性**繼承自父級客戶**。如果你能看到該客戶，就能看到它的所有聯絡人。沒有需要管理的單獨聯絡人共享模型。

這讓安全機制變得簡單：把客戶共享設定正確，聯絡人就會隨之而來。

## 標準列表視圖

- **我的聯絡人**——你負責的聯絡人。
- **主要聯絡人**——`is_primary = true`。
- **決策者**——職位包含 "VP"、"Chief" 或 "Director"。
- **按職位**——分組。
- **最近新增**——最新的在前。

## AI Copilot 如何使用聯絡人

當你讓 Sales Copilot 起草一封郵件時，它會使用：

- 聯絡人的名和職位（用於個人化）。
- 客戶名稱和產業（用於上下文）。
- 產品目錄（用於相關談話要點）。
- 聯絡人的溝通偏好（以跳過退訂項）。

因此 *"Draft a follow-up to Jane"* 能在幾秒內給你一封個人化的、符合品牌調性的郵件。

## 給銷售代表的提示

- ✅ 始終設定職位和部門——它會被報告和 Copilot 使用。
- ✅ 使用匯報對象欄位——它讓客戶會議的準備工作容易得多。
- ✅ 每個客戶恰好標記一個主要聯絡人。

## 給管理員的提示

- 部門列表（Sales、Marketing、Engineering、Finance、IT、Operations、HR、Legal、Executive、Other）可按選擇列表值設定。參見 [Customization › Extending Objects](/zh-Hant/docs/customization/extending-objects)。
- 歡迎郵件範本可以在你的郵件範本設定中自訂。
- 來自客戶的共享繼承意味著你通常永遠不需要針對特定客戶的聯絡人共享規則。
