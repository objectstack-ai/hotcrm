# 報表

報表是可篩選、可匯出的清單，帶有分組和彙總合計。儀表板展示*是什麼*，而報表回答*為什麼*和*哪些*。

## 標準報表

HotCRM 開箱即用地提供以下報表：

### 📈 銷售報表

| 報表 | 顯示內容 |
| --- | --- |
| **Pipeline by Stage** | 所有未結交易按階段分組，帶 $ 合計 |
| **Forecast vs Actual** | 成交贏單對比預測，按週期 |
| **Win/Loss Analysis** | 已結交易按贏單/丟單分組，帶原因分解 |
| **Sales Cycle Length** | 從建立到成交的天數，按擁有者和產品 |
| **Top Performing Reps** | 成交排行榜 |
| **Stale Opportunities** | 14 天以上無活動的交易 |
| **Big Deals Won** | ≥ $100K 的成交贏單商機 |
| **Discount Approval Activity** | 所有審批請求，按狀態和審批人 |

### 🎯 潛在客戶報表

`src/reports/lead.report.ts` 發布的潛在客戶報表只有 **一份**：

| 報表 | 顯示內容 |
| --- | --- |
| **Lead Engagement by Month × Source** | 已聯絡潛在客戶數量的矩陣 —— 橫列是潛在客戶來源，直欄是 **Last Contacted** 所在的月份。從未聯絡過的潛在客戶被排除在外：它們沒有互動月份 |

本節曾經列出的三份報表，一份都沒有發布，其中兩份還用了一個並不存在的潛在客戶狀態：

- **Lead Conversion Funnel** 與 **Aged Leads** 以任何形式都不存在。兩者都依賴一個 *Working* 狀態，而 `crm_lead.status` 根本沒有這個取值 —— 真實路線是 *New → Contacted → Qualified → Unqualified → Converted*（`src/objects/lead.object.ts`），其中 *Unqualified* 從任何開放狀態都能進入。*Working* 是匯入別名表（`src/mappings/lead_import.mapping.ts`）裡的一行，它在記錄匯入時把這個歷史寫法對應到 **Contacted**；產品從不顯示這個詞。宣告出來的路線見 [狀態機](/zh-Hant/docs/administration/state-machines)。
- **Lead Source ROI** 同樣不存在，而且按它寫的口徑，語義層也答不出來：`lead_metrics`（`src/datasets/lead.dataset.ts`）只宣告了一個度量 —— 潛在客戶計數 —— 外加四個維度（狀態、來源、建立日期、最後聯絡月份）。「按來源的數量」可以直接從它得到；轉化率要你自己在按狀態分組的計數上做除法；而收入根本不在這個資料集裡 —— 它從不跨到商機那一側。

潛在客戶計數也是別處唯一會讀的潛在客戶數字：[Executive Overview](/zh-Hant/docs/analytics/dashboards) 儀表板上的 **Open Leads** 磁貼正是用同一個資料集數未轉化的潛在客戶。其餘的請自建 —— 見下文《自訂報表》。

### 🎧 服務報表

| 報表 | 顯示內容 |
| --- | --- |
| **Case Volume by Origin** | 新工單按 Email / Phone / Web / Chat / Portal |
| **SLA Performance Report** | 工單數、**SLA 違約率** 與平均解決時長，按優先順序 —— 只統計已關閉的工單 |
| **Case Resolution Time** | 平均解決時間，按類別和客服 |
| **Top Accounts by Case Volume** | 工單最多的客戶 |
| **Reopened Cases** | 週期內重開的工單（品質訊號） |
| **CSAT by Agent** | 按客服的平均客戶滿意度 |

**SLA Performance Report 裡沒有任何首次回應數字**，而且它那個 SLA 數字是 **SLA Violated** 標誌的平均值，也就是違約 *率*，不是準時率。本應用根本不度量首次回應：**First Response Date** 只在工單上第一次記錄 *已經發生過* 的通話或會議時被蓋上，此後從不與任何目標比較；`case_metrics` 沒有宣告任何首次回應度量，所以沒有報表、也沒有儀表板磁貼能報出一個來。參見 [SLA 與升級](/zh-Hant/docs/service/sla-and-escalation)。

## 使用報表

每個報表都有相同的基本控制項：

| 控制項 | 作用 |
| --- | --- |
| **Filter** | 新增條件（日期範圍、擁有者、階段等） |
| **Group by** | 按任意欄位彙總——擁有者、階段、產品、地區 |
| **Sort** | 點擊任意欄標題 |
| **Summary** | 在分組和整體層級顯示合計、平均值、最小值、最大值 |
| **Drill in** | 點擊任意列以開啟來源記錄 |
| **Export** | 下載為 CSV 或 Excel |
| **Save as** | 用新名稱儲存你篩選/分組後的版本 |
| **Schedule** | 按重複排程透過電子郵件傳送 PDF 或 CSV |
| **Subscribe** | 報表變更時收到通知 |

## 權限

- 使用者只能看到他們有權存取的記錄——執行 *Pipeline by Stage* 的業務代表看到自己的交易；經理看到團隊的。
- 管理員可以透過**欄位級安全**鎖定哪些欄位出現在報表中。
- 敏感報表可以限制給特定的 [設定檔](/zh-Hant/docs/administration/profiles)。

## 自訂報表

擁有 *Report Builder* 權限的任何人都可以：

1. 選擇一個**來源物件**（潛在客戶、商機、工單等）。
2. 選擇要顯示的**欄**。
3. 新增**篩選條件**。
4. 選擇**分組**和**彙總欄位**。
5. 選擇一個**圖表**進行視覺化。
6. **儲存並共享**。

對於更進階的分析——多物件聯結、時間序列、群組分析——請使用 [多維資料集](/zh-Hant/docs/analytics/cubes)。

## 訂閱與定時推送

消費報表最常見的方式是**電子郵件訂閱**：

- **頻率**：每日、每週、每月。
- **推送日期與時間**。
- **格式**：PDF（已格式化）或 CSV（原始資料）。
- **收件人**：你自己、團隊別名，或特定使用者（受其自身權限約束）。

一種常見模式：

- *Pipeline by Stage* → 週一早上 8 點發給銷售團隊。
- *SLA Performance* → 每日下午 6 點發給服務經理。
- *Top Accounts by Case Volume* → 週五下午 4 點發給客戶成功團隊。

## 給使用者的提示

- ✅ 為你每週執行的檢視儲存篩選版本——不要從頭重新篩選。
- ✅ 在團隊報表上使用 **Group by Owner**，以突出表現優異者和落後者。
- ✅ 僅在需要與外部資料合併時才匯出到 Excel——否則留在應用內以取得即時資料。

## 給經理的提示

- ✅ 每週向你的團隊安排 **Stale Opportunities**——它能強制跟進紀律。
- ✅ 每月與銷售教練一起使用 **Win/Loss Analysis**——它是最好的單一輔導工具。

## 給管理員的提示

- ✅ 當使用者反覆建構同一份報表時，**將其提升**到標準庫。
- ✅ 淘汰無人執行的報表——保持庫的精煉。
- ✅ 按團隊（銷售、服務、行銷、高階主管）設定**預設報表資料夾**，以便輕鬆發現。
