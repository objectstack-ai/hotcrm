# 权限档案

**权限档案** 是分配给用户的权限集合。它控制用户在整个 CRM 中能查看、编辑、删除和配置的内容。每个用户都恰好拥有一个权限档案。

## 六种内置权限档案

| 权限档案 | 面向 | 典型用户 |
| --- | --- | --- |
| 👑 **System Administrator** | CRM 管理员 | IT、运营、实施负责人 |
| 👔 **Executive** | C 级高管 | CEO、CRO、销售/服务副总裁 |
| 💼 **Sales User** | 销售代表 | AE、SDR、BDR |
| 🎧 **Service User** | 服务专员 | 支持专员、成功经理 |
| 📣 **Marketing User** | 营销人员 | 需求生成、活动经理 |
| 👀 **Read Only** | 审计员、观察者 | 财务审查员、外包人员 |

## 每种权限档案能做什么

### 👑 System Administrator

- 对 **所有** 对象拥有完整的读/写/删除权限
- 可以配置 **一切**：对象、字段、权限档案、共享、自动化、AI 技能
- 可以模拟其他用户（用于支持 / 调试）
- 绕过共享规则和字段级安全

⚠️ **谨慎使用** —— 通常每个组织 2–3 人。

### 👔 Executive

- 对所有 CRM 对象拥有完整 **读取** 权限（覆盖全公司）
- 仅对自己拥有或所属团队的记录有 **编辑** 权限
- 访问所有 **仪表板** 和 **报表**，包括高管记分卡
- 不能删除记录
- 不能配置系统

为 *“看到一切，不改任何东西”* 的领导层设计。

### 💼 Sales User

- 对自己拥有或所属团队的 **客户** 拥有完整读/写权限
- 对与其客户关联的 **联系人**、**商机**、**报价**、**合同** 拥有完整读/写权限
- 对自己拥有的 **潜在客户** 拥有完整读/写权限
- 读/写 **任务** 和 **事件**
- **提交审批**（例如折扣审批）
- 对 **产品**（目录）拥有读取权限
- 不能删除记录（经理权限）
- 无配置访问权限

### 🎧 Service User

- 对其队列中或分配给自己的 **案例** 拥有完整读/写权限
- 对与这些案例关联的 **客户**、**联系人**、**合同** 拥有完整读取权限
- 对 **知识库** 文章拥有读/写权限（受 KB 工作流约束）
- 对 **产品** 拥有读取权限
- 对与客户关联的 **商机** 拥有读取权限（用于了解背景）
- 无配置访问权限

### 📣 Marketing User

- 对 **活动** 和 **活动成员** 拥有完整读/写权限
- 对 **潜在客户**（尤其是无所有者的）拥有完整读/写权限
- 对 **联系人**、**客户**、**商机** 拥有读取权限（用于 ROI 分析）
- 对 **销售知识** 和 **竞争情报** 知识库拥有读/写权限
- 无配置访问权限

### 👀 Read Only

- 对 **所有** 标准对象拥有读取权限
- 无编辑、删除或创建权限
- 对仪表板和报表拥有读取权限
- 无导出权限（可配置）

## 分配权限档案

1. 前往 **设置 → 用户**。
2. 打开用户记录。
3. 从下拉菜单中选择 **权限档案**。
4. 保存 —— 更改立即生效。

一个用户一次只能拥有 **一个权限档案**。要在其基础权限档案之上授予额外权限，请使用 **权限集**（即 *“额外帽子”* 机制）。

## 克隆权限档案

如果某个内置权限档案 *几乎* 合适但需要微调：

1. **设置 → 权限档案**。
2. 打开该权限档案并点击 **克隆**。
3. 重命名（例如 *“高级销售代表”*）。
4. 调整权限。
5. 保存并分配给用户。

⚠️ **不要修改内置权限档案** —— 克隆它们。HotCRM 的更新可能会重置内置权限档案的设置。

## 权限档案里有什么

每个权限档案控制：

| 权限领域 | 控制项 |
| --- | --- |
| **对象权限** | 对每个对象的读取、创建、编辑、删除 |
| **字段级安全** | 每个字段的可见性和读取/编辑 |
| **应用访问** | 用户可以打开哪些应用（Enterprise CRM、Admin 等） |
| **系统权限** | 特殊能力（批量编辑、导出、查看所有数据、修改所有数据） |
| **AI 权限** | 用户可以调用哪些 AI 技能 |
| **审批权限** | 提交、批准、撤回 |

## 权限档案 vs 角色 vs 共享 —— 有什么区别？

这会让新管理员犯迷糊。简短的答案：

- **权限档案** = *你能做什么*（动词：创建、编辑、删除、提交审批）。
- **角色** = *你在层级中的位置*（决定你能看到谁的记录）。
- **共享规则** = *例外情况*（例如“即便不在角色层级中，EU 中的每个人都能看到 EU 客户”）。

一个销售代表拥有 **Sales User 权限档案**（让其能编辑商机）以及一个像 *AE - East* 这样的 **角色**（控制 *谁的* 商机）。两者都必须允许访问，他们才能看到 + 编辑某条记录。

关于角色 + 共享这一面，参见 [共享与安全](/zh-Hans/docs/administration/sharing-and-security)。

## 给管理员的提示

- ✅ **从内置权限档案开始** —— 除非必要，否则不要自定义。
- ✅ 拿不准时，**克隆** 而非修改。
- ✅ 对于一次性授权（“Sarah 在第三季度需要导出权限”），使用 **权限集** 而非创建新的权限档案。
- ✅ **每季度审计权限档案** —— 当人们换岗位时，他们的权限档案往往没变。
- ✅ 将 System Administrator 限制在 **最多 2–3 人** —— 这是通往王国的钥匙。

## 给用户的提示

如果你无法做某件你认为自己应该能做的事：

1. 检查你的权限档案（右上角 → 你的名字 → 权限档案）。
2. 询问管理员你的权限档案对你的岗位是否正确。
3. 如果权限档案正确但你仍然看不到某条特定记录，那是一个 [共享](/zh-Hans/docs/administration/sharing-and-security) 问题，而非权限档案问题。
