# 商机

**商机**是一笔活跃的交易——一个有已知客户、金额、成交日期和阶段的潜在营收事件。这是销售代表每天都要处理的记录。

## 7 个销售阶段

每个商机都会经历这些阶段。系统会跟踪你所处的位置并自动更新赢单概率。

| 阶段 | 默认赢单概率 | 处于此阶段时 |
| --- | --- | --- |
| ⚪ **寻找客户** | 10% | 首次接触，审核预算和需求 |
| 🟠 **资格审查** | 25% | 你已识别出决策者 |
| 🟡 **需求分析** | 40% | 需求已被记录 |
| 🔵 **提案** | 60% | 报价已发送 |
| 🟣 **谈判** | 80% | 正在协商定价和条款 |
| 🟢 **成交** | 100% | **交易赢得** *(最终阶段)* |
| 🔴 **失败** | 0% | **交易失去** *(最终阶段)* |

你可以从任何开放阶段直接移动到**失败**（交易随时可能失去），但你不能向前跳过——你必须一次一个阶段地走过漏斗。系统会拦截无效跳转，以保持你的预测真实可靠。

## 关单必须填写原因

关闭商机时必须多填一个字段,否则记录保存不了:

| 关单方式 | 必填字段 |
| --- | --- |
| 🟢 **成交** | **赢单原因** —— 产品更优 / 价格更优 / 客户关系 / 支持更好 / 最佳契合 / 其他 |
| 🔴 **失败** | **丢单原因** —— 价格过高 / 输给竞争对手 / 无预算 / 未决策 / 时机不合适 / 功能缺失 / 其他 |

旁边的 **赢/丢单详情** 是自由文本框,写下半年后同事真正需要的那句话("对方市场部被 HubSpot 两年合同锁定,续约时再谈")。

两点须知:

- **这是服务端校验**,不只是表单提示。导入、API 调用或批量更新在缺少对应原因时同样会被拒绝。
- **已关单的商机是锁定的**。关单之后只有叙述性字段(描述、后续步骤)还能编辑,原因无法事后补填——请在关单那一刻就选好。

如果商机是因为客户接受报价而成交,HotCRM 会自动关单并把赢单原因记为 **报价被接受**,详见[报价](/docs/sales/quotes)。

这两个字段正是销售仪表盘 **Win Rate** 与 **Why We Lose** 组件的数据来源,详见[仪表盘](/docs/analytics/dashboards)。

## 商机记录存储的内容

详情界面有 7 个区块：

| 区块 | 字段 |
| --- | --- |
| **基本信息** | 名称、客户、主要联系人、负责人 |
| **财务** | 金额、预期营收 *(自动)*、概率 *(从阶段自动得出)* |
| **销售流程** | 阶段、成交日期、创建日期、进入当前阶段日期 |
| **分类** | 类型（新业务 / 升级 / 续约 / 扩展）、线索来源、赢单原因、丢单原因、赢/丢单详情 |
| **营销活动** | 来源营销活动 |
| **备注与后续步骤** | 描述、后续步骤 |
| **预测与指标** | 行项目合计、审批状态 |

## 商机类型

| 类型 | 含义 |
| --- | --- |
| **新业务** | 全新的品牌 / 客户 |
| **现有 - 升级** | 现有客户升级到更高层级 |
| **现有 - 续约** | 现有合同续约 |
| **现有 - 扩展** | 现有客户增加新产品线 |

按类型拆分交易对于准确的营收预测至关重要——新业务和续约的赢单率差异很大。

## 自动发生的事

你无需记住其中任何一项——系统会为你完成：

- 每当你推进交易时，**概率**会从阶段中设定（如果你有特殊情况，*可以*手动覆盖，但下次阶段变化时它会重置）。
- **预期营收** = 金额 × 概率 ÷ 100，每当金额或概率变化时重新计算。
- **进入当前阶段日期**在交易创建时打上，之后每次移动到新阶段都会重新打上。**当前阶段停留天数**由它推算，因此始终是最新的——这正是暴露停滞交易的依据。
- 当你将一笔交易标记为**成交且金额为 $100K 及以上** 时，销售管理层会收到邮件。
- 当金额超过 **$500K** 时，交易会自动进入 [折扣审批](/zh-Hans/docs/revenue/approvals) 流程。

## 行项目——实际在销售什么

每个商机可以有行项目——每个所售产品一项。每一行存储：

- 产品（来自目录）
- 数量
- 单价（默认为产品的标价，可以被覆盖）
- 折扣 %
- 行合计

所有行项目之和汇总到商机**金额**中。如果你更愿意直接手动键入金额而不配置行项目，也可以——两种方式都行。

## 高价值交易的折扣审批

如果一笔交易的**金额超过 $500,000**，商机会被自动路由进行审批：

1. 商机被**锁定**——无人可以编辑它。
2. **销售经理**首先审核。
3. 如果批准，**销售总监**签字确认。
4. 最终批准后，阶段会被自动设为**成交**。
5. 如果在任何步骤被拒绝，交易会被退回给销售代表重新论证。

审批状态会显示为商机详情界面顶部的横幅。完整流程参见 [Revenue › Approvals](/zh-Hans/docs/revenue/approvals)。

## 共享——谁能看到哪笔交易

默认情况下商机是**私有**的——只有负责人能看到。岗位是扁平的，**什么都不会上卷**，所以没有人因为“在负责人之上”而看到某笔交易；其他能看到的人都由下面的规则点名。

在此之上：

- **$100K 或以上的开放商机**会以*只读*方式共享给 `sales_director` 岗位 —— 而且因为什么都不会上卷，另有一条规则把同一批交易共享给 `executive`。这样领导层无需跟进就能看到大单。
- **审批中的高价值交易**无论归属如何，审批人都可见。

## 标准列表视图

商机列表默认打开**进行中商机**，列表顶部的视图切换器里就是下面这九个已保存视图——只有这九个：

| 视图 | 展示什么 |
| --- | --- |
| **进行中商机**（默认打开） | 所有未赢单、未丢单的交易，按成交日期由近及远排列，行按阶段着色。**金额**与**预期营收**两列带合计。 |
| **我的进行中商机** | 同样的"进行中"过滤条件，只保留你负责的交易。 |
| **销售流水线** | 看板视图——每个阶段一列，只含进行中的交易，拖动卡片即可推进阶段。也可从侧边栏的**销售管道**直接进入。 |
| **全部商机** | 不过滤的完整台账，*含*已结束的交易，按成交日期由远及近排列。赢单/丢单复盘和审计从这里开始。 |
| **预测日历** | 所有交易按成交日期落在月历上，按阶段着色。 |
| **商机时间线** | 每笔交易一根横条，从创建当天延伸到成交日期，按负责人分组、以月为刻度。 |
| **商机卡片** | 卡片墙——客户、金额、阶段、赢单概率、成交日期、负责人——用于流水线评审和管理层过会。 |
| **⚠️ 停滞商机 · 按阶段停留时间排序** | 进行中的交易按在当前阶段停留的时间排序，停得最久的排在最上面。这里不按停留天数做截断——**当前阶段停留天数**是一列，等了多久直接在行上读。真正据此行动的是每日的[停滞商机提醒](/zh-Hans/docs/administration/automation)：一笔交易在同一阶段停满 14 天，就会提醒负责人。 |
| **本季度待成交商机** | 处于**承诺（Commit）**或**最佳情况（Best Case）**、且成交日期落在当前季度内的进行中交易——见下文。 |

### 本季度待成交商机

这是销售经理在季度末真正使用的视图，它同时受三个条件约束：

- **预测类别**——只要**承诺（Commit）**和**最佳情况（Best Case）**。
- **仍在进行中**——赢单和丢单永远不会出现。
- **成交日期落在当前季度内**——季度的两端都是列表每次查询时现算的，因此它会自己滚进下一个季度，不需要有人去改视图。

第三个条件才是让这个名字名副其实的那个：把**金额**列加总，得到的是*本季度*的承诺数，而不是"所有迟早会成交的进行中交易"之和。一笔预计明年 3 月成交的交易不会出现在这里——它待在**进行中商机**里，等它的季度到了才过来。记录按成交日期由近及远排列。

**这里空着是一个答案，而不是视图坏了。** 没有记录匹配时，视图会用一段说明取代表格——*本季度暂无待成交商机*，并指回**进行中商机**——因为"本季度的承诺全部滑出去了"恰恰是经理必须看见的状态。刚装好示例数据的演示环境在季度最后几天也会看到同一屏：此时所有样例交易都落在了下个季度。

## 商机详情布局

当你打开一个商机时，会看到：

- **头部**——名称、带 7 阶段路径的阶段徽章、金额、成交日期、负责人。点击路径上的任意阶段可直接跳转到它。
- **销售路径**——一键阶段推进。
- **报价**相关列表——带有一个**生成报价**按钮，可运行 [报价生成流程](/zh-Hans/docs/sales/quotes)。
- **行项目**——带有一个**添加产品**按钮。
- **活动时间线**——统一汇集评论、已记录通话（`sys_activity`）、外发邮件（`sys_email`）、任务完成以及字段历史审计条目。商机上每个被跟踪的更改（阶段、金额、成交日期、负责人）都会自动出现在这里；没有单独的"历史"标签页。
- **竞争对手与备注**——不存在这样一个面板。这一页（`src/pages/opportunity_detail.page.ts`）声明了三个区域：一个头部、一个装着那组标签页的主列，以及一条窄侧栏（`aside`），而侧栏里唯一的组件就是下一条讲的参考栏。页面上没有任何组件渲染「谈话要点」，也没有竞争对手字段可渲染了：商机上那个**竞争对手**多选字段只有三个占位选项（*Competitor A*、*Competitor B*、*Competitor C*），应用里没有任何界面把它读回来，#1061 已将其退役。应用里仅存的竞争对手信号，是「输给竞争对手」这条丢单原因，以及它旁边的自由文本 **丢单详情**。这一页上最接近「备注」的，是 *Details* 标签页里那个可折叠的 **描述** 分区，里面放着 **描述** 与 **下一步**。
- **AI 参考栏**——参考栏确实存在，但里面没有任何一条建议，这一页上也没有任何一个组件是 AI 驱动的。它是那条侧栏里的一个 `record:reference_rail`，三张卡片每一张都只是已经关联到本商机的记录快照：报价单 `crm_quote`（经其 **商机** 查找字段）、本商机的 `crm_opportunity_line_item` 明细行、任务 `crm_task`（经 **关联商机** 字段）。每张卡片给出关联记录总数的徽章、最多三条记录，以及一个跳转到完整列表的 *View all* 链接；查出来是空的卡片会折叠成一个 *+ N empty* 小按钮。卡片的标题按你当前阅读界面的语言取自对象标签——中文界面下是**报价单**、**商机产品明细**、**任务**——因为参考栏的条目自己不声明标题，标题是到译文包里查的，与全站其他地方取对象名的来源是同一处。两点提醒。参考栏的条目无法过滤，这三条也都没有声明过滤条件：查询只按关联字段走，所以任务那张卡片统计和列出的是本商机的全部任务，不分状态。这也正是它的标题是**任务**而不是「待办任务」的原因——真正过滤掉 *Completed*、一次十条的，是 *Related* 标签页上的 **Open Tasks** 列表。另外，参考栏里没有 Customer 360、没有营收预测，也没有任何「相关信号」，整页都没有：那些技能是靠提问去用的——见下文《AI Copilot 如何提供帮助》。

## AI Copilot 如何提供帮助

当你打开一个商机时，可以提问：

- *"What's at risk here?"*——营收预测技能会检查阶段停留时长、活动空档和成交日期滑移。
- *"Draft a follow-up email"*——邮件起草技能会撰写下一条外发消息。
- *"Summarise this account"*——Customer 360 技能给你一屏的客户历史简报。

## 给销售代表的提示

- ✅ **及时推进阶段**——如果你的阶段错了，概率就是错的。
- ✅ **添加行项目**以进行恰当的营收预测；汇总后的金额更准确。
- ✅ **填写后续步骤**——这是交接和站会中最有用的单个字段。
- ✅ **在成交时记录赢单/丢单原因**——*赢单原因*、*丢单原因* 与 *丢单详情* 是应用里仅有的竞争数据，而它们只有你填了才存在。
- ❌ 不要为了让交易看起来还在正轨上就把成交日期往后推。日期诚实，**本季度待成交商机**的合计才是对的；而一笔停下来的交易，会按它在当前阶段停留的时间浮现在**停滞商机**里，跟成交日期写成什么无关。

## 给管理员的提示

- 阶段列表、默认概率和合法的状态转换分散在源码的三处，而不是某个 Setup 界面：共享选择列表 `OPPORTUNITY_STAGE_OPTIONS`（`src/objects/_picklists.ts`），由 `stage` 字段渲染；`opportunity_lifecycle` 钩子里的 `STAGE_PROBABILITY` 映射（`src/objects/opportunity.hook.ts`），每次保存都据此重新同步*成交概率*；以及商机对象上名为 `opportunity_stage_progression` 的状态机校验规则（`src/objects/opportunity.object.ts`）。三处需同步修改。参见 [Customization › Extending Objects](/zh-Hans/docs/customization/extending-objects)。
- $500K 折扣审批阈值可以在 [审批流程配置](/zh-Hans/docs/revenue/approvals) 中更改。
- $100K 大单通知阈值同样不是 Setup 界面上的字段：它是 `opportunity_won_alert` 流程的 CEL 起始条件——`src/flows/opportunity-won-alert.flow.ts` 里的 `record.amount >= 100000`。收件人则由该流程 `notify` 节点的 `recipients` 决定，列表里只有 `{record.owner_id}` 一项，即商机负责人本人。
