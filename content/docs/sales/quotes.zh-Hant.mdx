# 報價

**報價**是發送給客戶的正式定價提案。報價始終屬於某個商機，並擷取其呈現時刻的定價。一旦報價被接受，它就成為合約的基礎。

## 6 種報價狀態

| 狀態 | 含義 |
| --- | --- |
| ⚪ **草稿** | 正在內部準備 *(新建報價的預設值)* |
| 🟠 **審核中** | 等待內部審核（例如折扣審批） |
| 🔵 **已提交** | 已發送給客戶 |
| 🟢 **已接受** | 客戶已同意——自動觸發合約建立 |
| 🔴 **已拒絕** | 客戶已拒絕 |
| ⚪ **已過期** | 有效期已過但未作出決定 |

一段典型的旅程：**草稿 → 已提交 → 已接受 →（合約）**。

## 報價記錄儲存的內容

詳情介面有 5 個區塊：

| 區塊 | 欄位 |
| --- | --- |
| **報價資訊** | 報價編號、名稱、狀態、客戶、聯絡人、商機、負責人 |
| **定價** | 小計、折扣 %、折扣金額、稅費、運費及手續費、總計 |
| **條款與有效期** | 報價日期、到期日期、付款條款、運輸條款 |
| **地址** | 帳單地址、收貨地址 |
| **系統** | 描述（面向客戶）、內部備註（僅供你查看） |

### 付款條款

Net 15 · Net 30 *(預設)* · Net 60 · Net 90 · Due on Receipt。

## 價格是如何計算的

系統會為你完成計算：

```
Subtotal       = sum of all line items
Discount       = Subtotal × Discount % ÷ 100
Total Price    = Subtotal − Discount + Tax + Shipping & Handling
```

你在行項目、折扣、稅費或運費欄位中更改的任何內容，合計都會自動更新。

## 行項目

一份報價可以有任意數量的行項目——每個所售產品一項。每一行儲存：

- 產品（來自目錄）
- 數量
- 單價（預設為產品的標價）
- 單行折扣 %
- 行合計

行項目之和彙總到報價小計中。

## 內建規則

- **到期日期必須晚於報價日期**——不能建立即到期的報價。
- **折扣不能超過 100%**——基本的合理性檢查。

## 自動發生的事

- **每日到期掃描**——每晚凌晨 1 點，系統會將任何到期日期已過的報價標記為**已過期**（除非它已被接受或拒絕）。保持你的活躍列表乾淨整潔。
- **接受時**——把一份報價標記為*已接受*，就是起草合約的那個動作。系統會插入一份*草稿*狀態的合約，合約類型為*訂閱合約*，期限 12 個月、從今天起算，帶著報價上的所屬客戶、主要聯絡人、關聯商機、負責人和總金額。隨後它把關聯的商機推進到*成交*，成交日期取今天；並且僅當銷售代表沒有填贏單原因時，才補上**報價被接受**。已經關閉的商機——不論成交還是失敗——原樣不動。

有兩件事讀者常以為在這一步就發生了，其實要等到**有人去啟用那份合約**才發生，不在接受報價這一步：

- **客戶是在合約啟用時轉正的，不是在報價接受時。** 把客戶的類型從*潛在客戶*改成*正式客戶*，是合約啟用時的那次寫入，而接受報價產出的是一份*草稿*。在 Sales Manager 或管理員把那份合約啟用之前，這個客戶仍然是潛在客戶。
- **續約提醒不在這一步排，也不是 60 天那一條。** 續約提醒來自每日續約掃描，它只讀*已啟用*的合約，用的是每份合約自己的**續約通知（天）**——預設 **30**，而且逐份可設。停在*草稿*的合約它根本掃不到，所以這份合約一條提醒也不會有。

這兩件事的完整說明在[合約](/zh-Hant/docs/revenue/contracts)頁。

這些連結是抄過來的，不是憑空補出來的：起草出來的合約要求填**主要聯絡人**，而它取自報價；推進成交那一步認的是報價上的**關聯商機**。所以在標記接受之前，先把這兩項掛到報價上——報價上沒有的，接受這一步也傳不下去。

## 生成報價

你不需手動建立報價——而是打開任意商機並點擊**生成報價**。會彈出一個簡短的表單：

- 報價名稱
- 有效期（天）——預設 30
- 折扣 %

然後系統會一步完成：

1. 以**草稿**狀態建立報價，並將商機的金額作為小計。
2. 套用折扣並重新計算總計。
3. 將商機推進到**提案**階段。
4. 將商機的最近活動蓋戳為今天。
5. 向你發送一封確認郵件。

隨後銷售代表審核該草稿，附上一份 PDF（或使用內建範本），並將狀態更改為*已提交*以將其發送給客戶。

## 將報價發送給客戶

在報價詳情頁，點擊**發送給客戶**。這會將狀態設為*已提交*，並使用報價封面郵件範本將 PDF 透過郵件發送。Sales Copilot 可以為你起草封面郵件——*"Draft a cover note for this quote"*。

## 標記為已接受 / 已拒絕

詳情介面上的兩個按鈕可以閉合循環：

- **標記已接受** → 狀態 = 已接受；觸發上文所述的合約鏈。
- **標記已拒絕** → 狀態 = 已拒絕；商機保持開放（你可以以更低的價格重新報價）。

## 高價值折扣審批

如果一份報價的總計超過折扣審批閾值（例如總計 > $500K 或折扣 > 30%），關聯的商機會進入 [折扣審批](/zh-Hant/docs/revenue/approvals) 流程。報價頂部會顯示一個橫幅——在審批通過之前你無法將其標記為*已提交*。

## 標準列表視圖

報價單列表預設打開**全部報價單**，切換器裡就是下面這三個已儲存視圖——只有這三個：

| 視圖 | 展示什麼 |
| --- | --- |
| **全部報價單**（預設打開） | 所有報價單，按**報價日期**由近及遠排列，**報價單編號**固定在最左側，點它進入記錄。**小計**、**稅額**、**總金額**三欄帶合計，畫面上有什麼，合計就是什麼；列上還有所屬客戶、關聯商機、狀態、到期日期、折扣和負責人。每頁 25 列。 |
| **報價流水線** | 同一批報價單以看板呈現，一個狀態一欄（六種狀態見上文的狀態表），每欄彙總**總金額**。「有多少卡在審核裡」「發出去的報價一共多少錢」這兩個問題在這裡看；已接受那一欄就是贏下來的報價。 |
| **報價日曆** | 每張報價單在月曆上畫成一根橫條，從**報價日期**延伸到**到期日期**，標題是報價單編號，按狀態著色。快要失效的，就是那根結束時間離今天最近的橫條。 |

這三個視圖都不帶過濾條件——不按負責人切，不開時間窗，也沒有「只看進行中」。有兩件事讓它照樣夠用：

- **狀態本身就是過濾器。** 看板把還在推進中的幾欄和已結束的幾欄分開擺；每晚的過期清掃又會把過了到期日的報價自動改成已過期，所以不需要誰去維護一張「進行中」的名單，前面幾欄自己就是乾淨的。
- **到期日期這一欄可以排序。** 在全部報價單裡按它升序排，就是「最近要失效的」那張表——而且是對整本帳冊排的，不是固定一週的窗口。

剛建好的組織裡一張報價單也沒有——報價只能從商機生成、不能憑空建立——所以列表這時候是空的，這很正常。這三個視圖都沒有宣告空態文案，因此你看到的會是一張空網格，而不是一段說明。

## 給銷售代表的提示

- ✅ 如果你大幅折扣，請始終在*內部備註*中包含折扣原因。
- ✅ 從商機使用**生成報價**按鈕，而不是從頭建立報價——它會自動填充所有內容。
- ✅ 檢查有效期（到期日期）是否與你的業務週期相匹配。按季採購的買家需要有效期到季末的報價。
- ❌ 不要更改已提交報價上的定價——它會讓客戶困惑。改為建立一個新修訂版。

## 給管理員的提示

- 每日到期掃描在凌晨 1 點執行。要更改時間，請調整報價物件工作流上的排程。
- 報價 PDF 範本（封面和行項目版面）儲存在你的郵件範本設定中。
- 要在系統級 $500K 閾值之下要求經理審批（例如對每個折扣 >20% 的報價），請新增一個工作流，將報價翻轉為*審核中*並通知經理。參見 [Administration › Automation](/zh-Hant/docs/administration/automation)。
