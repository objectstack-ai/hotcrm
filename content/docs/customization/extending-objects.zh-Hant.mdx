# 擴展物件

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

HotCRM 物件位於擁有它的那個套件的 `objects/` 目錄下——`src/sales/`、`src/service/`、`src/revenue/` 或 `src/marketing/`——每個套件各自從該目錄的 `index.ts` 註冊自己的物件。`src/` 下沒有頂層的 `objects/` 目錄：`src/` 下的一個目錄**就是**一個套件（ADR-0130）。下面這個 warranty 放進 revenue 套件，與 `crm_product`、`crm_contract` 這些它緊挨著的物件為鄰；你自己的物件放在它所屬領域的那個套件裡。

## 新增物件

```ts
// src/revenue/objects/warranty.object.ts
import { ObjectSchema, Field } from '@objectstack/spec/data';

export const Warranty = ObjectSchema.create({
  name: 'crm_warranty',
  label: 'Warranty',
  pluralLabel: 'Warranties',
  icon: 'shield',
  fields: {
    warranty_number: Field.autonumber({ label: 'Warranty Number', format: 'WR-{000000}' }),
    crm_account: Field.lookup('crm_account', { label: 'Account', required: true }),
    crm_product: Field.lookup('crm_product', { label: 'Product' }),
    status: Field.select({
      label: 'Status',
      defaultValue: 'active',
      options: [
        { label: 'Active', value: 'active', default: true },
        { label: 'Expired', value: 'expired' },
      ],
    }),
  },
  enable: {
    apiEnabled: true,
    searchable: true,
    trackHistory: true,
  },
});
```

然後匯出：

```ts
// src/revenue/objects/index.ts
export { Warranty } from './warranty.object.js';
```

## 新增生命週期邏輯

`*.hook.ts` 與它命名的那個 `*.object.ts` 並排放在同一個套件裡，並從該套件自己的 `objects/hooks.ts` 註冊——這裡是 `src/revenue/objects/hooks.ts`——再由 `objectstack.composition.ts` 彙入 `allHooks`。兩處都沒到達的 hook 會被靜默忽略：建置照樣是綠的，而處理函式永遠不會執行。

```ts
// src/revenue/objects/warranty.hook.ts
import type { Hook } from '@objectstack/spec/data';

const warrantyHook: Hook = {
  name: 'crm_warranty_hook',
  object: 'crm_warranty',
  events: ['beforeInsert', 'beforeUpdate'],
  handler: async (ctx) => {
    const doc = ctx.input.doc as Record<string, unknown>;
    if (doc.status === 'expired' && !doc.end_date) {
      throw new Error('Expired warranties need an end date.');
    }
  },
};

export default warrantyHook;
```

## 新增自動化

多步驟自動化寫在其觸發物件所屬套件的 `flows/` 目錄下——`src/sales/flows/`、`src/service/flows/`、`src/revenue/flows/` 或 `src/marketing/flows/`。warranty 提醒由 `crm_warranty` 觸發，所以它和上面那個物件一樣歸 revenue 套件。

```ts
// src/revenue/flows/warranty-alert.flow.ts
import type * as Automation from '@objectstack/spec/automation';

type Flow = Automation.Flow;

export const WarrantyAlertFlow: Flow = {
  name: 'warranty_alert',
  label: 'Warranty Alert',
  type: 'record_change',
  status: 'active',
  variables: [],
  nodes: [
    { id: 'start', type: 'start', label: 'Warranty updated', config: { objectName: 'crm_warranty', triggerType: 'record-after-update' } },
    { id: 'end', type: 'end', label: 'End' },
  ],
  edges: [{ id: 'e1', source: 'start', target: 'end', type: 'default' }],
};
```

註冊分兩步，漏掉第二步會讓這條流程被靜默丟棄。先從該套件的 barrel 重新匯出，再把它加入
`objectstack.composition.ts` 裡的 `allFlows` —— 正是這個陣列、而不是那個 barrel，被
`objectstack.config.ts` 交給 `defineStack({ flows })`：

```ts
// src/revenue/flows/index.ts —— 套件自己的 barrel：只做重新匯出，別無其它
export { WarrantyAlertFlow } from './warranty-alert.flow.js';
```

```ts
// objectstack.composition.ts —— 全應用的那份清單，按流程註冊順序排列
import { WarrantyAlertFlow } from './src/revenue/flows/index.js';

export const allFlows = [
  // …既有的流程
  WarrantyAlertFlow,
];
```

只進 barrel 是不夠的。`allFlows` 之所以是一份顯式有序清單，是因為註冊順序在四個套件之間交錯，
任何按套件切分的 barrel 都承載不了它。一條到了 barrel 卻沒進這個陣列的流程，註冊它的是零：
`pnpm validate` 照樣退出 0，而且哪裡都不會提到它——能發現它的是 `pnpm test`，套件會點名任何
被套件匯出、卻不在 `allFlows` 裡的流程。
