# Introduction

**HotCRM is a self-hosted, metadata-driven CRM application.** It is built on top of the [ObjectStack runtime](https://github.com/objectstack-ai/framework) and ships everything an early-stage sales team needs: accounts, contacts, leads, opportunities, quotes, contracts, campaigns, cases, and tasks.

Unlike a SaaS CRM, every piece of HotCRM's behaviour — fields, validation rules, page layouts, automation flows, AI agents — is **TypeScript source code in this repository**. There is no clicking through admin UIs hoping to remember what you changed; the code is the source of truth.

## What's in v0.1

| Layer | Count | Examples |
|---|---|---|
| Business objects | 13 | account, contact, lead, opportunity, quote, contract, campaign, case, task |
| Server-side hooks | 10 | account_protection, lead_validation, opportunity_close_guard |
| State machines | 2 | lead (open → qualified → converted), opportunity (prospecting → won/lost) |
| List views | 10 | one per core object |
| Pages | 12 | Home, App Launcher, detail pages, action modals |
| Automation flows | 5 | inline declarative pipelines |
| AI agents / skills | 2 / 2 | callable via `/api/v1/ai/*` |
| Sharing rules | 4 | + 10-level role hierarchy |
| Approval processes | 1 | quote discount approval |

About **90 seed records** ship in the box; they insert the first time a user signs up.

## Three Core Principles

### 1. Metadata-First

Everything is `*.object.ts`, `*.hook.ts`, `*.page.ts`, etc. There is no YAML or JSON. The compiler validates every field, every reference, every page binding **at build time** using `@objectstack/spec` schemas.

```ts
// src/objects/account.object.ts
export const Account = ObjectSchema.parse({
  name: 'account',
  label: 'Account',
  fields: {
    name: Field.text({ required: true, unique: true }),
    annual_revenue: Field.currency({ scale: 2 }),
    industry: Field.select({ options: industryOptions }),
    owner: Field.lookup({ object: 'sys_user' }),
  },
});
```

### 2. ObjectQL, not SQL

Data access goes through `broker.find(...)` / `broker.create(...)`. The runtime translates to SQL, MongoDB, or whichever driver is plugged in. Your business code stays driver-agnostic.

```ts
await ctx.api.find('opportunity', {
  filters: [['amount', '>', 50_000], ['stage', '!=', 'lost']],
  orderBy: [{ field: 'close_date', dir: 'asc' }],
});
```

### 3. AI-Native

AI agents are first-class metadata, not bolt-ons. The same `ctx.api` exposed to hooks is exposed to agents via tool definitions in `*.action.ts`. A human in `/_console/` and an LLM in `/api/v1/ai/agents/run` see exactly the same data plane.

## How It Compares

| | SaaS CRM (e.g. Salesforce) | HotCRM |
|---|---|---|
| Customisation | Clicks-then-code, locked schema | TypeScript everywhere |
| Hosting | Vendor cloud | Your machine, your VPC, your K8s |
| Data | Vendor's DB | SQLite / Postgres / Mongo / Turso |
| Plugin model | AppExchange | npm + plugin protocol |
| AI | Einstein (closed) | Bring-your-own LLM, declared in metadata |
| Source of truth | Production org | Git repo |
| Price | Per-seat SaaS | Open-source runtime + your infra |

## Who Is This For?

- **Engineering teams** that need a CRM but refuse a closed SaaS lock-in.
- **AI startups** building agent-driven business systems and need a real data plane.
- **Platform teams** that want to extend a working CRM rather than build from scratch.

## What HotCRM Is **Not** (yet)

The legacy 146-object scope (HR, Healthcare, Education, Real Estate, Financial Services) has been removed from the active codebase. The previous version of those docs is archived on the `legacy-archive` branch. If you need one of those verticals, port the relevant `*.object.ts` files into `src/objects/` and verify hooks against the runtime — see [Creating Objects](/docs/developers/creating-objects).
