# 订单与回款

合同签订后，销售最关心三个问题：**开票了吗？回款了吗？有没有逾期？**「订单与回款」回答的就是这三个问题。它是 HotCRM 的一个模块，有自己的应用**订单与回款**，财务在其中工作。

## 是窗口，不是账本 [#a-window-not-a-book]

每张发票、每笔回款都保存在财务记账的地方：ERP、财务软件，或财务自己的记录。「订单与回款」是销售**查看**它们的窗口。财务在记录页面上录入，或批量导入；ERP 也可以通过同一个导入编号写入。数字从不在 HotCRM 里更正：在源头更正后，再按同样的方式进来。

因此这个模块不做任何记账。它不开具、不审批发票，不分摊收款，不与银行对账，不催收，也不确认收入。[与财务软件的边界](/zh-Hans/docs/sales/billing-handoff)一页介绍了在赢单和合同生效时仍会通知计费系统的两个事件。

销售在这里维护的只有一样东西：自己的**回款计划**。

## 包含什么 [#what-is-in-it]

| 记录 | 是什么 | 由谁录入 |
| --- | --- | --- |
| **回款计划** | 按订单或合同制定的回款计划中的一步：预付款、上线、验收、质保金，或一个订阅周期 | 客户的销售团队 |
| **发票** | 财务开给客户的一张发票，可以针对订单或合同，也可以都不针对 | 财务 |
| **回款** | 客户付来的款项：对应发票、回款计划、订单、合同，或暂时都不对应 | 财务 |

三者都属于**客户**。回款计划写明它按哪张订单或哪份合同制定；发票和回款只在有订单或合同时才填。所以一张发票对应多个订单，或暂时对应不上任何发票的预收款，都只记在客户上。客户的**回款计划**、**发票**和**回款**标签页列出它的全部记录；订单和合同的标签页列出填了它的记录。归在合同下的订单，它的记录两者都填，所以合同的标签页和汇总包括它所有订单下的记录。

| 页面 | 内容 |
| --- | --- |
| [回款计划](./collection-plan) | 规划合同的回款计划，以及「已开票」「已回款」「未回款」各统计什么 |
| [发票与回款](./invoices-and-payments) | 录入和导入发票与回款、到期日、逾期发票 |

## 在哪里找到它 [#where-to-find-it]

| 谁 | 在哪里 |
| --- | --- |
| 财务（应收会计） | **订单与回款**应用：**应收**下的**发票**、**回款**和**回款计划**，**跟进**下的**逾期发票**和**本月计划回款**，以及这些记录所属的**合同**和**客户**。这是财务启动器上唯一的应用。 |
| 销售代表和销售经理 | **销售**应用**回款计划**分组下的**回款计划**，以及每张订单和每份合同上的**回款计划**、**发票**、**回款**标签页。销售代表的启动器上没有「订单与回款」应用。 |
| 销售经理和管理员 | 两处都有：他们的启动器提供全部四个应用。 |

启动器决定的是提供哪些应用，而不是能打开哪些：启动器上没有的应用，用地址照样能打开；每条记录的访问权限仍由它的共享规则决定。

## 谁能做什么 [#who-can-do-what]

| 人员 | 回款计划 | 发票与回款 |
| --- | --- | --- |
| 销售代表 | 在自己能查看的客户上新建、编辑、删除回款计划 | 只读 |
| 销售经理 | 在自己能查看的客户上新建、编辑、删除回款计划 | 只读 |
| 应收会计（财务） | 只读 | 在所有客户上录入、编辑、删除和导入 |
| 管理员 | 全部 | 全部 |

能查看客户，就足以按上表写入它的回款计划、发票和回款：销售代表不用编辑客户或合同就能维护回款计划，财务在只能查看的客户上录入发票和回款。不能查看客户的人，这三类记录都写不了。

其他能查看客户的人，在其角色本身能查看这些记录的范围内，也能随客户一起查看它的回款计划、发票和回款：这三类记录跟随客户的共享设置。财务的权限来自**应收会计**岗位，由管理员在 **Setup → Position Holders** 中指派。

销售从不录入回款。销售看到的数字永远是财务录入的，所以按回款计算的提成方案不会读到销售自己填写的数字。

## 不是每个客户都要用 [#not-every-customer-uses-it]

不需要「订单与回款」的公司，由管理员停用这个模块。它的应用、销售应用里的菜单项、记录，以及订单、合同和客户页面上的相关标签页和汇总数字都会随之消失；订单本身照常可用。

## 订单、合同和客户上的汇总 [#totals]

订单、合同和客户上各有本模块的汇总数字，销售不用打开页签就能看到：

| 字段 | 所在记录 | 统计什么 |
| --- | --- | --- |
| **计划回款** | 订单、合同 | 回款计划各节点的计划金额合计 |
| **已开票** | 订单、合同、客户 | 状态为**已开具**的发票金额合计；已作废的发票不计入 |
| **已回款** | 订单、合同、客户 | 回款金额合计 |
| **应收余额** | 合同、客户 | 客户在未结清发票上仍欠的金额：**已开具**发票的**未付**金额之和。尚未对应到发票的回款（例如预收款）只计入**已回款**，所以预收款不会让余额变成负数。多付的发票未付为零，所以多付也不会让余额变成负数 |

客户的汇总覆盖该客户的所有发票和回款，包括没填订单或合同的；订单和合同的汇总覆盖填了它的记录。这些数字都不是手工填写的：保存回款计划、发票或回款时随之更新。在订单上，它们显示在“价格”分区；在合同上，显示在“合同金额”分区；在客户上，显示在“财务信息”分区。交易业绩只按订单自己的合计统计，从不统计这些数字。能查看订单或合同的人都能看到它上面的汇总。客户上的汇总要有和客户款项打交道的角色才能看到：销售、财务、市场、服务、项目经理和管理员都能看到；只有每个成员都有的 **CRM User** 权限集的人，以及参与项目的顾问，能查看客户，但看不到这些汇总。没有人能编辑。

**订单上的记录跟着订单的合同走。** 订单的回款计划、发票和回款已经保存之后，订单才有了合同（点了**起草合同**，或选了订单的**关联合同**），这些记录里没填合同的会带上订单的合同，合同的汇总随即把它们算进去，不需要逐条重新保存。把订单改到另一份合同下时，原来跟着旧合同的记录一起改到新合同：旧合同的汇总减少，新合同的汇总增加。清空订单的合同时，这些记录的合同也一起清空，订单下一次有了合同（例如点了**起草合同**）再把它们补上。填了其他合同的记录保持不变。这一改动替修改订单的人完成，所以销售改订单会连带改掉财务的发票和回款上的合同，此外什么都不改；每条记录的历史里都能看到这次修改。
