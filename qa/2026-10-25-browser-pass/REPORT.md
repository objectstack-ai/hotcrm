## 2. 高优先级（影响理解或信任）

### 2.1 销售代表通过 URL 可打开被导航隐藏的「高管总览」
- 现象：`na.rep` 的侧栏没有「首页 / 高管总览」入口（`EXECUTIVE_AUDIENCE` 排除 sales_rep），但直接访问 `/dashboard/executive_dashboard` 页面完整渲染，11 个图表全部出数（按其可见数据聚合）。截图 `r7-rep-exec-dashboard.png`。
- 影响：导航可见性只是客户端礼貌，不是访问控制；如果「高管总览」的本意是管理层专属，这是一个信息边界问题。
- 建议：若只是「不想让代表看到」，现状可接受但应在文档写明；若是边界要求，需要在权限集层面限制仪表盘（服务端门控），这是平台能力（ADR-0124 D1），应上游提 issue。归属：平台 + HotCRM 权限集。

### 2.2 无可见记录时的空态误导为「还没有数据」
- 现象：销售代表打开工单列表显示「这里还没有数据 / 创建第一条记录即可开始」，而实际是 38 条工单对其不可见，且该用户根本没有「新建」按钮。截图 `r6-rep-cases.png`。
- 建议：区分三种空态——对象无记录 / 当前视图筛选无结果 / 当前用户无可见记录（「你没有可查看的工单，如需访问请联系管理员」）。归属：平台默认文案（objectui）。

### 2.3 「我的 xx」视图空态缺少行动引导
- 现象：我的商机、我的线索、我的工单、销售主页 My Leads 在没有记录时都只显示「没有匹配的记录 / 没有符合该视图筛选条件的记录」。截图 `35-crm_opportunity_view_my_open_deals.png`、`39-crm_case_view_my_open_cases.png`、`21-page_sales_home_page.png`。
- 建议：「我的」视图给面向动作的空态（「你还没有负责的商机 → 新建商机 / 去转化线索」）。按 AGENTS 规则 4，应改平台默认（视图可声明 emptyState 的动作按钮），而不是每个视图手写。归属：平台默认 + 视图元数据。

### 2.4 工单列表整行红底过多，列几乎全空
- 现象：全部工单 38 行里 29 行整行红底（`rowColor: is_sla_violated`），红色失去警示意义；深色模式下大片暗红更刺眼。「联系人 / 提交人姓名 / 提交人邮箱」三列在首屏 16 行里只有 3 个非空值。截图 `23-crm_case.png`、`d3-dark-case-list.png`。
- 建议：(a) 行级着色只用于「已违约且未关闭」，已关闭工单不再标红，或改为 SLA 列的徽标；(b) 演示种子把 SLA 违约比例降到 10–20%，否则演示观感很差；(c) 把 supplied_name / supplied_email 合并成一列「提交人」，或从默认列移到「网站来源」视图。归属：HotCRM（`src/service/views/case.view.ts` + 种子数据）。

### 2.5 线索转化后没有结果反馈与去向
- 现象：转化 Hugo Dubois 成功后停留在原线索页，只有 toast「线索转化成功！」，页面上没有新客户 / 联系人 / 商机的链接；通知中心的两条通知也没有链接。同时转化自动创建的客户「Nimbus Aerospace」触发了「客户审批」，出现在销售经理的审批箱里，转化人并不知情。截图 `75-lead-convert-result.png`、`87-notifications.png`、`g2-mgr-approvals.png`。
- 转化对话框本身也偏简陋：只有一段说明和一个「是否创建商机」圆形勾选，没有展示将创建的联系人、可选匹配已有客户。截图 `74-lead-convert-dialog.png`。
- 建议：转化完成后显示结果卡片（客户 / 联系人 / 商机三个链接 + 「客户待审批」状态）；对话框预览即将创建的三类记录并允许选择已有客户。归属：HotCRM flow（屏幕流结束页）+ 平台屏幕流完成态组件。

## 3. 中优先级（效率与一致性）

### 3.1 联系人默认视图首屏看不到任何联系人
- 现象：默认按所属客户分组且全部折叠，首屏是 9 个折叠的客户行，每组 1 条。截图 `28-crm_contact.png`。
- 建议：默认平铺列表（姓名、客户、职位、邮箱、电话），分组视图作为第二个视图保留；或分组默认展开。归属：HotCRM（`contact.view.ts` `grouping.collapsed: true`）。

### 3.2 销售预测双层分组噪音
- 现象：按「周期起始」再按「周期标签」两层分组，每组只有 1 行，6 条记录用了 18 行高度。源码注释说明这是因为平台分组不能按另一个字段排序而做的变通。截图 `45-crm_forecast.png`。
- 建议：上游给 `GroupingFieldSchema` 增加 `orderBy` 字段（objectui/spec）；短期把外层分组改成隐藏标题或把 period_label 做成可排序的「2026-10」格式。归属：平台缺口，HotCRM 暂时变通。

### 3.3 「客户工作台」与「客户」列表几乎相同
- 现象：两个导航入口，同样的列、同样的 9 行，仅多了三个快捷筛选芯片。截图 `26-crm_account.png` vs `27-page_account_workbench.png`。
- 建议：要么差异化（顶部放健康度 / 行业分布 KPI、风险客户提醒，做成真正的「工作台」），要么把快捷筛选并入客户列表并从导航移除。归属：HotCRM 页面。

### 3.4 i18n 遗漏
- 销售主页三个页签 `My Leads / My Open Deals / My Open Tasks` 在中文界面仍为英文（`home.page.ts` 硬编码 label）。截图 `21-page_sales_home_page.png`。
- 报表索引页 10 个报表的名称与描述全部英文（导航项有中文翻译「各阶段商机」，报表自身 label 没有），且索引页名称与导航名称不一致：「Cases Opened by Priority × Day」vs 导航「Cases Opened by Day」、「Lead Engagement by Month × Source」vs「Lead Inflow」。截图 `42-reports.png`、`94-report-opps-by-stage.png`。
- 客户地图加载失败提示为英文（见 3.9）。
- 归属：HotCRM 翻译包（报表 label / 页面页签），报表索引页的渲染归平台。

### 3.5 详情页空字段处理不一致、按钮重复
- 现象：商机详情中「分类」「资格评估」折叠为「显示 N 个空字段」，而「商机叙述」「备注与下一步」四个空字段用「—」平铺（`hideEmpty: false`）；同一页面两种规则。审批中的商机，「撤回」在顶部审批横幅和明细页签各出现一次（「撤回」/「撤回审批」）。截图 `51-opportunity-tall.png`。
- 建议：统一为折叠规则，叙述类长文本为空时显示一个「添加叙述」占位即可；撤回只保留一处。归属：HotCRM 页面配置 + 平台记录头。

### 3.6 文本截断
- 现象：工单详情表单里主题被截断为「Data export timing out for large...」（单行省略，长文本字段应换行）；关键字段带的 SLA 到期显示「2026/10/2…」；知识文章摘要「A five-minute tour of accounts,...」。截图 `52-case-tall.png`、`57-article-tall.png`。
- 建议：详情只读态的文本 / 长文本字段换行显示；关键字段带日期时间优先缩短格式而不是省略。归属：平台 objectui。

### 3.7 讨论流噪音
- 现象：营销活动详情的讨论区 13 条完全相同的「系统 · Updated Campaign "CPG-0001 - ..."」，看不出改了什么字段。截图 `56-campaign-tall.png`。
- 建议：系统更新事件显示字段变更摘要（如「实际收入 0 → 70,000」），同一分钟内同一操作者的多次更新折叠为一条。归属：平台审计 / 动态流。

### 3.8 仪表盘图表的 Brush 滑块
- 现象：「月度收入趋势」「每周活动量」「收入趋势」在只有 8–12 个点时也显示底部范围滑块，占高度且移动端难操作。截图 `30-dashboard_sales_dashboard.png`、`41-dashboard_sales_activity_dashboard.png`、`44-dashboard_crm_overview_dashboard.png`。
- 建议：点数少于阈值（如 24）时默认不渲染 brush。归属：平台图表默认（或 widget 配置）。

### 3.9 KPI 口径不一致且未标注
- 现象：销售主页「销售管道金额 2,017,500」vs 销售业绩「管道总额 1,878,000」（后者受「本季度」筛选）；高管总览「年度累计收入 1,290,000」vs CRM 总览「总收入 610,000」（本季度）。同义指标在不同页面数字不同，卡片没有写时间范围。
- 建议：KPI 卡片标题带口径（「本季度管道」「年度累计收入」），或副标题写明时间范围；同一指标在不同仪表盘用同一名称。归属：HotCRM 仪表盘 / 页面元数据。

### 3.10 侧栏折叠分组与单子项分组
- 现象：市场营销、数据洞察、报表三个分组默认折叠，管理员首屏看不到营销活动、预测、CRM 总览入口，分组标题也没有「有内容」的暗示；「报表」组实际只显示一个「全部报表」子项。截图 `10-hotcrm-landing.png`、`50-account-tall.png`（左栏）。
- 建议：单子项分组直接平铺为一级入口；折叠分组显示子项数量徽标。归属：HotCRM 导航 + 平台侧栏。

### 3.11 客户地图依赖外网瓦片
- 现象：地图视图请求 `demotiles.maplibre.org`，内网 / 离线时整块灰色并显示英文告警「Map failed to load (AJAXError...) configure a custom map style for production use」。截图 `92-account-map.png`。
- 建议：提供可配置的默认地图样式（Setup 里配置），失败时降级为带中文提示的地址列表。归属：平台（objectui map renderer）+ Setup 设置项。

## 4. 低优先级（细节打磨）

1. 客户详情「基本信息」里的 Markdown 描述占满首屏，电话 / 网站 / 地址 / 健康度被推到第二屏；建议描述放到独立页签或默认折叠显示前 3 行。截图 `50-account-tall.png`。归属：HotCRM 页面。
2. 相关页签里 0 条的「客户 0 暂无相关记录」「线索 0 暂无相关记录」仍各占一行；建议折叠到底部「其他（2 个为空）」。截图 `50-account-related.png`。归属：平台。
3. 桌面列表默认列过多：工单 14 列、报价「折扣」列被裁切需横向滚动；建议默认列控制在 8 列以内，其余放「列设置」。归属：HotCRM 视图。
4. 新建线索表单：名 / 姓分两列对中文用户不自然（中文环境下姓前名后或单字段「姓名」）；陌拜线索「邮箱」必填偏严格；顶部整段提示「请检查表单中标记的字段:名、姓、公司...」与逐字段红字重复。截图 `70-new-lead-form.png`、`71-new-lead-empty-submit.png`。归属：HotCRM 对象 / 平台表单。
5. 活动详情阶段条右侧「× 已取消 客户未到」两个终态挤在一起。截图 `60-event-tall.png`。归属：平台阶段条。
6. 控制台 warning（用户不可见但说明元数据有冗余键）：联系人 / 商机页面「form section { group: 'buying_centre' / 'qualification' } also declares collapsible, collapsed — ignored」，可清理；非管理员访问 `/api/v1/meta/_drafts` 返回 403（平台请求噪音）。
7. 首屏性能：冷加载 94 个 JS 文件约 13 MB 未压缩（`vendor-objectstack` 6.1 MB、`ui-components` 1.1 MB、`plugin-chatbot` 0.6 MB），仪表盘 37 个 API 请求约 3.5 MB，图表 2.1 s 出现。SPA 内切换很快（100–600 ms），所以体感主要在首次进入；建议平台侧拆分 vendor 包、聊天插件懒加载、meta 请求合并缓存。归属：平台。

## 5. 做得好的地方（建议保持）

- 视觉系统统一：品牌橙、徽标色、卡片与分隔一致，深色模式完整无漏色。
- 多视图完整：每个对象都有网格 / 看板 / 日历 / 时间线 / 卡片（客户还有地图），看板列头带数量与金额合计。
- 记录页信息架构好：标题 + 关键字段带 + 阶段进度条 + 页签 + 右侧相关摘要，商机 / 报价 / 合同 / 工单 / 文章都遵循同一骨架。
- 审批体验完整：通过 / 拒绝 / 转签 / 退回修改 / 退回补充 / 回复，列表有 j/k/a/r 快捷键，通过后记录即时显示「已批准 + 批准时间」。
- 表单校验友好：必填逐字段提示 + 顶部汇总，Ctrl+Enter 提交评论。
- ⌘K 全局搜索跨 6 类对象并按类型分组。
- 移动端自动切换卡片列表 + 悬浮新建按钮，详情页关键字段纵向堆叠，无横向溢出。
- 整轮测试 0 个 4xx/5xx（除预期的匿名 get-session 401）、0 个前端运行错误。
