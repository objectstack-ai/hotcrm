# 營收雲

營收模組涵蓋**銷售說"我們贏了"之後**發生的一切：管理產品目錄和價格、治理合約和續約，以及審批高價值折扣。

## 包含內容

| 領域 | 作用 |
| --- | --- |
| [**產品**](/zh-Hant/docs/revenue/products) | 你所銷售內容的目錄——名稱、編碼、標價、計費類型。 |
| [**合約**](/zh-Hant/docs/revenue/contracts) | 與客戶簽署的協議——條款、價值、續約。 |
| [**審批**](/zh-Hant/docs/revenue/approvals) | 針對高價值折扣的多步驟審批。 |

## 營收生命週期

```
Product (catalog)
   │
   ▼
Quote with line items
   │ (accepted)
   ▼
Contract (Activated)
   │
   ▼ (renewal_notice_days before end_date)
Renewal task ──► Renewal opportunity
```

1. **建立目錄**——帶編碼、標價、計費類型的產品。
2. **構建報價**——使用目錄中的明細行（參見 [報價](/zh-Hant/docs/sales/quotes)）。
3. **接受時**系統會以報價的條款建立一份合約。
4. **合約被啟用**——帳戶被提升為 *Customer*。
5. **合約結束前**，系統會安排一個續約任務和一個續約提醒。
6. **續約商機**可在客戶希望延期時建立。

## 系統為你做的事

- **自動提升帳戶**——合約被啟用的那一刻將帳戶提升為 *Customer*。
- **自動蓋簽署日期**——同一次啟用會在**合約**上寫入當天日期，且僅當合約上還沒有簽署日期時才蓋。**帳戶**上不會蓋任何日期：沒有 *Customer Since* 欄位，也沒有任何其它名字的欄位記錄帳戶何時成為客戶，所以做同期群分析只能讀合約的**簽署日期**或**開始日期**。
- **每日到期掃描**——午夜時分，超過結束日期的合約被標記為 *Expired* 並通知所有者。
- **每日續約提醒**——當合約進入它自己的通知視窗（**續約通知（天）**，不改就是 30 天）時，**合約負責人**會收到一個續約任務和一條提醒（站內收件匣 + 郵件）。除他之外無人被通知——帳戶所有者不會，帳戶上的續約負責人也不會。
- **折扣審批**——超過 $500K 的商機自動路由給經理 + 總監簽批。

## 在哪裡找到這些內容

Enterprise CRM 應用裡**沒有 Products（產品）群組**。產品目錄在側邊欄上唯一的入口是 **Marketing**（市場行銷）群組下的 **Products**（產品）——參見 [Marketing](/zh-Hant/docs/marketing/index)。除了這一項和全域搜尋之外，只能從報價或商機的明細列反查到產品記錄。

**Contracts**（合約）掛在 **Sales**（銷售）群組下，與 Leads、Accounts、Contacts、Opportunities、Pipeline、Quotes 並列——因為合約屬於銷售流程。這也是整個應用側邊欄裡通往合約的唯一入口。

**Approvals**（審批）群組只有一項：

- **Inbox**——等著你處理的審批請求（`sys_approval_request`）。側邊欄上的 label 就是 **Inbox**（本應用提供 en / zh-CN / ja-JP / es-ES 四種介面語言，簡體中文介面下這一項顯示為「待我审批」）；應用裡沒有任何條目叫 *Approval Requests*（審批請求）。

本頁過去列出的另外兩個名字，不在這個群組裡：

- **Action History**（操作歷史）——側邊欄上沒有叫這個名字的條目。審批的操作留痕本身是真實資料，由審批外掛以 `sys_approval_action` 儲存，但本應用裡沒有任何導覽條目能打開它。
- **Processes**（流程）——是被**刻意刪掉**的，不是漏掉的：任何已安裝的外掛裡都不存在 `sys_approval_process` 物件，該條目的 *requires object* 守衛會在每一次安裝裡把它永遠隱藏。除非將來有這樣一個物件上線，它不會回來。

**Marketing** 與 **Approvals** 兩個群組都**預設摺疊**——與 Sales、My Work、Activity、Service 不同，它們不會在應用載入時自動展開。先把群組點開，再判斷某樣東西在不在這裡。
