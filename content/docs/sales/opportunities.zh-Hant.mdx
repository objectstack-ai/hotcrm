# 商機

**商機**是一筆活躍的交易——一個有已知客戶、金額、成交日期和階段的潛在營收事件。這是銷售代表每天都要處理的記錄。

## 7 個銷售階段

每個商機都會經歷這些階段。系統會追蹤你所處的位置並自動更新贏單機率。

| 階段 | 預設贏單機率 | 處於此階段時 |
| --- | --- | --- |
| ⚪ **尋找客戶** | 10% | 首次接觸，審核預算和需求 |
| 🟠 **資格審查** | 25% | 你已識別出決策者 |
| 🟡 **需求分析** | 40% | 需求已被記錄 |
| 🔵 **提案** | 60% | 報價已發送 |
| 🟣 **談判** | 80% | 正在協商定價和條款 |
| 🟢 **成交** | 100% | **交易贏得** *(最終階段)* |
| 🔴 **失敗** | 0% | **交易失去** *(最終階段)* |

你可以從任何開放階段直接移動到**失敗**（交易隨時可能失去），但你不能向前跳過——你必須一次一個階段地走過漏斗。系統會攔截無效跳轉，以保持你的預測真實可靠。

## 結案必須填寫原因

關閉商機時必須多填一個欄位,否則記錄無法儲存:

| 結案方式 | 必填欄位 |
| --- | --- |
| 🟢 **成交** | **贏單原因** —— 產品更優 / 價格更優 / 客戶關係 / 支援更好 / 最佳契合 / 其他 |
| 🔴 **失敗** | **丟單原因** —— 價格過高 / 輸給競爭對手 / 無預算 / 未決策 / 時機不合適 / 功能缺失 / 其他 |

旁邊的 **贏/丟單詳情** 是自由文字框,寫下半年後同事真正需要的那句話（「對方行銷部被 HubSpot 兩年合約鎖定,續約時再談」）。

兩點須知:

- **這是伺服器端驗證**,不只是表單提示。匯入、API 呼叫或批次更新在缺少對應原因時同樣會被拒絕。
- **已結案的商機是鎖定的**。結案之後只有敘述性欄位（描述、後續步驟）還能編輯,原因無法事後補填——請在結案當下就選好。

如果商機是因為客戶接受報價而成交,HotCRM 會自動結案並把贏單原因記為 **報價被接受**,詳見[報價](/docs/sales/quotes)。

這兩個欄位正是銷售儀表板 **Win Rate** 與 **Why We Lose** 元件的資料來源,詳見[儀表板](/docs/analytics/dashboards)。

## 商機記錄儲存的內容

詳情介面有 7 個區塊：

| 區塊 | 欄位 |
| --- | --- |
| **基本資訊** | 名稱、客戶、主要聯絡人、負責人 |
| **財務** | 金額、預期營收 *(自動)*、機率 *(從階段自動得出)* |
| **銷售流程** | 階段、成交日期、建立日期、進入當前階段日期 |
| **分類** | 類型（新業務 / 升級 / 續約 / 擴展）、潛在客戶來源、贏單原因、丟單原因、贏/丟單詳情 |
| **競爭與行銷活動** | 競爭對手、來源行銷活動 |
| **備註與後續步驟** | 描述、後續步驟 |
| **預測與指標** | 行項目合計、審批狀態 |

## 商機類型

| 類型 | 含義 |
| --- | --- |
| **新業務** | 全新的品牌 / 客戶 |
| **現有 - 升級** | 現有客戶升級到更高層級 |
| **現有 - 續約** | 現有合約續約 |
| **現有 - 擴展** | 現有客戶增加新產品線 |

按類型拆分交易對於準確的營收預測至關重要——新業務和續約的贏單率差異很大。

## 自動發生的事

你無需記住其中任何一項——系統會為你完成：

- 每當你推進交易時，**機率**會從階段中設定（如果你有特殊情況，*可以*手動覆蓋，但下次階段變化時它會重置）。
- **預期營收** = 金額 × 機率 ÷ 100，每當金額或機率變化時重新計算。
- **進入當前階段日期**在交易建立時打上，之後每次移動到新階段都會重新打上。**當前階段停留天數**由它推算，因此始終是最新的——這正是暴露停滯交易的依據。
- 當你將一筆交易標記為**成交且金額超過 $100K** 時，銷售管理層會收到郵件。
- 當金額超過 **$500K** 時，交易會自動進入 [折扣審批](/zh-Hant/docs/revenue/approvals) 流程。

## 行項目——實際在銷售什麼

每個商機可以有行項目——每個所售產品一項。每一行儲存：

- 產品（來自目錄）
- 數量
- 單價（預設為產品的標價，可以被覆蓋）
- 折扣 %
- 行合計

所有行項目之和彙總到商機**金額**中。如果你更願意直接手動鍵入金額而不設定行項目，也可以——兩種方式都行。

## 高價值交易的折扣審批

如果一筆交易的**金額超過 $500,000**，商機會被自動路由進行審批：

1. 商機被**鎖定**——無人可以編輯它。
2. **銷售經理**首先審核。
3. 如果批准，**銷售總監**簽字確認。
4. 最終批准後，階段會被自動設為**成交**。
5. 如果在任何步驟被拒絕，交易會被退回給銷售代表重新論證。

審批狀態會顯示為商機詳情介面頂部的橫幅。完整流程參見 [Revenue › Approvals](/zh-Hant/docs/revenue/approvals)。

## 共享——誰能看到哪筆交易

預設情況下商機是**私有**的——只有負責人以及角色層級中位於其之上的人才能看到。

在此之上：

- **$100K 或以上的開放商機**會以*唯讀*方式與銷售總監及層級中位於其之下的所有人共享。這樣領導層無需跟進就能看到大單。
- **審批中的高價值交易**無論歸屬如何，審批人都可見。

## 標準列表視圖

商機列表預設打開**進行中商機**，列表頂部的視圖切換器裡就是下面這九個已儲存視圖——只有這九個：

| 視圖 | 展示什麼 |
| --- | --- |
| **進行中商機**（預設打開） | 所有未贏單、未丟單的交易，按成交日期由近及遠排列，列按階段著色。**金額**與**預期營收**兩欄帶合計。 |
| **我的進行中商機** | 同樣的「進行中」過濾條件，只保留你負責的交易。 |
| **銷售流水線** | 看板視圖——每個階段一欄，只含進行中的交易，拖動卡片即可推進階段。也可從側邊欄的**銷售管道**直接進入。 |
| **全部商機** | 不過濾的完整帳冊，*含*已結束的交易，按成交日期由遠及近排列。贏單／丟單複盤和稽核從這裡開始。 |
| **預測日曆** | 所有交易按成交日期落在月曆上，按階段著色。 |
| **商機時間線** | 每筆交易一根橫條，從建立當天延伸到成交日期，按負責人分組、以月為刻度。 |
| **商機卡片** | 卡片牆——客戶、金額、階段、贏單機率、成交日期、負責人——用於流水線評審和管理層過會。 |
| **⚠️ 停滯商機 · 按階段停留時間排序** | 進行中的交易按在當前階段停留的時間排序，停得最久的排在最上面。這裡不按停留天數做截斷——**當前階段停留天數**是一欄，等了多久直接在列上讀。真正據此行動的是每日的[停滯商機提醒](/zh-Hant/docs/administration/automation)：一筆交易在同一階段停滿 14 天，就會提醒負責人。 |
| **本季度待成交商機** | 處於**承諾（Commit）**或**最佳情況（Best Case）**、且成交日期落在當前季度內的進行中交易——見下文。 |

### 本季度待成交商機

這是銷售經理在季度末真正使用的視圖，它同時受三個條件約束：

- **預測類別**——只要**承諾（Commit）**和**最佳情況（Best Case）**。
- **仍在進行中**——贏單和丟單永遠不會出現。
- **成交日期落在當前季度內**——季度的兩端都是列表每次查詢時現算的，因此它會自己滾進下一個季度，不需要有人去改視圖。

第三個條件才是讓這個名字名副其實的那個：把**金額**欄加總，得到的是*本季度*的承諾數，而不是「所有遲早會成交的進行中交易」之和。一筆預計明年 3 月成交的交易不會出現在這裡——它待在**進行中商機**裡，等它的季度到了才過來。記錄按成交日期由近及遠排列。

**這裡空著是一個答案，而不是視圖壞了。** 沒有記錄符合時，視圖會用一段說明取代表格——*本季度暫無待成交商機*，並指回**進行中商機**——因為「本季度的承諾全部滑出去了」恰恰是經理必須看見的狀態。剛裝好範例資料的示範環境在季度最後幾天也會看到同一屏：此時所有範例交易都落在了下個季度。

## 商機詳情版面

當你打開一個商機時，會看到：

- **頭部**——名稱、帶 7 階段路徑的階段徽章、金額、成交日期、負責人。點擊路徑上的任意階段可直接跳轉到它。
- **銷售路徑**——一鍵階段推進。
- **報價**相關列表——帶有一個**生成報價**按鈕，可執行 [報價生成流程](/zh-Hant/docs/sales/quotes#generating-a-quote)。
- **行項目**——帶有一個**新增產品**按鈕。
- **活動時間線**——統一彙集評論、已記錄通話（`sys_activity`）、外發郵件（`sys_email`）、任務完成以及欄位歷史稽核條目。商機上每個被追蹤的更改（階段、金額、成交日期、負責人）都會自動出現在這裡；沒有單獨的「歷史」標籤頁。
- **競爭對手與備註**——帶有談話要點的側邊面板。
- **AI 參考欄**——Sales Copilot 建議（Customer 360、營收預測、相關訊號）。

## AI Copilot 如何提供協助

當你打開一個商機時，可以提問：

- *"What's at risk here?"*——營收預測技能會檢查階段停留時長、競爭對手訊號和成交日期滑移。
- *"Draft a follow-up email"*——郵件起草技能會撰寫下一條外發訊息。
- *"Summarise this account"*——Customer 360 技能給你一屏的客戶歷史簡報。

## 給銷售代表的提示

- ✅ **及時推進階段**——如果你的階段錯了，機率就是錯的。
- ✅ **新增行項目**以進行恰當的營收預測；彙總後的金額更準確。
- ✅ **填寫後續步驟**——這是交接和站會中最有用的單個欄位。
- ✅ **選擇競爭對手**——AI 會用它來呈現制勝策略。
- ❌ 不要為了讓交易看起來還在正軌上就把成交日期往後推。日期誠實，**本季度待成交商機**的合計才是對的；而一筆停下來的交易，會按它在當前階段停留的時間浮現在**停滯商機**裡，跟成交日期寫成什麼無關。

## 給管理員的提示

- 階段列表、預設機率和合法的狀態轉換分散在原始碼的三處，而不是某個 Setup 介面：共享選擇列表 `OPPORTUNITY_STAGE_OPTIONS`（`src/objects/_picklists.ts`），由 `stage` 欄位算繪；`opportunity_lifecycle` 鉤子裡的 `STAGE_PROBABILITY` 對映（`src/objects/opportunity.hook.ts`），每次儲存都據此重新同步*成交機率*；以及商機物件上名為 `opportunity_stage_progression` 的狀態機驗證規則（`src/objects/opportunity.object.ts`）。三處需同步修改。參見 [Customization › Extending Objects](/zh-Hant/docs/customization/extending-objects)。
- $500K 折扣審批閾值可以在 [審批流程設定](/zh-Hant/docs/revenue/approvals) 中更改。
- $100K 大單通知閾值同樣不是 Setup 介面上的欄位：它是 `opportunity_won_alert` 流程的 CEL 起始條件——`src/flows/opportunity-won-alert.flow.ts` 裡的 `record.amount > 100000`。收件人則由該流程 `notify` 節點的 `recipients` 決定，列表裡只有 `{record.owner_id}` 一項，即商機負責人本人。
