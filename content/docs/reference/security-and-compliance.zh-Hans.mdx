# 安全与合规

本页介绍 HotCRM 中可用的安全与合规控制。许多控制在平台层配置；有些则是你作为管理员所做的策略选择。

## 身份验证

### 用户名 + 密码

- 强制执行强密码策略（最小长度、复杂度、历史、过期）。
- 使用 Bcrypt 哈希；绝不以明文存储。
- N 次失败尝试后账户锁定（可配置；默认 5 次）。

### 多因素身份验证（MFA）

- TOTP（Google Authenticator、Authy、1Password）—— 推荐所有用户使用。
- WebAuthn / 硬件密钥（YubiKey、Touch ID）。
- 备用恢复码。
- **管理员应强制要求所有用户使用 MFA** —— Setup → Security → MFA Policy。

### 单点登录（SSO）

支持的协议：

- **SAML 2.0** —— Okta、Azure AD、Google Workspace、OneLogin、Ping。
- **OpenID Connect (OIDC)** —— Auth0、AWS Cognito。
- **OAuth 2.0** —— 用于委托应用访问。

在 **Setup → SSO Providers** 处配置（位于 *Access Control* 分组下 —— 设置里没有 *Security* 这个分组）。启用 SSO 后，你可以完全禁用密码登录。

### SCIM 配置

自动从你的身份提供商同步用户：

- 新 IdP 用户 → 具有正确简档 + 角色的新 HotCRM 用户。
- IdP 组更改 → HotCRM 权限集更改。
- IdP 用户停用 → HotCRM 用户停用，记录重新分配。

**设置里没有 SCIM 页面。** 这个能力本身是真的 —— 平台把 SCIM 提供方存为记录，认证插件也带了适配器 —— 但它没有自己的导航入口，所以没有可点的地方。在界面里能配置的是 SSO，位置是 **Setup → SSO Providers**。

## 授权

完整的分层模型见[共享与安全](/zh-Hans/docs/administration/sharing-and-security)。快速摘要：

| 层 | 控制 |
| --- | --- |
| **简档** | 用户可以执行哪些操作（创建/编辑/删除） |
| **权限集** | 在简档之上的额外操作 |
| **组织范围默认值** | 每个对象的基线记录可见性 |
| **岗位** | 共享规则可以点名的扁平访问群体——岗位之间什么都不会上卷 |
| **共享规则** | OWD 的例外 |
| **客户团队** | 按记录共享 |
| **字段级安全** | 逐字段读/写 |

## 网络与登录控制

- **IP 允许列表** —— 限制登录到特定 IP/范围（按简档）。
- **登录时间** —— 限制登录到工作时间（按简档）。
- **会话超时** —— 空闲超时（默认 30 分钟）和绝对超时（默认 12 小时）。
- **并发会话** —— 每用户的最大同时会话数。
- **设备信任** —— 标记新设备并要求邮件确认。

**不存在 Session Policy 这个屏幕。** 登录与认证设置在 **Setup → Authentication**；正在进行的会话（以及吊销某个会话）在 **Setup → Sessions**。上面列出的按简档的 IP 允许列表、登录时间、并发会话上限与设备信任，本应用在任何地方都没有对应的设置项。

## 审计日志

每个有意义的操作都会被不可变地记录：

| 类别 | 记录内容 |
| --- | --- |
| **身份验证** | 登录成功 / 失败、MFA、IP、设备 |
| **授权更改** | 简档 / 权限集 / 角色更改 |
| **记录更改** | 创建 / 更新 / 删除及前后值 |
| **配置** | 字段、验证、流程、共享规则编辑 |
| **数据导出** | 谁在何时导出了什么、多少行 |
| **AI 调用** | 哪个用户在哪条记录上调用了哪个技能 |
| **集成活动** | Webhook 投递、OAuth 授权 |
| **批量操作** | 批量编辑、批量删除、批量分配 |

保留期：

- 实时审计日志 UI 中 **90 天**。
- 归档审计日志（S3 / 对象存储）中 **7 年**。
- 对于受监管行业可配置为更长。

在 **Setup → Audit Logs** 处读取审计日志（位于 *Diagnostics* 分组下）。导出为 CSV 或流式传输到你的 SIEM（Splunk、Datadog、Elastic）。

## 加密

### 静态加密

- 数据库：对敏感字段（SSN、支付、健康数据）进行 **AES-256** 列级加密。
- 文件存储：**AES-256** 服务器端加密。
- 备份：使用单独的密钥加密。

### 传输加密

- 所有 HTTP 流量使用 **TLS 1.3**。
- 内部服务之间使用 **mTLS**。
- Webhook 使用 HMAC-SHA256 签名以保证完整性。

### 字段级加密

在字段定义中将敏感字段标记为**加密**。加密字段：

- 在数据库中加密存储。
- 仅对拥有 *View Encrypted Data* 权限的用户可见。
- 从 SQL 级查询中排除（仅平台可以解密）。
- 在审计日志中以掩码后的解密值记录。

## 数据驻留

选择客户数据的存储位置：

- **美国**（北美客户默认）
- **欧盟**（法兰克福 / 都柏林）
- **亚太**（东京 / 悉尼）
- **自托管** —— 你的 VPC，你的掌控。

为符合欧盟数据驻留规则，可按租户禁用跨区域传输。

## GDPR

### 访问权

**不存在“Setup → Privacy”这个屏幕，也没有数据主体请求这种记录类型。** 访问权请求今天要靠人工完成：把引用到这个人的每一条记录找出来 —— 联系人、线索、工单、活动、营销活动成员 —— 再自己从列表视图导出。没有任何东西会替你拼出 JSON / PDF 包，也没有任何东西会把这次请求登记为一个隐私事件。

### 被遗忘权

同样靠人工，而且更不留情：删除就是把你挑中的记录**硬删除**（没有回收站可以再捞回来 —— 参见 [FAQ](/zh-Hans/docs/reference/faq)），或者由你自己编辑 PII 字段来做匿名化。没有“将受影响内容”的预览，也不会生成什么审计证书；你能拿到的，是你动过的每条记录各自的那条普通审计日志。

通常仍然首选匿名化 —— 它保留历史报表的完整性。

### 同意管理

对于市场营销：

- 联系人/线索上的**同意字段** —— 捕获合法依据和同意日期。
- **退订** —— 由邮件营销活动自动处理；更新联系人。
- **抑制列表** —— 任何退订的人都会被全局排除在所有未来营销活动之外。

### 数据处理协议

**应用不附带 DPA 模板** —— 也没有 *Privacy* 页面来存放它。请向你的法务团队索取这份协议。

## SOC 2 / ISO 27001

对于 SaaS 部署，HotCRM 在 SOC 2 Type II 和 ISO 27001 控制下运营。报告可通过你的客户团队在 NDA 下获取。

关键控制：

- 工程团队的最小权限访问。
- 通过即时审批进行生产访问。
- 季度访问评审。
- 年度渗透测试。
- 每年测试两次的灾难恢复。
- 漏洞赏金计划。

## HIPAA / PHI

作为面向医疗保健客户的附加组件提供 —— 需要额外的 BAA、加密控制和审计日志保留。请联系你的客户团队启用。

## 灾难恢复

- **RPO**（恢复点目标）：1 小时。
- **RTO**（恢复时间目标）：4 小时。
- 每日快照保留 30 天。
- 每周快照保留 1 年。
- 企业版套餐生产租户的跨区域复制。

自托管客户 —— 请参见[设置清单](/zh-Hans/docs/administration/setup)了解推荐的备份频率。

## 安全事件响应

- **状态页面** —— `status.your-hotcrm-url` —— 实时报告事故。
- **通知** —— 影响客户数据的安全事件按 GDPR 在 **72 小时**内报告。
- **安全邮箱** —— `security@yourcompany.com` 用于报告漏洞。
- **漏洞赏金** —— 请参见计划页面。

## 给管理员的提示

- ✅ **强制要求所有用户使用 MFA** —— 最大的安全 ROI。
- ✅ 当用户超过 10 人时尽快**开启 SSO + SCIM**。
- ✅ **将系统管理员限制**在最多 2-3 人。
- ✅ **每月评审审计日志** —— 留意异常的导出量或登录失败激增。
- ✅ **将审计日志流式传输到 SIEM** 以进行集中监控。
- ✅ 每年**进行一次桌面演练** —— 如果管理员账户被入侵会发生什么？
