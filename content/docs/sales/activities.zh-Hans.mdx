# 活动

**活动**是你相对于另一条记录去做、或者欠下的任何事项。HotCRM 把活动放在**两个**对象里，本页讲的是第一个：

- **任务**（`crm_task`）——你仍然**欠**某人的事：要打的电话、要发的邮件、要安排的跟进。它锚在**截止日期**上。
- **活动（Event）记录**（`crm_event`）——占用某个人日历上一个时段的会议或电话，无论它已经发生，还是预约在以后。它锚在**开始时间与结束时间**上，在场的每个人都是一条真实记录。见[会议与电话](/zh-Hans/docs/sales/meetings-and-calls)，那一页有完整的任务 / 活动记录对照表。

两者都几乎可以附加到任何东西上：客户、联系人、商机、线索或工单。

## 活动有什么用

- 🗓 **跟踪你对客户的承诺**——*"周二跟进 Jane"*。
- 🔁 **标准化打法**——*"演示后 24 小时发送提案回顾邮件"*。
- 📈 **衡量活动量**——一个本周没有记录任何通话的销售代表是一个辅导机会。
- 🤝 **交接**——当你休假时，你的经理可以看到你的开放任务。

## 5 种活动状态

| 状态 | 含义 |
| --- | --- |
| ⚪ **未开始** | 已创建但尚未开始 *(默认)* |
| 🟠 **进行中** | 你正在处理它 |
| 🟡 **等待中** | 被他人阻塞 |
| 🟢 **已完成** | 完成 |
| ⚪ **已推迟** | 无限期推迟 |

## 4 个优先级别

| 优先级 | 何时使用 |
| --- | --- |
| 🔵 **低** *(默认)* | 锦上添花 |
| 🟢 **普通** | 例行工作 |
| 🟠 **高** | 重要，今天就做 |
| 🔴 **紧急** | 放下一切 |

当你创建一个紧急任务时，负责人会收到一封邮件提醒。

## 6 种活动类型

- **电话**——你还要打的一通电话
- **邮件**——外发或入站邮件
- **会议**——你还要张罗的一次对话
- **跟进**——一次通用的回访
- **演示**——一次产品演示
- **其他**——其他任何事项

这里的*电话*和*会议*标注的是一件**待办**——*"周二给 Jane 回个电话"*。任务带的是截止日期，而不是开始与结束时间，也没有参与者名单。真正打完的那通电话、你正要预约到下周的那场会议，是一条活动（Event）记录——由记录上的 **Log a Call**、**Log a Meeting**、**Schedule a Meeting** 三个按钮写入。见[会议与电话](/zh-Hans/docs/sales/meetings-and-calls)。

## 活动记录存储的内容

| 区块 | 字段 |
| --- | --- |
| **基本** | 主题、描述、类型、状态、优先级 |
| **日程** | 截止日期、提醒日期/时间、完成日期 |
| **分配** | 负责人 |
| **关联到** | 客户、联系人、商机、线索或工单 |
| **重复** | 它是重复性的吗？每日 / 每周 / 每月 / 每年，带间隔和结束日期 |
| **跟踪** | 进度 % |

## 重复任务

将一个任务标记为重复，并选择节奏（每日 / 每周 / 每月 / 每年）和间隔（每 1 周、每 2 个月等）。当你完成当前实例时，系统会生成新实例，一直持续到重复结束日期。

用例：

- *与关键客户的季度回访*——每月重复 × 3。
- *每日站会记录*——每日重复。

这两条都得你自己手动设，而且这也是重复系列在这里唯一的起点：**HotCRM 不会替你把任何任务标记成重复任务**——没有流程、没有操作、也没有种子数据会去勾**重复任务**这个框。你勾上之后，系统会在你完成当前实例时把这个系列接着往下排；你不勾，这个应用里就一条重复任务都没有。

**续约提醒不在其列。** 每日续约扫描建的是一条普通的高优先级跟进任务——它身上没有任何重复字段——针对的是结束日期已经进入这份合同自己的**续约通知（天）**窗口的*已激活*合同，默认 **30** 天、逐份可设，不是固定的 60 天。它每天早上再次出现，是因为扫描又跑了一遍、并跳过还挂着未完成提醒的合同，不是因为什么重复规则：把它标记完成，只要合同仍在窗口内，第二天早上的扫描就会再建一条新的。这条扫描的完整说明在[合同](/zh-Hans/docs/revenue/contracts)页。

## 自动发生的事

- **标记已完成** → `is_completed` 被设为 true，`completed_date` 被盖戳为现在，`progress_percent` 变为 100。这些你都不必手动设置。
- **已逾期** → 如果一个任务超过其截止日期且未完成，系统会将其标记为**逾期**（列表视图中的红色徽章）。
- **紧急提醒** → 创建或保存一个*紧急*任务会向负责人发送邮件。

## 内置规则

- 一个标记为**已完成**的任务必须有完成日期（系统会为你填上）。
- 一个**重复**任务必须设置重复类型，否则系统会要求你提供。
- 一个警告提示会建议将任务关联到至少一条相关记录（客户、商机等），以免它丢失。

## 活动出现在哪里

活动会出现在**三个**地方：

1. **任务列表**——**我的工作 › 我的任务**打开它，并落在*我的待办任务*上。完整的任务清单就是旁边的 **全部任务** 标签页，连同下面描述的其余六个视图标签页；侧边栏里没有单独的*全部任务*入口。
2. **相关记录上的活动标签页**——打开一个客户、线索、商机或工单，它的活动标签页会把挂在这条记录上的任务与活动（Event）汇总在一起。
3. **销售主页**——主页上的 **My Open Tasks** 标签页内嵌的就是同一个*我的待办任务*视图，你欠下的事就摆在落地页上。销售主页上**没有**任何活动类**指标**：顶部四个磁贴全是管道指标（Revenue (Won)、Deals Won、Pipeline Value、Open Leads）。活动量的读数在 Sales Activity 仪表盘上——见下文。

## 标准列表视图

任务是全仓库看法最多的对象：八个已保存视图，列表顶部一个标签页对应一个，顺序如下。每个标签页用的就是视图自己的名字——标签页没有另一套更短的名字。

| 视图 | 展示什么 |
| --- | --- |
| **全部任务**（默认打开） | 所有任务。未完成的在前，同组内按截止日期由近及远；行上有完成勾选框、状态、优先级、截止日期、负责人和逾期标记，并按优先级着色——紧急红色、高橙色、普通绿色、低灰色。每页 50 行，可勾选多行批量处理。从**我的任务**以外的任何地方进来，页面默认落在的就是这个标签页。 |
| **任务看板** | 看板视图，一个状态一列，卡面是主题、优先级、截止日期和进度。已完成的任务不在板上——这里只放还在动的活。点开卡片是从侧边滑出的抽屉，不会把你带离看板。 |
| **任务日程** | 任务按**截止日期**落在日历上，按优先级着色。它不做任何过滤，所以已完成的任务仍留在它发生的那一天。 |
| **执行计划** | 甘特图：每个任务是一根从**提醒日期**到**截止日期**的横条，按进度百分比填充。 |
| **工时时间线** | 同样是提醒日期到截止日期的跨度，按周铺开并按**负责人**分组，按状态着色——谁手上扛着什么、什么时候。 |
| **我的待办任务** | **你**负责且尚未完成的任务，按截止日期由近及远。**我的工作 › 我的任务**和销售主页的 **My Open Tasks** 标签页背后是同一个视图。 |
| **📅 我的优先任务** | 处于*未开始*或*进行中*、优先级为**高**或**紧急**的任务，按截止日期由近及远，同一天内紧急排在高之前。名字要仔细读：它的过滤条件里**完全没有日期**，所以这是优先级队列，不是"今天到期"清单；它同样没有负责人条件，因此展示的是你有权看到的所有高/紧急待办任务，不只是你自己的。 |
| **⏰ 待办任务 · 按逾期时长排序** | 所有未完成的任务，截止日期最早的排在最上面。这个名字是老实的：它**不是**筛出"确已过期"的那批，而是把待办积压按等得最久的排在前面。**全部任务**标签页上的**逾期**勾选也不是第二个答案：它是**保存**任务时盖上的，告诉你的是上次编辑那一刻的情况，而不是今天的情况。 |

## 系统如何使用活动

- **客户最近活动日期**——沉默客户报表所依据的客户接触时点时钟。任务完成只是刷新它的**四个**动作之一：一条活动（Event）记录变为**已举行**、一个任务被完成、在联系人上 **Send Email**、一个工单被置为*已解决*。这个时点戳还会**沿关系链向上走**——你在商机、联系人或工单上完成任务，系统会顺着关联给背后的客户盖戳，这正是一个往来频繁的客户不会在整个销售周期里显得沉默的原因。完整表格（含唯一一个非互动来源：修改客户的负责人或类型同样会盖戳）见[会议与电话](/zh-Hans/docs/sales/meetings-and-calls)的「什么会刷新最后互动」一节。
- **停滞的交易**——商机上**没有**属于自己的最近活动字段；你记录在交易上的活动，刷新的是它背后的**客户**。让一笔安静下来的交易浮出水面的是**当前阶段停留天数**（由进入当前阶段日期推算），以及每日的[停滞商机提醒](/zh-Hans/docs/administration/automation)——它会提醒负责人并创建一个跟进任务。
- **Sales Activity（销售活动）仪表盘**——活动量指标在这张仪表盘上，不在 Sales Performance（销售业绩）上，后者只承载管道指标。**Activity by Rep** 按负责人拆分已记录的互动量——统计的是状态为 **Held（已举行）** 的活动（Event）记录，也就是真正发生过的电话与会议，**不含任务**；已完成的任务由同一张仪表盘上的 **Tasks Completed** 磁贴单独统计。两者都没有按周的时间窗：这张仪表盘刻意不带日期范围选择器，按周的读数由相邻的 **Activity Volume by Week** 图表给出。参见[仪表盘](/zh-Hans/docs/analytics/dashboards)。

## 给销售代表的提示

- ✅ 已经打完的电话用 **Log a Call** 记录，而不是建一个*电话*任务——它写入的是一条带参与者和时长的[活动（Event）记录](/zh-Hans/docs/sales/meetings-and-calls)，也正是它会进入客户的互动历史。*电话*任务留给你还没打的电话。
- ✅ 如果你会在截止日期前忘记，请设置*提醒日期/时间*。
- ✅ 将任务关联到**商机**，而不仅仅是客户——这才能让它出现在商机时间线上。

## 给服务坐席的提示

- ✅ 对正在等待客户的工单使用*跟进*任务；将截止日期设为今天 + 3 以记得去催。

## 给管理员的提示

- 紧急任务邮件提醒模板可以自定义。
- 重复任务每个周期生成一个新实例。没有日历式的重复编辑器——请逐个调整间隔。
- 活动类型（电话 / 邮件 / 会议 / 等）可以通过选择列表扩展。参见 [Customization › Extending Objects](/zh-Hans/docs/customization/extending-objects)。
