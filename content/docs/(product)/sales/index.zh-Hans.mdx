# 销售

销售模块覆盖完整的**从线索到回款**旅程。同一条记录从首次入站咨询一路流转到签署合同，每位团队成员都能清楚看到每笔交易所处的位置。

## 全局概览

一笔典型交易看起来是这样的：

```
Lead  ──►  Account + Contact  ──►  Opportunity  ──►  Quote  ──►  Contract
(prospect)   (qualified)           (active deal)     (proposal)   (signed)
```

你引入线索、对其进行资格审核、将其转化为客户、推动商机走过 7 个销售阶段、发送报价，并最终以合同形式成交。活动（电话、会议、跟进）挂接在每一个步骤上。

## 系统自动为你完成的事

这些你无需手动操作——HotCRM 会在后台处理：

- **线索评分**——每条新线索都会根据公司规模、行业、职位和互动情况获得 0-100 的评分。
- **热门线索提醒**——评级为 4 星及以上的线索会将下次跟进日期设为今天并通知负责人。
- **概率更新**——当你将商机移动到新阶段时，赢单概率会自动更新（寻找客户 10% → 成交 100%）。
- **预期营收**——`amount × probability` 会为你计算好。
- **大单通知**——当一笔金额 $100K 及以上的交易被标记为成交时，该交易的负责人会收到邮件通知——只通知负责人本人，不通知其经理。
- **报价过期**——超过有效期的报价每晚会被自动标记为已过期。
- **大额交易审批**——金额 $100K 及以上的商机会自动路由给你的销售经理审批，高于 $500K 的还要再经销售总监审批。
- **接受报价即创建订单**——接受报价单会把商机以*成交*关闭，并创建它的订单，带着报价单的明细；这次销售需要合同时，再从订单起草（**起草合同**）。管理员可以重新开启自动起草合同。
- **自动升级客户**——合同激活的那一刻，客户被升级为*正式客户*，合同若还没有**签署日期**则记下当天。*客户*上不记任何日期：做客户群组报表时，读合同的**签署日期**或**开始日期**。
- **续约提醒与到期**——在管理员打开了定时任务的环境里，每日续约巡检会在合同进入通知期（**续约通知（天）**，默认 30）时给**合同负责人**建一个续约任务并发出提醒，每日到期扫描则把过了结束日期的合同标记为*已过期*。

## 销售 AI 技能

[销售技能](/zh-Hans/docs/ai-copilot/sales-copilot)在你的环境运行平台助手时附着在它上面；你[通过 MCP 接入](/zh-Hans/docs/ai-copilot/connect-your-agent)的智能体也在同一批记录上工作。两者都可以：

- 使用 BANT 方法（预算、决策权、需求、时间线）**审核线索资格**并给出评分。
- **起草外呼邮件**，针对联系人进行个性化，并以产品目录为依据。
- **预测营收**并标记看起来有风险的交易。
- 在你下次会议之前**总结某个客户**（Customer 360）。

可以这样问它：*"qualify this lead"*、*"draft a follow-up email"*、*"what's at risk this quarter?"*

## 在哪里找到这些功能

**HotCRM 应用**的侧边栏将所有内容归到**销售**之下，这个分组一共十二个条目——九个对象入口，外加三个打开的不是对象列表的条目：

- 线索 · 客户 · 联系人 · 商机 · 合同 · 订单 · 报价 · 产品 · 价格表
- **销售业绩**（Sales Performance）——你的每日 KPI，来自 `sales_dashboard` 仪表盘。没有任何侧边栏条目叫 *销售仪表盘* / *Sales Dashboard*。
- **产品目录**（Product Catalog）——按类别统计的产品目录价，来自收入模块的 `product_catalog_dashboard` 仪表盘。它排在**价格表**之后，随收入模块一起消失。
- **知识库**（Knowledge）——只对销售代表显示：已发布的知识文章，销售代表在这里、也能通过搜索框找到它们。其他人在 Service 应用的**服务**分组下找到**知识库**，销售代表的启动器不提供这个应用。

**产品**（Products）归在本分组而不是**市场营销**下：产品目录是每一条报价行项目和商机行项目所指向的主数据，本质上是收入侧的数据，只是当初被顺手放在了营销旁边——参见 [Products](/zh-Hans/docs/sales/products)。

在侧边栏里，**合同**和**订单**排在**销售业绩**（Sales Performance）之后，**报价**、**产品**、**价格表**和**产品目录**排在其后：它们属于 HotCRM 的收入模块，而模块贡献的条目排在应用自己放进分组的条目之后。销售代表的**知识库**来自服务模块，排在最后。

大额商机的审批在**我的工作**下等你处理：

- **Inbox**——点开后进入平台的**审批中心**，在那里批准或拒绝等着你处理的审批。侧边栏上的 label 就是 **Inbox**，简体中文界面下显示为**待我审批**；应用里没有任何条目叫 *Approval Requests*（审批请求）。参见[审批](/zh-Hans/docs/sales/approvals)。

侧边栏里没有 *销售管道*（Pipeline）这一条。看板是**商机**列表页上的一个标签页，与查看同一批交易的其他方式并列；那个视图自身的 label 是**销售流水线**（Sales Pipeline，`pipeline_kanban`）。

如果你是新手，请按以下顺序阅读：

1. [线索](/zh-Hans/docs/sales/leads)——每笔交易开始的地方。
2. [商机](/zh-Hans/docs/sales/opportunities)——你每天都要处理的核心记录。
3. [销售管道管理](/zh-Hans/docs/sales/pipeline-management)——漏斗是如何被治理的。
4. [报价](/zh-Hans/docs/sales/quotes)——如何发送一份提案。
5. [产品](/zh-Hans/docs/sales/products)和[价格表](/zh-Hans/docs/sales/price-books)——报价单据以定价的目录。
