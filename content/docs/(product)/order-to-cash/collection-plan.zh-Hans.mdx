# 回款计划

一笔交易的回款计划由若干条**回款计划**记录组成，每条是计划中的一个节点：它写明销售预计在哪一天收多少钱。回款计划做在**订单**上；交易没有订单时，做在**合同**上。一笔软件交易可能是预付款 30%、上线 40%、验收 25%，一年后再收 5% 质保金；订阅则每个计费周期一个节点。回款计划属于客户，所以客户页面会列出它所有订单和合同的回款计划。

回款计划属于销售。财务的发票和回款会对照它统计，但从不修改它。

## 制定回款计划 [#building-the-plan]

在订单上打开**回款计划**标签页，为付款安排的每一部分添加一个节点；没有订单的交易，在合同上同样操作。节点总要写明它的订单或合同：两者都没有的节点会被拒绝。

**一笔交易的回款计划只放在一个地方：有订单时放在订单上，没有订单时才放在合同上。** 系统不会拦着你在另一条记录上为同一笔交易再做一份计划，所以请只做一份：否则两个页面会各显示一份计划。

| 字段 | 填写什么 |
| --- | --- |
| **节点名称** | 合同里这一步的说法：「预付款 30%」「上线」「第二年」 |
| **计划金额** | 这一步应收多少 |
| **计划日期** | 预计哪天收到 |
| **验收日期** | 按验收付款的节点：客户签字验收的日期。由你记录，系统不会代填 |
| **备注** | 团队需要知道的其他信息 |

选择**订单**或**合同**会带出节点的**客户**。选择另一个客户的订单或合同会被拒绝，并写明是哪一个。订单归在某份合同（框架合同或订阅合同）下时，节点也会带上这份合同，所以订单页面显示它自己的计划，合同页面汇总它所有订单的计划，每个节点只计一次。填了订单、却填了另一份合同的节点会被拒绝；订单和合同属于不同客户时也会被拒绝。

销售代表、销售经理和管理员，只要能查看这个客户，就能在它上面添加、修改或删除回款计划，不需要能编辑客户或合同。财务可以查看回款计划，但从不修改。合同变更后，请相应修订回款计划：回款计划是预测，从来不是账本。

## 数字统计什么 [#figures]

每个节点显示三个数字。它们不需要你填写，而是跟随财务的记录变化。

| 数字 | 统计什么 |
| --- | --- |
| **已开票** | 财务关联到这个节点的**已开具**发票的金额。已作废的发票不计入。 |
| **已回款** | 计入这个节点的回款：财务直接关联到它的回款（开票前收到的预付款），以及针对这个节点的发票收到的回款。 |
| **未回款** | **计划金额**减去**已回款**。收到的比计划多时会小于零。 |

针对发票收到的回款会自动计入这张发票所属的节点，财务只需关联发票。如果财务之后把发票改到另一个节点，已记录的回款保留原来的节点；在这样的回款上重新选择一次发票，它也会随之改过去。

## 本月计划回款 [#planned-this-month]

**本月计划回款**列表（「订单与回款」应用的**跟进 → 本月计划回款**，也是**回款计划**列表上的一个标签页，即**销售**应用的**回款计划 → 回款计划**），按日期先后列出你能看到的、**计划日期**在当前自然月内的所有节点，以及目前已开票和已回款的金额。它随日历变化：每月 1 日起显示新的月份。
