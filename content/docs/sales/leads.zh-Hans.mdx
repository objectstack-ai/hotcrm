# 线索

**线索**是一次入站咨询——某人表现出了兴趣，但尚未被确认为真正的销售商机。在你决定值得跟进之前，线索会与你真正的客户和联系人分开存放。

## 何时该用线索（而非联系人）

| 场景 | 使用…… |
| --- | --- |
| 有人填写了网页表单 | 线索 |
| 展会名单上的一个名字 | 线索 |
| 你购买了一份营销名单 | 线索 |
| 现有客户的新采购方加入 | 联系人（归在现有客户之下） |
| 真实客户处已确认的决策者 | 联系人 |

关键是把未经审核的噪声挡在你真正的客户数据库之外。

## 5 种线索状态

每条线索都会经历这些状态。通常的路径是向前走——从新建，经已联系、已确认，到已转化，未通过则是出口——但应用并不强制销售代表走这条路径：偏离它的状态变更，比如把一条已确认的线索改回新建，照样会保存，应用只在服务器日志里记下一条警告。应用真正强制的只有已转化这一步：只有**转化线索**能设置它。

| 状态 | 含义 | 你通常接下来做什么 |
| --- | --- | --- |
| **新建** | 刚到达，还没人联系 | 在 SLA 内进行首次联系 |
| **已联系** | 销售代表已通过电话/邮件联系 | 应用 BANT 资格审核 |
| **已确认** | 通过 BANT——值得跟进 | **转化**为客户、联系人和商机 |
| **未通过** | 不匹配（行业不对、没有预算等） | 如情况变化可稍后重新开启 |
| **已转化** | 已成为真正的客户和联系人 | （线索现已锁定） |

如果情况发生变化（预算释放、新项目启动），你还可以将一条未通过的线索**重新开启**回*新建*。

## 每条线索记录存储的内容

线索记录把自己的字段声明为 **10 个区块**。线索自己的记录页只把其中一部分挑进**详情**标签页，所以下表是一条线索携带的字段全集，而不是逐屏对照表：

| 区块 | 其中内容 |
| --- | --- |
| **身份信息** | 称谓、名/姓、全名、显示名称 |
| **公司信息** | 公司、职位、行业——另有一个隐藏的公司名称规范化副本，线索转化与重复检测按它匹配 |
| **联系方式** | 邮箱、电话、手机、网站 |
| **资格评估** | 状态、线索评分（1-5 星评级）、线索来源、下次跟进日期、最近联系时间、未通过原因 |
| **分配** | 负责人 |
| **地址** | 一个结构化的地址字段 |
| **附加信息** | 年营收、员工人数、描述、备注 |
| **沟通偏好** | 禁止致电、拒收邮件 |
| **转化** | 已转化、转化客户、转化联系人、转化商机、转化日期——都在线索转化时自动写入 |
| **重复线索管理** | 重复于（存活的那条记录属于哪个对象）、重复的线索、重复的联系人、重复状态——下文*重复线索*用的就是这些字段 |

可选**行业**包括 Technology、Software/SaaS、Finance、Healthcare、Retail、Manufacturing、Education、Real Estate、Media、Logistics、Hospitality、Energy、Government、Non-profit 和 Other。

可选**线索来源**包括 Web、Referral、Event、Trade Show、Webinar、Partner、Advertisement、Cold Call 和 Other。

## 线索评分——评分的含义

一条线索上只有**一个**质量数字：**线索评分**，一个 **1-5 星的星级评级**。列表视图里*线索评分*那一列显示的就是同一个字段——不存在另一个 0 到 100 的分数，背后也没有预算或时间线字段。

### 星级是怎么来的

线索被创建时如果**没有带评级**，系统会用线索自己的字段算一个出来并存下。它看的全都是你眼前这条记录上的信息——背后没有任何网页访问或互动追踪：

| 它看什么 | 加多少星 |
| --- | --- |
| 企业邮箱地址——只要不是 gmail、yahoo、hotmail、outlook、qq、163 | +1 |
| 填了任意电话号码 | +0.5 |
| 资深职位——CEO、CTO、CFO、CIO、COO、Founder、VP、Vice President、Director、Head of | +1.5 |
| 行业是 Technology、Finance 或 Healthcare | +1 |
| 员工人数 200 及以上 | +0.5 |
| 年营收 $10M 及以上 | +0.5 |

合计上限为 5、下限为 1，并四舍五入到**整星**：线索不会被评为 0 星，也从不存半星。

有两条边界值得记住：

- 它**只在创建时运行**。事后补上职位或员工人数**不会**重新评分——情况变了就自己改星级。
- 它绝不覆盖随线索一起进来的评级。导入时带了评级，或在新建表单上手动设了星级，保留的就是你的值。

### 星级会触发什么

新线索路由只在线索落库那一刻读一次评级：

| 评级 | 盖的下次跟进日期 | 给线索负责人的提醒 |
| --- | --- | --- |
| **四星及以上** | **明天** | *"Hot lead — follow up within 24h"*，**站内收件箱和邮件**两个通道都发，标为警告级 |
| **其余全部**，包括完全没有评级的线索 | **三天后** | *"New lead assigned to you"*，**仅站内收件箱**，且只在线索是别人交给你时才发 |

热门的门槛就只有四星这一道：五星线索的路由与四星完全相同，满五星不会另外触发任何事。

两种提醒都发给线索负责人，告诉对方这条线索归他跟进。标准提醒发不发，要看是谁把线索记到你名下：

- **别人** —— 轮询分配把一条 Web-to-Lead 咨询分给了你、某个集成写明了你，或者同事替你录入了这条线索。你会收到 *"New lead assigned to you"*。
- **你自己** —— 线索是你自己创建的，无论通过表单还是 API。你不会收到标准提醒：跟进日期已经写在线索上，它也在**我的线索**里。

热门线索无论如何都会提醒负责人，因为评级是系统的判断，不一定是你填的：创建时没有评级的线索会当场打分。没有负责人的线索只盖跟进日期、不发提醒，因为 HotCRM 没有可以通知的线索队列。

> 上面这些权重写在线索的自动化代码里，而不是某个设置界面——参见本页末尾的「给管理员的提示」。

## 重复线索

同一个人再次咨询是正常现象，不是错误。老客户再次填写网站表单，或者你导入的展会名单与已有名单有重叠，都会产生**第二条线索**——HotCRM 会记录这层关系，而不是拒绝这条记录。

当新线索的邮箱在系统中已经存在时，保存时会带上：

- **重复状态 = 疑似重复**——这只是系统的猜测，尚未下任何结论。
- **重复于**——它疑似重复的那条记录：如果这个人已经是**联系人**，就指向该联系人；否则指向使用同一邮箱、**最早的未关闭线索**。每次重复提交都指向同一条原始记录，因此一组重复线索是一个列表，而不是一条链。

从线索列表视图切换器里的**疑似重复线索**视图处理它们。打开这两条记录逐一比对，然后二选一：

- **是老客户的新咨询**——清空重复状态，按正常线索推进。预算重新到位的老客户是真实商机。
- **是同一次咨询重复录入**——把线索置为*未通过*，原因选**重复**。此时表单会要求你指明存活的那条记录，并把重复状态设为**已确认重复**。不指明存活记录就无法以重复为由作废，所以作废分析里的每一条都能点开。

> 匿名 Web-to-Lead 提交永远会被接受，并且和其他线索一样会被查重：来自 CRM 中已有地址的网页咨询会被标记。查重在你这一侧完成——访客只会得知咨询已收到，因此公开表单永远不会透露某个地址是否已被记录。

## 转化一条已确认的线索

**重复状态**为**已确认重复**的线索无法转化。点击**转化线索**后弹出的是一条拒绝说明，而不是转化表单：
已经有人把这条线索与某条既有记录做过比对，并判定它是重复的，此时转化会为同一个买家再造一套客户、
联系人和商机。线索上的**重复线索管理**区块指明了保留下来的那条记录——请把已确认的重复线索按重复
关闭，而不是转化它。仅被标记为*疑似重复*的线索仍然可以转化：那只是系统的猜测，转化界面会提示你，
但不会拦住你。

当一条线索通过资格审核后，点击**转化线索**。会弹出一个小表单询问：

- 我们是否也要创建一个商机？
- 如果是——商机名称和金额是多少？

在这些问题上方，表单会在你提交之前告诉你该线索将加入哪个客户：匹配到的现有客户（显示该客户的名称），或者在没有你能查看的客户与之匹配时，一个以线索公司命名的新客户。如果这不是你预期的客户——比如线索写的是 `Acme Corp`，而你的客户是 `Acme Corporation`——请取消，更正线索的**公司**，然后重新转化。

匹配只查看你能查看的客户。同事拥有、且没有共享给你的客户不会被匹配到，因此表单会显示将新建客户。如果那个客户的名称与之完全相同，转化随后会因重复记录而被拒绝，不会创建任何内容；如果名称只在大小写或空格上不同，则会再创建一个客户。所以，当你认为这家公司已经是现有客户、而表单却显示要新建客户时，请先请**客户负责人**或管理员把该客户共享给你，再进行转化。

然后系统会一步完成：

1. 根据线索的公司信息创建一个**客户**——或者直接复用表单所列出的现有客户。匹配时忽略大小写和多余空格，因此公司名为 `ACME  Corp` 的线索会落到你已有的 `Acme Corp` 上，而不是再建一个客户。这不是模糊匹配：`Acme Corp` 与 `Acme Corporation` 仍然是两家不同的公司。这里新建的客户不进入[客户审批](/zh-Hans/docs/sales/accounts#account-approval)：线索的资格判定就是那道关，因此客户立即可用，它的**来源线索**链接回这条线索。
2. 根据线索的个人信息创建一个**联系人**，附加到该客户上。只有当该客户还没有主要联系人时，它才成为主要联系人：转化到一个已有主要联系人的客户时，原来的主要联系人保持不变。
3. *（可选）* 在*寻找客户*阶段创建一个**商机**，预计成交日期设为 90 天后。
4. 将线索标记为**已转化**并锁定它。
5. 向你发送一封确认邮件，总结所创建的内容。

转化后，线索变为只读——所有后续活动都发生在新的客户、联系人和商机上。

## 线索详情布局 [#lead-detail-layout]

打开一条线索后，页头下方有四个标签页：**Details**、**Related**、**Activity** 和 **History**。**Related** 标签页汇集与该线索关联的记录：

- **Tasks**——该线索尚未完成的任务，最先到期的排在最前。
- **Events**——与该线索的通话、会议等活动。已预约的排在前面，已经发生的跟在后面，最近的在前。
- **Campaign Members**——该线索加入过的营销活动、加入时间以及它的响应情况。
- **Conversion**——线索转化后，链接到由它生成的客户、联系人和商机，并显示转化日期。未转化的线索不会出现这一区块；它默认折叠，点击 **Conversion** 即可展开链接。

只有当你有权创建某类记录时，对应列表才带 **New** 按钮，新建的记录会自动关联到该线索。销售人员可以在这里预约活动。把线索加入营销活动属于市场工作，因此只有拥有 Marketing User 权限集的用户和管理员会在 **Campaign Members** 上看到 **New**；销售代表和销售经理只能查看该列表。

## AI Copilot 如何提供帮助

当你打开一条线索时，AI 助手会出现在侧边面板。试着提问：

- *"Qualify this lead"*——运行 BANT，给你一个评分以及每个维度的一行理由。
- *"Is this a hot lead?"*——快速是/否加上推理。
- *"Draft an intro email"*——撰写一封个性化的首次外联邮件。

Copilot 会推荐下一步行动（例如，安排通话、发送跟进、取消资格）。

## 标准列表视图

线索列表没有裁剪过的页签，所以切换器里列出的就是全部已保存视图——一共八个，顺序如下：

| 视图 | 展示什么 |
| --- | --- |
| **全部线索**（默认打开） | 所有线索，最新的在前；姓名是进入记录的链接，同行还有公司、邮箱、状态、评分、来源和负责人。每页 25 行，可导出 CSV / XLSX；可以加入营销活动成员的用户勾选后可批量**加入营销活动**。组织里还没有线索时它会直说——*还没有线索 · 创建第一条线索，从这里开始*。 |
| **我的线索** | 你负责的线索，评分高的在前，同评分内最新的在前。侧边栏的**我的工作 › 我的线索**进的也是它。 |
| **🔥 高热度线索** | 仍处于**新建**或**已联系**、评分**四星及以上**的线索——正是新线索路由判为热、给出次日跟进日期、并向负责人发出「24 小时内跟进」告警的那一批。按**下次跟进日期**由近及远排序，行上带电话、邮箱和负责人，从上往下打就行。 |
| **高优先级** | 同一批线索（**四星及以上**，同样只看新建和已联系），只是摆成一张速览表而不是工作队列：不带跟进日期，行上给出线索来源。 |
| **疑似重复线索** | 上文说的复核队列：**重复状态**为*疑似重复*的线索，最早被怀疑的排在最前，重复关联字段就在行上。处理一条少一条——确认或清除之后它就掉出队列。没有待复核的时候它会写明：*没有疑似重复 · 无需复核——每个重复录入的邮箱都已检查过。* |
| **线索流水线** | 看板视图，一个状态一列，每列汇总**年营收**。卡片以姓名为标题，下面是公司、邮箱和星级评分。点开卡片是从侧边滑出的抽屉，不会把你带离看板。 |
| **线索日历** | 线索按**下次跟进日期**落在月历上，标题是公司名，按状态着色——看的是你已经约定的跟进，一天一天排开。没有下次跟进日期的线索不落在日期格里，而是在月历下方单独列出。 |
| **线索卡片** | 卡片墙，一条线索一张卡，以姓名为标题，卡面上是公司、职位、邮箱、电话、状态和评分。 |

## 给销售代表的提示

- ✅ 让**下次跟进日期**保持真实——**🔥 高热度线索**就是按它排序的，日期放着不更新，会把一条活着的线索压到队列底部。新线索会自动拿到一个（四星及以上是明天，其余是三天后），**安排跟进**动作则会用你刚建的那个任务的到期日重新盖章。
- ✅ 有强烈的直觉判断时就自己设星级——新建时你填的评级会原样保留，自动评分只在你留空时才补上。
- ✅ 不要过早转化——已转化的线索无法还原。在确认期间使用*已确认*状态。
- ❌ 不要永远把噪声留在*新建*中——3 次联系失败后就取消其资格。

## 给管理员的提示

- 评分公式位于线索的自动化中。要重新设定权重，请编辑 `src/sales/objects/lead.hook.ts`（绑定到 `crm_lead`）。参见 [Customization](/zh-Hans/docs/customization/extending-objects)。
- 通过授予访客门户配置文件对线索对象的*仅插入*权限，可以启用 Web-to-Lead——参见 [系统管理 › 权限档案](/zh-Hans/docs/administration/profiles)。
- 要添加新的行业或线索来源，请编辑线索对象的选择列表——参见 [Customization](/zh-Hans/docs/customization/extending-objects)。
