# 项目与人员安排

## 新建项目

项目经理在**全部项目**中点**新建**，或者在客户、商机、合同、订单的**项目**标签页中新建项目。项目需要填写**项目名称**和**客户**；**商机**、**合同**和**订单**会从该客户下提供可选项。三者都不是必填：项目交付的销售没有合同时，填写**订单**即可。

每个项目都有一个**类型**：

| 类型 | 用途 |
| --- | --- |
| **售前** | 为赢单所做的工作：概念验证、试点、范围调研 |
| **交付** | 客户购买的工作。如果之前有售前项目，**来源售前项目**指向它 |
| **内部** | 为本公司做的工作：能力建设、培训、工具 |

三种类型的工时填报、人员安排和成本计算方式完全相同，所以售前和内部投入也会和交付一样体现为成本。**计费方式**（固定总价、按人天计费、包年服务、不计费）记录客户如何付费。

## 状态

项目从**草稿**开始，每次向前推进一步：

| 从 | 到 |
| --- | --- |
| 草稿 | 审批中、已取消 |
| 审批中 | 已批准、已驳回、退回草稿、已取消 |
| 已批准 | 进行中、已取消 |
| 已驳回 | 草稿、已取消 |
| 进行中 | 暂停、已完成、已取消 |
| 暂停 | 进行中、已取消 |
| 已完成 | 已关闭，或退回进行中 |
| 已关闭、已取消 | 终态 |

其他任何变更都会被拒绝，提示信息会列出这些步骤。项目经理不会删除项目：不再进行的项目设为**已取消**，完成的项目设为**已关闭**。

## 提交立项审批

新项目从**草稿**开始。计划和预算准备好后，项目经理把**状态**设为**审批中**。项目的[第 1 版预算](/zh-Hans/docs/projects/budgets#version-1)随之提交，所以没有第 1 版、或第 1 版还不完整的项目不能提交：审批批的就是这份预算。

1. 每一位**项目总监**和**项目管理办公室**岗位的人都会在自己的**待我审批**（**我的工作**分组下）里看到这个项目。第一个做出决定的人代表所有人决定。
2. 第 1 版合计达到 **100,000** 或以上的项目，随后还要交给**财务控制**审批。
3. 所有审批人都批准后，项目变为**已批准**，第 1 版成为基线，项目经理在工作开始时把它设为**进行中**。

被驳回的项目变为**已驳回**：把它退回**草稿**，修改后再次提交。项目在等待审批时，项目经理也可以在待我审批里撤回，项目会回到**草稿**。

等待审批期间项目被锁定，任何人都不能编辑。也没有人能手工设置**已批准**或**已驳回**：这两个状态只由审批写入。只有管理员可以手工设置，用来修复审批无法运行的项目。

## 预算

**批准预算**是项目可以花的成本。它不能直接填写：它是项目基线预算版本的合计，追加预算版本获批时随之变化。版本的说明见[项目预算](./budgets)。**计划收入**是客户为这个项目支付的金额，毛利以它为基准计算。

项目的[成本和毛利字段](/zh-Hans/docs/projects#money)会随工时和费用的批准自动填写。项目花费超过批准预算时，**预算使用率**会超过 100%。

### 预算状态与锁定 [#budget-lock]

**预算状态**随预算使用率自动变化：

| 预算状态 | 什么时候 |
| --- | --- |
| **正常** | 低于批准预算的 80% |
| **预警** | 达到 80% |
| **超支** | 达到 100% |

一旦进入**预警**或**超支**，项目经理和每一位财务控制都会收到一条站内通知和一封邮件。每越过一次线只通知一次：项目停留在预警期间，再批准更多工时也不会重复通知。

通知会建议锁定项目，由人来决定。在项目上勾选**锁定工时与费用**后，这个项目上的工时单和费用都不能提交，无论是谁提交。草稿仍然可以填写。取消勾选（例如商定了新的预算之后），就又可以提交了。

新的预算是一个[追加预算版本](/zh-Hans/docs/projects/budgets#top-up)，由项目总监或项目管理办公室批准；使批准预算增加 10% 或以上时，还要经过财务批准。追加预算获批会立即改变预算状态，所以只有经过这次审批，项目才会回到正常。

## 为项目安排人员

在项目的**项目成员**标签页或**人员安排**中为项目安排人员。每一行包括：

| 字段 | 含义 |
| --- | --- |
| **人员** | 安排的是谁。这条记录以他的姓名命名，列表、搜索和创建后的提示都显示他的姓名，用户改名后也会跟着更新 |
| **职责** | 他在项目上的角色：项目经理、项目总监、客户经理、架构师、顾问、质量保证、财务伙伴或分包商 |
| **费率卡** | 他的工作职级。他的工时按这张卡的单价计算成本和计费 |
| **投入比例** | 他投入这个项目的时间占比 |
| **开始日期**、**结束日期** | 他在项目上的时间 |
| **可计费** | 他的工时是否向客户计费。不可计费成员的工时仍然计入成本，但不计费 |

安排一个人会对项目产生两个效果：

- **他可以查看项目。**项目的**项目团队**列出除项目经理以外所有被安排的人，每个人都能查看这个项目。删除这一行，他就失去这份访问权限。
- **职责为项目经理的成员成为项目的项目经理。**这个人可以查看和编辑项目、安排人员，并审批项目的工时单和费用，所以不会再列在项目团队里。项目上的这个字段是只读的：要改项目经理，就改人员安排。

> **先把自己安排上。**新项目在有人以项目经理职责被安排之前没有项目经理。新建项目的人作为项目负责人可以编辑它，但在安排项目经理之前创建的工时单和费用没有审批人。

只有被安排在项目上的人才能在这个项目上填报工时。

## 费率卡

**费率卡**是一个工作职级，带有两个价格：

| 字段 | 含义 |
| --- | --- |
| **成本单价** | 这个职级一小时或一天让公司付出的成本 |
| **计费单价** | 向客户收取的价格 |
| **单位** | 按小时或按天。一天按 8 小时计 |
| **职级** | 初级、中级、高级、资深或专家 |
| **内部** | 用于内部工作。只有内部费率卡的计费单价可以低于成本单价 |
| **生效日期**、**失效日期** | 这张卡的使用期间，仅供参考：以成员那一行上的费率卡为准 |

费率卡由财务和项目管理办公室维护。所有人都能查看，但成本单价对项目成员隐藏。

> **修改费率卡不会改变过去的成本。**每条工时明细在保存时都会复制当时有效的单价。修改之前填报的工时保留旧单价，修改之后填报的工时使用新单价。
