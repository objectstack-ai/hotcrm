# 导入与导出

如何将数据**导入** HotCRM（批量导入、迁移）以及**导出**（导出、GDPR、备份）。

## 从 CSV / Excel 导入

最简单的途径。适用于：潜在客户、客户、联系人、产品、商机、工单、合同。

### 分步操作

1. 前往 **设置 → 数据 → 导入向导**。
2. 选择要导入到的**对象**。
3. 上传 **CSV** 或 **Excel** 文件（每次上传最大 50 MB；更大的文件请拆分）。
4. **将列映射**到字段 —— 向导会按表头名称自动建议匹配。
5. 选择**冲突行为**：
   - **仅插入** —— 跳过与现有记录匹配的行。
   - **插入并更新** —— 更新现有记录（按邮件 / 外部 ID 匹配）。
   - **仅更新** —— 如果未找到则失败。
6. 运行**试运行** —— 向导会报告有多少会成功 / 失败，而不进行写入。
7. **提交** —— 执行导入。你会看到一个进度条；大型导入在后台运行，完成后你会收到一封邮件。

### 字段映射提示

- **所有者** —— 提供用户的邮件地址；导入器会解析为用户 ID。
- **查找字段** —— 提供被引用记录的 *Name* 或 *External ID*；导入器会进行解析。
- **选项列表** —— 值必须与选项列表定义的值完全匹配（不区分大小写）。
- **日期** —— ISO 格式（`2025-03-15`）在任何地方都适用；否则请指定格式。
- **多选** —— 用分号分隔各值。

### 外部 ID（推荐）

添加一个 `external_id` 列（例如 `legacy_account_id = ACME-001`）并将其标记为匹配键。这让你能够：

- 幂等地重新运行导入而不创建重复记录。
- 在对象之间交叉引用（例如，导入潜在客户及其原始客户的外部 ID，导入器会将它们关联起来）。

## 从 Salesforce 迁移

随附了一个专门构建的迁移向导。

1. **设置 → 数据 → 从 Salesforce 迁移**。
2. 通过 OAuth 授权 —— 向导会从你的 Salesforce 沙盒或生产环境中读取。
3. 向导会自动将 Salesforce 对象映射到 HotCRM 对应项：

   | Salesforce | HotCRM |
   | --- | --- |
   | Account | account |
   | Contact | contact |
   | Lead | lead |
   | Opportunity | opportunity |
   | OpportunityLineItem | opportunity_line_item |
   | Quote / QuoteLineItem | quote / quote_line_item |
   | Contract | contract |
   | Case | case |
   | Campaign / CampaignMember | campaign / campaign_member |
   | Product2 | product |
   | Task / Event | task / event |
   | User | user *（按邮件匹配或邀请）* |

4. **字段映射** —— 默认值合理；审阅并调整自定义字段。
5. **选项列表映射** —— 将 Salesforce 的值映射到 HotCRM 的值（尤其是阶段、状态、优先级）。
6. **所有者映射** —— 按邮件将 Salesforce 用户映射到 HotCRM 用户。
7. **选择数据切片** —— 全部历史数据，或一个日期范围（用于分阶段切换）。
8. **试运行**，审阅报告，**提交**。

向导会将 Salesforce ID 保留为 `external_id` 以便追溯。

## 从 HubSpot 迁移

在 **设置 → 数据 → 从 HubSpot 迁移** 中有一个类似的向导。将 Hub 对象类型映射到 HotCRM：

| HubSpot | HotCRM |
| --- | --- |
| Company | account |
| Contact | contact |
| Deal | opportunity |
| Ticket | case |
| Line item | opportunity_line_item |
| Product | product |
| Quote | quote |

交易管道映射到商机阶段 —— 请仔细审阅选项列表映射。

## 迁移操作手册

1. **首先映射角色和用户** —— 没有所有者，一切都会成为孤立数据。
2. **在沙盒中试运行** —— 切勿对生产环境运行首次迁移。
3. **按此顺序迁移**以保持引用关系完整：
   1. 用户
   2. 产品
   3. 客户（+ 外部 ID）
   4. 联系人（+ 关联到客户）
   5. 潜在客户
   6. 商机（+ 关联到客户 + 联系人）
   7. 商机行项目
   8. 报价 / 报价行项目
   9. 合同
   10. 工单
   11. 营销活动
   12. 营销活动成员
   13. 任务 / 事件 / 备注 / 文件
4. **核对数量** —— 源系统的总数 vs. HotCRM。调查任何 >0.1% 的差距。
5. **端到端手动抽查 10 条记录**。
6. 在上线前**获得**销售 / 服务负责人的**签字批准**。

## 导出数据

### 临时导出

从任何列表视图或报表 → **导出** → CSV 或 Excel。受用户权限和 FLS 约束。

### 计划导出

用于数据仓库加载（Snowflake、BigQuery、Redshift）：

- **设置 → 数据 → 计划导出** → 选择对象、字段、筛选条件、计划、目标位置。
- 目标位置：S3 / Azure Blob / GCS / SFTP。
- 格式：CSV、Parquet 或 JSON Lines。
- 增量 —— 仅自上次运行以来发生变更的数据。

### 批量 API 导出

用于编程式导出 —— 使用 [API 参考](/zh-Hans/docs/customization/api-reference)。用 ObjectQL 查询任何对象；结果分页返回。

## GDPR / 数据删除请求

当客户请求 *"删除我的所有个人数据"* 时：

1. **设置 → 隐私 → 数据主体请求 → 新建**。
2. 识别该人 —— 按邮件或联系人 ID。
3. 向导会显示与他们关联的所有内容：联系人记录、潜在客户、工单、已记录的邮件、营销活动成员资格、文件。
4. 选择 **删除** 或 **匿名化**（用 `[redacted]` 替换姓名/邮件，同时保留记录以供分析）。
5. 确认 —— 系统会进行处理并生成一份你可以交给客户的**审计证书**。

通常更推荐匿名化 —— 它在不保留 PII 的情况下保持了历史报表的完整性。

## 备份与灾难恢复

备份行为取决于 HotCRM 的托管方式：

- **SaaS** —— 备份由平台管理（通常每日快照，30 天保留期）。
- **自托管** —— 由你负责；备份数据库和文件存储桶。请参阅 [管理 › 设置](/zh-Hans/docs/administration/setup) 了解推荐的频率。

要获取经过测试的**灾难恢复**操作手册，请参阅 [参考 › 安全与合规](/zh-Hans/docs/reference/security-and-compliance)。

## 提示

- ✅ **始终试运行**大型导入。
- ✅ **始终添加外部 ID** 列 —— 让你永远摆脱重复记录。
- ✅ **先在沙盒中迁移**，然后在切换的周末运行最终的增量迁移。
- ✅ 对于导出，使用**计划导出**而非临时导出 —— 可重复、受监控、失败时会重试。
- ✅ 对于 GDPR，使用**匿名化**而非删除 —— 让报表保持真实。
