# 快速導覽

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

帶你導覽你每天都會用到的畫面。

## 1. 主頁儀表板

HotCRM 是六個應用（見第 2 節），每個應用打開時都落在你的側邊欄顯示的第一個條目上，除非應用為你的角色指定了落地條目，所以你落在哪裡取決於你是誰。在 **Sales** 裡，銷售經理、管理員或行銷使用者落在 **Home**，即唯一的固定條目。銷售代表的側邊欄裡沒有 **Home**，**Sales** 為銷售代表打開的是 **My Work** 下的 **My Deals**：銷售代表自己名下的未結商機。服務專員與服務經理在 **Service** 裡工作，它打開時落在 **Service Overview**。**Home** 打開的是 **Executive Overview** 儀表板——9 個磁貼，講收入、客戶與管道：

| 磁貼 | 它顯示什麼 |
| --- | --- |
| **Total Revenue (YTD)** | 本年度已成交收入 |
| **Active Accounts** | 至少存在一項活躍關係的客戶 |
| **Total Contacts** | 通訊錄中的聯絡人 |
| **Open Leads** | 漏斗中尚未轉換的線索 |
| **Revenue Trend** | 過去 12 個月的已成交收入 |
| **Revenue by Industry** | 本年度已成交收入按客戶產業拆分 |
| **Pipeline by Stage** | 各銷售階段的進行中商機金額，每個階段一根橫條——是金額，不是商機筆數 |
| **New Accounts** | 過去 6 個月的客戶建立節奏 |
| **Accounts by Industry** | 各產業的年營收總額與客戶數 |

上表用的是原始碼裡的英文 label，也就是英文介面上看到的名字。本應用提供 en / zh-CN / ja-JP / es-ES 四種介面語言，沒有繁體語言包——簡體中文介面下這些名字會顯示為語言包裡的譯名，例如 **Open Leads** 顯示為「未转化线索」、**Pipeline by Stage** 顯示為「阶段管道分布」，儀表板 **Executive Overview** 自己顯示為「高管总览」。

磁貼上方是三個面板級控制項：一個按預計成交日期的日期範圍選擇器（預設本季）、一個 **Owner** 篩選器和一個 **Lead Source** 篩選器。開頭 4 個 KPI 磁貼各自框定了自己的週期（本年度累計、"活躍"、"未轉換"），不受日期選擇器收窄，所以這幾個數始終是完整的，而收入類圖表跟著選擇器走。

對銷售經理與管理員來說，它就是每日開始工作的著陸頁。

本節過去承諾的 4 樣東西，這塊儀表板上沒有任何磁貼對應；另有一個名字，它屬於另一塊儀表板：

- **CRM Overview** 是一塊真實存在的儀表板，但它不是 **Home** 打開的那塊。它掛在 **Insights** 群組下，在側邊欄靠下的位置——所以它要點一下才打開，不是"第一眼看到"的東西。**Open Deals (Selected Period)**（進行中商機的筆數）、**Deals Won (Selected Period)** 與 **Pipeline by Owner** 是它的磁貼，不是這塊的。
- *等待你回應的工單*：兩塊儀表板上都沒有。**Executive Overview** 與 **CRM Overview** 都沒有任何磁貼在數工單。**Open Cases**、**Critical Cases**、**Open Cases Past SLA** 在 **Service** 群組下的 **Service Overview** 上——參見 [Service](/zh-Hant/docs/service/index)。
- *按管道價值排名的頂級客戶*：本應用裡根本沒有這樣一個磁貼。**Accounts by Industry** 是按產業歸組，不是給客戶排名；全應用最接近的排名是 **CRM Overview** 上的 **Pipeline by Owner**，那是按業務代表排，不是按客戶排。
- *近期活動（最近的通話、會議、郵件）*：也不在這裡。**Interactions Logged**、**Meetings Booked** 與 **Customer Minutes** 在 **Activity** 群組下的 **Sales Activity** 上。
- *給經理看的團隊級彙總*：這塊儀表板不做這件事。每個磁貼對所有人跑的都是同一個查詢，變的是你被允許讀到哪些記錄，而那由你的權限集決定。本應用的職位是扁平的——沒有可供可見性向上彙總的匯報線——而 **Sales Manager** 權限集直接授予 `viewAllRecords`，所以經理讀到的是全組織的合計，而不是某個團隊的切片。

➜ 了解更多：[儀表板](/zh-Hant/docs/analytics/dashboards)

## 2. 應用啟動器

點擊**應用啟動器**（左上角網格圖示）以在應用之間切換。HotCRM 按業務線分成多個應用，所以控制台打開時停在首頁，首頁的 *Your apps* 一欄列出你的啟動器提供的應用，點一個即可進入：

- **Sales** —— 線索、客戶、商機、報價與合約：銷售團隊的應用。
- **Service** —— 工單、知識庫，以及它們所屬的客戶。
- **Marketing** —— 行銷活動，以及它觸達的線索、聯絡人與客戶；行銷模組啟用時才有。
- **Order to Cash** —— 發票、回款和回款計劃，以及它們所屬的合約與客戶：財務的應用；訂單與回款模組啟用時才有。
- **Project Delivery** —— 項目、人員配置、預算、工時單，以及每個項目的成本：交付團隊的應用；項目交付模組啟用時才有。
- **Expenses** —— 費用、報銷單和出差申請：每一位員工的應用；費用報銷模組啟用時才有。
- **Admin** —— 面向系統管理員。

啟動器只列出你的工作需要的應用。銷售代表看到 **Sales**，服務專員與服務經理看到 **Service**，行銷人員看到 **Sales** 與 **Marketing**，應收會計看到 **Order to Cash**，項目經理與項目成員看到 **Sales** 與 **Project Delivery**，銷售經理與管理員全都看得到。**Expenses** 在每個人的啟動器上，因為每個人都會為公司花錢。這決定的是啟動器顯示什麼，而不是你能打開什麼：啟動器上沒有的應用，用它的位址照樣能打開；記錄連結會在你目前所在的應用裡打開。

在 Sales 內，左側導覽最上面是一個固定條目——**Home**，它打開的是 **Executive Overview** 儀表板；其餘內容分在 7 個群組裡：

| 分組 | 內容 |
| --- | --- |
| **Sales** | Leads、Accounts、Contacts、Opportunities、Sales Performance、Contracts、Orders、Quotes、Products、Price Books、Product Catalog、Knowledge |
| **Collection Plan** | Billing Milestones |
| **My Work** | My Tasks、My Deals、My Leads、My Calendar、Inbox |
| **Activity** | Events、Sales Activity |
| **Insights** | CRM Overview、Forecasts |
| **Reports** | Opportunities by Stage、Won Opportunities by Owner、Pipeline Coverage by Quarter、Opportunity Funnel by Owner、Lead Engagement by Month、Accounts by Industry and Type、Customer Churn Signals |
| **Help** | User Manual、Admin Manual、Revenue Manual、Order to Cash Manual |

上表用的是原始碼裡的英文 label，也就是英文介面上看到的名字。本應用提供 en / zh-CN / ja-JP / es-ES 四種介面語言，沒有繁體語言包——簡體中文介面下這些名字會顯示為語言包裡的譯名，例如 **Inbox** 顯示為「待我审批」、**Knowledge** 顯示為「知识库」、**My Work** 顯示為「我的工作」。

**Reports** 和 **Help** 這兩個群組在應用載入時是摺疊的——**Sales**、**Collection Plan**、**My Work**、**Activity**、**Insights** 都會自動展開。先把 **Reports** 點開，再判斷某份報表在不在這裡。**Help** 開啟應用內手冊；**Admin Manual** 只對管理員顯示。

建立在商機之上的條目——**Home**、**Sales Performance**、**CRM Overview**，以及 **Reports** 下的四張商機報表——不能讀取商機的人在側邊欄裡看不到；服務專員與服務經理即使用位址打開 Sales 應用，也按職位看不到它們：他們名下沒有商機，**Opportunities** 與 **My Deals** 對他們總是空的，所以這兩個條目也不對他們顯示。其餘報表對各自的資料也是同樣的要求。銷售代表也看不到 **Home**，所以銷售代表的側邊欄從 **Sales** 開始，應用為銷售代表打開的是 **My Deals**。**Sales** 最後一項 **Knowledge** 是給銷售代表的：它開啟已發布的文章，只對銷售代表顯示。其他人在 **Service** 裡找到 **Knowledge**。

一個去處只佔一列，這是刻意的。同一個物件如果有多種檢視方式，它們是該物件列表頁頂部的標籤頁，而不是導覽裡另起一列——這樣側邊欄才短到能一眼掃完。

本頁過去列出的 5 個群組名，應用裡根本不存在；另有幾個條目名，真身並不在它說的位置：

- *Products*（產品）不是群組。產品目錄是 **Sales** 群組下的 **Products** 條目——產品是收入側的主資料，理應放在銷售裡——參見 [Products](/zh-Hant/docs/sales/products)。
- *Approvals* 現在也不是群組了。它下面唯一的條目 **Inbox** 本質上是一個「等你處理」的個人佇列，因此已併入 **My Work** 群組——參見 [Approvals](/zh-Hant/docs/sales/approvals)。
- 本頁過去列出的 4 個條目名已經不在側邊欄了，但功能一個都沒少——它們各自成了所屬列表頁上的一個標籤頁：*Pipeline* 是 **Opportunities** 頁面上的 Sales Pipeline 標籤頁；*Calendar* 與 *Interaction History* 是 **Events** 頁面上的 Event Calendar 與 ✅ Interaction History 標籤頁；*All Tasks* 則是 **My Tasks** 打開的那個頁面的第一個標籤頁。
- *Activities* 不是群組，真實的群組叫 **Activity**，而且任務不在裡面。`crm_task` 在側邊欄上就是 **My Work** 群組下的 **My Tasks** 一項。
- *Analytics* 不是群組。跨職能的儀表板 **CRM Overview** 在 **Insights** 群組下，應用自帶的每一張報表都在 **Reports** 群組下，上表已按各自的名字列出。沒有任何條目叫 *Dashboards*。
- *AI* 不是群組，也沒有叫 *Copilot* 或 *Knowledge Bases* 的側邊欄條目。HotCRM 不自帶助手；你的智能體透過 MCP 接入，而不是透過側邊欄條目（見下文第 8 節），知識文章則是 **Service** 裡 **Service** 群組下的 **Knowledge**。
- *Knowledge Base* 不是 HotCRM 使用的 label。在 **Service** 裡，這個條目叫 **Knowledge**，應用打開時落在的儀表板叫 **Service Overview**——參見 [Service](/zh-Hant/docs/service/index)。
- *Campaign Members* 不是側邊欄條目。行銷活動成員要從行銷活動詳情頁或全域搜尋進入——參見 [Campaign Members](/zh-Hant/docs/marketing/campaign-members)。
- *Approval Requests* 與 *Action History* 也都不是條目：本應用在審批側只有 **Inbox** 這一個入口。審批的操作留痕本身是真實資料，由審批外掛以 `sys_approval_action` 儲存，但本應用裡沒有任何導覽條目能打開它。

在 Service 內，左側導覽最上面是 **Service Overview**，即服務團隊的儀表板；其餘內容分在 5 個群組裡：

| 分組 | 內容 |
| --- | --- |
| **Service** | Cases、Knowledge |
| **Customers** | Accounts、Contacts |
| **My Work** | My Cases、Inbox、My Tasks、My Calendar |
| **Reports** | Cases by Status and Priority、SLA on Closed Cases、Cases Opened by Day、Customer Churn Signals |
| **Help** | Service Manual |

**Reports** 和 **Help** 這兩個群組在應用載入時是摺疊的——**Service**、**Customers**、**My Work** 都會自動展開。不能讀取工單的人看不到 **Service Overview** 和那三張工單報表；銷售代表即使用位址打開這個應用，也看不到任何工單條目。

在 Marketing 內，左側導覽最上面是 **Campaigns**；其餘內容分在 4 個群組裡：

| 分組 | 內容 |
| --- | --- |
| **Audience** | Leads、Contacts、Accounts |
| **My Work** | Inbox、My Tasks |
| **Reports** | Lead Engagement by Month |
| **Help** | Marketing Manual |

**Reports** 和 **Help** 這兩個群組在應用載入時是摺疊的——**Audience**、**My Work** 都會自動展開。**Lead Engagement by Month** 與 **Customer Churn Signals** 各出現在兩個應用裡；兩處條目打開的是同一份報表。

在 Order to Cash 內，左側導覽打開在第一個群組的第一項 **Invoices** 上；全部內容分在 5 個群組裡：

| 分組 | 內容 |
| --- | --- |
| **Receivables** | Invoices、Payments、Billing Milestones |
| **Follow-up** | Overdue Invoices、Planned This Month |
| **Orders, Contracts and Accounts** | Contracts、Orders、Accounts |
| **My Work** | Inbox、My Tasks |
| **Help** | Order to Cash Manual |

**Help** 在應用載入時是摺疊的——**Receivables**、**Follow-up**、**Orders, Contracts and Accounts**、**My Work** 都會自動展開。編寫回款計劃的銷售代表和經理在 **Sales** 的 **Collection Plan** 下找到 **Billing Milestones**，在它的 **Help** 下找到 **Order to Cash Manual**；兩處條目打開的是同一個列表或手冊。

## 3. 你的第一條線索

**線索**是已表達興趣但尚未通過資格審查的人。

1. 點擊 **Sales → Leads → New**。
2. 填寫 **Name**、**Company**、**Email**。
3. 儲存。線索會自動指派給你。
4. 如果你接入了智能體（見 [AI 與智能體](/zh-Hant/docs/ai-copilot/index)），請它 *「判定此線索資格」*：[線索資格審查技能](/zh-Hant/docs/ai-copilot/skills) 會按 BANT 給出 0–100 的評分並建議下一步操作。
5. 準備就緒後，點擊 **轉化線索** 一步將線索轉化為 Account + Contact + Opportunity。

➜ 了解更多：[線索](/zh-Hant/docs/sales/leads)

## 4. 你的第一個商機

**商機**是你正在處理的真實交易。

1. 由線索轉化自動建立，或 **Sales → Opportunities → New**。
2. 設定 **Account**、**Amount**、**Close Date**、**Stage**。
3. 隨著交易推進，將其在各階段間移動：*Prospecting → Qualification → Proposal → Negotiation → Closed Won*。
4. 系統會強制執行[狀態機](/zh-Hant/docs/administration/state-machines) —— 你不能隨意跳過階段。
5. 透過接受它的報價單來贏單：商機以 *Closed Won* 關閉，系統根據報價單建立一張草稿訂單，並通知團隊。這次銷售需要合約時，在訂單上點 **Draft Contract**。手動把階段設為 *Closed Won* 也會贏單，但不會建立訂單。

➜ 了解更多：[商機](/zh-Hant/docs/sales/opportunities)

## 5. 一個工單

**工單**是一個客戶問題。

1. 工單透過郵件、Web 表單、電話、聊天或入口網站到達。
2. 新工單進入佇列 —— 專員接手。
3. 接入智能體後，請它 *「分流此工單」* —— [工單分流技能](/zh-Hant/docs/ai-copilot/skills) 會建議優先順序、分類以及匹配的知識庫文章。
4. SLA 計時器開始 —— 在工單頁面查看回應時間 / 解決時間倒數計時。
5. 回覆客戶；解決後關閉工單。

➜ 了解更多：[工單](/zh-Hant/docs/service/cases)

## 6. 一個項目

**項目**交付已售出的內容：為一個客戶做的一項工作，帶著它的團隊、預算和成本。

1. 在 **Project Delivery** 裡打開 **All Projects → New**，或者打開客戶、商機、合約或訂單上的 **Projects** 分頁。
2. 給它一個名稱和所屬客戶，並寫明它交付的商機、合約或訂單。
3. 規劃預算，然後提交審批；核准後，由項目經理把它設為 *Active*。
4. 配置人員：每位成員都按一張費率卡安排，帶有成本單價和計費單價。
5. 團隊在工時單上填報工時，項目經理在 **Inbox** 裡審批。已核准的工時和已核准的費用構成項目的成本，與預算對照。

➜ 了解更多：[項目交付](/zh-Hant/docs/projects)

## 7. 一筆費用

每個人都在 **Expenses** 裡記錄為公司花的錢。

1. 打開 **My Expenses → New**，填寫金額和日期，附上票據。
2. 選取一筆或多筆費用，點擊 **Submit for Reimbursement**：它們進入一張報銷單，每個項目一張，並在同一次點擊中提交審批。
3. 你的經理在 **Inbox** 裡審批這張報銷單（項目上的報銷單由項目經理審批；金額從 2,000 起，財務也要審批）。
4. 財務把已核准的報銷單標記為已付款。HotCRM 不付出任何款項；這個標記只記錄款項已經付過。

➜ 了解更多：[費用報銷](/zh-Hant/docs/expenses)

## 8. 你的智能體

HotCRM 不自帶助手。透過 MCP 接入你的智能體，它就和你在同一批紀錄上工作，以你的身分、在你的權限與共用規則之下：你讀不到的紀錄，它也讀不到。如果你的環境運行著平台的助手，HotCRM 的八項技能會教它審查線索資格、起草郵件、做預測、產生客戶 360°、分流工單，以及代填和檢查費用。

➜ 了解更多：[AI 與智能體](/zh-Hant/docs/ai-copilot/index)
