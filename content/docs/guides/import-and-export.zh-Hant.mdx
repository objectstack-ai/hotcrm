# 匯入與匯出

如何將資料**匯入** HotCRM（批量匯入、遷移）以及**匯出**（匯出、GDPR、備份）。

## 從 CSV / Excel 匯入

最簡單的途徑。適用於：潛在客戶、客戶、聯絡人、產品、商機、工單、合約。

### 分步操作

1. 前往 **設定 → 資料 → 匯入精靈**。
2. 選擇要匯入到的**物件**。
3. 上傳 **CSV** 或 **Excel** 檔案（每次上傳最大 50 MB；更大的檔案請拆分）。
4. **將欄映射**到欄位 —— 精靈會按表頭名稱自動建議比對。
5. 選擇**衝突行為**：
   - **僅插入** —— 跳過與現有記錄比對的列。
   - **插入並更新** —— 更新現有記錄（按郵件 / 外部 ID 比對）。
   - **僅更新** —— 如果未找到則失敗。
6. 執行**試運行** —— 精靈會報告有多少會成功 / 失敗，而不進行寫入。
7. **提交** —— 執行匯入。你會看到一個進度條；大型匯入在背景執行，完成後你會收到一封郵件。

### 欄位映射提示

- **擁有者** —— 提供使用者的郵件地址；匯入器會解析為使用者 ID。
- **查閱欄位** —— 提供被引用記錄的 *Name* 或 *External ID*；匯入器會進行解析。
- **選項清單** —— 值必須與選項清單定義的值完全比對（不區分大小寫）。
- **日期** —— ISO 格式（`2025-03-15`）在任何地方都適用；否則請指定格式。
- **多選** —— 用分號分隔各值。

### 外部 ID（推薦）

新增一個 `external_id` 欄（例如 `legacy_account_id = ACME-001`）並將其標記為比對鍵。這讓你能夠：

- 冪等地重新執行匯入而不建立重複記錄。
- 在物件之間交叉引用（例如，匯入潛在客戶及其原始客戶的外部 ID，匯入器會將它們關聯起來）。

## 從 Salesforce 遷移

隨附了一個專門建構的遷移精靈。

1. **設定 → 資料 → 從 Salesforce 遷移**。
2. 透過 OAuth 授權 —— 精靈會從你的 Salesforce 沙箱或生產環境中讀取。
3. 精靈會自動將 Salesforce 物件映射到 HotCRM 對應項：

   | Salesforce | HotCRM |
   | --- | --- |
   | Account | account |
   | Contact | contact |
   | Lead | lead |
   | Opportunity | opportunity |
   | OpportunityLineItem | opportunity_line_item |
   | Quote / QuoteLineItem | quote / quote_line_item |
   | Contract | contract |
   | Case | case |
   | Campaign / CampaignMember | campaign / campaign_member |
   | Product2 | product |
   | Task / Event | task / event |
   | User | user *（按郵件比對或邀請）* |

4. **欄位映射** —— 預設值合理；審閱並調整自訂欄位。
5. **選項清單映射** —— 將 Salesforce 的值映射到 HotCRM 的值（尤其是階段、狀態、優先級）。
6. **擁有者映射** —— 按郵件將 Salesforce 使用者映射到 HotCRM 使用者。
7. **選擇資料切片** —— 全部歷史資料，或一個日期範圍（用於分階段切換）。
8. **試運行**，審閱報告，**提交**。

精靈會將 Salesforce ID 保留為 `external_id` 以便追溯。

## 從 HubSpot 遷移

在 **設定 → 資料 → 從 HubSpot 遷移** 中有一個類似的精靈。將 Hub 物件類型映射到 HotCRM：

| HubSpot | HotCRM |
| --- | --- |
| Company | account |
| Contact | contact |
| Deal | opportunity |
| Ticket | case |
| Line item | opportunity_line_item |
| Product | product |
| Quote | quote |

交易管道映射到商機階段 —— 請仔細審閱選項清單映射。

## 遷移操作手冊

1. **首先映射角色和使用者** —— 沒有擁有者，一切都會成為孤立資料。
2. **在沙箱中試運行** —— 切勿對生產環境執行首次遷移。
3. **按此順序遷移**以保持引用關係完整：
   1. 使用者
   2. 產品
   3. 客戶（+ 外部 ID）
   4. 聯絡人（+ 關聯到客戶）
   5. 潛在客戶
   6. 商機（+ 關聯到客戶 + 聯絡人）
   7. 商機行項目
   8. 報價 / 報價行項目
   9. 合約
   10. 工單
   11. 行銷活動
   12. 行銷活動成員
   13. 任務 / 事件 / 備註 / 檔案
4. **核對數量** —— 來源系統的總數 vs. HotCRM。調查任何 >0.1% 的差距。
5. **端到端手動抽查 10 條記錄**。
6. 在上線前**獲得**銷售 / 服務負責人的**簽字核准**。

## 匯出資料

### 臨時匯出

從任何清單檢視或報表 → **匯出** → CSV 或 Excel。受使用者權限和 FLS 約束。

### 排程匯出

用於資料倉儲載入（Snowflake、BigQuery、Redshift）：

- **設定 → 資料 → 排程匯出** → 選擇物件、欄位、篩選條件、排程、目標位置。
- 目標位置：S3 / Azure Blob / GCS / SFTP。
- 格式：CSV、Parquet 或 JSON Lines。
- 增量 —— 僅自上次執行以來發生變更的資料。

### 批量 API 匯出

用於程式化匯出 —— 使用 [API 參考](/zh-Hant/docs/customization/api-reference)。用 ObjectQL 查詢任何物件；結果分頁返回。

## GDPR / 資料刪除請求

當客戶請求 *「刪除我的所有個人資料」* 時：

1. **設定 → 隱私 → 資料主體請求 → 新增**。
2. 識別該人 —— 按郵件或聯絡人 ID。
3. 精靈會顯示與他們關聯的所有內容：聯絡人記錄、潛在客戶、工單、已記錄的郵件、行銷活動成員資格、檔案。
4. 選擇 **刪除** 或 **匿名化**（用 `[redacted]` 替換姓名/郵件，同時保留記錄以供分析）。
5. 確認 —— 系統會進行處理並生成一份你可以交給客戶的**稽核憑證**。

通常更推薦匿名化 —— 它在不保留 PII 的情況下保持了歷史報表的完整性。

## 備份與災難復原

備份行為取決於 HotCRM 的託管方式：

- **SaaS** —— 備份由平台管理（通常每日快照，30 天保留期）。
- **自託管** —— 由你負責；備份資料庫和檔案儲存桶。請參閱 [管理 › 設定](/zh-Hant/docs/administration/setup) 了解推薦的頻率。

要獲取經過測試的**災難復原**操作手冊，請參閱 [參考 › 安全與合規](/zh-Hant/docs/reference/security-and-compliance)。

## 提示

- ✅ **始終試運行**大型匯入。
- ✅ **始終新增外部 ID** 欄 —— 讓你永遠擺脫重複記錄。
- ✅ **先在沙箱中遷移**，然後在切換的週末執行最終的增量遷移。
- ✅ 對於匯出，使用**排程匯出**而非臨時匯出 —— 可重複、受監控、失敗時會重試。
- ✅ 對於 GDPR，使用**匿名化**而非刪除 —— 讓報表保持真實。
