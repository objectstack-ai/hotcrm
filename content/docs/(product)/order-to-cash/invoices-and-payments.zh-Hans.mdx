# 发票与回款

这里的**发票**，是财务在自己系统中开具的一张发票的记录；**回款**，是收到款项的记录。两者都由财务录入或导入。销售在客户、订单、合同和**订单与回款**下的列表中查看它们。

两者都属于**客户**。订单和合同都可填可不填：针对一张订单的发票填这张订单；一张发票对应多个订单，或暂时对应不上任何发票的预收款，只需填客户。

**应收会计**岗位在所有客户上录入和导入它们。这个岗位能查看所有客户，但不能编辑任何客户：能查看客户，就足以写入它的发票和回款。

## 发票 [#invoices]

| 字段 | 内容 |
| --- | --- |
| **发票号码** | 财务开具的发票上的号码 |
| **客户** | 这张发票开给的客户。必填；选择订单、合同或回款计划时自动带出 |
| **订单** | 这张发票针对的订单（如有）。选择订单会带出它的客户，归在合同下的订单还会带出这份合同；另一个客户的订单会被拒绝 |
| **合同** | 这张发票针对的合同（如有） |
| **回款计划** | 这张发票对应的回款计划（如有）。选择节点会带出它的客户，发票没填订单或合同时还会带出它的订单和合同；另一个客户的节点会被拒绝 |
| **开票日期** | 开具的日期 |
| **到期日** | 应付款的日期（见下文） |
| **金额** | 开票金额，含税 |
| **状态** | **已开具**或**已作废** |
| **已付** | 针对这张发票收到的回款合计 |
| **未付** | **金额**减去**已付**，最低为零；已作废的发票为零 |
| **多付** | 付款超出**金额**的部分（如有，见下文） |
| **发票文件** | 发票文件（如已附上） |

**到期日。** **到期日**留空时，保存时会自动填写：**开票日期**加上合同的**付款条款**；没有合同或合同没填付款条款时，取订单的**付款条款**（Net 15、30、60 或 90 天；Due on Receipt 即开票当天）。填写了日期则按填写的保存。既没有订单也没有合同的发票没有付款条款可用，请手工填写到期日。

**多付。** 让**已付**超过**金额**的回款照样接受，无论是手工录入还是导入，因为这笔钱确实收到了。发票随即按已付清处理：**未付**为零，超出的部分显示在**多付**里。多付的金额不会冲抵这位客户的其他发票，合同和客户的**应收余额**也不会因此变成负数。

**已作废的发票。** 在源头作废或全额红冲的发票，在这里设为**已作废**。它随即退出所有统计：所属节点不再把它计为已开票，未付金额为零。

**发票选了另一个客户的回款计划会被拒绝。** 提示会写明是哪个节点；发票上还留着节点带出的订单或合同时，写明的是那个订单或合同。表单会列出所有客户的回款计划，所以在保存时检查。

## 逾期发票 [#overdue-invoices]

**逾期发票**列表（「订单与回款」应用的**跟进 → 逾期发票**，也是其**发票**列表上的一个标签页），按到期日从早到晚列出你能看到的、状态为**已开具**、**到期日**早于今天且仍有**未付**金额的发票。回款付清当天，或财务将其作废后，发票就会离开这个列表。

## 回款 [#payments]

| 字段 | 内容 |
| --- | --- |
| **回款编号** | 自动编号：PAY-00001、PAY-00002…… |
| **客户** | 付款的客户。必填；选择订单或合同时自动带出 |
| **订单** | 这笔款项针对的订单（如有）。留空时从发票带出，没有发票时从回款计划带出 |
| **合同** | 这笔款项针对的合同（如有）。留空时从订单、发票带出，都没有时从回款计划带出 |
| **发票** | 这笔款项支付的发票（如有）。只提供这笔回款所属客户的发票 |
| **回款计划** | 这笔款项计入的节点。有发票时从发票带入；开票前收到的预付款，请自行选择 |
| **回款日期** | 收到款项的日期 |
| **金额** | 收到多少 |
| **方式** | **银行转账**或**其他** |

**每张发票一行。** 一笔收款支付了多张发票时，按财务已有的拆分，每张发票记录一笔回款。HotCRM 中没有分摊这一步。

**开票前的预付款。** 把回款记录到回款计划上；还没有节点对应时，只记在客户上。发票开具后，在同一笔回款上填写**发票**。

**针对其他客户发票的回款会被拒绝**，提示会写明是哪张发票。这只可能发生在导入中，因为表单只提供本客户的发票。

**发票或回款上选择另一个客户的订单或合同会被拒绝**，提示会写明是哪一个。填了订单之外的另一份合同，或订单和合同属于不同客户，同样会被拒绝。导入时 **Account** 留空，就由订单或合同带出。

## 导入 [#importing]

财务可以用**Invoice Import (CSV)** 和 **Payment Import (CSV)** 两个导入映射，从电子表格、财务软件或 ERP 的导出文件批量导入发票和回款。带有正确列标题的模板是 `assets/import-templates/` 下的 `invoices.csv` 和 `payments.csv`。

| 列 | 发票 | 回款 |
| --- | --- | --- |
| ERP Reference | ✓ 唯一编号 | ✓ 唯一编号 |
| Account | ✓ 客户名称；填了订单或合同时可留空 | ✓ 填了订单、合同、发票或节点时可留空 |
| Order | ✓ 订单编号，例如 SO-0001，或订单的**外部编号**；可选 | ✓ 可选 |
| Contract | ✓ 合同编号，例如 CTR-0001；可选 | ✓ 可选 |
| Invoice Number | ✓ | — |
| Invoice | — | ✓ 发票号码 |
| Billing Milestone | ✓ 节点名称 | ✓ |
| Issue Date、Due Date、Amount、Status | ✓ | — |
| Payment Date、Amount、Method | — | ✓ |

- **ERP 编号是唯一键。** 导入一行时，如果它的 **ERP 编号**已在某张发票上，就更新这张发票，而不会再添加一张。因此财务修改文件后可以再次导入。ERP 通过接口写入时使用同一个编号。
- **每一条导入的记录都有标记。** 它的**来源**为**导入**，**同步时间**为导入的时刻，读者可以看出数字从哪里来、有多新。手工录入的记录，来源为**手工录入**。
- **引用按名称匹配。** 客户名称、订单编号或外部编号、合同编号、发票号码或节点名称匹配不到任何记录时，该行导入失败，导入报告会写明原因。客户、订单和合同都没填（回款还可以是发票或节点）的行同样失败：客户是必填的。
- **多份合同上有同名节点时，该行导入失败。** 节点常常同名（「预付 30%」「第二年」），而导入会在所有合同里查找这个名称，不只在该行的合同里查找，所以导入报告会写「匹配到多条记录」。这时在 **Billing Milestone** 列填写节点的记录 ID，它在节点页面地址的末尾。两个客户同名时，**Account** 列也会这样失败。

金额使用公司的币种，与 HotCRM 中所有金额一样。请在导入前完成换算。
