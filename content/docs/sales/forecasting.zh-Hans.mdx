# 预测

**预测**是某一时刻销售管道的冻结快照。每个负责人每个周期一条记录——通常是每位销售代表每季度或每月一条。你通过堆叠快照来构建趋势（"我们的 Q3 数字逐周是如何变化的？"），而不是通过重新读取实时商机数据。

本页讲的是存储这些快照的**预测对象**。关于*生成*预测叙述的 AI 对话，请参见 **AI Copilot → 营收预测**。

## 预测记录上存储的内容

| 区块 | 字段 |
| --- | --- |
| **周期** | 负责人、周期（`month` / `quarter`）、周期开始。周期结束和友好标签（例如 **Q3 2026**）是派生的。 |
| **数字** | 配额、销售管道金额、最佳情况金额、承诺金额、已成交金额。 |
| **来源** | `scheduled`（每晚作业）、`ai`（Copilot 生成）、`manual`（销售代表录入）。 |
| **叙述** | 可选的评述——发生了什么变化、什么有风险、下次一对一要问什么。 |

销售管道、最佳情况、承诺和已成交是相互独立的桶——它们回答不同的问题：

- **销售管道**——本周期内的每一笔开放交易，无论信心如何。
- **最佳情况**——销售代表认为通过冲刺努力可以赢下的交易。
- **承诺**——销售代表愿意以自己名义担保的交易（按惯例 ≥ 80% 概率）。
- **已成交**——已经赢得；无法移动。

## 周期是如何派生的

你输入 `period` 和 `period_start`；系统计算其余部分。对于一个从 2026-07-01 开始的季度预测：

- `period_end` → 2026-09-30
- `period_label` → **Q3 2026**

因此你绝不会看到一条标记为"2026-07-01 至 ???"的记录——只有人类可读的标签。列表视图和仪表盘会直接按 `period_label` 分组。

## 预测是如何创建的

有三种来源，记录在 `source` 字段中：

1. **Scheduled**——一个每晚作业（构建于平台的流程引擎之上）为每位销售代表的销售管道拍快照。这是历史趋势的脊柱。
2. **AI**——Copilot 技能根据当前销售管道 + 近期阶段移动 + 类似的过往交易生成预测。对话记录会与该记录一并存储。
3. **Manual**——经理直接录入一个数字。用于调整和覆盖。

你可以为同一个负责人/周期拥有全部三种——它们在趋势图中并排显示，因此分歧是可见的。

## 你用它们来做什么

- **汇总仪表盘**——销售仪表盘按 `period_label` 分组并在整个团队上对 `commit_amount` 求和。
- **趋势**——选择一个负责人和一个周期，按每个快照的 `created_at` 绘制 `commit_amount` 的图表。突然的下降会触发*"为什么这周承诺下降了 ¥800k？"*的对话。
- **达成率**——`closed_amount / quota` 在报告层计算；没有专门的字段。
- **AI 依据**——AI 代理读取近期快照，将其叙述建立在真实的进展之上，而非凭空想象的交易。

## 谁能编辑

预测继承标准的 CRM 权限模型：

- **销售代表**查看并编辑自己的预测。
- **销售经理**查看并编辑其辖区内所有人的预测（通过角色层级）。
- **销售运营**查看所有预测，并可以覆盖任何数字。
- 所有编辑都会在平台审计日志中被跟踪——每次承诺更改都会被归因并加上时间戳。

## 常见问题

**我应该每周拍快照还是只在季末拍？**
每周。预测的全部价值在于趋势，季末的单个快照什么也告诉不了你。

**如果销售代表在两次快照之间移动了一笔交易会怎样？**
两个快照都会被保留。下次仪表盘刷新显示新数字；趋势图将旧数字显示为一个历史点。

**预测能自动从商机汇总吗？**
你放到快照上的数字可以是你想要的任何值——通常由你的流程或你的 AI 代理从实时商机计算得出。对象本身不会重新计算它们；它有意保留快照那一刻的值。

**这与已保存的报告有何不同？**
报告针对*当前*数据运行。预测是一个*冻结*的数字——即使六个月后，查看上季度的承诺也会给你销售代表当时所担保的数字，而不是从此后已经变动的记录重新计算出的数字。
