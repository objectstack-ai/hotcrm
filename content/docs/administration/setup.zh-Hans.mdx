# 设置清单

为新 HotCRM 管理员准备的实用的第一周清单。请按顺序逐项完成 —— 每个部分都建立在前一个之上。

## ✅ 第 1 天 —— 基础

### 1. 公司资料

导航至 **设置 → 公司信息**：

- [ ] 公司名称、地址、时区、默认货币
- [ ] 财年起始月份（所有预测报表都会用到）
- [ ] 默认语言

### 2. 营业时间 —— 没有需要配置的东西

**不存在“设置 → 营业时间”这个屏幕。** 本应用没有工作日日历，没有工作时段设置，也没有节假日清单 —— 这里没有任何可填的项，也不存在任何可供截止时间去对照的东西。这一节保留下来，只是为了让被指去找那个屏幕的管理员别再找了。

由此带来的后果落在 SLA 一侧：截止时间按**日历小时**走。本应用唯一会算出来的截止时间是 Critical 工单的目标 —— `src/objects/case.hook.ts` 往当前时钟上加 4 小时（`due.setHours(due.getHours() + 4)`）—— 所以一个周五下午 4 点建的 Critical 工单，截止时间就是同一个周五晚上 8 点，夜间、周末与节假日一律照算进去。其余优先级根本不会被打上截止时间：High 的 8 小时目标以及其余各档，都是你的团队自己守的服务承诺，不是应用在跑的计时器。参见 [SLA 与升级](/zh-Hans/docs/service/sla-and-escalation)。

### 3. 电子邮件设置

**设置 → 电子邮件**：

- [ ] 案例的入站邮件转发（例如 `support@yourdomain.com`）
- [ ] 出站邮件签名模板
- [ ] 用于发件人身份验证的 DKIM / SPF

## ✅ 第 2 天 —— 人员

### 4. 用户邀请

**设置 → 用户**：

- [ ] 导入或邀请所有用户
- [ ] 为每个用户分配一个 [权限档案](/zh-Hans/docs/administration/profiles)
- [ ] 在层级中为每个用户分配一个角色
- [ ] 为每个用户设置一名经理（驱动审批路由）

### 5. 角色层级

**设置 → 角色**：

- [ ] 确认默认层级（高管 → 总监 → 经理 → 代表）与你的组织相符
- [ ] 为区域或专门团队添加自定义角色

### 6. 权限档案与权限

**设置 → 权限档案**：

- [ ] 审查六种内置权限档案（参见 [权限档案](/zh-Hans/docs/administration/profiles)）
- [ ] 如有需要，克隆并自定义（例如一个删除权限有限的 *初级销售代表* 权限档案）

## ✅ 第 3 天 —— 数据基础

### 7. 客户与联系人所有权

- [ ] 为客户和联系人决定组织范围默认值（私有 vs 公开读取 vs 公开读/写）—— 参见 [共享与安全](/zh-Hans/docs/administration/sharing-and-security)
- [ ] 如果你以小组而非单个代表的方式销售，配置客户团队

### 8. 潜在客户路由

**设置 → 潜在客户设置**：

- [ ] 默认潜在客户所有者 / 队列（无规则匹配时）
- [ ] 路由规则（按区域、行业、来源）
- [ ] 对来自网页表单的新潜在客户的自动回复邮件

### 9. 产品目录

- [ ] 导入 [产品](/zh-Hans/docs/revenue/products) —— 至少：代码、名称、标价、计费类型
- [ ] 设置产品经理（每条产品线的联系人）
- [ ] 上传数据表 —— 产品记录上的一个 PDF 文件字段，供人打开查看；没有任何知识库会摄取它

## ✅ 第 4 天 —— 流程

### 10. 商机阶段

确认 7 阶段默认管道与你的销售流程相符。各阶段及其概率为：

| 阶段 | 概率 |
| --- | --- |
| Prospecting | 10% |
| Qualification | 25% |
| Needs Analysis | 40% |
| Proposal | 60% |
| Negotiation | 80% |
| Closed Won | 100% |
| Closed Lost | 0% |

如果你的流程不同，那是一次源码修改，不是在某个屏上调整：**并不存在「设置 → 商机 → 阶段」这个页面**。七个阶段是 `stage` 字段自己的选项（`src/objects/_picklists.ts` 里的 `OPPORTUNITY_STAGE_OPTIONS`），概率则是 `src/objects/opportunity.hook.ts` 里的 `STAGE_PROBABILITY` 映射 —— 它在每次保存时都按阶段重新推导 **Probability** 与 **Expected Revenue**，所以手工填在商机上的概率撑不过下一次保存。改动其中任何一项都是代码改动加一次重新部署。

### 11. 案例 SLA

确认默认的 [SLA 矩阵](/zh-Hans/docs/service/sla-and-escalation)：

| 优先级 | 解决 |
| --- | --- |
| Critical | 4 小时 |
| High | 8 小时 |
| Medium | 2 个工作日 |
| Low | 7 个工作日 |

**只有 Critical 这一行是应用真正在守的期限。** `case_sla_defaults` 钩子（`src/objects/case.hook.ts`）在 Critical 工单上把 `sla_due_date` 盖成 *当前时间 + 4 个自然小时*，其余三个优先级什么都不写 —— 而每小时跑一次的 `case_sla_monitor` 只捞到期日已过的工单，所以 Critical 以下根本没有一个日期可以过期。那三行是你们团队的服务承诺，不是应用替你跑的钟。

**这里没有「首次响应目标」可确认。** 本清单曾经带着整整一列 *首次响应*（Critical 1 小时一直到 Low 1 个工作日），这四个数字在应用里哪儿都不存在；本节链过去的那一页 SLA 文档也根本没提过首次响应。真正存在的是那个时间戳：**First Response Date** 在工单上第一次记录 *已经发生过* 的通话或会议时被写入（`logActivityAction`，`src/actions/global.actions.ts`）。它从不与任何目标比较 —— `case_metrics` 没有声明任何首次响应度量，因此没有报表、没有仪表盘磁贴会报它，也没有任何流程会为它告警。你当然可以对客户承诺一个首次响应时长；应用只是记下它何时发生，别的什么都不做。

如果你的支持承诺不同，请自行调整 —— Critical 的这 4 小时写在 `src/objects/case.hook.ts` 里，不在任何设置屏上。

### 12. 审批流程

- [ ] 确认折扣审批阈值（默认 $500K）—— 参见 [审批](/zh-Hans/docs/revenue/approvals)
- [ ] 确认审批人（按角色：经理 + 总监）
- [ ] 通过提交一个示例商机进行测试

## ✅ 第 5 天 —— 知识与 AI

### 13. 知识文章

HotCRM 只附带**一个**知识对象，而不是一组知识库。下面每一条都是你在**服务 → 知识**下创建的普通记录，归入该对象定义的七个分类之一。

- [ ] 把最热门的 20 个 FAQ 写成文章，归入**故障排查**、**操作指南**或**入门指南**
- [ ] 把支持时间、SLA 承诺和数据处理说明归入**政策制度**
- [ ] 逐篇设置**受众** —— 操作手册用*仅内部*，你愿意发给客户的用*公开*
- [ ] 把它们**发布** —— Copilot 只查询已发布的文章，草稿等于不存在
- [ ] 收工前复核一遍分类和标签：匹配靠的是分类与标签而不是语义，归错的文章就是找不到的文章

没有任何叫 *销售知识*、*产品信息* 或 *竞争情报* 的东西可以填充种子内容 —— HotCRM 不附带这些库，也没有可供对战卡挂靠的竞争对手对象。Copilot 拿一篇文章能做什么、不能做什么，参见 [知识库](/zh-Hans/docs/ai-copilot/knowledge-bases)。

### 14. AI Copilot

- [ ] 确认 AI Copilot 已启用（设置 → AI）
- [ ] 选择要启用哪些技能
- [ ] 运行一个示例查询（*“给我 [测试客户] 的 Customer 360”*）以验证
- [ ] 配置数据敏感性规则 —— Copilot 必须脱敏哪些字段

## ✅ 第 6 天 —— 仪表板与报表

- [ ] 将 **CRM 概览** 固定为所有人的主页仪表板
- [ ] 设置团队专属仪表板（销售 / 服务 / 高管）
- [ ] 为经理安排每周订阅邮件
- [ ] 审查 [标准报表](/zh-Hans/docs/analytics/reports) 并自定义筛选器

## ✅ 第 7 天 —— 上线

- [ ] 运行 **迁移检查**（所有导入的记录都有所有者和必填字段）
- [ ] 运行 **冒烟测试**：创建潜在客户 → 转化 → 商机 → 报价 → 赢单 → 合同
- [ ] 培训用户掌握他们的日常工作流（45 分钟的基于角色的会话）
- [ ] 设置一个内部 **#hotcrm-help** 频道用于答疑

## 上线后

- **第 2 周**：审查仪表板使用情况和采用指标。
- **第 1 个月**：首次回顾 —— 哪些有效，哪些无效。
- **每季度**：审查权限档案、共享规则、知识库是否有漂移。
