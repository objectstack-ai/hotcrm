# 客户

**客户**是你与之开展业务的公司（或任何组织）。它是其他一切所依附的中心枢纽：

- 联系人*为*某个客户工作。
- 商机是*与*某个客户的。
- 工单是*由*某个客户*提出*的。
- 报价和合同是*由*某个客户*签署*的。

## 4 种客户类型

每个客户都有一个**类型**，它决定了系统其余部分如何处理它：

| 类型 | 何时使用 |
| --- | --- |
| 🟠 **潜在客户** | 售前——尚无合同。*（新建客户的默认值。）* |
| 🟢 **客户** | 正在付费的活跃客户。 |
| 🔵 **合作伙伴** | 经销商、集成商或渠道合作伙伴。 |
| ⚪ **流失客户** | 已流失——保留以用于赢回营销活动。 |

当为某个潜在客户激活一份合同时，系统会自动将该客户提升为**客户**。你无需记着去更新它。

## 商务能力——可以和谁开商机

**类型**说明的是客户与你之间的关系走到了哪一步。**商务能力**回答的是另一个问题：*究竟能不能在它身上承接新业务？*

| 商务能力 | 含义 |
| --- | --- |
| 🟢 **完整** | 一切照常。*（新建客户的默认值。）* |
| 🟠 **仅结算** | 记录留着，生意不做。该客户依然完整可用于开票、付款与收款，但**不能再为它新建商机**。 |

招标代理、名义经销商、集团内部结算主体和休眠客户，是典型的*仅结算*场景：钱照样通过它们收付，只是不向它们销售。

这是一道**闸门，不是一个标签**。在新建商机上选择被标为*仅结算*的客户，保存会被拒绝，并给出一条点名该客户、说明该怎么办的提示。它刻意**不**做两件事：

- **它绝不破坏历史数据。** 已经挂在该客户上的商机照常可用、照常可编辑，即便之后有人把该客户改成*仅结算*也是如此。被拒绝的只有*新建*的关联。
- **它不是合规锁。** 它是由人填写的一项分类，同一个人在关系变化时也可以把它改回*完整*。

两个维度互相独立：一个*仅结算*客户可以是潜在客户、正式客户或流失客户；赢下一笔交易也绝不会悄悄解除这项限制。

## 客户审批

新建的客户以**待审批**开始。它会出现在审批收件箱里，由销售经理通过或驳回。**审批状态**在表单上是只读的，因此它只会通过对那条审批请求的裁定而改变——没有人能靠手填把它写成*已通过*。被驳回的客户仍然保留在档，以便修正资料后再次送审。

**审批状态**回答的是*「这条记录被签核了吗？」*，而**活跃**回答的是*「这个客户还在用吗？」*。两者刻意分开：已通过的客户之后仍可被停用，而待审批也不等于非活跃。

如果你所在的组织不需要对客户做签核，管理员把**审批状态**的默认值改成*已通过*即可，此后新建客户不会再进入审批队列——见[管理 › 自动化](/zh-Hans/docs/administration/automation)。

## 每条客户记录存储的内容

客户详情界面分为 7 个区块：

| 区块 | 字段 |
| --- | --- |
| **基本信息** | 客户编号、登记证件号、名称、类型、商务能力、行业、描述 |
| **财务** | 年营收、员工人数、子公司年营收合计 |
| **业务信息** | 现有供应商、年度采购预算、付款周期 |
| **联系信息** | 电话、网站、账单地址、办公地点（含地图） |
| **归属与状态** | 负责人、父级客户、活跃标志、审批状态 |
| **品牌** | 品牌颜色（用作头像强调色）、公司标识（上传的图片——PNG、JPEG、SVG 或 WebP，最大 2 MB） |
| **系统** | 时间戳、审计追踪 |

其中两项需要额外说明。

**登记证件号**是对方在*它自己*所属的政府登记机关取得的登记标识——无论那是哪一个登记机关。它刻意不以任何单一国家的登记制度命名：正确答案随注册地不同而不同，而这个字段必须能装下所有这些情况。开票、征信和识别重复公司都以它为键；它可被搜索，因此你能在全局搜索和任何客户选择器里用它找到客户。它**不是****客户编号**——后者是由*我方*发放的序列号，并且已经出现在记录标题里。

**业务信息**记录的是这家客户怎么采购：目前由谁承接（**现有供应商**）、本年度计划向供应商支出多少（**年度采购预算**）、以及怎么付款（**付款周期**）。这些都不同于**年营收**——那是该客户自己*赚到*的钱，而预算是它将要*花出去*的钱。

## 客户层级

使用**父级客户**来建模带有子公司的全球性企业：

```
Acme Corp Global
├── Acme Corp US
├── Acme Corp EMEA
│   ├── Acme Corp UK
│   └── Acme Corp Germany
└── Acme Corp APAC
```

该层级给你带来：

- **汇总营收**——*财务*区块上的**子公司年营收合计**，是本客户**直属**子公司**年营收**之和。它由平台维护：子公司营收被修改、子公司被改挂到另一个父级、或子公司被删除时，这个数字都会随之变动。它只汇总一层，因此祖父级看到的是它自己直属子级的合计，而不是整棵树的合计。
- **更便捷的导航**——从子级你可以跳转到全球父级。

该层级刻意**不**做两件事。它**不**级联共享：客户是私有的，把父级授权给某人并不会带来任何子级的权限——需要这种效果请使用 [管理 › 共享](/zh-Hans/docs/administration/sharing-and-security) 上的共享规则。它也**不**汇总其它任何东西：商机、工单和联系人属于它们各自指向的那个客户，没有任何报表会沿着这棵树向上求和。

## 内置规则

- 客户**名称在你所在的组织内必须唯一**。如果你尝试用一个已存在的名称再建一个客户，会收到错误。同一平台上的其他组织可以有自己的 "Acme Corp" —— 这条规则只作用于你自己的数据，而不是整个平台。唯一性校验按原样精确比较名称，因此 `Acme Corp` 与 `ACME  Corp` 可以作为两个独立的客户同时存在。线索转化则更宽松：它在寻找可复用的客户时会忽略大小写和多余空格（见[线索](./leads)），因此转化公司名为 `ACME  Corp` 的线索时，会挂到你已有的 `Acme Corp` 上，而不是新建一个近似重复的客户。
- **年营收必须为零或正数**——不允许负数。
- 你**无法删除**一个有开放商机或活跃合同的客户。改为将其设为*非活跃*（`is_active = false`）。
- 对于**商务能力**为*仅结算*的客户，你**无法为它新建商机**。它已有的商机不受影响，照常可编辑。

## 自动更新

- 每当客户更换负责人或类型时，**最近活动日期**会被自动盖戳，因此你总能知道上次发生有意义的进展是什么时候。
- 首次合同激活时，客户的**类型**被改成*正式客户*——但**不会随之记下任何日期**。没有 *Customer Since* 字段，也没有任何其它名字的字段记录该客户何时成为客户，所以「上个季度赢下了哪些客户」这类同期群问题只能从合同的**签署日期**或**开始日期**去回答。
- **商机总金额**和**赢单商机金额**会自动从相关商机汇总。
- **开放工单数**始终是实时的，因此你能一眼看出某个客户是否正经历困难时期。

## 客户详情布局

当你打开一个客户时，会看到以下标签页：

- **概览**——描述、关键联系人、负责人、主地址及一张小地图。
- **商机**——所有相关交易，按阶段分组，顶部显示销售管道总额。
- **联系人**——该客户处的所有人，主要联系人被高亮显示。
- **工单**——开放及近期关闭的支持工单。
- **活动**——电话、邮件、会议，最新的在前。
- **合同**——活跃及历史合同。
- **文件**——附加的文档（徽标、已签署 PDF、数据表）。

## 共享——谁能看到哪个客户

默认情况下客户是**私有**的——只有负责人能看到。岗位是扁平的，**什么都不会上卷**，所以没有人因为“在负责人之上”而看到某个客户；其他能看到的人都由下面的规则点名。

在此之上：

- **活跃客户账户**会自动与所有销售经理共享（读/编辑）。
- **辖区规则**按**销售区域**共享客户：
  - `na` → 北美销售团队
  - `emea` → 欧洲销售团队
  - `other` → 没有对应的区域团队

**销售区域**是客户上的只读选项列表，由你在**账单地址**里填的国家/地区推导而来。它不能直接编辑——改地址，区域随之改变。

| 销售区域 | 国家/地区 | 同时接受的写法 |
| --- | --- | --- |
| 北美（`na`） | `US`, `CA`, `MX` | `United States`, `United States of America`, `USA`, `Canada`, `Mexico` |
| 欧洲、中东与非洲（`emea`） | `GB`, `DE`, `FR`, `IT`, `ES` | `UK`, `United Kingdom`, `Great Britain`, `Germany`, `France`, `Italy`, `Spain` |
| 其他（`other`） | 其余所有国家/地区，以及没有账单国家的客户 | — |

大小写和首尾空格都不影响——`de`、`DE`、` de ` 是同一个国家。凡是这张表里没有的，都归入**其他**：这是一个明确的值，不是空白，所以“没有任何区域覆盖的客户”是看得见的，而不是从每张列表里悄悄消失。**销售区域**和**账单国家**（按录入原样保存的国家）都在客户的 *Locations* 分区里；区域团队说某个客户没出现在他们列表里时，先看这两个字段。

管理员可以更改这些规则——参见 [Administration › Sharing](/zh-Hans/docs/administration/sharing-and-security)。

## 谁能编辑什么

- **年营收**对**销售代表是只读的**。只有销售经理及以上才能更改它（保护财务估算）。
- **描述**可由任何有该客户访问权限的人编辑。

## 标准列表视图

客户列表默认打开**全部客户**，列表顶部的视图切换器里就是下面这六个已保存视图——只有这六个：

| 视图 | 展示什么 |
| --- | --- |
| **全部客户**（默认打开） | 不分类型的完整台账，按**年营收**由高到低排列。**年营收**列带合计、**员工人数**列带平均值，抬头这一行就是整本账的概览。行按**是否活跃**着色——灰色的就是已停用（`is_active = false`）的客户；停用记录留在这里，不另设一张清理用的列表。每页 50 行，可导出 CSV / XLSX；勾选记录后可批量执行**更新客户分层**、**转移负责人**、**删除**。 |
| **客户卡片** | 同一批客户以品牌色卡片呈现，每张卡片以该客户的**公司标识**作为封面图——客户名下面是行业、年营收、员工人数、电话、网站和负责人。未上传标识的客户仍有卡片，只是没有封面图。 |
| **客户地图** | 客户按地理位置落在地图上。图钉取自**办公地点**，而不是账单地址：只填了账单地址、没填办公地点的客户不会出现在这张图上——也只在这张图上缺席。 |
| **企业客户** | **年营收 ≥ 1000 万美元**的客户，金额大的在前；网格上方还有**行业**（带每个取值的记录数）、**类型**、**客户负责人**三个快捷筛选下拉。注意这是按营收切的，不是按**客户分层**字段：一个被标成"企业客户"分层、年营收却只有 500 万的客户不在这里。 |
| **我的客户** | 你负责的客户，按**最近活动日期**由近及远排列。 |
| **⚠️ 风险客户** | **健康度**为*风险*或*流失中*的正式客户——客户成功团队的工作队列，同行还有客户细分和最近活动日期。 |

<Callout type="info">
  **要找即将到期的续约？它在合同上。** 打开**合同**并切到**续约日历**标签，或者把**全部合同**按**结束日期**排序——每日续约提醒真正据以行动的就是这些日期。客户列表过去自带一张*即将续约*视图，建在客户级的**下次续约日期**和**续约负责人**之上，而产品里从来没有任何东西写过或读过这两个字段：日期显示的是最后一次手工填进去的值，而不是真正要到期的东西；在那里指定一位续约负责人，那个人什么也收不到。与其留着两个看起来已经接好线的字段，不如把它们删掉。续约提醒如何选择收件人，见[收入](/zh-Hans/docs/revenue/index)。
</Callout>

### 这个客户成功队列为什么会是空的

**风险客户**读的是客户上那组客户成功字段（客户分层、客户细分、健康度），而且先按**类型 = 正式客户**过滤：

- 潜在客户和合作伙伴永远不会出现在这张列表里，那几个字段填得再全也一样。先把客户提升为*正式客户*——激活合同会自动做这件事。
- **健康度**由维护这段客户关系的人手工填写，没有默认值。组织里没人填过它，*风险客户*就是空的——那是数据缺口，不是过滤条件坏了。

## 给销售代表的提示

- ✅ 始终设置一个**主要联系人**——许多流程默认使用它（报价、合同）。
- ✅ 使用**父级客户**，而不是为每个区域创建重复的客户。
- ✅ 一签署合同就立即将潜在客户提升为客户（这会自动发生，但请核实）。

## 给管理员的提示

- 要添加新的行业或国家辖区？参见 [Administration › Sharing](/zh-Hans/docs/administration/sharing-and-security) 和 [Customization › Extending Objects](/zh-Hans/docs/customization/extending-objects)。
- 详情界面上的 6 个默认区块可以按配置文件重新排序或隐藏。
