# 营销活动成员

**营销活动成员**是 [营销活动](/zh-Hans/docs/marketing/campaigns) 与某个人（一个 [线索](/zh-Hans/docs/sales/leads) 或一个 [联系人](/zh-Hans/docs/sales/contacts)）之间的联系。它记录营销活动已经触达该人，以及后来发生了什么：他们是否响应、其线索是否转化、还是要求不再收到联系。

## 成员如何加入

三种方式：

1. **在营销活动上批量加入** — 打开一个营销活动，在记录页头部点击 **Enroll Members**（批量加入成员）；该操作在营销活动处于 *Planning* 或 *In Progress* 时提供。它会打开 [Campaign Enrollment flow](/zh-Hans/docs/marketing/campaigns#campaign-enrollment-flow) 的 *Enrollment Criteria* 屏幕，由你自己在那里挑选受众——线索按状态，联系人按部门——然后为每个匹配的人创建一条状态为 *Sent* 的成员记录，并跳过已加入的人和已退订的人。没有任何东西会替你运行它：条件是在那个屏幕上回答的，而定时运行没有人来回答它们。没有人被拒绝时，运行结束于 *Enrollment Result*（加入结果）屏幕，给出三个数字：新加入多少人、已是成员多少人、因退订邮件或没有邮箱地址而跳过多少人；屏幕上的营销活动名称可以点回该活动。只要有人被拒绝，运行就以拒绝结束，给出这三个数字和被拒绝的人数。被拒绝的人不在该活动中。
2. **从线索列表或联系人列表加入** — **Add to Campaign**（加入营销活动）两边都有。在**全部线索**或**全部联系人**里勾选需要的记录后，从选择工具栏批量运行；在任何按行排列的列表里，也可以从某一行的 ⋮ 菜单对这一条运行。两种方式都由记录选择器来选定营销活动。列表标题栏上没有这个按钮，那里还什么都没有选中。从工具栏运行时，确认步骤会列出你勾选的人，每个人单独加入，结果显示 *Succeeded* 和人数；从行菜单运行时，随后弹出的提示会写明营销活动，并说明这个人是新加入还是已是成员（*Spring Launch: 0 added, 1 already a member.*）。它在两个对象上都是列表操作，所以打开一条线索或一个联系人并不会提供它。已经在该活动里的人会被跳过；工具栏的 *Succeeded* 计数仍包含他们，因为它统计的是动作运行了多少行，所以重复运行不会把一次触达算成两次——跳过检查按关系各查各的，因此同一个人以线索身份加入一次、又以联系人身份加入一次，是刻意保留的两条成员记录，而不是一次重复。营销活动上仍然没有一个 *Add Members* 选人器供你从线索和联系人列表视图中挑人。
3. **在营销活动上逐条新建** — 打开营销活动，在 *Related*（相关）选项卡里找到 **Campaign Members** 面板，用面板上的 **New**（新建）按钮手工填写一条成员记录。

**谁能加入成员。** 把一个人加入活动就是创建一条营销活动成员记录，三种方式都以操作者本人的身份检查同一项权限：其权限档案是否允许创建营销活动成员。Marketing User 和管理员拥有这项权限。Sales Rep 和 Sales Manager 没有：他们的权限档案只能查看营销活动成员，加入成员交给市场部，所以他们看不到 **Enroll Members** 和 **Add to Campaign**；无论经由这两个操作、面板上的 **New** 还是 API，他们想创建的成员都会被拒绝。

**哪些营销活动、哪些人可以加入。** 只有处于 *Planning* 或 *In Progress* 的营销活动接受成员，已退订邮件的人不会被加入。**Enroll Members** 只在这样的营销活动上提供，并把已退订的人排除在所选人群之外。**Add to Campaign** 无论从哪里启动，都遵守同样的两条规则。从某一行的 ⋮ 菜单运行时，营销活动选择器只列出 *Planning* 和 *In Progress* 的营销活动；选择工具栏上的选择器会列出全部营销活动。无论哪种方式，只要选中的是已结束的营销活动或已退订的人，就不会加入任何人，营销活动的数字不变，并会弹出一条消息，指明是哪个营销活动已结束、或哪个人已退订。因此 *Completed* 的营销活动会保留它结束时的发送数、线索数和响应数。用其他方式添加成员时，这两条规则同样适用：在营销活动的 **Campaign Members** 列表上点 **New**、通过导入或通过 API 添加，都会被拒绝并显示同样的消息，什么都不会保存。这条消息目前在所有语言下都以英文显示。

一个人随着时间推移可以加入多个营销活动，但每个营销活动只能加入一次（每人每个营销活动一个成员身份）。

## 4 种成员状态

成员状态就是响应生命周期，其中每一个取值在应用里都有真实的写入方：

| 状态 | 含义 | 由谁写入 |
| --- | --- | --- |
| ⚪ **已发送** | 营销活动已触达他们 *(新成员的默认状态，无论以哪种方式创建)* | 加入 |
| 🟢 **已响应** | 他们作出了回应——回复、注册、下载 | 成员上的 **Mark Responded**（标记为已响应） |
| 🟣 **已转化** | 其线索后来成为了客户 | 该线索转化时自动写入 |
| 🔴 **已退订** | 他们要求不再收到联系 | 可以编辑营销活动成员的用户，在成员记录上设置 |

这四个取值并不是一部只升不降的阶梯。大多数成员停在*已发送*；作出回应的移到*已响应*；仍处于*已发送*或*已响应*、其线索后来转化的成员会被自动提升为*已转化*。把成员改回去——纠正一次误点，或为了重发而重置回*已发送*——会连同响应时间戳一起清除。把一个已经响应过的成员设为*已退订*则不会：响应留在成员上，仍算作营销活动的一次响应。*已退订*的成员永远不会被那次转化扫描提升：退订不会被一个营销结果覆盖掉。

## 为什么同时支持线索和联系人？

营销活动成员可以关联到一个**线索**（尚未合格的人）或一个**联系人**（现有客户处的人）——但不能同时关联两者。这由一条内置规则强制执行：`crm_lead` 或 `crm_contact` 必须且只能设置其一。

这种双重支持意味着：

- 市场营销可以针对**潜在客户**（线索）开展漏斗顶端营销活动。
- 市场营销可以针对**现有客户**（联系人）开展追加销售、交叉销售或续约营销活动。

如果一个线索后来被转化为联系人，现有的营销活动成员身份仍与该线索关联，而新的营销活动可以将同一个人作为联系人重新定位。

## 成员记录存储什么

| 字段 | 用途 |
| --- | --- |
| Member Number | 这条成员记录自己的编号（CM-00001），保存时自动生成 |
| Campaign | 营销活动——必填 |
| Lead | 线索：该人加入时身份为线索的，记录在此 |
| Contact | 联系人：该人是已有联系人的，记录在此 |
| Added Date | 该人加入的时间——无论通过上面三种方式中的哪一种加入，都在保存成员记录的那一刻自动写入，之后只读 |
| Status | 该人走到了哪一步（见上文四种状态） |
| Response Date | 他们响应的时间，在首次进入已响应状态时打上 |
| Has Responded | 此人是否曾经响应过，由系统维护——*已转化*同样算作已响应；重置回*已发送*会清除它；响应过的成员退订后仍保留它 |

## 什么被跟踪，什么没有

> **本应用不跟踪打开、点击或退信。** 平台的邮件服务负责发信，并记录这条消息的去向——*Queued → Sent*（已排队 → 已发送），或者 *Failed*（失败）——但它不带跟踪像素、没有点击回调、也没有退信数据源。任何依赖它们的成员状态都只会永远停在默认值上，所以产品里没有这样的状态。应用真正能观察到的，是一个人作出了回应、以及一条线索发生了转化——这正是这四种状态所讲述的内容。

每一种状态都有真实的写入方：

- **已发送** — 在成员记录被创建时写入，上文的每一条加入路径都会写。
- **已响应** — 成员记录上的 **Mark Responded**（标记为已响应）按钮。记录一次响应就是编辑这条成员记录，所以这个按钮只提供给可以编辑营销活动成员的用户（Marketing User 和管理员），并且只在成员仍处于*已发送*时出现：已响应、已转化或已退订的成员没有什么可记录的，而已退订的人更不该被一次误点重新拉回漏斗。它会连同状态一起打上*响应时间*与*已响应*标识。
- **已转化** — 自动写入。当某个成员的线索被转化时，该线索所加入的每一个营销活动都会提升自己的成员记录并重算指标。转化是这个应用唯一能自行观察到的营销活动结果。
- **已退订** — 由可以编辑营销活动成员的用户（Marketing User 和管理员）在成员记录上设置，通常是在此人要求不再收到联系的时候。应用里没有任何东西会自动设置它：一次退订请求只有在这些用户把它记到成员记录上时才会到达这里。设置它的同时会勾上此人线索或联系人上的 **Email Opt Out**（拒收邮件），这才是让他们不再进入后续活动的机制：加入流程会跳过已退订的人。它只朝一个方向走——把一个人标记为退订，并不会改写他已有的成员记录，因为那些记录的是当时发生的事实。

## 指标如何汇总

营销活动详情页会汇总其成员：

```
Sent          = 该营销活动的全部成员
Responses     = 曾经响应过的成员（Has Responded），含后来退订的
Response rate = Responses ÷ Sent，以百分比表示
```

转化以营销活动上的「已转化线索数」抵达该页面；商机一旦带上营销活动，就会进入同一页面的商机与 ROI 数字。退订不是营销活动上的计数：你在成员记录上看到它，也在此人的 **Email Opt Out**（拒收邮件）上看到它。

这些数字会在每一次成员变化时重算——有人加入、有人被标记为已响应、有人被移除——所以正在进行中的营销活动报的就是真实数字，不必等一个夜间作业。把一个成员标记为*已响应*，营销活动的响应率随之变动。

## 成员在哪里查看

在营销活动详情页的 **Related**（相关）选项卡下，一个标题为 **Campaign Members** 的面板里。该面板列出这个活动的每一位成员，五列——**Lead**（线索）、**Contact**（联系人）、**Added Date**（加入日期）、**Status**（状态）和 **Response Date**（响应日期）——并带着上面提到的 **New**（新建）按钮。列的顺序就是这行记录发生的顺序：谁被加入、什么时候加入、后来怎么响应。

读者常带着两个预期过来，它们真正的落点是：

- **没有 *Members* 选项卡。** 成员面板只是活动在共用的 *Related* 选项卡上的关联记录面板之一。
- **没有任何成员列表视图** —— *All Members*、*Responded*、*Unsubscribed*、*Converted to Opportunity* 都不存在。Campaign Member 对象一个列表视图都没有；即便有，关联列表面板也不读子对象的列表视图：面板的列是在活动关联字段上直接定好的，从来不来自视图。产品里没有任何东西能把这个面板按状态筛选，也没有面向 Campaign Member 的报表，所以「所有响应过的人」是活动上的一个**数字**而不是一份可以打开的名单——见上文《指标如何汇总》一节，那里的响应率由成员的响应实时算出。

## 给营销人员的提示

- ✅ **盯住退订**——每一次退订都会同时把这个人从邮件里排除，于是他会自动退出后续的每一次加入。退订数上升，是该换内容的信号，而不是该换名单的信号。
- ✅ **用*已响应*和*已转化*来评判一个营销活动**——它们是这个应用真正能观察到的两个结果。
- ✅ **在商机上标记营销活动来源**——没有它，转化就无法汇总。

## 给销售代表的提示

- ✅ 当你打开一个线索时，查看侧边栏中的 **Campaign Memberships**——它会告诉你他们被投放过哪些营销活动、以及他们怎么回应的。
- ✅ 用营销活动作为对话开场白——*"我看到你参加了我们最近关于……的网络研讨会。"*

## 给管理员的提示

- 没有什么打开/点击跟踪可供开启，也没有哪个连接器能加上它。如果某个营销活动的响应数字偏低，先确认市场部是否在用 **Mark Responded**（标记为已响应）记录回复——那个按钮，以及线索发生转化，是仅有的能把成员移出*已发送*的两件事。销售代表和销售经理按不了它：他们的权限档案只能查看营销活动成员，不能编辑。
- "*Lead* 或 *Contact* 必须且只能设置其一"这条规则存在于 campaign_member 对象的验证规则中。
