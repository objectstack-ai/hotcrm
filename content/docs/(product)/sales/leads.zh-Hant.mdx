# 線索

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**線索**是一次入站詢問——某人表現出了興趣，但尚未被確認為真正的銷售商機。在你決定值得跟進之前，線索會與你真正的客戶和聯絡人分開存放。

## 何時該用線索（而非聯絡人）

| 情境 | 使用…… |
| --- | --- |
| 有人填寫了網頁表單 | 線索 |
| 展會名單上的一個名字 | 線索 |
| 你購買了一份行銷名單 | 線索 |
| 現有客戶的新採購方加入 | 聯絡人（歸在現有客戶之下） |
| 真實客戶處已確認的決策者 | 聯絡人 |

關鍵是把未經審核的雜訊擋在你真正的客戶資料庫之外。

## 5 種線索狀態

每筆線索都會經歷這些狀態。通常的路徑是向前走——從新建，經已聯絡、已確認，到已轉化，未通過則是出口——但應用並不強制銷售代表走這條路徑：偏離它的狀態變更，比如把一筆已確認的線索改回新建，照樣會儲存，應用只在伺服器日誌裡記下一條警告。應用真正強制的只有已轉化這一步：只有**轉化線索**能設置它。

| 狀態 | 含義 | 你通常接下來做什麼 |
| --- | --- | --- |
| **新建** | 剛到達，還沒人聯絡 | 在 SLA 內進行首次聯絡 |
| **已聯絡** | 在新建線索上記錄第一次電話、會議或郵件時自動設置 | 了解對方需要什麼、大致值多少 |
| **已確認** | 銷售代表點了**確認線索**，填了需求類型和預計金額 | **轉化**為客戶、聯絡人和商機 |
| **未通過** | 不匹配（產業不對、沒有預算等） | 如情況變化可稍後重新開啟 |
| **已轉化** | 已成為真正的客戶和聯絡人 | （線索現已鎖定） |

如果情況發生變化（預算釋放、新項目啟動），你還可以將一筆未通過的線索**重新開啟**回*新建*。

其中兩步有自己的規則：

- **已聯絡自動設置。** 在*新建*線索上記錄第一次電話、會議或郵件，它就變為*已聯絡*。之後再記錄不會改變狀態，其他狀態的線索也保持不變。
- **已確認需要依據。** 在線索頁面點擊**確認線索**。它要求填寫**需求類型**和**預計金額**，兩項都必填，然後設為*已確認*。線索上已經有的值會自動帶出，可以保留，也可以修改。用其他方式（編輯表單、狀態條、匯入或 API）設為*已確認*時，只要有一項為空就會被拒絕。預計金額就是之後轉化時商機金額的預填值。

你也可以點擊頁面頂部**狀態條**上的某個狀態並確認，來推進線索。點擊和編輯一樣受檢查：*已確認*仍要兩項都填，*已轉化*仍然只能由**轉化線索**設置。商機和工單頁面同樣可以點。

## 每筆線索記錄儲存的內容

線索記錄把自己的欄位宣告為 **10 個區塊**。線索自己的記錄頁只把其中一部分挑進**詳情**標籤頁，所以下表是一筆線索攜帶的欄位全集，而不是逐屏對照表：

| 區塊 | 其中內容 |
| --- | --- |
| **身份資訊** | 稱謂、名字/姓氏、姓名、顯示名稱 |
| **重複線索管理** | 重複於（存活的那筆記錄屬於哪個物件）、重複的線索、重複的聯絡人、重複狀態——下文*重複的線索*用的就是這些欄位 |
| **公司資訊** | 公司、職位、產業——另有一個隱藏的公司名稱正規化副本，線索轉化與重複檢測按它比對 |
| **聯絡方式** | 郵箱、電話、手機、網站 |
| **資格評估** | 狀態、線索評分（1-5 星評級）、線索來源、下次跟進日期、最近聯絡時間、未通過原因 |
| **分配** | 負責人 |
| **地址** | 一個結構化的地址欄位 |
| **附加資訊** | 年營收、員工人數、描述、備註 |
| **溝通偏好** | 禁止致電、拒收郵件 |
| **轉化** | 已轉化、轉化客戶、轉化聯絡人、轉化商機、轉化日期——都在線索轉化時自動寫入 |

**姓名**由**名字**和**姓氏**組成。**姓氏**用中文、日文或韓文書寫時，姓氏在前、名字在後，中間不加空格——姓氏「張」名字「偉」顯示為 **張偉**；其他姓名按「名字 空格 姓氏」顯示（*Ada Lovelace*）。這條規則看的是姓名本身，而不是介面語言，所以每個人在記錄標題、列表、查找、搜尋和通知裡看到的都是同一個姓名。每個列表和卡片都以姓名打頭，所以不論你填的是哪一部分，點姓名都能打開記錄。

可選**產業**包括 Technology、Software/SaaS、Finance、Healthcare、Retail、Manufacturing、Education、Real Estate、Media、Logistics、Hospitality、Energy、Government、Non-profit 和 Other。

可選**線索來源**包括 Web、Referral、Event、Trade Show、Webinar、Partner、Advertisement、Cold Call 和 Other。

## 線索評分——評分的含義

一筆線索上只有**一個**品質數字：**線索評分**，一個 **1-5 星的星級評級**。列表檢視裡*線索評分*那一欄顯示的就是同一個欄位——不存在另一個 0 到 100 的分數，背後也沒有預算或時間線欄位。

### 星級是怎麼來的

線索被建立時如果**沒有帶評級**，系統會用它自己的欄位算一個出來並存下。它看的全都是你眼前這筆記錄上的資訊——背後沒有任何網頁造訪或互動追蹤：

| 它看什麼 | 加多少星 |
| --- | --- |
| 企業郵箱地址——只要不是 gmail、yahoo、hotmail、outlook、qq、163 | +1 |
| 填了任意電話號碼 | +0.5 |
| 資深職位——CEO、CTO、CFO、CIO、COO、Founder、VP、Vice President、Director、Head of | +1.5 |
| 產業是 Technology、Finance 或 Healthcare | +1 |
| 員工人數 200 及以上 | +0.5 |
| 年營收 $10M 及以上 | +0.5 |

合計上限為 5、下限為 1，並四捨五入到**整星**：線索不會被評為 0 星，也從不儲存半星。

有兩條邊界值得記住：

- 它**只在建立時執行**。事後補上職位或員工人數**不會**重新評分——情況變了就自己改星級。
- 它絕不覆蓋隨線索一起進來的評級。匯入時帶了評級，或在新建表單上手動設了星級，保留的就是你的值。

### 星級會觸發什麼

新線索路由只在線索落庫那一刻讀一次評級：

| 評級 | 蓋的下次跟進日期 | 給線索負責人的提醒 |
| --- | --- | --- |
| **四星及以上** | **明天** | *"Hot lead — follow up within 24h"*，**站內收件匣和郵件**兩個通道都發，標為警告級 |
| **其餘全部**，包括完全沒有評級的線索 | **三天後** | *"New lead assigned to you"*，**僅站內收件匣**，且只在線索是別人交給你時才發 |

熱門的門檻就只有四星這一道：五星線索的路由與四星完全相同，滿五星不會另外觸發任何事。

兩種提醒都發給線索的負責人，告訴對方這筆線索歸他跟進。標準提醒發不發，要看是誰把線索記到你名下：

- **別人** —— Lead Intake 的指派規則把一筆 Web-to-Lead 詢問分給了你、某個整合寫明了你，或者同事替你建立了這筆線索。你會收到 *"New lead assigned to you"*。
- **你自己** —— 線索是你自己建立的，無論透過表單還是 API。你不會收到標準提醒：跟進日期已經寫在線索上，它也在**我的線索**裡。

熱門線索無論如何都會提醒負責人，因為評級是系統的判斷，不一定是你填的：建立時沒有評級的線索會當場評分。沒有負責人的線索只蓋跟進日期、不發提醒，因為 HotCRM 沒有可以通知的線索佇列。

> 上面這些權重寫在線索的自動化程式碼裡，而不是某個設定介面——參見本頁末尾的「給管理員的提示」。

## 重複的線索

同一個人再次詢問是正常現象，不是錯誤。老客戶再次填寫網站表單，或者你匯入的展會名單與既有名單有重疊，都會產生**第二筆線索**——HotCRM 會記錄這層關係，而不是拒絕這筆記錄。

當新記錄的電子郵件在系統中已經存在時，儲存時會帶上：

- **重複狀態 = 疑似重複**——這只是系統的猜測，尚未下任何結論。
- **重複於**——它疑似重複的那筆記錄：如果這個人已經是**聯絡人**，就指向該聯絡人；否則指向使用同一電子郵件、**最早的未結案線索**。每次重複提交都指向同一筆原始記錄，因此一組重複記錄是一份清單，而不是一條鏈。

從線索列表視圖切換器裡的**疑似重複線索**視圖處理它們。打開這兩筆記錄逐一比對，然後二選一：

- **是老客戶的新詢問**——清空重複狀態，按正常流程推進。預算重新到位的老客戶是真實商機。
- **是同一次詢問重複輸入**——把記錄設為*未通過*，原因選**重複**。此時表單會要求你指明存活的那筆記錄，並把重複狀態設為**已確認重複**。不指明存活記錄就無法以重複為由作廢，所以作廢分析裡的每一筆都能點開。

> 匿名 Web-to-Lead 提交永遠會被接受，並且和其他線索一樣會被查重：來自 CRM 中既有地址的網頁詢問會被標記。查重在你這一側完成——訪客只會得知詢問已收到，因此公開表單永遠不會透露某個地址是否已被記錄。

### 存活記錄後來被刪除時 [#when-the-surviving-record-is-later-deleted]

刪除一位聯絡人，或者它上層的客戶，永遠不會因為有線索指向它而被阻止——包括你已經以「已確認重複」結案的線索。線索會怎樣，取決於複核進行到了哪一步：

- **仍為疑似重複**——什麼都還沒決定，所以這個標記會被整個清除。這筆線索不再聲稱重複了任何記錄，回到正常佇列。
- **已由複核人確認**——結論保留。重複狀態仍是**已確認重複**，**重複於**變為**記錄已刪除**，於是這筆線索讀作*「一筆已確認的重複記錄，它所重複的記錄後來已被刪除」*。作廢本身及其原因不受影響。

**記錄已刪除**不是你能選擇的值。只有當線索指向的那筆記錄真的被刪除時，系統才會寫入它；因此在線索上看到它，就可靠地證明刪除確實發生過，而不是有人手動填寫的。正因如此，一項刪除請求可以被完整執行，而不會順帶悄悄刪掉複核人的結論。

## 轉化一筆已確認的線索

**重複狀態**為**已確認重複**的線索無法轉化。點擊**轉化線索**後彈出的是一條拒絕說明，而不是轉化
表單：已經有人把這筆線索與某筆既有記錄做過比對，並判定它是重複的，此時轉化會為同一個買家再造
一套客戶、聯絡人和商機。記錄上的**重複線索管理**區塊指明了保留下來的那筆記錄——請把已確認的重複
線索按重複關閉，而不是轉化它。僅被標記為*疑似重複*的線索仍然可以轉化：那只是系統的猜測，
轉化介面會提示你，但不會攔住你。

當一筆線索通過資格審核後，點擊**轉化線索**。會彈出一個小表單詢問：

- 我們是否也要建立一個商機？
- 如果是——商機名稱和金額是多少？

在這些問題上方，表單會在你提交之前告訴你該線索將加入哪個客戶：比對到的既有客戶（顯示該客戶的名稱），或者在沒有你能查看的客戶與之相符時，一個以線索公司命名的新客戶。如果這不是你預期的客戶——比如線索寫的是 `Acme Corp`，而你的客戶是 `Acme Corporation`——請取消，更正線索的**公司**，然後重新轉化。

比對只查看你能查看的客戶。同事擁有、且沒有共享給你的客戶不會被比對到，因此表單會顯示將新建客戶。如果那個客戶的名稱與之完全相同，轉化隨後會因重複記錄而被拒絕，不會建立任何內容；如果名稱只在大小寫或空格上不同，則會再建立一個客戶。所以，當你認為這家公司已經是既有客戶、而表單卻顯示要新建客戶時，請先請**客戶負責人**或管理員把該客戶共享給你，再進行轉化。

然後系統會一步完成：

1. 根據線索的公司資訊建立一個**客戶**——或者直接重用表單所列出的既有客戶。比對時忽略大小寫與多餘空格，因此公司名為 `ACME  Corp` 的線索會落到你既有的 `Acme Corp` 上，而不是再建一個客戶。這不是模糊比對：`Acme Corp` 與 `Acme Corporation` 仍然是兩家不同的公司。這裡新建的客戶不進入[客戶審批](/zh-Hant/docs/sales/accounts#account-approval)：線索的資格判定就是那道關，因此客戶立即可用，它的**來源線索**連結回這筆線索。
2. 根據線索的個人資訊建立一個**聯絡人**，附加到該客戶上。只有當該客戶還沒有主要聯絡人時，它才成為主要聯絡人：轉化到一個已有主要聯絡人的客戶時，原本的主要聯絡人保持不變。
   聯絡人的郵箱不能重複，所以當你能查看的某個聯絡人已經使用線索的郵箱時，線索會併入這個聯絡人，表單會在你提交前寫明是哪個聯絡人。轉化只補填它空著的**電話**、**手機**和**職位**，其他內容不變。如果這個聯絡人的姓名與線索不同，會多出一個畫面，要求勾選**把這條線索轉化到這個聯絡人**；不勾選就不會轉化。比較的是兩邊完整的姓名，而不是名字對名字、姓氏對姓氏：聯絡人 歐陽娜娜（姓氏「歐陽」、名字「娜娜」）和錄成姓氏「歐」、名字「陽娜娜」的線索是同一個姓名，不會多出這個畫面。如果這是兩個不同的人，請先修改線索的郵箱。
3. *（可選）* 在*尋找客戶*階段建立一個**商機**，預計成交日期設為 90 天後。如果線索回應過行銷活動，商機的**行銷活動**會設為它最近一次回應的那個活動，活動的商機數、贏單數和收入都會算上這筆交易；只寄送過、從未回應的活動不計入。你看不到的活動不在考慮範圍內。
4. 將線索標記為**已轉化**並鎖定它。
5. 向你發送一封確認郵件，總結所建立的內容。

完成後，表單不會直接關閉，而是顯示轉化結果：列出客戶、聯絡人，以及（如果你選擇了建立）商機，每一項都以名稱顯示，並連結到對應記錄的頁面，方便你直接開啟接下來要跟進的記錄。如果轉化時沒有建立商機，那一行顯示一個短橫線。同一介面還會說明該客戶是否正在等待銷售經理的客戶審批，這樣仍需審批的新客戶不會被忽略。提交這個介面即完成轉化，線索頁面隨之重新整理，顯示該線索已轉化。該介面出現之前所有內容就已儲存，因此用其他方式關閉它也不會撤銷任何操作，只是線索頁面在你重新載入之前仍顯示原來的狀態。

轉化後，線索變為唯讀——所有後續活動都發生在新的客戶、聯絡人和商機上。

## 線索詳情版面 [#lead-detail-layout]

線索打開的是 HotCRM 每個物件共用的記錄頁：

- **頁首**顯示線索的姓名和公司，以及下一步要用的按鈕：**Qualify Lead**、**Convert Lead** 和 **Schedule Follow-up**；**Log a Call**、**Log a Meeting** 和 **Schedule a Meeting** 收在 **⋯** 裡。按鈕只在適用時出現：已確認的線索不再提供 **Qualify Lead**，已轉化的線索不提供 **Edit**。
- **關鍵資訊**——Status、Lead Score、Lead Source、Email 和 Phone——以及**狀態進度條**。點擊進度條上的某個階段，線索就移到那個階段；這和編輯 Status 是同一次修改，規則也相同（進入 Qualified 需要填寫 Need Type 和 Estimated Amount）。
- 左欄按分區顯示**明細**。**Duplicate Management** 排在第二，緊接身份資訊；疑似重複或已確認重複的線索，它預設展開：顯示 **Duplicate Status**，並連結到重複的那筆記錄，打開線索就能看到判定，不必等到按 **Convert Lead**（見上文*重複的線索*）。正常的線索這一區是空的，不顯示；**Conversion** 預設摺疊，線索轉化後，它連結到由線索產生的客戶、聯絡人和商機，並顯示轉化日期。
- 右欄為每類**關聯記錄**各顯示一張卡片：**Tasks**（只列未完成的，最先到期的在前）、**Events**（先看時間、再看是否已發生，最近的在前）、**Event Attendees** 和 **Campaign Members**。沒有記錄的列表收成一行，可以展開。下面是 **Attachments** 和 **Activity**：評論、在線索上記錄的通話和會議，以及受追蹤欄位的變更，最新的在前。

頁面頂部的標籤頁可以單獨打開每個列表。只有當你有權建立某類記錄時，對應列表才帶 **New** 按鈕，新建的記錄會自動關聯到該線索。銷售人員可以在這裡預約活動。把線索加入行銷活動屬於行銷工作，因此只有擁有 Marketing User 權限集的使用者和管理員會在 **Campaign Members** 上看到 **New**；銷售代表和銷售經理只能檢視該列表。

## 智能體如何提供協助

接入智能體後（參見 [AI 與智能體](/zh-Hant/docs/ai-copilot/index)），試著就一筆線索問它：

- *"Qualify this lead"*——執行 BANT，給你一個評分以及每個維度的一行理由。
- *"Is this a hot lead?"*——快速是/否加上推理。
- *"Draft an intro email"*——撰寫一封個人化的首次外聯郵件。

智能體會推薦下一步行動（例如，安排通話、發送跟進、取消資格）。

## 標準列表視圖

線索列表沒有裁剪過的頁籤，所以切換器裡列出的就是全部已儲存視圖——一共八個，順序如下：

| 視圖 | 展示什麼 |
| --- | --- |
| **全部線索**（預設打開） | 所有線索，最新的在前；姓名是進入記錄的連結，同列還有公司、郵箱、狀態、評分、來源和負責人。每頁 25 列，可匯出 CSV / XLSX；可以加入行銷活動成員的使用者勾選後可批次**加入行銷活動**。組織裡還沒有線索時它會直說——*還沒有線索 · 建立第一條線索，從這裡開始*。 |
| **我的線索** | 你負責的線索，評分高的在前，同評分內最新的在前。側邊欄的 **My Work › My Leads** 進的也是它。 |
| **🔥 高熱度線索** | 仍處於**新建**或**已聯絡**、評分**四星及以上**的線索——正是新線索路由判為熱、給出次日跟進日期、並向負責人發出「24 小時內跟進」告警的那一批。按**下次跟進日期**由近及遠排序，列上帶電話、郵箱和負責人，從上往下打就行。 |
| **高優先級** | 同一批線索（**四星及以上**，同樣只看新建和已聯絡），只是擺成一張速覽表而不是工作佇列：不帶跟進日期，列上給出線索來源。 |
| **疑似重複線索** | 上文說的複核佇列：**重複狀態**為*疑似重複*的線索，最早被懷疑的排在最前，重複關聯欄位就在列上。處理一條少一條——確認或清除之後它就掉出佇列。沒有待複核的時候它會寫明：*沒有疑似重複 · 無需複核——每個重複錄入的郵箱都已檢查過。* |
| **線索流水線** | 看板視圖，一個狀態一欄，每欄彙總**年營收**。卡片以姓名為標題，下面是公司、郵箱和星級評分。點開卡片是從側邊滑出的抽屜，不會把你帶離看板。 |
| **線索日曆** | 線索按**下次跟進日期**落在月曆上，標題是公司名，按狀態著色——看的是你已經約定的跟進，一天一天排開。沒有下次跟進日期的線索不落在日期格裡，而是在月曆下方單獨列出。 |
| **線索卡片** | 卡片牆，一條線索一張卡，以姓名為標題，卡面上是公司、職位、郵箱、電話、狀態和評分。 |

## 給銷售代表的提示

- ✅ 讓**下次跟進日期**保持真實——**🔥 高熱度線索**就是按它排序的，日期放著不更新，會把一條活著的線索壓到佇列底部。新線索會自動拿到一個（四星及以上是明天，其餘是三天後），**安排跟進**動作則會用你剛建的那個任務的到期日重新蓋章。
- ✅ 有強烈的直覺判斷時就自己設星級——新建時你填的評級會原樣保留，自動評分只在你留空時才補上。
- ✅ 不要過早轉化——已轉化的線索無法還原。在確認期間使用*已確認*狀態。
- ❌ 不要永遠把雜訊留在*新建*中——3 次聯絡失敗後就取消其資格。
