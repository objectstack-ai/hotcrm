# 費用報銷

費用報銷面向每一位為公司花錢的員工，不只是項目人員。它是 HotCRM 的一個模組，有自己的應用 **Expenses**，管理員可以把它關掉。

出差前先申請，請填寫[出差申請](/zh-Hant/docs/expenses/travel-requests)。

## 記錄一筆費用

在 **Expenses** 應用裡打開 **My Expenses**，點 **New**：

| 欄位 | 填寫什麼 |
| --- | --- |
| **Description** | 這筆錢花在哪裡 |
| **Date** | 什麼時候花的 |
| **Category** | Travel、Lodging、Meals、Equipment 或 Other |
| **Amount** | 花了多少，使用貴公司的本位幣。外幣票據請先換算再錄入 |
| **Paid By** | **Employee**（你先墊付，再報銷給你，預設值）或 **Company**（例如用公司卡支付） |
| **Merchant** | 在哪裡花的，可選 |
| **Receipt Number** | 票據上的號碼，如有 |
| **Billable** | 是否向客戶收取 |

在 **Files** 分頁上傳票據。**Source** 說明這筆記錄從哪裡來：你手動填寫時是 **Manual**，由助手或匯入寫入時是 **Agent** 或 **Import**。啟用項目交付後，表單上還有 **Project**：見[項目上的費用](#on-a-project)。

**Review Notes** 用來寫下檢查這筆費用時發現的情況，由助手或你本人填寫：超出某條[費用標準](#expense-standards)、票據號以前出現過、缺少票據等。審批人在報銷單的費用列表裡閱讀它。HotCRM 自己不會往這裡寫任何內容；報銷單提交後，它和這筆費用的其他內容一起鎖定，所以 Review Notes 要在每筆費用提交之前寫好。報銷單自己也有 **Review Notes**，但審批中的報銷單整張鎖定，審批人也不例外：只有報銷單退回草稿時才能填寫。

## 提交報銷

在 **My Expenses** 裡勾選你的費用，在選擇列中點 **Submit for Reimbursement**。只報一筆時，記錄頁上也有同一個按鈕。不需要再填寫任何內容：這些費用放進一張**報銷單**（Expense Report），報銷單在同一次點擊中送審。在 **My Reports** 裡跟進。

- **每個項目一張報銷單。**啟用項目交付後，每個項目的費用各自放進一張報銷單，其餘的另放一張；一次出差涉及兩個項目，就生成兩張報銷單。見[項目上的費用](#on-a-project)。
- 報銷單的 **Title** 是這些費用的日期範圍。**Total** 彙總單上每一筆費用；**To Pay Back** 只彙總員工墊付的費用。
- 只能提交你自己的、尚未放進報銷單且未批准的費用。勾選的費用中只要有一筆不符合，就一筆也不提交，提示會逐筆寫明原因。

費用的狀態跟隨所在的報銷單，你不需要自己設定。

| 報銷單狀態 | 含義 |
| --- | --- |
| **Draft** | 已撤回，或被駁回後重新打開。單上的費用可以再次修改 |
| **Submitted** | 等待審批。報銷單及其費用被鎖定 |
| **Approved** | 已批准，等財務把錢報銷給你 |
| **Paid** | 財務已記錄錢報銷給你。最終狀態 |
| **Rejected** | 被退回。點 **Back to Draft**，修改費用後再點 **Submit** |

## 出差的費用 [#expenses-of-a-trip]

如果這些費用屬於你事先申請過的一次出差，在 **Submit for Reimbursement** 旁邊改選 **Submit for a Trip**，再選[出差申請](/zh-Hant/docs/expenses/travel-requests)。只列出你自己 **Approved** 的申請。報銷單的生成和送審與上面完全一樣，只是寫明這張申請；一次出差可以分幾張報銷單報銷，一張報銷單最多對應一張申請。申請在提交時選擇，事後不能再加到報銷單上。沒有出差的費用，**Submit for Reimbursement** 仍然一鍵完成。

這樣的報銷單會給審批人看出差的預計金額、這次出差已申報多少、是否超出預計。超出只是提醒，不會攔住。

## 由誰審批

- **你的上級**，即你使用者記錄上的 **Manager**。沒有上級時，改由 **Finance Controller** 決定。
- **Total** 達到 **2,000** 或以上的報銷單，隨後還要交給 **Finance Controller** 審批，他們也批准後才算批准。

審批人在 **Inbox**（在 **My Work** 下）裡點 **Approve** 或 **Reject**。**Reports to Approve** 列出等你審批的報銷單，可以先打開查看，單上的每一筆費用也都能打開。沒有人審批自己的報銷單，也沒有人能手動設定 **Approved** 或 **Rejected**。

**想撤回？** 在等待期間從 Inbox 裡撤回報銷單，它連同費用回到 **Draft**；點 **Submit** 即可再次送審。只有 Draft 狀態的報銷單可以刪除，單上的費用會保留，可以再次提交。

**管理員**也可以刪除 **Submitted** 或 **Rejected** 的報銷單，用來修復。單上的費用回到 **Draft**，可以再次提交。**Approved** 或 **Paid** 的報銷單不能刪除，管理員也不能：它連同單上的費用保留在記錄中。

**只有一個人的組織。** 沒有人能審批自己提交的報銷單，管理員也一樣，所以報銷單需要另一位能審批它的使用者：你的上級、一位 **Finance Controller** 或一位管理員；項目上的報銷單則是項目的項目經理或一位管理員。**Total** 達到 **2,000** 或以上時，還需要一位 **Finance Controller** 或管理員。在這個人加入之前，提交的報銷單停在 **Submitted**，沒有人能決定它：請在 Inbox 裡撤回，等這個人加入後再次提交。

## 報銷付款

已批准的報銷單列在 **Finance Controller** 和 **AR Accountant** 的 **Reports to Pay** 裡。錢到了員工手上之後，他們點 **Mark as Paid**，填寫付款日期，如有付款參考號也一併填寫。HotCRM 只記錄這次付款：不會轉出任何款項，也不記帳。已付款的報銷單不能再修改。

## 費用標準 [#expense-standards]

**Expenses** 應用裡的 **Expense Standards** 列出公司的花費標準，一條規定一行：

| 欄位 | 內容 |
| --- | --- |
| **Name** | 這條規定，例如「住宿，一線城市」 |
| **Category** | 針對的費用類別；留空表示所有類別 |
| **Limit** 和 **Per** | 最多可花多少，使用貴公司的本位幣，按每晚、每天、每筆或每次出差計算。只有文字的規定（例如「火車二等座」）沒有限額 |
| **Applies To** | 用文字寫明適用於誰、哪裡，例如「經理及以上」 |
| **Details** | 數字說不清的部分 |
| **Active** | 取消勾選即可停用一條標準，而不必刪除 |

有 **Expenses** 應用的人都能查看全部費用標準。由 **Finance Controller** 和 **AR Accountant** 維護，管理員也可以。

標準只是參考：HotCRM 從不拿費用和標準比較，超出標準的費用照常儲存、照常提交。為你工作的助手查閱標準、進行比較，在你提交之前把發現寫進這筆費用的 **Review Notes**；為審批人工作的助手把發現告訴審批人。由審批人做決定。

## 藉助助手 [#with-an-assistant]

有兩項技能教助手使用本模組，無論是平台助手，還是你透過 MCP 接入的自己的智能體（見[技能](/zh-Hant/docs/ai-copilot/skills#expense-filing)）：

- **費用代填**（Expense Filing），給花錢的人：它按票據記下費用（**Source** 為 Agent），檢查有沒有相同票據號、或相同日期、金額和商戶的費用，給你一個一次性連結附上票據，並把對照費用標準的發現寫進這筆費用的 **Review Notes**。它也可以起草出差申請。**Submit for Reimbursement**、**Submit for a Trip** 等發送類步驟，要你同意後它才執行。
- **費用檢查**（Expense Check），給審批人和財務：它列出報銷單裡值得一看的地方（超出標準、可能重複、缺少票據、出差超出預計），不改動任何東西。它會給出一段文字，審批人可以放進自己的審批意見；它從不審批、駁回或標記已付。

**Mark as Paid** 不對任何助手開放。智能體可以執行的全部動作見[對智能體開放的動作](/zh-Hant/docs/ai-copilot/agent-actions)。

## 誰能看到什麼

你能看到自己的費用和報銷單，以及請你審批的報銷單。財務在 **All Expenses** 裡能看到所有費用，也能看到所有報銷單，銷售經理和銷售管理層也能看到。沒有人手動新建報銷單：報銷單由 **Submit for Reimbursement** 產生。

## 項目上的費用 [#on-a-project]

啟用[項目交付](/zh-Hant/docs/projects)後，費用可以選擇一個 **Project**。項目人員在項目交付應用的 **Time and Expenses** 下也能找到 **My Expenses** 和 **Reports to Approve**。

項目帶來三處變化，它們和項目的工時一起，只在[工時與費用](/zh-Hant/docs/projects/time-and-expenses#費用)裡講一次：

- **由誰審批。** **Submit for Reimbursement** 會把每個項目的費用各自放進一張報銷單，交給該項目的項目經理審批，而不是你的上級。
- **項目成本。**報銷單批准後，單上的費用計入項目成本；標記已付款不會改變這些數字。
- **鎖定與項目結束。**項目被鎖定、Closed 或 Cancelled 時，它的報銷單不能提交：提交會當場被拒絕並說明原因，報銷單仍是 **Draft**。**Submit for Reimbursement** 和 **Submit for a Trip** 仍會提交你其他項目的報銷單；這次點擊以一條寫明未提交報銷單的錯誤提示結束。

有一條規則屬於報銷單本身：

- 費用在報銷單上時（哪怕報銷單是 **Draft**），不能改它的 **Project**：報銷單按提交時的項目交給審批人。要改項目，先刪除這張 Draft 報銷單（費用會被釋放），再改項目、重新提交。

關閉項目交付後，費用和報銷單上都不顯示項目欄位，每次勾選只產生一張報銷單，所有報銷單都交給你的上級審批。費用和報銷單原來選的項目會保留，重新啟用項目交付後再次顯示。

## 從逐筆審批升級

在有報銷單之前，每筆費用單獨提交、單獨審批。**Approved** 的費用保持已批准，仍計入所在項目的成本；它不在任何報銷單上，因此沒有付款記錄。Rejected 的費用和其他費用一樣提交。升級時**正在等待審批**的費用已無法再審批：批准它原來的請求，會提示該審批已無法繼續。提交人用 **Submit for Reimbursement** 把它報上去（它接受不在任何報銷單上的 Submitted 或 Rejected 費用，把它和其他費用一起報銷），然後在 Inbox 裡撤回原來的請求，讓它從審批人的列表中消失（管理員也可以撤回）。只撤回不提交報銷時，費用保持 **Submitted**。
