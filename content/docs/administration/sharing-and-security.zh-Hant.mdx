# 共用與安全

共用回答這個問題：*「這個使用者能檢視和編輯哪些記錄？」* 在 HotCRM 中，四個層級疊加在一起為你給出答案：

1. **組織範圍預設值 (OWD)** —— 基線（「預設情況下，商機是私有的」）。
2. **角色階層** —— 經理自動看到其團隊的記錄。
3. **共用規則** —— 例外和開放（「EU 團隊可以看到 EU 客戶」）。
4. **客戶團隊** —— 記錄級的「你和我一起在跟進這個客戶」。

外加用於隱藏敏感欄位的 **欄位級安全**。

## 第 1 層 —— 組織範圍預設值

OWD 是每個物件的 *最嚴格* 設定。其他一切要麼放寬，要麼維持存取權限。

| 物件 | 預設 OWD | 原因 |
| --- | --- | --- |
| Lead | 私有 | 代表跟進自己的潛在客戶 |
| Account | 私有 | 客戶所有權很重要 |
| Contact | 由父級控制（Account） | 可見性隨客戶而定 |
| Opportunity | 私有 | 敏感的交易資料 |
| Quote | 由父級控制（Opportunity） | 隨交易而定 |
| Contract | 私有 | 敏感的商業條款 |
| Product | 公開唯讀 | 每個人都能看到目錄 |
| Case | 公開讀/寫 | 服務團隊中的任何人都可接手 |
| Campaign | 公開唯讀 | 行銷建立，銷售檢視 |
| Campaign Member | 由父級控制（Campaign） | 隨活動而定 |
| Task / Event | 私有 | 個人活動項 |

**OWD 的選項**：私有 / 公開唯讀 / 公開讀/寫 / 由父級控制。

⚠️ 出於安全考量，**降低 OWD 是一道單向門** —— 從私有 → 公開很容易；要退回去可能需要清理共用規則。

## 第 2 層 —— 角色階層

角色階層是用於可見性的 **組織架構圖**。經理自動看到其下屬擁有的一切。

HotCRM 自帶一個 10 角色的預設設定，可以乾淨地對應到一個典型的銷售 / 服務 / 行銷組織，在一個高管父級之下：

```
Executive
 ├── Sales Director
 │    └── Sales Manager
 │         └── Sales Representative
 ├── Service Director
 │    └── Service Manager
 │         └── Service Agent
 └── Marketing Director
      └── Marketing Manager
           └── Marketing User
```

一個 *Sales Director* 自動看到其下任何人擁有的每一個商機。他們看不到服務或行銷記錄（那些是同級，不是子級）。要將一個區域拆分為多個團隊（例如 *Sales Manager — East* 和 *Sales Manager — West*），請複製 **Sales Manager** 節點。

在 **設定 → 角色** 中設定角色。

## 第 3 層 —— 共用規則

共用規則在 OWD + 階層之外 **開放** 存取。它們處理這樣的情況：

- *「所有北美代表都能看到所有北美客戶，即便在其階層之外。」*
- *「客戶成功團隊可以讀取所有活躍的客戶帳戶。」*
- *「財務可以讀取所有贏單的商機。」*

### 兩種形式

| 類型 | 共用給誰 | 範例 |
| --- | --- | --- |
| **基於條件** | 任何匹配記錄篩選條件的人 | *「Region = EU 的客戶」* → 與 EU 公開組共用 |
| **基於所有者** | 某個組中使用者擁有的所有記錄 | *「SDR 擁有的所有記錄」* → 與 AE 組共用 |

### 內建共用規則

HotCRM 開箱即帶這些：

- **VIP 客戶** —— 等級為 *Platinum* 的客戶與所有高管以唯讀方式共用。
- **活躍合約** —— *Activated* 的合約與客戶成功團隊以唯讀方式共用。
- **贏單商機** —— *Closed Won* 的商機與財務團隊以唯讀方式共用。
- **公開產品** —— 產品對所有使用者唯讀。

在 **設定 → 共用設定** 中建立新規則。

## 第 4 層 —— 客戶團隊

對於由一個 **小組**（AE + SDR + SE + CSM）跟進的客戶，**客戶團隊** 是一個針對每條記錄的共用清單。每個成員可以對客戶及其子記錄擁有 **讀取** 或 **讀/寫** 權限。

在 **設定 → 客戶團隊** 中設定團隊範本，這樣新增一個新的「企業小組」客戶時會自動指派團隊。

## 這些層級如何組合

如果以下任一條件為真，使用者就能看到記錄：

1. 他們 **擁有** 該記錄。
2. 他們的 **權限設定檔** 在該物件上授予 *檢視所有*。
3. **OWD** 為公開（或更高）。
4. **共用規則** 授予他們存取權限。
5. 他們在角色階層中 **高於** 所有者。
6. 他們在 **客戶團隊** 中（針對客戶/商機/合約/案例）。
7. 該記錄被 **手動共用** 給他們。

如果都不適用 → 無存取權限。（而且如果無存取權限，記錄是不可見的 —— 不是「你沒有權限」，而是從搜尋和清單中直接 *消失*。）

## 欄位級安全 (FLS)

FLS 控制一條記錄內某個權限設定檔能檢視和編輯 **哪些欄位**。

常見用途：

- 對代表隱藏 **佣金 %**（只有經理才能看到）。
- 對非 HR 使用者隱藏 **生日**。
- 讓 **收入區間** 對除財務以外的所有人唯讀。

在 **設定 → 物件 → 欄位 → 欄位級安全** 中設定。

FLS 在 **任何地方** 都強制執行 —— 清單檢視、報表、API、AI Copilot。如果一個欄位被隱藏，Copilot 也無法引用它。

## AI Copilot 的共用

Copilot 代表使用者行事 —— 它看到的恰好是使用者看到的，不多不少。這意味著：

- 共用規則自動適用。
- FLS 自動適用。
- 執行 Copilot 的管理員會比代表看到更多 —— 這是設計使然。

不存在「AI 繞過」 —— Copilot 無法洩露使用者尚不能看到的資料。

## 給管理員的提示

- ✅ **從嚴格開始** —— 對 Lead/Account/Opportunity 使用私有 OWD。按需透過共用規則放開。
- ✅ **每季度稽核共用規則** —— 它們會累積；修剪掉不再需要的。
- ✅ 使用 **公開組** 讓共用規則易於管理（「與 EU 團隊共用」而非「與這 47 個使用者共用」）。
- ✅ 不要在權限設定檔中過度使用 **檢視所有** —— 它是繞過每條共用規則的大鎚。

## 給使用者的提示

如果你認為自己應該能看到某條記錄卻看不到：

1. 檢查 **誰擁有它**（在聊天中詢問）。
2. 檢查 **你是否在客戶團隊中**（開啟客戶 → 團隊選項卡）。
3. 詢問管理員是否應該新增一條 **共用規則**。

通常最乾淨的修復方式是把你加入客戶團隊，而非為所有人擴展一條共用規則。
