# 出差申请

出差申请在出差之前提出：去哪里、什么时候、为什么、大约花多少钱。你的上级在花钱之前批准或驳回。它在**费用报销**应用的**出差申请**下。

出差申请不是必需的。没有申请也可以录入和提交费用。

## 填写申请

打开**我的出差申请**，点**新建**：

| 字段 | 填写什么 |
| --- | --- |
| **出差事由** | 为什么去（必填） |
| **目的地** | 去哪里（必填） |
| **开始日期**和**结束日期** | 出差的第一天和最后一天（必填）。**天数**首尾两天都算 |
| **预计金额** | 整次出差的一个总数，使用贵公司的本位币，不论每一部分由谁支付（必填） |
| **客户** | 为哪个客户出差，可选 |
| **行程** | 计划：机票、火车、酒店 |
| **备注** | 其他内容 |

在**附件**标签页上传文件。**来源**说明这条记录从哪里来，**检查提示**是助手或规则写给审批人看的发现。两者都不影响任何判断：助手可以以你的身份通过接口起草申请、估算金额或检查，决定仍由你的上级做出。

## 提交和审批

| 状态 | 含义 |
| --- | --- |
| **草稿** | 还在填写 |
| **已提交** | 已交给上级，等待期间锁定 |
| **已批准** | 同意。计划不再改动 |
| **已驳回** | 被退回。改回草稿，修改计划后重新提交 |
| **已取消** | 批准后不去了。最终状态 |
| **已关闭** | 出差已结束。最终状态 |

点**提交**即送审。由**你的上级**（你用户记录上的**上级**）在**收件箱**中决定；没有上级时，改由**财务控制**决定。只有一级：财务在之后的费用上把关，不审批出差申请。**待我审批的出差申请**列出等待你审批的申请。不能审批自己的申请，也没有人能手动设置**已批准**或**已驳回**。

**等待期间改主意了？**在收件箱中撤回，申请回到**草稿**。

## 批准之后

批准针对的是这份计划，所以已批准申请的**出差事由**、**目的地**、日期和**预计金额**都不再改动。要改计划，请点**取消出差**，再重新申请。出差结束后，点**关闭**。

## 谁能看到

你能看到自己的申请，以及请你审批的申请。财务能在**全部出差申请**里看到所有申请，销售经理和销售领导也一样；他们都不能修改别人的申请。出差申请不出现在销售、客服、市场应用里，也不出现在客户页面上。

无论项目交付是否启用，出差申请的用法都一样。
