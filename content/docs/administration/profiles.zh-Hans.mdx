# 权限档案

**权限档案**（在平台术语中即 *权限集*）是分配给用户的权限集合，它控制用户在 CRM 中能创建、查看、编辑和删除什么。

权限集是 **显式允许** 的：如果某个对象没有出现在权限集里，持有该权限集的用户就完全无法访问它 —— 管理员也不例外。不存在“其余对象默认可读”这样的隐含规则。

## 六种内置权限档案

| 权限档案 | 机器名 | 面向 | 典型用户 |
| --- | --- | --- | --- |
| 👑 **System Administrator** | `system_admin` | CRM 管理员 | IT、运营、实施负责人 |
| 📈 **Sales Manager** | `sales_manager` | 一线销售管理者 | 区域经理、销售总监 |
| 💼 **Sales Representative** | `sales_rep` | 销售代表 | AE、SDR、BDR |
| 🎧 **Service Agent** | `service_agent` | 支持团队 | 支持专员、成功经理 |
| 📣 **Marketing User** | `marketing_user` | 营销人员 | 需求生成、活动经理 |
| 🌐 **Guest (Public Forms)** | `guest_portal` | 匿名网站访客 | 无人 —— 它分配给未登录的表单流量 |

## 每种权限档案能做什么

### 👑 System Administrator

- 对 CRM 中 **每一个** 对象拥有完整的创建/读取/编辑/删除权限
- 对每个对象拥有 **查看所有** 和 **修改所有** —— 绕过记录级共享
- 配置系统：对象、字段、权限档案、共享、自动化、AI 技能

⚠️ **谨慎使用** —— 通常每个组织 2–3 人。

### 📈 Sales Manager

- 对 **线索**、**客户**、**联系人**、**商机**、**报价** 和 **任务** 拥有组织范围的读写权限 —— 经理处理任何代表的记录，而不只是自己的
- 创建和编辑 **合同**、**产品** 和 **市场活动**（删除属于管理员操作）
- 完整掌控 **商机行项和报价行项**，因此可以修正任何代表交易上的定价
- 读取 **工单**、**知识文章** 和 **活动成员**
- **预测**：读取每位代表的快照并调整承诺数字 —— 预测本身就是经理的交付物
- 维护 **竞争对手** 战卡
- 看不到其他用户标记为 **Private（私有）** 的交易（参见[共享与安全](/zh-Hans/docs/administration/sharing-and-security)）

### 💼 Sales Representative

- 创建、读取和编辑 **自己的** 线索、客户、商机、报价和任务
- **联系人** 跟随客户：代表能看到自己可见的每个客户下的联系人，包括通过区域规则或客户团队共享获得的客户
- **商机行项和报价行项** —— 对自己的交易和报价拥有完整权限，这正是“Products”相关列表和报价编制所需要的
- 读取 **产品** 目录、**市场活动**、**活动成员**、**知识文章** 和 **竞争对手** 战卡，并可登记在交易中遇到的新竞争对手
- 读取 **自己的预测快照**（由每晚的预测作业写入，从不手工填写）
- 读取自己的 **合同** 和 **工单**；删除属于经理权限（自己的任务除外）

### 🎧 Service Agent

- 创建、读取和编辑自己队列中的 **工单** 和 **任务**；紧急工单通过升级共享规则到达更广的服务团队
- 组织范围读取 **客户**、**联系人**（可编辑）和 **线索** —— 脱离客户背景的工单毫无意义
- **知识文章**：读取所有文章并撰写、修订（草稿 → 审阅中 → 已发布 的生命周期由知识库流程约束，而非权限）。归档属于管理员操作
- 读取 **产品** 目录
- 无权访问商机、报价和预测

### 📣 Marketing User

- 组织范围创建、读取和编辑 **线索**、**联系人** 和 **市场活动**
- **活动成员**：登记与更新成员关系 —— 这正是“Add to Campaign”动作写入的内容
- 组织范围读取 **客户** 和 **商机**，用于活动→管道 ROI（标记为 **Private** 的交易仍然隐藏）
- 读取 **知识文章** 和 **竞争对手** 战卡
- 不能删除记录

### 🌐 Guest (Public Forms)

- 通过公开的 Web-to-Lead / Web-to-Case 表单，对 **线索** 和 **工单** **仅可插入**
- **对任何内容都没有读取权限。** 其余每个对象 —— 包括面向公众受众的知识文章 —— 均被拒绝

## 字段级安全

权限档案还会屏蔽单个字段。当前随产品提供的配置：

| 字段 | 谁可读 | 谁可编辑 |
| --- | --- | --- |
| `crm_opportunity.amount` / `probability` | 销售代表、销售经理、营销用户 | 销售代表、销售经理 |
| `crm_account.annual_revenue` | 销售代表 | 销售经理（对代表只读） |
| `crm_account.health_score` | 销售代表、服务专员、营销用户、销售经理 | 销售经理 |
| `crm_case.internal_notes` | 服务专员、销售经理 | 服务专员 |
| `crm_case.is_sla_violated` / `resolution_time_hours` | 服务专员 | 无人 —— 它们是计算得出的 |
| `crm_quote.internal_notes` | 销售代表、销售经理 | 销售代表、销售经理 |

被屏蔽的字段在任何地方都是空白 —— 列表视图、报表、API 和 AI Copilot 一样。销售代表打开工单时看不到服务团队的内部备注。

## 分配权限档案

1. 进入 **设置 → 用户**。
2. 打开用户记录。
3. 从下拉框中选择 **权限档案**。
4. 保存 —— 变更立即生效。

若要在用户的基础权限档案之上追加权限，请分配额外的 **权限集**（“额外的帽子”），而不要修改基础权限档案 —— 权限集是叠加式的、按并集合并。

## 克隆权限档案

如果某个内置权限档案 *几乎* 合适但需要微调：

1. **设置 → 权限档案**。
2. 打开权限档案并点击 **克隆**。
3. 重命名（例如 *“高级销售代表”*）。
4. 调整权限。
5. 保存并分配给用户。

⚠️ **不要修改内置权限档案** —— 克隆它们。HotCRM 的更新可能会重置内置权限档案的设置。

## 权限档案里有什么

| 权限领域 | 控制项 |
| --- | --- |
| **对象权限** | 每个对象的创建、读取、编辑、删除 |
| **记录范围** | “读取”能到多广：仅自己的记录，还是组织范围（*查看所有* / *修改所有*） |
| **字段级安全** | 每个字段的读取与编辑 |
| **系统权限** | 设置访问、用户管理、查看/修改所有数据、共享管理 |
| **行级规则** | 额外的记录过滤，例如对组织范围读取者隐藏标记为 *Private* 的商机 |

## 权限档案 vs 岗位 vs 共享 —— 有什么区别？

- **权限档案（权限集）** = *你能做什么* —— 动词：创建、编辑、删除，以及作用在哪些对象上。
- **岗位（position）** = *你属于哪个群体*，用于分发共享授权。岗位是 **扁平的**：没有层级，因此不会自动从经理向总监上卷。
- **共享规则** = *例外* —— “EU 区域的每个人都能编辑 EU 客户”“服务总监能看到每个紧急工单”。

两者都必须允许：权限档案决定你 *是否* 能读商机，共享决定你能读 *谁的*。

关于岗位 + 共享这一面，参见 [共享与安全](/zh-Hans/docs/administration/sharing-and-security)。

## 给管理员的提示

- ✅ **新对象需要授权。** 在某个权限集点名它之前，它对任何人都不可读 —— 缺失的授权看起来像界面坏了，而不像权限错误。
- ✅ **从内置权限档案开始** —— 除非必要，否则不要自定义。
- ✅ 拿不准时，**克隆** 而非修改。
- ✅ **每季度审计权限档案** —— 当人们换岗位时，他们的权限档案往往没变。
- ✅ 将 System Administrator 限制在 **最多 2–3 人**。

## 给用户的提示

如果你无法做某件你认为自己应该能做的事：

1. 检查你的权限档案（右上角 → 你的名字 → 权限档案）。
2. 询问管理员该权限档案是否授予了这个对象。
3. 如果权限档案正确但缺少某条具体 *记录*，那是[共享](/zh-Hans/docs/administration/sharing-and-security)问题，而非权限档案问题。
