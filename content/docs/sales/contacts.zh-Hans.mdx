# 联系人

**联系人**是某个客户处的个人——通常是决策者、影响者或最终用户。每个联系人都属于一个客户。

## 联系人记录存储的内容

联系人详情界面有 6 个可折叠区块：

| 区块 | 字段 |
| --- | --- |
| **身份** | 称谓、名、姓、全名 |
| **客户与角色** | 客户、职位、部门、主要联系人标志 |
| **联系信息** | 邮箱、电话、手机 |
| **邮寄地址** | 完整的结构化地址 |
| **附加信息** | 描述、生日、线索来源、汇报对象 |
| **沟通偏好** | 拒绝邮件、禁止致电 |

## 主要联系人

每个客户有**一个主要联系人**——通常是主要决策者或业务发起人。将某个联系人设为主要会自动清除前一个联系人上的标志，因此你绝不会出现两个的情况。

主要联系人会被自动建议为以下场景的默认值：

- 商机（主要联系人字段）
- 报价（联系人字段）
- 合同（主要联系人字段）

这能省去大量点击。

## 客户处的组织架构图

使用**汇报对象**来建模客户内部的组织结构：

```
CEO
├── VP Sales
│   └── Sales Director
└── VP Engineering
```

客户详情页将其渲染为一棵可点击的树，因此你能一眼看出谁向谁汇报。AI Copilot 在总结客户时会用到它——它能告诉你哪些人是决策者、哪些是影响者。

## 沟通偏好（GDPR / CCPA）

两个退订标志用于记录此人不希望被联系。它们都是联系人记录**沟通偏好**区块里的复选框，区别在于产品对它们的落实程度：

| 标志 | 目前真正会发生什么 |
| --- | --- |
| **拒绝邮件** | **已强制执行。** 对已退订的联系人，**发送邮件**动作会被隐藏——记录页头部和列表行上都不再出现；创建这样的联系人时，也不会给负责人推送「去打个招呼」的提醒。 |
| **禁止致电** | **仅是一个标记。** 产品不会阻止你给带此标记的联系人打电话，也不会阻止你记录*电话*任务。它是给正要拿起电话的销售代表看的。 |

两者都是普通的可编辑复选框：任何能编辑该联系人的人都能勾选或取消。没有任何字段级规则把它们保留给管理员，因此请把它们当作对本人意愿的记录、需要团队自觉遵守，而不是一把锁。

## 内置规则

- **邮箱地址在你所在的组织内必须唯一**。同一个地址不能同时用于两个联系人，即使这两个联系人隶属于不同的客户——第二次保存会被拒绝，并提示 *"Another contact … with email … already exists."*。同一平台上的其他组织可以有自己使用该地址的联系人——这条规则只作用于你自己的数据，而不是整个平台。邮箱在存储和比较前会统一转为小写，因此 `Ada@Example.com` 与 `ada@example.com` 视为同一个地址。因此，若同一个人同时在两家公司与你往来，两条联系人记录需要各自使用不同的邮箱地址。
- **欢迎邮件**——当创建一个联系人时，系统会自动向其发送 *contact_welcome* 邮件模板。

## 共享——谁能看到哪个联系人

联系人可见性**继承自父级客户**。如果你能看到该客户，就能看到它的所有联系人。没有需要管理的单独联系人共享模型。

这让安全机制变得简单：把客户共享设置正确，联系人就会随之而来。

## 标准列表视图

联系人列表默认打开**全部联系人**，切换器里就是下面这三个已保存视图——只有这三个：

| 视图 | 展示什么 |
| --- | --- |
| **全部联系人**（默认打开） | 所有联系人，**按所属客户分组，分组默认折叠**：你展开正在跟的那个客户，而不是从一张平铺的大名单里翻。组内按姓氏 A→Z 排序，行上是头像、所属客户、职位、部门、邮箱、电话和负责人。每页 50 行，可导出 CSV / XLSX。 |
| **联系人目录** | 同一批人以照片卡片呈现，卡片正面就是联系人头像——开会前把人和脸对上最快的一屏。卡片上有姓名、职位、部门、邮箱、电话和所属客户。 |
| **主要联系人** | 只列被标记为**主要联系人**的人（每个客户一个，见上文），按所属客户排列。发报价或群发邮件之前值得过一遍这张表，因为各处的默认联系人正是从这一批里取的。 |

没有"我的联系人"这类按负责人过滤的视图；就可见性而言也不需要：联系人不单独共享，而是继承所属客户的共享（见上文）。想看"自己的人"，从[客户](./accounts)列表的**我的客户**进入客户记录，或者在**全部联系人**里展开自己那几个客户的分组。

## AI Copilot 如何使用联系人

当你让 Sales Copilot 起草一封邮件时，它会使用：

- 联系人的名和职位（用于个性化）。
- 客户名称和行业（用于上下文）。
- 产品目录（用于相关谈话要点）。
- 联系人的沟通偏好（以跳过退订项）。

因此 *"Draft a follow-up to Jane"* 能在几秒内给你一封个性化的、符合品牌调性的邮件。

## 给销售代表的提示

- ✅ 始终设置职位和部门——它会被报告和 Copilot 使用。
- ✅ 使用汇报对象字段——它让客户会议的准备工作容易得多。
- ✅ 每个客户恰好标记一个主要联系人。

## 给管理员的提示

- 部门列表（Sales、Marketing、Engineering、Finance、IT、Operations、HR、Legal、Executive、Other）可按选择列表值配置。参见 [Customization › Extending Objects](/zh-Hans/docs/customization/extending-objects)。
- 欢迎邮件模板可以在你的邮件模板设置中自定义。
- 来自客户的共享继承意味着你通常永远不需要针对特定客户的联系人共享规则。
