# 项目预算

项目的预算在**项目预算**中编制：一个个版本，每个版本有自己的**预算明细**。当前生效的已批准版本是项目的**基线**，项目的**批准预算**就是它的合计。批准预算不能直接填写，只有新版本获批时才会变化。

版本显示在项目的**相关**标签页中；在项目交付应用的**预算**下可以看到所有项目的版本，**全部预算版本**旁边还有**基线预算**和**未结预算版本**两个列表。

## 谁编制，谁审批

| 谁 | 能做什么 |
| --- | --- |
| 项目经理、项目负责人、管理员 | 新建版本、编制明细并提交审批 |
| 项目总监和项目管理办公室 | 在**待我审批**（**我的工作**分组下）中批准或驳回版本 |
| 财务控制 | 查看所有版本；和项目经理一起编制；批准或驳回增幅 10% 及以上的追加预算 |
| 配置在项目上的人员 | 无权限：预算属于成本，对他们隐藏，项目的批准预算也一样 |

## 一个版本

| 字段 | 含义 |
| --- | --- |
| **预算** | 名称，保存时自动填写：项目名称加版本号，例如 *斯塔克医疗试点交付 · v2* |
| **版本** | 按创建顺序编号为 1、2、3…… |
| **状态** | 草稿、审批中、已批准、已驳回或已被取代 |
| **基线** | 批准预算所取自的那个已批准版本上会勾选 |
| **随项目一起审批** | 第 1 版随立项审批期间会勾选 |
| **原因** | 为什么需要这个版本。提交追加预算时必填 |
| **总成本**、**人工成本**、**人工工时** | 由明细汇总 |

一个项目**同一时间只能有一个未结版本**：已有草稿、审批中或已驳回的版本时，不能再新建。请先提交或删除它。只能删除未结版本；已批准或已被取代的版本是项目的历史记录。

## 一条明细

| 字段 | 含义 |
| --- | --- |
| **类别** | 人工、外包服务、第三方采购、费用或其他 |
| **说明** | 这项成本是什么 |
| **月份** | 成本发生的月份。填写任何一天都会保存为该月的第一天 |
| **费率卡** | 人工明细：工时按哪个级别计划 |
| **工时** | 人工明细：计划的工时 |
| **数量** | 其他明细：多少个单位 |
| **单位成本** | 人工按每小时，其他按每单位。有费率卡但没填单位成本的人工明细，取该费率卡每小时的成本费率（按天计价的费率卡按每天八小时折算） |
| **金额** | 人工为工时 × 单位成本，其他为数量 × 单位成本。不能直接填写 |

只有版本处于**草稿**或**已驳回**时，明细才能修改。提交后明细即被锁定；如需调整，请新建一个版本。

## 第 1 版随项目一起审批 [#version-1]

新项目的第一版预算和项目一起审批：

1. 项目处于**草稿**时，项目经理添加第 1 版及其明细。
2. 把项目设为**审批中**时，第 1 版随之提交。如果没有第 1 版，或版本还不完整（没有明细、合计为零、人工明细没有费率卡或工时、其他明细没有数量），项目会被拒绝提交。
3. 立项审批同时决定两者。第 1 版合计达到 **100,000** 及以上的项目，还要经过财务控制审批。
4. **批准**：第 1 版变为已批准并成为基线，项目的批准预算就是它的合计。**驳回**或撤回：第 1 版退回草稿，修改后随项目再次提交。

项目获批之前，第 1 版不能单独提交审批。

## 追加预算 [#top-up]

项目需要更多或不同的预算时，项目经理新建一个版本：

1. 在项目的**相关**标签页中新建版本。它从草稿开始，编号接在上一个版本之后。
2. 按完整的新预算编制明细，而不是只填差额：获批后，它的合计就是新的批准预算。
3. 填写**原因**，再把**状态**设为**审批中**。
4. 任何一位**项目总监**或 **项目管理办公室** 在待我审批中审批，第一位处理的人即代表全体。使批准预算增加 **10%** 及以上的追加预算，还要经过**财务控制**审批。
5. **批准**：该版本成为基线，之前的版本变为**已被取代**，批准预算、**剩余预算**、**预算使用率**和**预算状态**随即更新。**驳回**：基线不变，可以把版本改回草稿，修改后再次提交。等待期间，项目经理也可以在待我审批中撤回。

一个项目最多只有一个基线。

## 预算版本之前的项目

在预算版本之前直接填写了批准预算的项目，会保留原来的数字。管理员可以用 `scripts/backfill-project-budget-baseline.ts` 把它转为第 1 版，以便之后追加预算（见脚本自身的说明）。不加 `--apply` 时只出报告，已有版本的项目不会被改动。
