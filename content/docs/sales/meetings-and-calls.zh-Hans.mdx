# 会议与电话

**一次会议或一通电话都存储为一条活动（Event）记录**（`crm_event`）——占用某个人日历上一个时段的互动，每次一行；无论它已经发生（你刚刚记录的一通电话），还是预约在下周二。

活动记录是*「和这个客户之间发生过什么，什么时候发生的？」*这个问题的可查询答案。它与[任务](/zh-Hans/docs/sales/activities)刻意不是同一样东西：

| | **任务** | **活动（Event）** |
| --- | --- | --- |
| 它是什么 | 你仍然**欠**某人的事 | **发生过**的事 |
| 锚点 | 一个截止日期 | 一个开始时间和结束时间 |
| 有参与者 | 无 | 有——而且是记录 |
| 归属界面 | 你的待办清单 | 你的日历 |

邮件是第三种形态：它不是一个日历时段，因此 **Send Email** 不写入任何活动记录（见[邮件与日历](/zh-Hans/docs/guides/email-and-calendar)）——但它同样会刷新客户的接触时点，就像一场已举行的会议一样。

## 三个按钮

每一条**线索、联系人、客户、商机和工单**都带有同样的三个操作：

| 操作 | 写入的活动记录 | 什么时候用 |
| --- | --- | --- |
| 📞 **Log a Call**（记录电话） | 类型*电话*、状态**已举行**、开始时间为*此刻* | 电话刚打完 |
| 📅 **Log a Meeting**（记录会议） | 类型*会议*、状态**已举行**、开始时间为*此刻* | 会议刚开完 |
| ➕ **Schedule a Meeting**（预约会议） | 类型*会议*、状态**已计划**、开始时间由你填写 | 你在为以后预约 |

你可以在记录页头部、列表视图行的 ⋮ 菜单以及相关列表中找到它们。（在工单上，记录页头部带的是 **Log a Call**，与*升级*、*关闭*并列；另外两个操作同样注册在工单上，可从列表视图行的菜单进入。）

### 每个表单会问什么

**Log a Call** 和 **Log a Meeting** 都会问：

- **主题**（必填）
- **时长（分钟）**——三个操作上都是选填
- **联系人参与者**——可选任意多个联系人
- **内部参与者**——可选任意多位同事
- **备注**——聊了什么

**Schedule a Meeting** 额外收集 **Start Date (UTC)**、**Start Time (UTC)** 和**地点**，并把备注框改名为 **Agenda**（议程）。

> ⚠️ **预约会议的开始日期与时间按 UTC 解读**，这也是两个字段标签写明 UTC 的原因。请先换算再填写：UTC+8 的 15:00 会议要填 `07:00`。HotCRM 存储的一切都是 UTC 时刻；只是这个选择器目前还不知道你所在的时区。

### 一次点击产生了什么

在一个商机上记录一通电话，写入的是三样东西，不是一样：

1. **活动记录本身**——主题、类型、状态、开始时间、时长、地点、备注，负责人是你，并回链到你发起操作的那条记录。
2. **参与者**——每个人一行（见下文）。你会被加为**组织者**，回复直接置为*已接受*；如果你是在联系人或线索上发起的，那个人也会被加为参与者。
3. **一条时间线条目**——该记录的活动时间线上多出一条指向这条活动记录的条目，因此从时间线钻取打开的是真实记录，而不是一段摘要字符串。

**预约**会议产生的是前两样，没有第三样。活动时间线记录的是*已经发生*的事，而下周日历上的会议还没有发生。因此预约出现在**日历**上、以及该记录的 **Events（活动记录）**相关列表里——两处读的都是活动记录本身，所以它并没有被藏起来。

在**工单**上，第一通*已举行*的电话或会议还会写入工单的**首次响应时间**——客户第一次得到回音的时刻。仅仅*预约*的会议不算响应，状态变更也不算。

## 已计划 vs 已举行——让报表保持诚实的那条分界

每条活动记录都带一个状态：

| 状态 | 含义 |
| --- | --- |
| 🔵 **已计划** | 已预约，尚未发生 *（新建活动的默认值）* |
| 🟢 **已举行** | 它发生了 |
| ⚪ **已取消** | 被取消 |
| 🟠 **客户未到** | 没有人出现 |

**只有*已举行*的活动记录会刷新客户的接触时点。** 预约在下个季度的会议并不是一次已经发生的互动；让一次预约重置这个时钟，正是「风险客户」报表学会说谎的方式——把一个其实没人联系过的客户报成刚刚接触过。

所以有一个习惯值得养成：

> 会议结束后，打开这条活动记录，把**状态改为「已举行」**。

时钟在*进入*「已举行」的那一次转变上推进——只推进一次，而不是之后每次保存都推进。「已取消」和「客户未到」的记录会保留（尝试过本身就是证据），但它们的**时长会被清零**，因此「本周面向客户的分钟数」不会虚高。

## 什么会刷新「最后互动」

有两个字段承载客户接触时点，[销售活动仪表盘](/zh-Hans/docs/analytics/dashboards)上的沉默客户磁贴等报表都建立在它们之上：

- **客户 → 最后活动日期**（Last Activity Date）
- **联系人 / 线索 → 最后联系时间**（Last Contacted Date）

刷新它们的恰好是这些动作：

| 你做了什么 | 客户 | 联系人 | 线索 |
| --- | --- | --- | --- |
| 一条活动记录变为**已举行** | ✅ | ✅ | ✅ |
| 一条**任务**被完成 | ✅ | ✅ | ✅ |
| 在联系人上 **Send Email** | ✅（该联系人所属客户） | ✅ | — |
| 一张**工单**被置为*已解决* | ✅（该工单所属客户） | — | — |

客户上的时点戳会**沿关系链向上走**。销售代表是在商机、联系人或工单上记录电话的——几乎从不直接记在客户行上——所以活动记录会顺着关联向上找到背后的客户并给它打戳。没有这个向上追溯，一个往来频繁的客户会在整个销售周期里看起来一片沉默。

有两件事这张表**刻意**没有包含：

- 处于**已计划**的活动记录，以及保存之前就已经是「已举行」的活动记录。
- 没有任何关联记录的会议。活动记录在没有设置关联记录时会给出警告，而一次没有挂到任何客户上的互动，也无法刷新任何客户的时钟。

管理员还需要知道：修改客户的**负责人**或**类型**，会作为这次编辑的副作用给它的最后活动日期打戳。它并不是一次互动；如果你在审计「沉默」，请读活动记录，而不是只读这个日期。

## 参与者是记录，不是一个文本框

会议室里的每个人都是挂在这场会议下的一条真实记录（`crm_event_attendee`）——正因如此，*「这个季度有哪些联系人拒绝了两次？」*和*「这位销售代表真正参加过什么？」*才成为可回答的问题。

每条参与者记录保存：

| 字段 | 说明 |
| --- | --- |
| **参与者类型** | *联系人*、*线索* 或 *内部用户*——说明这一行指向的是哪类人 |
| **联系人 / 线索 / 内部用户** | 那个人，以指向其记录的真实链接形式 |
| **外部参与者** | 自由文本，也是最后的手段：留给完全不在任何 CRM 对象里的客人（客户方的律师）。不是用来粘贴一串名单的地方。 |
| **回复** | *未回复*（默认）、*已接受*、*已拒绝*、*待定* |
| **组织者** | 召集这场会议的人 |
| **邀请时间** | 邀请被记录的时间 |
| **参与者编号** | 自动编号 `EA-00001` |

一条参与者记录必须指向一个联系人、一条线索、一位内部用户或一位外部客人——指向不到任何人的参与者会被拒绝。

### 删除人与删除会议

- **删除一个人**（联系人、线索或同事）→ 他的参与者记录随之删除，而**会议本身保留**，主题、时间和会后纪要都在。正是这一点让人可以被删除：在改成这样之前，任何一个曾被记录为参会人的人都根本删不掉。
- **删除一场仍有参与者的会议** → 会被拒绝，并明确指出是哪些参与者记录挡住了它。先删掉参与者记录，会议才能删除。一场会议的参会名单是这场会议历史记录的一部分，绝不会被悄悄丢弃。

## 系统自动为你完成的事

- **时长 ↔ 结束时间。** 给出开始和结束，时长就由它们*测量*得出（即使你另外填了一个数字也一样——一个和自己的时间戳互相矛盾的时长，正是把报表算成一堆废数的原因）。给出开始和时长，结束时间就被推算出来，这正是让一通已记录的电话出现在日历上的原因。
- **全天活动**不保留分钟数，因此「全天」与「我们忘了填」始终可以区分。
- **已取消 / 客户未到** → 时长清零。
- **结束早于开始**会被直接拒绝。
- **没有关联记录**会触发警告——把会议关联到那笔交易或那张工单，否则它在真正需要它的地方是不可见的。

## 到哪里找活动记录

在侧边栏的**活动**分组里：

| 入口 | 显示什么 |
| --- | --- |
| **活动** | 你能看到的全部活动记录，最新在前 |
| **日历** | 同样的记录以日历呈现，按类型着色 |
| **互动历史** | 只显示已举行的活动记录——真正发生过的事 |

在**我的工作 → 我的日历**里是你自己的活动记录；活动列表本身还带有**全部**、**活动日历**、**团队日程**（每位销售代表一条泳道）、**我的日历**、**即将开始**（已计划，按时间升序）和**互动历史**这几个页签。

六种活动类型——**会议**（默认）、**电话**、**演示**、**线上研讨会**、**上门拜访**、**其他**——为日历着色，并驱动[销售活动仪表盘](/zh-Hans/docs/analytics/dashboards)上的活动构成分析。

这里没有按日期过滤的「过去的活动」，这是刻意的：状态是人写下的、不会随时间失效，而基于日期的标记在时钟走过那一刻就已经过时。

## 谁能看到什么

- 活动记录是**私有**的：销售代表看到自己的，销售经理看到整个团队的，管理员看到全部。客服可以在工单上记录并查看自己的活动记录。
- **参与者记录目前的表现不同。** 对它的访问本应从会议派生，但在当前平台上这条派生不会按归属收窄，因此任何权限集授予了「活动参与者」读权限的用户，都能读到他打不开的那些会议的参与者记录。在把这个对象授予更大范围的人群之前请记住这一点；收窄是平台侧在推进的修复，而不是一个应用设置。

## AI assistant 如何提供帮助

因为会议现在是一条普通记录，assistant 的 **Live Data** 技能可以像读任何其他对象一样读它——*「上个季度我们和 Acme 开了多少次会？」*、*「我的哪些客户 60 天内没有任何互动？」*——而且是对着实时 schema 读的，所以你今天新增的字段在同一段对话里就能用上。没有任何技能会写入活动记录；写入者就是上面那三个按钮。

## 给销售代表的建议

- ✅ 从**商机或工单**上记录电话，而不是从客户上——这条关联决定了它会出现在哪条记录上，而客户上的时点戳无论如何都会替你打好。
- ✅ 记得回头把会议改成**已举行**。一个满是「已计划」的日历既不能告诉经理任何事，也不推进任何客户的时钟。
- ✅ 把真实的参与者填进去。「客户方有谁从来没参加过电话会议？」只有你填了才答得出来。
- ✅ 用活动记录上的**会后纪要**写下达成了什么共识——记录表单里的备注写的是聊了什么，会后纪要写的才是下一个人需要的东西。

## 给管理员的建议

- ✅ 辅导要盯**已举行**，而不是盯数量：沉默客户磁贴的诚实程度，取决于这个状态字段。
- ✅ 关注**客户未到**——某个客户的爽约率上升，往往远早于续约就已经是一个流失信号。
- ✅ 活动是私有对象。如果某位经理反映日历是空的，先检查其权限集的记录范围，再去怀疑数据。
- ✅ 为 UTC 以外时区的团队写内部操作指引时，记得写上开始时间按 UTC 填写这件事。
