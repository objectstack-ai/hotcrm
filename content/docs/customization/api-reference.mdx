# API Reference

HotCRM runs on ObjectStack. The web UI, automation, actions, and AI skills all work against the same object metadata registered by `objectstack.config.ts`.

## Local base URL

When running HotCRM locally:

```bash
pnpm dev
```

the app is available at:

```text
http://localhost:4001
```

Object API routes are served by the ObjectStack runtime. Route shape can vary by runtime version and enabled capabilities, so prefer the runtime API explorer when available in your environment.

## Current objects

The object roster is deliberately **not** restated here — `src/*/objects/*.object.ts` is
its source of truth, one file per object, each registering its `crm_`-prefixed `name`.
The model spans four business domains: Sales, Service, Marketing, and Revenue.

## ObjectQL shape

Use ObjectQL-style filters and field selection in actions, flows, hooks, and integrations that call the ObjectStack data layer.

```json
{
  "filters": [
    ["stage", "in", ["proposal", "negotiation"]],
    ["amount", ">", 100000]
  ],
  "sort": [{ "field": "amount", "direction": "desc" }],
  "limit": 50,
  "fields": ["id", "name", "amount", "stage", "crm_account"]
}
```

Common operators include `=`, `!=`, `>`, `>=`, `<`, `<=`, `in`, `not_in`, `between`, `contains`, `starts_with`, `ends_with`, `is_null`, and `is_not_null`.

## Action bodies

HotCRM actions can include executable metadata bodies with constrained capabilities.

```ts
export const MarkPrimaryContactAction = {
  name: 'mark_primary',
  objectName: 'crm_contact',
  type: 'script',
  body: {
    language: 'js',
    capabilities: ['api.write'],
    source: `
      const id = ctx.recordId;
      await ctx.api.object('crm_contact').update({ id, is_primary: true }, { where: { id } });
      return { ok: true, id, is_primary: true };
    `,
  },
};
```

A body runs with system privilege. An action that writes on the caller's behalf, where the caller's own permissions must decide, is not a body: **Add to Campaign** (`create_campaign`, `add_contact_to_campaign`) is a flow action over a flow that runs as the caller, and **Mark Responded** (`mark_responded`) is a declarative update. Add to Campaign takes the campaign as `campaignId` and answers with the flow's result, whose `output.enrolled` is `true` for a new member and `false` for a person already on the campaign.

## Verification

After changing API-facing metadata:

```bash
pnpm validate
pnpm typecheck
pnpm test
```

Use `pnpm verify` before publishing.
