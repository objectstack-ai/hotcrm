# 行銷活動成員

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**行銷活動成員**是 [行銷活動](/zh-Hant/docs/marketing/campaigns) 與某個人（一個 [潛在客戶](/zh-Hant/docs/sales/leads) 或一個 [聯絡人](/zh-Hant/docs/sales/contacts)）之間的連接。它記錄行銷活動已經觸達該人，以及後來發生了什麼：他們是否回應、其潛在客戶是否轉化、還是要求不再收到聯絡。

## 成員如何加入

三種方式：

1. **在行銷活動上批次加入** — 開啟一個行銷活動，在記錄頁標頭點擊 **Enroll Members**（批次加入成員）；該操作在行銷活動處於 *Planning* 或 *In Progress* 時提供。它會開啟 [Campaign Enrollment flow](/zh-Hant/docs/marketing/campaigns#campaign-enrollment-flow) 的 *Enrollment Criteria* 畫面，由你自己在那裡挑選受眾——潛在客戶按狀態，聯絡人按部門——然後為每個符合的人建立一筆狀態為 *Sent* 的成員記錄，並略過已加入的人和已退訂的人。沒有任何東西會替你執行它：條件是在那個畫面上回答的，而定時執行沒有人來回答它們。能加的人都加上了，執行結束時顯示 *Eligible members enrolled in campaign.*；只要有人被拒絕，執行就以拒絕結束，並同時給出兩個數字：加入了多少人、被拒絕了多少人。被拒絕的人不在該活動中。
2. **從潛在客戶清單或聯絡人清單加入** — **Add to Campaign**（加入行銷活動）兩邊都有。在**全部線索**或**全部聯絡人**裡勾選需要的記錄後，從選擇工具列批次執行；在任何按列排列的清單裡，也可以從某一列的 ⋮ 選單對這一筆執行。兩種方式都由記錄選擇器來選定行銷活動。清單標題列上沒有這個按鈕，那裡還什麼都沒有選取。從工具列執行時，確認步驟會列出你勾選的人，每個人單獨加入，結果顯示 *Succeeded* 和人數；從列選單執行時，隨後彈出一則確認提示。它在兩個物件上都是清單操作，所以開啟一筆潛在客戶或一個聯絡人並不會提供它。已經在該活動裡的人會被略過，執行對他們同樣回報成功，所以重複執行不會把一次觸達算成兩次——略過檢查按關係各查各的，因此同一個人以潛在客戶身分加入一次、又以聯絡人身分加入一次，是刻意保留的兩筆成員記錄，而不是一次重複。行銷活動上仍然沒有一個 *Add Members* 選人器讓你從潛在客戶和聯絡人清單檢視中挑人。
3. **在行銷活動上逐筆新增** — 開啟行銷活動，在 *Related*（相關）索引標籤裡找到 **Campaign Members** 面板，用面板上的 **New**（新增）按鈕手動填寫一筆成員記錄。

**誰能加入成員。** 把一個人加入活動就是建立一筆行銷活動成員記錄，三種方式都以操作者本人的身分檢查同一項權限：其權限設定檔是否允許建立行銷活動成員。Marketing User 和管理員擁有這項權限。Sales Rep 和 Sales Manager 沒有：他們的權限設定檔只能檢視行銷活動成員，加入成員交給行銷部，所以他們看不到 **Enroll Members** 和 **Add to Campaign**；無論經由這兩個操作、面板上的 **New** 還是 API，他們想建立的成員都會被拒絕。

**哪些行銷活動、哪些人可以加入。** 只有處於 *Planning* 或 *In Progress* 的行銷活動接受成員，已退訂電子郵件的人不會被加入。**Enroll Members** 只在這樣的行銷活動上提供，並把已退訂的人排除在所選人群之外。**Add to Campaign** 無論從哪裡啟動，都遵守同樣的兩條規則。從某一列的 ⋮ 選單執行時，行銷活動選擇器只列出 *Planning* 和 *In Progress* 的行銷活動；選擇工具列上的選擇器會列出全部行銷活動。無論哪種方式，只要選中的是已結束的行銷活動或已退訂的人，就不會加入任何人，行銷活動的數字不變，並會彈出一則訊息，指明是哪個行銷活動已結束、或哪個人已退訂。因此 *Completed* 的行銷活動會保留它結束時的發送數、潛在客戶數和回應數。用其他方式新增成員時，這兩條規則同樣適用：在行銷活動的 **Campaign Members** 清單上點 **New**、透過匯入或透過 API 新增，都會被拒絕並顯示同樣的訊息，什麼都不會儲存。這則訊息目前在所有語言下都以英文顯示。

一個人隨著時間推移可以加入多個行銷活動，但每個行銷活動只能加入一次（每人每個行銷活動一個成員身分）。

## 4 種成員狀態

成員狀態就是回應生命週期，其中每一個取值在應用裡都有真實的寫入方：

| 狀態 | 含義 | 由誰寫入 |
| --- | --- | --- |
| ⚪ **已發送** | 行銷活動已觸達他們 *(新成員的預設狀態，無論以哪種方式建立)* | 加入 |
| 🟢 **已回應** | 他們作出了回應——回覆、註冊、下載 | 成員上的 **Mark Responded**（標記為已回應） |
| 🟣 **已轉化** | 其潛在客戶後來成為了客戶 | 該潛在客戶轉化時自動寫入 |
| 🔴 **已退訂** | 他們要求不再收到聯絡 | 可以編輯行銷活動成員的使用者，在成員記錄上設定 |

這四個取值並不是一部只升不降的階梯。大多數成員停在*已發送*；作出回應的移到*已回應*；仍處於*已發送*或*已回應*、其潛在客戶後來轉化的成員會被自動提升為*已轉化*。把成員改回去——修正一次誤點，或為了重寄而重設回*已發送*——會連同回應時間戳一起清除。把一個已經回應過的成員設為*已退訂*則不會：回應留在成員上，仍算作行銷活動的一次回應。*已退訂*的成員永遠不會被那次轉化掃描提升：退訂不會被一個行銷結果覆蓋掉。

## 為什麼同時支援潛在客戶和聯絡人？

行銷活動成員可以關聯到一個**潛在客戶**（尚未合格的人）或一個**聯絡人**（現有客戶處的人）——但不能同時關聯兩者。這由一條內建規則強制執行：`crm_lead` 或 `crm_contact` 必須且只能設定其一。

這種雙重支援意味著：

- 行銷可以針對**潛在客戶**（潛在客戶）開展漏斗頂端行銷活動。
- 行銷可以針對**現有客戶**（聯絡人）開展追加銷售、交叉銷售或續約行銷活動。

如果一個潛在客戶後來被轉化為聯絡人，現有的行銷活動成員身分仍與該潛在客戶關聯，而新的行銷活動可以將同一個人作為聯絡人重新定位。

## 成員記錄儲存什麼

| 欄位 | 用途 |
| --- | --- |
| Member Number | 這筆成員記錄自己的編號（CM-00001），儲存時自動產生 |
| Campaign | 行銷活動——必填 |
| Lead | 潛在客戶：該人加入時身分為潛在客戶的，記錄在此 |
| Contact | 聯絡人：該人是既有聯絡人的，記錄在此 |
| Added Date | 該人加入的時間——無論透過上面三種方式中的哪一種加入，都在儲存成員記錄的那一刻自動寫入，之後唯讀 |
| Status | 該人走到了哪一步（見上文四種狀態） |
| Response Date | 他們回應的時間，在首次進入已回應狀態時打上 |
| Has Responded | 此人是否曾經回應過，由系統維護——*已轉化*同樣算作已回應；重設回*已發送*會清除它；回應過的成員退訂後仍保留它 |

## 什麼被追蹤，什麼沒有

> **本應用不追蹤開啟、點擊或退信。** 平台的郵件服務負責寄信，並記錄這則訊息的去向——*Queued → Sent*（已排隊 → 已寄出），或者 *Failed*（失敗）——但它不帶追蹤像素、沒有點擊回呼、也沒有退信資料來源。任何依賴它們的成員狀態都只會永遠停在預設值上，所以產品裡沒有這樣的狀態。應用真正能觀察到的，是一個人作出了回應、以及一筆潛在客戶發生了轉化——這正是這四種狀態所講述的內容。

每一種狀態都有真實的寫入方：

- **已發送** — 在成員記錄被建立時寫入，上文的每一條加入路徑都會寫。
- **已回應** — 成員記錄上的 **Mark Responded**（標記為已回應）按鈕。記錄一次回應就是編輯這筆成員記錄，所以這個按鈕只提供給可以編輯行銷活動成員的使用者（Marketing User 和管理員），並且只在成員仍處於*已發送*時出現：已回應、已轉化或已退訂的成員沒有什麼可記錄的，而已退訂的人更不該被一次誤點重新拉回漏斗。它會連同狀態一起打上*回應時間*與*已回應*標識。
- **已轉化** — 自動寫入。當某個成員的潛在客戶被轉化時，該潛在客戶所加入的每一個行銷活動都會提升自己的成員記錄並重算指標。轉化是這個應用唯一能自行觀察到的行銷活動結果。
- **已退訂** — 由可以編輯行銷活動成員的使用者（Marketing User 和管理員）在成員記錄上設定，通常是在此人要求不再收到聯絡的時候。應用裡沒有任何東西會自動設定它：一次退訂請求只有在這些使用者把它記到成員記錄上時才會到達這裡。設定它的同時會勾上此人潛在客戶或聯絡人上的 **Email Opt Out**（拒收郵件），這才是讓他們不再進入後續活動的機制：加入流程會略過已退訂的人。它只朝一個方向走——把一個人標記為退訂，並不會改寫他既有的成員記錄，因為那些記錄的是當時發生的事實。

## 指標如何彙總

行銷活動詳情頁會彙總其成員：

```
Sent          = 該行銷活動的全部成員
Responses     = 曾經回應過的成員（Has Responded），含後來退訂的
Response rate = Responses ÷ Sent，以百分比表示
```

轉化以行銷活動上的「已轉化潛在客戶數」抵達該頁面；商機一旦帶上行銷活動，就會進入同一頁面的商機與 ROI 數字。退訂不是行銷活動上的計數：你在成員記錄上看到它，也在此人的 **Email Opt Out**（拒收郵件）上看到它。

這些數字會在每一次成員變化時重算——有人加入、有人被標記為已回應、有人被移除——所以正在進行中的行銷活動報的就是真實數字，不必等一個夜間作業。把一個成員標記為*已回應*，行銷活動的回應率隨之變動。

## 成員在哪裡檢視

在行銷活動詳情頁的 **Related**（相關）索引標籤下，一個標題為 **Campaign Members** 的面板裡。該面板列出這個活動的每一位成員，五欄——**Lead**（潛在客戶）、**Contact**（聯絡人）、**Added Date**（加入日期）、**Status**（狀態）和 **Response Date**（回應日期）——並帶著上面提到的 **New**（新增）按鈕。欄位的順序就是這筆記錄發生的順序：誰被加入、什麼時候加入、後來怎麼回應。

讀者常帶著兩個預期過來，它們真正的落點是：

- **沒有 *Members* 索引標籤。** 成員面板只是活動在共用的 *Related* 索引標籤上的關聯記錄面板之一。
- **沒有任何成員清單檢視** —— *All Members*、*Responded*、*Unsubscribed*、*Converted to Opportunity* 都不存在。Campaign Member 物件一個清單檢視都沒有；即便有，關聯清單面板也不讀子物件的清單檢視：面板的欄位是在活動關聯欄位上直接定好的，從來不來自檢視。產品裡沒有任何東西能把這個面板按狀態篩選，也沒有面向 Campaign Member 的報表，所以「所有回應過的人」是活動上的一個**數字**而不是一份可以開啟的名單——見上文《指標如何彙總》一節，那裡的回應率由成員的回應即時算出。

## 給行銷人員的提示

- ✅ **盯住退訂**——每一次退訂都會同時把這個人從郵件裡排除，於是他會自動退出後續的每一次加入。退訂數上升，是該換內容的訊號，而不是該換名單的訊號。
- ✅ **用*已回應*和*已轉化*來評判一個行銷活動**——它們是這個應用真正能觀察到的兩個結果。
- ✅ **在商機上標記行銷活動來源**——沒有它，轉化就無法彙總。

## 給業務代表的提示

- ✅ 當你開啟一個潛在客戶時，查看側邊欄中的 **Campaign Memberships**——它會告訴你他們被投放過哪些行銷活動、以及他們怎麼回應的。
- ✅ 用行銷活動作為對話開場白——*"我看到你參加了我們最近關於……的網路研討會。"*

## 給管理員的提示

- 沒有什麼開啟/點擊追蹤可供啟用，也沒有哪個連接器能加上它。如果某個行銷活動的回應數字偏低，先確認行銷部是否在用 **Mark Responded**（標記為已回應）記錄回覆——那個按鈕，以及潛在客戶發生轉化，是僅有的能把成員移出*已發送*的兩件事。業務代表和業務經理按不了它：他們的權限設定檔只能檢視行銷活動成員，不能編輯。
- "*Lead* 或 *Contact* 必須且只能設定其一"這條規則存在於 campaign_member 物件的驗證規則中。
