# 线索

**线索**是一次入站咨询——某人表现出了兴趣，但尚未被确认为真正的销售商机。在你决定值得跟进之前，线索会与你真正的客户和联系人分开存放。

## 何时该用线索（而非联系人）

| 场景 | 使用…… |
| --- | --- |
| 有人填写了网页表单 | 线索 |
| 展会名单上的一个名字 | 线索 |
| 你购买了一份营销名单 | 线索 |
| 现有客户的新采购方加入 | 联系人（归在现有客户之下） |
| 真实客户处已确认的决策者 | 联系人 |

关键是把未经审核的噪声挡在你真正的客户数据库之外。

## 5 种线索状态

每条线索都会经历这些状态。销售代表一次只能推进一步——系统会拦截无效的跳转。

| 状态 | 含义 | 你通常接下来做什么 |
| --- | --- | --- |
| **新建** | 刚到达，还没人联系 | 在 SLA 内进行首次联系 |
| **已联系** | 销售代表已通过电话/邮件联系 | 应用 BANT 资格审核 |
| **已审核** | 通过 BANT——值得跟进 | **转换**为客户、联系人和商机 |
| **不合格** | 不匹配（行业不对、没有预算等） | 如情况变化可稍后重新开启 |
| **已转换** | 已成为真正的客户和联系人 | （线索现已锁定） |

如果情况发生变化（预算释放、新项目启动），你还可以将一条不合格线索**重新开启**回*新建*。

## 每条线索记录存储的内容

线索详情界面有 9 个可折叠区块。只展开你需要的：

| 区块 | 其中内容 |
| --- | --- |
| **身份** | 称谓、名/姓、全名 |
| **公司信息** | 公司名称、职位、行业、年营收、员工人数、网站 |
| **联系信息** | 邮箱、电话、手机 |
| **资格审核** | 状态、评级（0-5 星）、评分（0-100）、预算、时间线 |
| **分配** | 负责人、下次跟进日期、线索来源 |
| **地址** | 邮寄地址 |
| **附加信息** | 描述、标签 |
| **沟通偏好** | 邮件退订、请勿致电 |
| **转换** | 线索转换后自动填充 |

可选**行业**包括 Technology、Software/SaaS、Finance、Healthcare、Retail、Manufacturing、Education、Real Estate、Media、Logistics、Hospitality、Energy、Government、Non-profit 和 Other。

可选**线索来源**包括 Web、Referral、Event、Trade Show、Webinar、Partner、Advertisement、Cold Call 和 Other。

## 线索评分——评分的含义

每条线索都会自动获得一个 **0 到 100 的评分**，每当线索被创建或更新时都会重新计算。评分会考虑：

- **公司规模**——公司营收和人数越大 → 评分越高。
- **行业匹配度**——默认情况下 Technology、Finance 和 Healthcare 评分最高。
- **职位资历**——VP 和 C 级头衔会加分。
- **互动信号**——近期网页访问、网络研讨会出席等。

你还可以设置手动**星级评级（0-5）**作为人工覆盖：

- ⭐⭐⭐⭐ 或更高 → 系统会将该线索标记为**热门**并将下次跟进设为今天。
- ⭐⭐⭐⭐⭐ → 立即向负责人发送邮件。

> 管理员可以调整评分权重——参见 [Administration › Automation](/zh-Hans/docs/administration/automation)。

## 重复线索

同一个人再次咨询是正常现象，不是错误。老客户再次填写网站表单，或者你导入的展会名单与已有名单有重叠，都会产生**第二条线索**——HotCRM 会记录这层关系，而不是拒绝这条记录。

当新线索的邮箱在系统中已经存在时，保存时会带上：

- **重复状态 = 疑似重复**——这只是系统的猜测，尚未下任何结论。
- **重复于**——它疑似重复的那条记录：如果这个人已经是**联系人**，就指向该联系人；否则指向使用同一邮箱、**最早的未关闭线索**。每次重复提交都指向同一条原始记录，因此一组重复线索是一个列表，而不是一条链。

在线索页签的**疑似重复线索**视图里处理它们。打开这两条记录逐一比对，然后二选一：

- **是老客户的新咨询**——清空重复状态，按正常线索推进。预算重新到位的老客户是真实商机。
- **是同一次咨询重复录入**——把线索置为*未通过*，原因选**重复**。此时表单会要求你指明存活的那条记录，并把重复状态设为**已确认重复**。不指明存活记录就无法以重复为由作废，所以作废分析里的每一条都能点开。

> 匿名 Web-to-Lead 提交永远会被接受。公开表单有意不具备读取 CRM 数据的权限，如果它无法查询已有记录，线索会以未标记的状态落库——请在常规线索队列中复核。

## 转换一条已审核的线索

当一条线索通过资格审核后，点击**转换**。会弹出一个小表单询问：

- 我们是否也要创建一个商机？
- 如果是——商机名称和金额是多少？

然后系统会一步完成：

1. 根据线索的公司信息创建一个**客户**——如果已经有同名客户，则直接复用。匹配时忽略大小写和多余空格，因此公司名为 `ACME  Corp` 的线索会落到你已有的 `Acme Corp` 上，而不是再建一个客户。这不是模糊匹配：`Acme Corp` 与 `Acme Corporation` 仍然是两家不同的公司。
2. 根据线索的个人信息创建一个**联系人**，附加到该客户上，并标记为主要联系人。
3. *（可选）* 在*开发期*阶段创建一个**商机**，成交日期设为 90 天后。
4. 将线索标记为**已转换**并锁定它。
5. 向你发送一封确认邮件，总结所创建的内容。

转换后，线索变为只读——所有后续活动都发生在新的客户、联系人和商机上。

## AI Copilot 如何提供帮助

当你打开一条线索时，Sales Copilot 会出现在侧边面板。试着提问：

- *"Qualify this lead"*——运行 BANT，给你一个评分以及每个维度的一行理由。
- *"Is this a hot lead?"*——快速是/否加上推理。
- *"Draft an intro email"*——撰写一封个性化的首次外联邮件。

Copilot 会推荐下一步行动（例如，安排通话、发送跟进、取消资格）。

## 标准列表视图

线索列表没有裁剪过的页签，所以切换器里列出的就是全部已保存视图——一共八个，顺序如下：

| 视图 | 展示什么 |
| --- | --- |
| **全部线索**（默认打开） | 所有线索，最新的在前；姓名是进入记录的链接，同行还有公司、邮箱、状态、评分、来源和负责人。每页 25 行，可导出 CSV / XLSX，勾选后可批量**加入营销活动**。组织里还没有线索时它会直说——*还没有线索 · 创建第一条线索，从这里开始*。 |
| **我的线索** | 你负责的线索，评分高的在前，同评分内最新的在前。侧边栏的**我的工作 › 我的线索**进的也是它。 |
| **🔥 高热度线索** | 仍处于**新建**或**已联系**、评分**四星及以上**的线索——正是新线索路由判为热、给出次日跟进日期、并向负责人发出「24 小时内认领」告警的那一批。按**下次跟进日期**由近及远排序，行上带电话、邮箱和负责人，从上往下打就行。 |
| **高优先级** | 同一批线索（**四星及以上**，同样只看新建和已联系），只是摆成一张速览表而不是工作队列：不带跟进日期，行上给出线索来源，并按评分着色——五星绿色，四星橙色。 |
| **疑似重复线索** | 上文说的复核队列：**重复状态**为*疑似重复*的线索，最早被怀疑的排在最前，重复关联字段就在行上。处理一条少一条——确认或清除之后它就掉出队列。没有待复核的时候它会写明：*没有疑似重复 · 无需复核——每个重复录入的邮箱都已检查过。* |
| **线索流水线** | 看板视图，一个状态一列，每列汇总**年营收**。点开卡片是从侧边滑出的抽屉，不会把你带离看板。 |
| **线索日历** | 线索按进入系统的日期落在月历上，标题是公司名，按状态着色——看的是流入的形状。 |
| **线索卡片** | 卡片墙，一条线索一张卡，以公司名为标题，卡面上是姓名、邮箱、电话、状态和评分。 |

## 给销售代表的提示

- ✅ 让**下次跟进日期**保持真实——**🔥 高热度线索**就是按它排序的，日期放着不更新，会把一条活着的线索压到队列底部。新线索会自动拿到一个（四星及以上是明天，其余是三天后），**安排跟进**动作则会用你刚建的那个任务的到期日重新盖章。
- ✅ 如果你有强烈的直觉判断，就使用星级评级——评分并不能捕捉一切。
- ✅ 不要过早转换——已转换的线索无法还原。在确认期间使用*已审核*状态。
- ❌ 不要永远把噪声留在*新建*中——3 次联系失败后就取消其资格。

## 给管理员的提示

- 评分公式位于线索的自动化中。要重新设定权重，请编辑 `src/objects/lead.hook.ts`（绑定到 `crm_lead`）。参见 [Customization](/zh-Hans/docs/customization/extending-objects)。
- 通过授予访客门户配置文件对线索对象的*仅插入*权限，可以启用 Web-to-Lead——参见 [Administration › Profiles](/zh-Hans/docs/administration/profiles)。
- 要添加新的行业或线索来源，请编辑线索对象的选择列表——参见 [Customization](/zh-Hans/docs/customization/extending-objects)。
