# 發票與回款

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

這裡的**發票**（**Invoice**），是財務在自己系統中開立的一張發票的紀錄；**回款**（**Payment**），是收到款項的紀錄。兩者都由財務輸入或匯入。業務在客戶、訂單、合約和 **Order to Cash** 下的清單中查看它們。

兩者都屬於**客戶**，而且**並行**：回款不填發票。發票填它開給的訂單或合約；回款填它收的回款計劃，或它付的訂單或合約。一張發票對應多個訂單，或暫時對應不上任何東西的預收款，只需填客戶。客戶還欠多少看訂單、合約和客戶上的 **Unpaid**，什麼逾期看回款計劃，不逐張看發票。

**應收會計**職位在所有客戶上輸入和匯入它們。這個職位能查看所有客戶，但不能編輯任何客戶：能查看客戶，就足以寫入它的發票和回款。

## 發票 [#invoices]

| 欄位 | 內容 |
| --- | --- |
| **Invoice Number** | 財務開立的發票上的號碼 |
| **Account** | 這張發票開給的客戶。必填；選擇訂單或合約時自動帶出 |
| **Order** | 這張發票針對的訂單（如有）。選擇訂單會帶出它的客戶，歸在合約下的訂單還會帶出這份合約；另一個客戶的訂單會被拒絕 |
| **Contract** | 這張發票針對的合約（如有） |
| **Issue Date** | 開立的日期 |
| **Due Date** | 應付款的日期（見下文） |
| **Amount** | 開票金額，含稅 |
| **Status** | **Issued** 或 **Cancelled** |
| **Invoice File** | 發票檔案（如已附上） |

**到期日。** **Due Date** 留空時，儲存時會自動填寫：**Issue Date** 加上合約的 **Payment Terms**；沒有合約或合約沒填時，取訂單的 **Payment Terms**（Net 15、30、60 或 90 天；Due on Receipt 即開票當天）。填寫了日期則按填寫的儲存。既沒有訂單也沒有合約的發票沒有 **Payment Terms** 可用，請手動填寫到期日。

**已作廢的發票。** 在源頭作廢或全額折讓的發票，在這裡設為 **Cancelled**。它隨即退出所有統計：訂單、合約和客戶的 **Invoiced** 不再計入它，**Uninvoiced** 相應增加。

## Unpaid 與 Uninvoiced [#unpaid-and-uninvoiced]

| 數字 | 訂單上 | 合約上 |
| --- | --- | --- |
| **Unpaid** | **Total Price** 減去 **Received** | 有 Confirmed 或 Completed 的訂單時 **Order Amount** 減去 **Received**，否則 **Contract Value** 減去 **Received** |
| **Uninvoiced** | **Total Price** 減去 **Invoiced** | 有 Confirmed 或 Completed 的訂單時 **Order Amount** 減去 **Invoiced**，否則 **Contract Value** 減去 **Invoiced** |

有訂單的合約按實際下單的金額計算，不按合約金額：一份 1,000,000 的框架合約，下單 600,000、已開票 100,000 時，**Uninvoiced** 是 500,000。實際下單的金額只算 **Confirmed** 和 **Completed** 的訂單：Draft 和 Cancelled 的訂單不計入，訂單全是 Draft 或 Cancelled 的合約按 Contract Value 計算。Draft 訂單確認後即計入。在訂單上輸入的發票和回款會帶上訂單的合約，所以合約的 **Invoiced** 和 **Received** 會算進它們，每筆只算一次。

兩者都不低於零：超過應收的回款照樣接受，無論是手動輸入還是匯入，因為這筆錢確實收到了，**Unpaid** 到零為止。客戶上的 **Unpaid** 和 **Uninvoiced** 把它已簽下的每筆交易各自的數加起來，每筆只算一次：每張 **Confirmed** 或 **Completed** 的訂單，以及每份沒有訂單的 **Activated** 或 **Expired** 合約。哪些計入，見[訂單、合約和客戶上的彙總](/zh-Hant/docs/order-to-cash#totals)。

**什麼算逾期**看的是回款計劃：過了 **Planned Date** 仍有 **Open** 金額的節點，在 Order to Cash 應用的 **Follow-up → Overdue Payment Plans** 裡。見[回款計劃](./collection-plan)。

## 回款 [#payments]

| 欄位 | 內容 |
| --- | --- |
| **Payment Number** | 自動編號：PAY-00001、PAY-00002…… |
| **Account** | 付款的客戶。必填；選擇訂單或合約時自動帶出 |
| **Order** | 這筆款項針對的訂單（如有）。留空時從回款計劃帶出 |
| **Contract** | 這筆款項針對的合約（如有）。留空時從訂單帶出，沒有訂單時從回款計劃帶出 |
| **Payment Plan** | 這筆款項計入的節點（如有）。只接受本客戶的節點：另一個客戶的會被拒絕 |
| **Payment Date** | 收到款項的日期 |
| **Amount** | 收到多少 |
| **Method** | **Bank Transfer** 或 **Other** |

**每個節點一行。** 一筆收款結清了多個節點或多張訂單時，按財務已有的拆分，每個節點或每張訂單記錄一筆回款。HotCRM 中沒有分攤這一步。

**預收款。** 把回款記錄到回款計劃或訂單上；還沒有任何東西對應時，只記在客戶上。之後開立發票時不用再填什麼：發票和回款不做比對。

**發票或回款上選擇另一個客戶的訂單或合約會被拒絕**，提示會寫明是哪一個。填了訂單之外的另一份合約，或訂單和合約屬於不同客戶，同樣會被拒絕。匯入時 **Account** 留空，就由訂單或合約帶出。

## 匯入 [#importing]

財務可以用 **Invoice Import (CSV)** 和 **Payment Import (CSV)** 兩個匯入對應，從試算表、會計軟體或 ERP 的匯出檔案批次匯入發票和回款。帶有正確欄位標題的範本是 `assets/import-templates/` 下的 `invoices.csv` 和 `payments.csv`。

| 欄 | 發票 | 回款 |
| --- | --- | --- |
| ERP Reference | ✓ 唯一編號 | ✓ 唯一編號 |
| Account | ✓ 客戶名稱；填了訂單或合約時可留空 | ✓ 填了訂單、合約或節點時可留空 |
| Order | ✓ 訂單編號，例如 SO-0001，或訂單的 **External Reference**；可選 | ✓ 可選 |
| Contract | ✓ 合約編號，例如 CTR-0001；可選 | ✓ 可選 |
| Invoice Number | ✓ | — |
| Billing Milestone | — | ✓ 節點名稱 |
| Issue Date、Due Date、Amount、Status | ✓ | — |
| Payment Date、Amount、Method | — | ✓ |

- **ERP Reference 是唯一鍵。** 匯入一行時，如果它的 **ERP Reference** 已在某張發票上，就更新這張發票，而不會再新增一張。因此財務修改檔案後可以再次匯入。ERP 透過介面寫入時使用同一個編號。
- **每一筆匯入的紀錄都有標記。** 它的 **Source** 為 **Import**，**Synced At** 為匯入的時刻，讀者可以看出數字從哪裡來、有多新。手動輸入的紀錄，**Source** 為 **Manual entry**。
- **參照按名稱比對。** 客戶名稱、訂單編號或外部編號、合約編號或節點名稱比對不到任何紀錄時，該行匯入失敗，匯入報告會寫明原因。客戶、訂單和合約都沒填（回款還可以是節點）的行同樣失敗：客戶是必填的。
- **多份合約上有同名節點時，該行匯入失敗。** 節點常常同名（「預付 30%」「第二年」），而匯入會在所有合約裡查找這個名稱，不只在該行的合約裡查找，所以匯入報告會寫「比對到多筆紀錄」。這時在 **Payment Plan** 欄填寫節點的紀錄 ID，它在節點頁面網址的末尾。兩個客戶同名時，**Account** 欄也會這樣失敗。
- **一筆收款分到兩張訂單時是兩行回款**，各需要自己的 **ERP Reference**，而它是唯一的。請和產生檔案的一方約定編號規則，例如收款編號加訂單編號。

金額使用公司的幣別，與 HotCRM 中所有金額一樣。請在匯入前完成換算。
