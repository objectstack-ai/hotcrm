# 导入数据——顺序、匹配与拒绝

写给要把现有客户数据导入 HotCRM 的管理员。本页讲 HotCRM 如何处理你的每一行数据；文件模板和导入界面的逐步操作，见产品文档里的导入指南。

## 按这个顺序导入

1. 先导入**客户**。
2. 再导入**联系人**：每个联系人都要写明所属客户，而这个客户必须已经存在。
3. 最后导入**线索**。

在**客户**、**联系人**或**线索**列表上打开**导入**并上传文件。如果文件的列就是 HotCRM 模板里的列，向导会自动选用 HotCRM 为这个对象提供的已保存映射，例如 **Account Import (CSV)**：它认得这些列标题，也会翻译其他系统使用的取值，所以不需要手动映射。在最后一步，**校验数据**会逐行检查且不写入任何内容；校验通过后再导入。

导入可以在同一个对话框的**历史记录**里撤销。请按相反的顺序撤销（先线索、再联系人、最后客户），这样就不会留下指向已删除客户的联系人。

## 一行数据会更新它匹配到的记录

每个已保存映射都按一个业务键把一行数据匹配到已有记录：

| 对象 | 匹配依据 | 含义 |
|---|---|---|
| **客户** | **客户名称** | 一行写着已存在客户的名称，就会更新那个客户。客户名称在你的组织内唯一。 |
| **联系人** | **邮箱** | 一行的邮箱已经属于某个联系人，就会更新那个联系人，包括它所属的客户。一个邮箱地址在你的组织内只属于一个联系人。 |
| **线索** | **邮箱** | 一行的邮箱已经属于某条线索，就会更新那条线索。 |

所以重新运行一份改正过的文件，会更新而不是重复创建。这也意味着一行可能匹配到你并不想动的记录：如果演示公司还在，一个与演示客户同名的真实客户会更新那条演示记录。请先清理演示记录，见[上线清单](./crm_admin_setup.md)。

## 重复已知人员的线索

线索从来不会因为邮箱重复而被拒绝。导入的一行如果邮箱匹配到已有线索，会像上面说的那样更新那条线索。如果新线索的邮箱属于某个联系人（或者，对于手工或网页表单创建的线索，属于一条更早的线索），线索仍会被创建，HotCRM 会把它的**重复状态**设为**疑似重复**，并关联到那条记录：联系人优先于线索，最早的线索优先于较新的线索。在**线索**的**疑似重复线索**标签页里复核它们。有人核对两条记录确是同一个人之后，再设为**已确认重复**；系统不会自动合并或删除任何记录。

## 负责人

每个文件都可以有一列负责人，填的是用户的邮箱地址。

- 邮箱匹配到某个用户，这个用户就是负责人。
- 邮箱匹配不到任何用户，这一行会失败。系统不做猜测：先邀请这个用户，或者清空这个单元格。
- 负责人留空，负责人就是**你**，也就是执行导入的人。线索也是如此：导入的线索不会像网页表单来的线索那样分给各位销售代表。如果需要，导入之后再重新分配。

## 常见的拒绝

被拒绝的行会写明行号和字段，方便你改好文件再运行一次。最常见的几种：

- **缺少必填值**——例如联系人缺少名、姓、邮箱或所属客户。
- **取值不在选项内**——选项列表接受 HotCRM 自己的标签或代码（不区分大小写），以及其他系统常用的说法。仍然无法识别的取值会让这一行失败，而不是被悄悄丢掉。
- **引用匹配不到记录**——联系人上的客户名称，或负责人邮箱，找不到对应的已有记录。
- **网址不完整**——请带上 `https://`。

导入时，业务规则与手工保存时完全一样地运行：新线索会拿到跟进期限；违反应用强制规则的行，会以那条规则自己的提示被拒绝。
