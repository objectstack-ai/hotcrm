# 安全與合規

本頁介紹 HotCRM 中可用的安全與合規控制。許多控制在平台層設定；有些則是你作為管理員所做的策略選擇。

## 身分驗證

### 使用者名稱 + 密碼

- 強制執行強密碼策略（最小長度、複雜度、歷史、過期）。
- 使用 Bcrypt 雜湊；絕不以明文儲存。
- N 次失敗嘗試後帳戶鎖定（可設定；預設 5 次）。

### 多因素身分驗證（MFA）

- TOTP（Google Authenticator、Authy、1Password）—— 推薦所有使用者使用。
- WebAuthn / 硬體金鑰（YubiKey、Touch ID）。
- 備用恢復碼。
- **管理員應強制要求所有使用者使用 MFA** —— Setup → Security → MFA Policy。

### 單一登入（SSO）

支援的協定：

- **SAML 2.0** —— Okta、Azure AD、Google Workspace、OneLogin、Ping。
- **OpenID Connect (OIDC)** —— Auth0、AWS Cognito。
- **OAuth 2.0** —— 用於委派應用存取。

在 **Setup → SSO Providers** 處設定（位於 *Access Control* 群組下 —— 設定裡沒有 *Security* 這個群組）。啟用 SSO 後，你可以完全停用密碼登入。

### SCIM 佈建

自動從你的身分提供商同步使用者：

- 新 IdP 使用者 → 具有正確設定檔 + 角色的新 HotCRM 使用者。
- IdP 群組變更 → HotCRM 權限集變更。
- IdP 使用者停用 → HotCRM 使用者停用，記錄重新指派。

**設定裡沒有 SCIM 頁面。** 這個能力本身是真的 —— 平台把 SCIM 提供方存為記錄，認證外掛也帶了轉接器 —— 但它沒有自己的導覽入口，所以沒有可點的地方。在介面裡能設定的是 SSO，位置是 **Setup → SSO Providers**。

## 授權

完整的分層模型見[共享與安全](/zh-Hant/docs/administration/sharing-and-security)。快速摘要：

| 層 | 控制 |
| --- | --- |
| **設定檔** | 使用者可以執行哪些操作（建立/編輯/刪除） |
| **權限集** | 在設定檔之上的額外操作 |
| **組織範圍預設值** | 每個物件的基線記錄可見性 |
| **職位** | 共享規則可以點名的扁平存取群體——職位之間什麼都不會上捲 |
| **共享規則** | OWD 的例外 |
| **客戶團隊** | 按記錄共享 |
| **欄位級安全** | 逐欄位讀/寫 |

## 網路與登入控制

- **IP 允許清單** —— 限制登入到特定 IP/範圍（按設定檔）。
- **登入時間** —— 限制登入到工作時間（按設定檔）。
- **工作階段逾時** —— 閒置逾時（預設 30 分鐘）和絕對逾時（預設 12 小時）。
- **並行工作階段** —— 每使用者的最大同時工作階段數。
- **裝置信任** —— 標記新裝置並要求郵件確認。

**不存在 Session Policy 這個畫面。** 登入與認證設定在 **Setup → Authentication**；正在進行的工作階段（以及撤銷某個工作階段）在 **Setup → Sessions**。上面列出的按設定檔的 IP 允許清單、登入時間、並行工作階段上限與裝置信任，本應用在任何地方都沒有對應的設定項。

## 稽核日誌

每個有意義的操作都會被不可變地記錄：

| 類別 | 記錄內容 |
| --- | --- |
| **身分驗證** | 登入成功 / 失敗、MFA、IP、裝置 |
| **授權變更** | 設定檔 / 權限集 / 角色變更 |
| **記錄變更** | 建立 / 更新 / 刪除及前後值 |
| **設定** | 欄位、驗證、流程、共享規則編輯 |
| **資料匯出** | 誰在何時匯出了什麼、多少列 |
| **AI 呼叫** | 哪個使用者在哪筆記錄上呼叫了哪個技能 |
| **整合活動** | Webhook 投遞、OAuth 授權 |
| **批量操作** | 批量編輯、批量刪除、批量指派 |

保留期：

- 即時稽核日誌 UI 中 **90 天**。
- 歸檔稽核日誌（S3 / 物件儲存）中 **7 年**。
- 對於受監管產業可設定為更長。

在 **Setup → Audit Logs** 處讀取稽核日誌（位於 *Diagnostics* 群組下）。匯出為 CSV 或串流傳輸到你的 SIEM（Splunk、Datadog、Elastic）。

## 加密

### 靜態加密

- 資料庫：對敏感欄位（SSN、支付、健康資料）進行 **AES-256** 列級加密。
- 檔案儲存：**AES-256** 伺服器端加密。
- 備份：使用單獨的金鑰加密。

### 傳輸加密

- 所有 HTTP 流量使用 **TLS 1.3**。
- 內部服務之間使用 **mTLS**。
- Webhook 使用 HMAC-SHA256 簽署以保證完整性。

### 欄位級加密

在欄位定義中將敏感欄位標記為**加密**。加密欄位：

- 在資料庫中加密儲存。
- 僅對擁有 *View Encrypted Data* 權限的使用者可見。
- 從 SQL 級查詢中排除（僅平台可以解密）。
- 在稽核日誌中以遮罩後的解密值記錄。

## 資料駐留

選擇客戶資料的儲存位置：

- **美國**（北美客戶預設）
- **歐盟**（法蘭克福 / 都柏林）
- **亞太**（東京 / 雪梨）
- **自託管** —— 你的 VPC，你的掌控。

為符合歐盟資料駐留規則，可按租戶停用跨區域傳輸。

## GDPR

### 存取權

**不存在「Setup → Privacy」這個畫面，也沒有資料主體請求這種記錄類型。** 存取權請求今天要靠人工完成：把引用到這個人的每一筆記錄找出來 —— 聯絡人、線索、工單、活動、行銷活動成員 —— 再自己從清單檢視匯出。沒有任何東西會替你拼出 JSON / PDF 包，也沒有任何東西會把這次請求登記為一個隱私事件。

### 被遺忘權

同樣靠人工，而且更不留情：刪除就是把你挑中的記錄**硬刪除**（沒有資源回收筒可以再撈回來 —— 參見 [FAQ](/zh-Hant/docs/reference/faq)），或者由你自己編輯 PII 欄位來做匿名化。沒有「將受影響內容」的預覽，也不會生成什麼稽核憑證；你能拿到的，是你動過的每筆記錄各自的那條普通稽核日誌。

通常仍然首選匿名化 —— 它保留歷史報表的完整性。

### 同意管理

對於市場行銷：

- 聯絡人/線索上的**同意欄位** —— 擷取合法依據和同意日期。
- **退訂** —— 由郵件行銷活動自動處理；更新聯絡人。
- **抑制清單** —— 任何退訂的人都會被全域排除在所有未來行銷活動之外。

### 資料處理協議

**應用不附帶 DPA 範本** —— 也沒有 *Privacy* 頁面來存放它。請向你的法務團隊索取這份協議。

## SOC 2 / ISO 27001

對於 SaaS 部署，HotCRM 在 SOC 2 Type II 和 ISO 27001 控制下營運。報告可透過你的客戶團隊在 NDA 下取得。

關鍵控制：

- 工程團隊的最小權限存取。
- 透過即時審批進行生產存取。
- 季度存取評審。
- 年度滲透測試。
- 每年測試兩次的災難恢復。
- 漏洞賞金計畫。

## HIPAA / PHI

作為面向醫療保健客戶的附加元件提供 —— 需要額外的 BAA、加密控制和稽核日誌保留。請聯絡你的客戶團隊啟用。

## 災難恢復

- **RPO**（恢復點目標）：1 小時。
- **RTO**（恢復時間目標）：4 小時。
- 每日快照保留 30 天。
- 每週快照保留 1 年。
- 企業版方案生產租戶的跨區域複製。

自託管客戶 —— 請參見[設定清單](/zh-Hant/docs/administration/setup)了解推薦的備份頻率。

## 安全事件回應

- **狀態頁面** —— `status.your-hotcrm-url` —— 即時報告事故。
- **通知** —— 影響客戶資料的安全事件按 GDPR 在 **72 小時**內報告。
- **安全信箱** —— `security@yourcompany.com` 用於報告漏洞。
- **漏洞賞金** —— 請參見計畫頁面。

## 給管理員的提示

- ✅ **強制要求所有使用者使用 MFA** —— 最大的安全 ROI。
- ✅ 當使用者超過 10 人時盡快**開啟 SSO + SCIM**。
- ✅ **將系統管理員限制**在最多 2-3 人。
- ✅ **每月評審稽核日誌** —— 留意異常的匯出量或登入失敗激增。
- ✅ **將稽核日誌串流傳輸到 SIEM** 以進行集中監控。
- ✅ 每年**進行一次桌面演練** —— 如果管理員帳戶被入侵會發生什麼？
