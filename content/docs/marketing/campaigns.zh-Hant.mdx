# 行銷活動

**行銷活動**是任何行銷舉措——一次郵件群發、一場網路研討會、一個展會展位、一次內容下載、一個付費社交廣告活動。每個行銷活動都有預算、目標受眾、持續時間和可衡量的結果（收入、潛在客戶、商機）。

## 4 種行銷活動狀態

| 狀態 | 含義 |
| --- | --- |
| ⚪ **Planning** | 設計中——受眾、預算、內容 *(預設)* |
| 🟠 **In Progress** | 進行中——成員已加入，回來的回應會記錄在他們身上 |
| 🟢 **Completed** | 已完成——活動本身已結束，指標仍在即時更新 |
| 🔴 **Aborted** | 完成前已取消 |

系統會在行銷活動結束日期的次日自動將其從 *In Progress* 移至 *Completed*——這樣你就不必記著了。

## 8 種行銷活動類型

| 類型 | 用途 |
| --- | --- |
| **Email** *(預設)* | 通訊、滴灌計畫、廣播郵件 |
| **Webinar** | 帶註冊和出席追蹤的虛擬活動 |
| **Trade Show** | 在產業活動上的線下展位展示 |
| **Conference** | 演講席位、贊助 |
| **Direct Mail** | 實體信件、禮品、包裹 |
| **Social Media** | 付費或自然社交行銷活動 |
| **Content Marketing** | 部落格文章、電子書、白皮書、門控內容 |
| **Partner Marketing** | 與通路合作夥伴的聯合行銷活動 |

以及 5 個主要通路：**Digital · Social · Email · Events · Partner**。選擇最能描述行銷活動如何觸達受眾的通路——它被通路組合報表使用。

## 行銷活動記錄儲存什麼

行銷活動沒有手工搭建的詳情頁：記錄畫面由物件自己的欄位分組派生，一共六個部分，順序如下。

| 部分 | 裡面有什麼 |
| --- | --- |
| **Campaign Information** | 行銷活動代碼、名稱、描述、類型、通路、狀態 |
| **Schedule** | 開始日期、結束日期 |
| **Budget & ROI** | 預算成本、實際成本、預期收入、實際收入 *(彙總)*、ROI *(公式計算)* |
| **Performance** | 目標人數、各項彙總計數，以及回應率 *(公式計算)* —— 見下文「衡量行銷活動」 |
| **Ownership** | 行銷活動負責人 |
| **Campaign Assets** | 著陸頁，以及行銷活動是否啟用 *(預設摺疊，需要自己點開)* |

這裡沒有 *Engagement* 部分，整個行銷活動上也不存在任何開啟或點擊欄位：它彙總的是加入人數、回應、轉化，以及歸因回來的收入。

**Campaign Code** 是自動產生的（例如 CAMP-000123），因此每個行銷活動都有一個唯一的簡短引用，用於郵件主旨行和追蹤 URL。

## 內建規則

- **結束日期必須在開始日期當天或之後** — 基本的合理性檢查。
- **超預算警告** — 如果實際成本超過預算成本，記錄上會顯示警告。它不會阻止儲存，但會標記該行銷活動以供財務審查。

## 自動發生的事

- **自動完成** — 每天凌晨 2 點，任何超過結束日期的 *In Progress* 行銷活動都會被標記為 *Completed*。這次掃描只翻轉狀態，也只翻轉狀態——在它執行之前，各項數字就已經是最新的了。
- **即時指標** — 指標區塊（傳送、回應、轉化、ROI）會在成員加入、成員回應、其潛在客戶轉化、商機歸因到該行銷活動時隨之重新計算。正在進行中的行銷活動報的就是真實數字；不必等它結束才能讀。
- **ROI 計算** — 行銷活動的實際收入是相關成交贏單商機金額的彙總總和。ROI =（實際收入 − 實際成本）÷ 實際成本。

成員加入被特意排除在這份清單之外：行銷活動進入 *In Progress* 時不會有任何東西加入成員，之後也沒有任何排程會加入。它是由人去按的一個按鈕——見下面的「行銷活動加入流程」。

## 行銷活動加入流程

批次加入是你去執行的一步，而不是自動發生在你身上的事。開啟行銷活動，在記錄頁標頭點擊 **Enroll Members**（批次加入成員）——該操作在行銷活動處於 *Planning* 或 *In Progress* 時提供——流程隨即在該行銷活動上開啟它的 *Enrollment Criteria* 畫面。

你在那個畫面上挑選受眾：

1. **Enroll** — *Leads*（潛在客戶）或 *Contacts*（聯絡人）。一次執行只加入一側，不會兩側都加入。
2. 該側的區隔——潛在客戶按**狀態**，聯絡人按**部門**。兩個欄位都帶預設值，所以你只需改動與所選一側相對應的那個。

然後流程會取出該區隔裡所有符合條件的人——有電子郵件地址、沒有退訂郵件，潛在客戶還必須尚未轉化——並為每個人建立一筆狀態為 *Sent* 的 [行銷活動成員](/zh-Hant/docs/marketing/campaign-members) 記錄。已經在該行銷活動裡的人會被略過，所以重複執行是給行銷活動補人，而不是把一次觸達算成兩次。

它背後沒有排程，而條件正是原因所在。條件是在那個畫面上回答的，而定時執行到來時沒有人回答它們——沒有行銷活動，也沒有區隔——所以加入成員被特意設計成由人來執行的一步。

對於即時行銷活動（例如帶註冊表單的網路研討會），你也可以從行銷活動詳情頁**手動**新增成員，或透過任何潛在客戶/聯絡人上的 **Add to Campaign** 操作新增。

## 衡量行銷活動

這些數字就在行銷活動記錄本身上——各項計數與回應率在 *Performance* 部分，金額與 ROI 在 *Budget & ROI* 部分。它們會隨著成員加入、成員回應、其潛在客戶轉化、商機歸因到該行銷活動而重新計算：

- **Number Sent** — 加入該行銷活動的全部成員，無論其狀態為何。
- **Number of Responses** — 狀態為*已回應* **或** *已轉化*的成員：潛在客戶已轉化的成員同樣作出過回應，這個計數把他們算了進來。
- **Response Rate %** — 回應數 ÷ 傳送數量的百分比。這是行銷活動上唯一的一個「率」。
- **Number of Leads** — 這些成員中不重複的潛在客戶數。
- **Converted Leads** — 其中後來完成了轉化的潛在客戶數。
- **Opportunities Created** 與 **Won Opportunities** — 以該行銷活動為來源的商機數，以及其中成交贏單的數量。
- **Actual Revenue** — 這些贏單商機金額的總和。行銷活動上任何地方都不彙總在途管道金額，它唯一彙總的錢就是成交贏單。
- **ROI %** —（實際收入 − 實際成本）÷ 實際成本的百分比。

> **行銷活動上沒有開啟率、點擊率，也沒有轉化率。** 它的成員只有*已發送*、*已回應*、*已轉化*、*已退訂*四個取值，彼此之間並沒有先後順序，所以「狀態 ≥ Opened 的成員」根本不是這個應用能被問到的問題；開啟、點擊、退信也完全不在追蹤之列，原因見[行銷活動成員](/zh-Hant/docs/marketing/campaign-members)。轉化是以 **Converted Leads** 與 **Opportunities Created** 這兩個計數抵達行銷活動的，而不是以一個百分比。

## 歸因：從行銷活動到收入

連接點是商機上的 **Source Campaign** 查閱欄位。當業務代表轉化一個來自行銷活動的潛在客戶時——或在商機上手動設定來源行銷活動時——系統會將收入歸功於該行銷活動。

對於受多個行銷活動影響的交易（多接觸點），慣例是記錄**末次接觸點**行銷活動（最接近轉化的那個）。要實現完整的多接觸點歸因，可考慮使用行銷活動影響聯結物件擴充模型——請參閱 [自訂](/zh-Hant/docs/customization/extending-objects)。

## 標準清單檢視

行銷活動一共儲存了**四個**檢視（`src/views/campaign.view.ts`），列表上方的標籤行改的是同一批行銷活動**怎麼畫**，而不是裡面有哪些行銷活動。一個檢視一個標籤，標籤上寫的就是檢視自己的名字：

| 檢視 | 它展示什麼 |
| --- | --- |
| **全部行銷活動** | 表格：名稱（釘在左側，也是進入記錄的連結）、通路、狀態、開始與結束日期、預算成本和預期營收——後兩欄帶欄位合計。按**開始日期**升序排列，每頁 25 列。 |
| **活動排期** | 每個行銷活動一根甘特條，從開始日期到結束日期，以名稱為標題，讓相互重疊的檔期對齊排布。 |
| **活動日曆** | 同一批行銷活動排在月曆上，落在各自的**開始日期**，按通路著色。 |
| **行銷時間線** | 同樣的起訖跨度畫在月度刻度上，按通路分組、按狀態著色。 |

四個檢視都沒有任何過濾條件，所以**你能看到的每個行銷活動在四個標籤裡都在**，切換標籤只是換一種畫法。不存在名為 *Active Campaigns*、*Upcoming Campaigns*、*Completed This Quarter*、*Over Budget*、*By Type* 或 *Best ROI* 的已儲存檢視：要把列表收窄到某個狀態，請自己對表格的欄位排序和過濾。**ROI** 並不在這些欄位裡——它在行銷活動記錄的 *Budget & ROI* 部分上，以及行銷儀表板裡。

## 共享——行銷活動預設公開

行銷活動對整個組織**公開唯讀**。銷售中的任何人都可以看到行銷正在執行什麼，並在客戶對話中使用該背景。編輯權限保留給行銷使用者。

## 給行銷人員的提示

- ✅ 在啟動時**設定預期收入**——這是財務預測行銷活動貢獻的依據。
- ✅ **一旦知道就記錄實際成本**——如果欄位為空，超預算警告就無濟於事。
- ✅ 如果你提前結束，請**將行銷活動狀態更新為 *Completed***；不要等待自動完成。
- ✅ 在描述中**記錄有效的做法**——未來的你和未來的同事會感謝你。

## 給業務代表的提示

- ✅ 當一個潛在客戶到來時，檢查他們是否在某個行銷活動中——它會告訴你他們被寄送過哪些行銷活動，以及他們是怎麼回應的。
- ✅ 在你成交的商機上設定 **Source Campaign**——沒有它行銷就無法衡量 ROI。

## 給管理員的提示

- 自動完成 cron（每天凌晨 2 點）是可設定的。沒有加入 cron 可設定——加入成員是 **Enroll Members**（批次加入成員）這個畫面流程，由人從行銷活動上執行。請參閱 [Administration › Automation](/zh-Hant/docs/administration/automation)。
- 要新增新的行銷活動類型或通路，請編輯行銷活動物件的選項清單。請參閱 [自訂 › 擴充物件](/zh-Hant/docs/customization/extending-objects)。
- 對於多接觸點歸因，請參閱自訂指南。
