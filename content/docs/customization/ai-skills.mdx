# AI Skills

AI skills live in the `skills/` directory of the package that owns them — `src/sales/skills/` and `src/service/skills/` today — and each package re-exports its own from that directory's `index.ts`.

HotCRM defines **no agents of its own** — there is no `src/agents/` directory. Skills
attach to the platform assistant (`ask`), which every ObjectStack environment already
provides. Registering a skill in `allSkills` is the whole wiring step.

## Add a skill

```ts
// src/sales/skills/renewal_pitch.skill.ts
import { defineSkill } from '@objectstack/spec';

export const RenewalPitchSkill = defineSkill({
  name: 'renewal_pitch',
  label: 'Renewal Pitch',
  description: 'Drafts renewal talk tracks from account and contract context.',
  instructions: `When asked for a renewal pitch, inspect the current
account and contract records, summarize risk, and draft a concise
  customer-facing talk track.`,
  tools: ['describe_object', 'query_records'],
});
```

## Register it

Registration is two steps, and skipping the second one loses the skill in silence. Re-export it
from its own package barrel, then add it to `allSkills` in `objectstack.composition.ts` — that
array, not the barrel, is what `objectstack.config.ts` passes to `defineStack({ skills })`:

```ts
// src/sales/skills/index.ts — the package barrel: a re-export, nothing else
export { RenewalPitchSkill } from './renewal_pitch.skill.js';
```

```ts
// objectstack.composition.ts — the app-wide list, assembled from the four packages
import { RenewalPitchSkill } from './src/sales/skills/index.js';

export const allSkills = [
  // …existing skills
  RenewalPitchSkill,
];
```

To make the skill activate on a particular record instead of everywhere, declare a
`triggerConditions` entry on it — for example
`{ field: 'objectName', operator: 'eq', value: 'crm_contract' }`.
