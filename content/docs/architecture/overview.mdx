# Architecture Overview

HotCRM is a thin metadata layer on top of the **ObjectStack runtime**. The repository contains no platform code — it imports `@objectstack/runtime` and ships **declarative TypeScript** that the runtime executes.

## Three-Layer Model

```
┌──────────────────────────────────────────────────────────────┐
│   HotCRM repository  (this codebase)                         │
│   ───────────────────────────────────────────                │
│   src/                                                       │
│   ├── objects/   ← 13 ObjectSchema definitions               │
│   ├── hooks/     ← 10 server-side behaviours                 │
│   ├── pages/     ← UI layouts                                │
│   ├── views/     ← List view configurations                  │
│   ├── flows/     ← Automation pipelines                      │
│   ├── agents/    ← AI agents + skills                        │
│   ├── data/      ← Seed records (defineDataset)              │
│   └── ...                                                    │
│   objectstack.config.ts  ← Stack definition (defineStack)    │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼  imports
┌──────────────────────────────────────────────────────────────┐
│   @objectstack/runtime  (the platform)                       │
│   ───────────────────────────────────────────                │
│   - Kernel & plugin loader                                   │
│   - ObjectQL engine + driver abstraction                     │
│   - Auth, Security, Sharing                                  │
│   - Automation, Approvals, Flows                             │
│   - REST API, Hono server                                    │
│   - QuickJS sandbox for hooks                                │
│   - Console / Studio / Account UI (when present)             │
└──────────────────────────────────────────────────────────────┘
                          │
                          ▼  reads/writes
┌──────────────────────────────────────────────────────────────┐
│   Storage driver                                             │
│   - @objectstack/driver-sql      (SQLite, Postgres, MySQL)   │
│   - @objectstack/driver-mongodb                              │
│   - @objectstack/driver-turso                                │
│   - @objectstack/driver-memory   (tests)                     │
└──────────────────────────────────────────────────────────────┘
```

```
├── src/
│   ├── objects/              ← Account, Contact, Lead, Opportunity, ...
│   ├── hooks/                ← index.ts re-exports per-object hooks
│   ├── pages/

│   ├── actions/
│   ├── dashboards/

│   ├── flows/

│   ├── approvals/
│   ├── sharing/
│   ├── profiles/
│   ├── apps/
│   ├── interfaces/
│   ├── cubes/
│   ├── rag/
│   ├── translations/

├── apps/

└── content/docs/             ← documentation source
```

HotCRM intentionally uses a **flat single-package layout**, not a monorepo of `packages/*`. The previous monorepo attempt is preserved on the `legacy-archive` branch — it traded simplicity for the unrealised promise of independently published business packages, while introducing build-order, type-resolution, and seed-loading bugs at every layer.

## How `defineStack` Wires Everything

`objectstack.config.ts` aggregates every metadata module and hands it to the runtime:

```ts
import { defineStack } from '@objectstack/spec';
import * as objects from './src/objects/index.js';
import * as pages from './src/pages/index.js';
import { allHooks } from './src/hooks/index.js';
import { CrmSeedData } from './src/data/index.js';
// ... and so on

export default defineStack({
  manifest: { id: 'com.example.crm', namespace: 'crm', version: '0.1.0', type: 'app' },

  // What platform capabilities this stack needs. The CLI auto-loads
  // matching service plugins (auth, ui, ai, automation, ...).
  requires: ['ai', 'automation', 'analytics', 'auth', 'ui', 'approvals', 'sharing'],

  objects: Object.values(objects),
  pages:   Object.values(pages),
  hooks:   allHooks,
  data:    CrmSeedData,
  // ...
});
```

At dev time, `objectstack dev`:

1. Reads `objectstack.config.ts`.
2. Compiles & validates every metadata entry against `@objectstack/spec` schemas.
3. Emits `dist/objectstack.json` — a single canonical artifact.
4. Boots the runtime, registers all capabilities, exposes:
   - REST API at `/api/v1/*`
   - `/_console/`, `/_studio/`, `/_account/` UIs
   - WebSocket / SSE channels for live updates

## Build → Artifact → Runtime

```
src/ + objectstack.config.ts
       │
       │  pnpm build   (objectstack build)
       ▼
dist/objectstack.json   ← canonical, signed, hashable
       │
       │  pnpm dev / pnpm start
       ▼
@objectstack/runtime in-process
       │
       ├── HTTP @ :3000
       ├── SQLite driver @ .objectstack/data/standalone.db
       └── QuickJS sandbox for hook handlers
```

The artifact is **the unit of deployment**. CI builds it, you ship it, the runtime executes it. No source code runs in production — only validated metadata.

## What HotCRM Adds

The runtime knows nothing about CRM concepts. HotCRM provides:

- **Domain objects** (Account, Lead, Opportunity, …) with their fields and relationships.
- **Business rules** (cannot delete a customer with open opportunities; website must be a URL; quote discount > 20 % requires approval).
- **Sales process** state machines for Lead and Opportunity.
- **Seed records** for demos and tests.
- **AI agents** purpose-built for sales workflows.

Add another vertical (e.g. ticketing, HR) by adding `*.object.ts` + `*.hook.ts` + `*.page.ts` under `src/` and re-exporting from the relevant `index.ts`. No platform changes.
