# 技能

**技能**是平台助手可以执行的细分到点的 AI 能力——比如 *"判定此线索资格"* 或 *"撰写客户回复"*。技能是 HotCRM 对助手的全部贡献；它们按两组编写文档：[销售技能](/zh-Hans/docs/ai-copilot/sales-copilot) 和 [服务技能](/zh-Hans/docs/ai-copilot/service-copilot)。

## 为什么用技能，而非"一个大 AI"

把能力打包为技能（而不是一段大提示词）使它：

- **可预测**——每项技能都有明确定义的输入、输出和行为。
- **可审计**——管理员可以看到每项技能从哪里读取、向哪里写入。
- **可改进**——你可以优化某一项技能（例如更好的线索资格判定），而不触及其他技能。
- **感知权限**——技能继承用户的记录可见性。

## 内置技能

HotCRM 内置六项核心技能：

| 技能 | 使用者 | 它做什么 |
| --- | --- | --- |
| **🔄 实时数据** | 销售 + 服务 | 读取实时模式和实时记录——每一轮 |
| **🎯 线索资格判定** | 销售 | 按 BANT 为线索评分，推荐下一步操作 |
| **✍️ 邮件撰写** | 销售 + 服务 | 撰写感知上下文的邮件或回复 |
| **📈 收入预测** | 销售 | 将管道汇总到 commit / best-case / pipeline 各桶 |
| **🔭 Customer 360°** | 销售 + 服务 | 客户或联系人的一页式摘要 |
| **🚦 工单分流** | 服务 | 建议优先级、分类、队列和匹配的知识库文章 |

### 🔄 实时数据

| | |
| --- | --- |
| **输入** | 任何关于 CRM 数据的自然语言问题（"哪些客户……"、"给我展示排名前……"） |
| **读取** | 提问那一刻的 **实时** 对象元数据（`describe_object`、`list_objects`）和 **实时** 记录（`query_records`、`get_record`、`aggregate_data`）——无缓存快照 |
| **输出** | 带引用记录 ID 的直接答案 |
| **写入** | 无——只读 |
| **知识库** | 无——纯粹是元数据 + 记录 |

这是 **[Wow #1 — 实时模式](/zh-Hans/docs/ai-copilot/live-schema)** 背后的技能：在管理控制台中添加一个字段，助手在下一轮就会使用它。其他每项销售 / 服务技能都构建在实时数据之上，因此同样的实时模式特性会传递地适用——线索资格判定可以根据 10 秒前添加的自定义字段为线索评分。

### 🎯 线索资格判定

| | |
| --- | --- |
| **输入** | 一条线索记录 |
| **读取** | 线索字段、活动参与、匹配的客户历史 |
| **输出** | 评级（热门/温热/冷淡）、BANT 评分、建议状态、理由 |
| **写入** | 如果用户接受，则更新 `rating` 和 `status` |
| **知识库** | 销售知识 |

### ✍️ 邮件撰写

| | |
| --- | --- |
| **输入** | 一条记录（线索、联系人、商机、工单）+ 一句目标 |
| **读取** | 记录字段、相关活动、联系人历史 |
| **输出** | 带主题 + 正文的邮件草稿 |
| **写入** | 不自动写入——由用户审查并发送 |
| **知识库** | 销售知识（销售上下文）、支持知识（服务上下文）、产品信息（技术内容） |

### 📈 收入预测

| | |
| --- | --- |
| **输入** | 一个用户（或团队）+ 一个周期（本季度、下季度、自定义） |
| **读取** | 用户可见的商机、商机历史 |
| **输出** | 按 Closed / Commit / Best Case / Pipeline 分桶的预测 + 风险提示 |
| **写入** | 无——只读 |
| **知识库** | 销售知识（用于预测方法论） |

### 🔭 Customer 360°

| | |
| --- | --- |
| **输入** | 一个客户或联系人 |
| **读取** | 客户、联系人、商机、合同、工单、近期活动、营销活动成员资格 |
| **输出** | 带销售、服务、合同和参与各部分的结构化快照 |
| **写入** | 无——只读 |
| **知识库** | 无——纯粹由数据驱动 |

### 🚦 工单分流

| | |
| --- | --- |
| **输入** | 一个新工单 |
| **读取** | 工单主题/描述、联系人和客户上下文、过往工单、产品 |
| **输出** | 建议的优先级、分类、团队、前 3 篇知识库文章、确认收悉草稿 |
| **写入** | 如果用户接受，则更新 `priority`、`category`、`queue` |
| **知识库** | 支持知识、产品信息 |

## 技能如何协同工作

技能可以调用其他技能。例如：

- *工单分流* 技能可以调用 *Customer 360* 来检查客户在分配优先级前是否为高价值客户。
- *邮件撰写* 技能可以调用 *Customer 360* 将邮件建立在真实的客户上下文之上。

这种组合是自动的——你问一个问题，助手会接好它所需的任何技能。

## 每项技能都遵循什么

- **共享规则**——为用户 X 运行的技能只能读取对 X 可见的记录。
- **字段级安全**——受限字段会从技能输入中隐藏。
- **审计日志**——每次技能调用，连同输入和输出，都会记录以供审查。
- **确认**——任何 *写入* 的技能在提交前都需要明确的用户确认。

## 添加你自己的技能

管理员和开发者可以构建自定义技能——例如：

- 为即将到期的合同 *生成续约推介*。
- *评估客户健康度*，综合使用情况、NPS 和工单量。
- 当某个产品达到里程碑时 *撰写一封发布说明邮件*。

参见 [自定义 › AI 技能](/zh-Hans/docs/customization/ai-skills)，了解如何定义一项新技能、它可以使用哪些知识库，以及如何测试它。

## 给管理员的提示

- ✅ 在 AI 仪表盘中 **监控技能使用情况**——哪些技能使用最多，哪些接受率低。
- ✅ 为表现不佳的技能 **调优知识库**——大多数准确性问题都是知识问题。
- ✅ **禁用** 不适合你业务的技能——每项技能都可以在管理设置中切换开关。
