# 技能

**技能**是平台助手可以執行的細分到點的 AI 能力——比如 *「判定此潛在客戶資格」* 或 *「撰寫客戶回覆」*。技能是 HotCRM 對助手的全部貢獻；它們按兩組編寫文件：[銷售技能](/zh-Hant/docs/ai-copilot/sales-copilot) 和 [服務技能](/zh-Hant/docs/ai-copilot/service-copilot)。

## 為什麼用技能，而非「一個大 AI」

把能力打包為技能（而不是一段大提示詞）使它：

- **可預測**——每項技能都有明確定義的輸入、輸出和行為。
- **可稽核**——管理員可以看到每項技能從哪裡讀取、向哪裡寫入。
- **可改進**——你可以優化某一項技能（例如更好的潛在客戶資格判定），而不觸及其他技能。
- **感知權限**——技能繼承使用者的記錄可見性。

## 內建技能

HotCRM 內建六項核心技能：

| 技能 | 使用者 | 它做什麼 |
| --- | --- | --- |
| **🔄 即時資料** | 銷售 + 服務 | 讀取即時結構和即時記錄——每一輪 |
| **🎯 潛在客戶資格判定** | 銷售 | 按 BANT 為潛在客戶評分，推薦下一步操作 |
| **✍️ 郵件撰寫** | 銷售 + 服務 | 撰寫感知上下文的郵件或回覆 |
| **📈 收入預測** | 銷售 | 將管道彙總到 commit / best-case / pipeline 各桶 |
| **🔭 Customer 360°** | 銷售 + 服務 | 客戶或聯絡人的一頁式摘要 |
| **🚦 工單分流** | 服務 | 建議優先級、分類、佇列和匹配的知識庫文章 |

### 🔄 即時資料

| | |
| --- | --- |
| **輸入** | 任何關於 CRM 資料的自然語言問題（「哪些客戶……」、「給我展示排名前……」） |
| **讀取** | 提問那一刻的 **即時** 物件元資料（`describe_object`、`list_objects`）和 **即時** 記錄（`query_records`、`get_record`、`aggregate_data`）——無快取快照 |
| **輸出** | 帶引用記錄 ID 的直接答案 |
| **寫入** | 無——唯讀 |
| **知識庫** | 無——純粹是元資料 + 記錄 |

這是 **[Wow #1 — 即時結構](/zh-Hant/docs/ai-copilot/live-schema)** 背後的技能：在管理主控台中新增一個欄位，助手在下一輪就會使用它。其他每項銷售 / 服務技能都構建在即時資料之上，因此同樣的即時結構特性會傳遞地適用——潛在客戶資格判定可以根據 10 秒前新增的自訂欄位為潛在客戶評分。

### 🎯 潛在客戶資格判定

| | |
| --- | --- |
| **輸入** | 一條潛在客戶記錄 |
| **讀取** | 潛在客戶欄位、活動參與、匹配的客戶歷史 |
| **輸出** | 評級（熱門/溫熱/冷淡）、BANT 評分、建議狀態、理由 |
| **寫入** | 如果使用者接受，則更新 `rating` 和 `status` |
| **知識庫** | 銷售知識 |

### ✍️ 郵件撰寫

| | |
| --- | --- |
| **輸入** | 一條記錄（潛在客戶、聯絡人、商機、工單）+ 一句目標 |
| **讀取** | 記錄欄位、相關活動、聯絡人歷史 |
| **輸出** | 帶主題 + 正文的郵件草稿 |
| **寫入** | 不自動寫入——由使用者審查並發送 |
| **知識庫** | 銷售知識（銷售上下文）、支援知識（服務上下文）、產品資訊（技術內容） |

### 📈 收入預測

| | |
| --- | --- |
| **輸入** | 一個使用者（或團隊）+ 一個週期（本季度、下季度、自訂） |
| **讀取** | 使用者可見的商機、商機歷史 |
| **輸出** | 按 Closed / Commit / Best Case / Pipeline 分桶的預測 + 風險提示 |
| **寫入** | 無——唯讀 |
| **知識庫** | 銷售知識（用於預測方法論） |

### 🔭 Customer 360°

| | |
| --- | --- |
| **輸入** | 一個客戶或聯絡人 |
| **讀取** | 客戶、聯絡人、商機、合約、工單、近期活動、活動成員資格 |
| **輸出** | 帶銷售、服務、合約和參與各部分的結構化快照 |
| **寫入** | 無——唯讀 |
| **知識庫** | 無——純粹由資料驅動 |

### 🚦 工單分流

| | |
| --- | --- |
| **輸入** | 一個新工單 |
| **讀取** | 工單主題/描述、聯絡人和客戶上下文、過往工單、產品 |
| **輸出** | 建議的優先級、分類、團隊、前 3 篇知識庫文章、確認收悉草稿 |
| **寫入** | 如果使用者接受，則更新 `priority`、`category`、`queue` |
| **知識庫** | 支援知識、產品資訊 |

## 技能如何協同工作

技能可以呼叫其他技能。例如：

- *工單分流* 技能可以呼叫 *Customer 360* 來檢查客戶在分配優先級前是否為高價值客戶。
- *郵件撰寫* 技能可以呼叫 *Customer 360* 將郵件建立在真實的客戶上下文之上。

這種組合是自動的——你問一個問題，助手會接好它所需的任何技能。

## 每項技能都遵循什麼

- **共享規則**——為使用者 X 執行的技能只能讀取對 X 可見的記錄。
- **欄位級安全**——受限欄位會從技能輸入中隱藏。
- **稽核日誌**——每次技能呼叫，連同輸入和輸出，都會記錄以供審查。
- **確認**——任何 *寫入* 的技能在提交前都需要明確的使用者確認。

## 新增你自己的技能

管理員和開發者可以構建自訂技能——例如：

- 為即將到期的合約 *生成續約推介*。
- *評估客戶健康度*，綜合使用情況、NPS 和工單量。
- 當某個產品達到里程碑時 *撰寫一封發布說明郵件*。

參見 [自訂 › AI 技能](/zh-Hant/docs/customization/ai-skills)，了解如何定義一項新技能、它可以使用哪些知識庫，以及如何測試它。

## 給管理員的提示

- ✅ 在 AI 儀表板中 **監控技能使用情況**——哪些技能使用最多，哪些接受率低。
- ✅ 為表現不佳的技能 **調優知識庫**——大多數準確性問題都是知識問題。
- ✅ **禁用** 不適合你業務的技能——每項技能都可以在管理設定中切換開關。
