# 權限設定檔

**權限設定檔**（在平台術語中即 *權限集*）是指派給使用者的權限集合，它控制使用者在 CRM 中能建立、檢視、編輯和刪除什麼。

權限集是 **明確允許** 的：如果某個物件沒有出現在權限集裡，持有該權限集的使用者就完全無法存取它 —— 管理員也不例外。不存在「其餘物件預設可讀」這樣的隱含規則。

## 六種內建權限設定檔

| 權限設定檔 | 機器名 | 面向 | 典型使用者 |
| --- | --- | --- | --- |
| 👑 **System Administrator** | `system_admin` | CRM 管理員 | IT、營運、實施負責人 |
| 📈 **Sales Manager** | `sales_manager` | 一線銷售管理者 | 區域經理、銷售總監 |
| 💼 **Sales Representative** | `sales_rep` | 銷售代表 | AE、SDR、BDR |
| 🎧 **Service Agent** | `service_agent` | 支援團隊 | 支援專員、成功經理 |
| 📣 **Marketing User** | `marketing_user` | 行銷人員 | 需求生成、活動經理 |
| 🌐 **Guest (Public Forms)** | `guest_portal` | 匿名網站訪客 | 無人 —— 它指派給未登入的表單流量 |

## 每種權限設定檔能做什麼

### 👑 System Administrator

- 對 CRM 中 **每一個** 物件擁有完整的建立/讀取/編輯/刪除權限
- 對每個物件擁有 **檢視所有** 和 **修改所有** —— 繞過記錄層級共用
- 設定系統：物件、欄位、權限設定檔、共用、自動化、AI 技能

⚠️ **謹慎使用** —— 通常每個組織 2–3 人。

### 📈 Sales Manager

- 對 **線索**、**客戶**、**聯絡人**、**商機**、**報價** 和 **任務** 擁有組織範圍的讀寫權限 —— 經理處理任何代表的記錄，而不只是自己的
- 建立和編輯 **合約**、**產品** 和 **行銷活動**（刪除屬於管理員操作）
- 完整掌控 **商機明細和報價明細**，因此可以修正任何代表交易上的定價
- 讀取 **工單**、**知識文章** 和 **行銷活動成員**
- **預測**：讀取每位代表的快照並調整承諾數字 —— 預測本身就是經理的交付物
- 看不到其他使用者標記為 **Private（私有）** 的交易（參見[共用與安全](/zh-Hant/docs/administration/sharing-and-security)）

### 💼 Sales Representative

- 建立、讀取和編輯 **自己的** 線索、客戶、商機、報價和任務
- **聯絡人**：代表能看到的那些客戶底下的聯絡人 —— 自己的客戶，加上區域規則或手動共用送到手上的每一個客戶。Contact 是「由父層控制」，而這份衍生跟隨客戶的共用（參見[共用與安全](/zh-Hant/docs/administration/sharing-and-security)，*「由父層控制」在實務中*）
- **商機明細和報價明細** —— 完整權限，這正是「Products」相關清單和報價編製所需要的。它們同樣是「由父層控制」，因此這份權限達到的是代表能看到的那些交易和報價的明細，別的都到不了
- 讀取 **產品** 目錄、**行銷活動**、**行銷活動成員** 和 **知識文章**
- 讀取 **自己的預測快照** —— 銷售代表自己從不寫入。每晚的預測作業負責開出並刷新它們，而經理或管理員也可以手動錄入一筆；手動錄入的當前季度那一筆，會讓這個每晚的作業對該負責人和週期停手，直到那一筆被刪除（參見[預測](/zh-Hant/docs/sales/forecasting)）
- 讀取自己的 **合約** 和 **工單**；刪除屬於經理權限（自己的任務除外）

### 🎧 Service Agent

- 建立、讀取和編輯自己佇列中的 **工單** 和 **任務**；緊急工單透過升級共用規則到達更廣的服務團隊
- 組織範圍讀取 **客戶**、**聯絡人** 和 **線索** —— 脫離客戶背景的工單毫無意義。也就到讀為止：客服開啟客戶的聯絡人去更正一個電話號碼，只有當這筆聯絡人既歸自己所有、又由自己建立時才存得下去，而隨客戶一起進來的聯絡人從來都不是（見下文《為什麼「組織範圍」說的是讀，不是寫》）
- **知識文章**：讀取所有文章並撰寫、修訂（草稿 → 審閱中 → 已發佈 的生命週期由知識庫流程約束，而非權限）。歸檔屬於管理員操作
- 讀取 **產品** 目錄
- 無權存取商機、報價和預測

### 📣 Marketing User

- **線索**：可以建立、可以讀取組織內的每一筆線索，能編輯的是自己所有且自己建立的那些 —— 組織範圍的讀取並不帶來組織範圍的編輯（見下文）
- **聯絡人**：可以讀取組織內的每一筆聯絡人。建立在實務上會被拒絕 —— 聯絡人是其客戶底下的主從（master-detail）子記錄，插入一筆需要對那個客戶有編輯權，而本權限設定檔在任何地方都不持有客戶編輯權。編輯則與線索一樣，受「自己所有且自己建立」這道門約束
- **行銷活動** 與 **行銷活動成員**：可以建立，並且能編輯*任意*一筆 —— 這兩個物件帶著專為本權限設定檔撰寫的列層級規則，正因如此，行銷人員才能接手同事規劃的活動、更新由加入流程建立的成員。這也正是「Add to Campaign」動作寫入的內容
- 組織範圍讀取 **客戶** 和 **商機**，用於活動→管道 ROI（標記為 **Private** 的交易仍然隱藏）
- 讀取 **知識文章**
- 不能刪除記錄

### 🌐 Guest (Public Forms)

- 透過公開的 Web-to-Lead / Web-to-Case 表單，對 **線索** 和 **工單** **僅可插入**
- **對任何內容都沒有讀取權限。** 其餘每個物件 —— 包括面向公眾受眾的知識文章 —— 均被拒絕

### 為什麼「組織範圍」說的是讀，不是寫

權限設定檔的物件授權說的是使用者**可以**做什麼。一次儲存到底存不存得下去，還要由平台按記錄再判一次 —— 而今天這道門很窄：只有當使用者既是記錄的**擁有者**、又是記錄的**建立者**時，才能更新它。組織範圍讀取（**View All**）不會放寬它：那是一個讀取範圍，從不授予寫入。這也是上面每一條要按物件說明「編輯」夠得到*任意*記錄還是只夠得到自己那些的原因。

例外是一個物件一個物件刻意寫出來的：物件上的**列層級規則**可以把更新放寬給某個權限設定檔的全部持有者。本應用只發佈了兩條，都在 Marketing User 上 —— **行銷活動** 與 **行銷活動成員** —— 因為登記與追蹤成員是圍繞加入流程（而非行銷人員本人）建立的記錄展開的團隊協作。凡是沒有這類規則的地方，無論讀取範圍寫著什麼，「編輯」都只意味著自己所有且自己建立的那些記錄。

## 欄位層級安全

權限設定檔還會遮罩單一欄位。目前隨產品提供的設定：

| 欄位 | 誰可讀 | 誰可編輯 |
| --- | --- | --- |
| `crm_opportunity.amount` / `probability` | 銷售代表、銷售經理、行銷使用者 | 銷售代表、銷售經理 |
| `crm_account.annual_revenue` | 銷售代表 | 銷售經理（對代表唯讀） |
| `crm_account.health_score` | 銷售代表、服務專員、行銷使用者、銷售經理 | 銷售經理 |
| `crm_case.internal_notes` | 服務專員、銷售經理 | 服務專員 |
| `crm_case.is_sla_violated` / `resolution_time_hours` | 服務專員 | 無人 —— 它們是計算得出的 |
| `crm_quote.internal_notes` | 銷售代表、銷售經理 | 銷售代表、銷售經理 |

被遮罩的欄位在任何地方都是空白 —— 清單檢視、報表、API 和 AI Copilot 一樣。銷售代表開啟工單時看不到服務團隊的內部備註。

## 指派權限設定檔

1. 進入 **Setup → Users**（平台未附繁體中文語言包，主控台介面顯示英文，因此本頁的導覽路徑一律以英文標示）。
2. 開啟使用者記錄。
3. 從下拉選單中選擇 **權限設定檔**。
4. 儲存 —— 變更立即生效。

若要在使用者的基礎權限設定檔之上追加權限，請指派額外的 **權限集**（「額外的帽子」），而不要修改基礎權限設定檔 —— 權限集是疊加式的、按聯集合併。

## 複製權限設定檔

如果某個內建權限設定檔 *幾乎* 合適但需要微調：

1. **Setup → Permission Sets** —— 這個畫面叫 *Permission Sets*；Setup 裡沒有 *Profiles* 這個入口。
2. 開啟權限集並點擊 **複製**。
3. 重新命名（例如 *「資深銷售代表」*）。
4. 調整權限。
5. 儲存並指派給使用者。

⚠️ **不要修改內建權限設定檔** —— 複製它們。HotCRM 的更新可能會重設內建權限設定檔的設定。

## 權限設定檔裡有什麼

| 權限領域 | 控制項 |
| --- | --- |
| **物件權限** | 每個物件的建立、讀取、編輯、刪除 |
| **記錄範圍** | 「讀取」能到多廣：僅自己的記錄，還是組織範圍（*檢視所有* / *修改所有*） |
| **欄位層級安全** | 每個欄位的讀取與編輯 |
| **系統權限** | 設定存取、使用者管理、檢視/修改所有資料、共用管理 |
| **列層級規則** | 額外的記錄過濾，例如對組織範圍讀取者隱藏標記為 *Private* 的商機 |

## 權限設定檔 vs 職位 vs 共用 —— 有什麼區別？

- **權限設定檔（權限集）** = *你能做什麼* —— 動詞：建立、編輯、刪除，以及作用在哪些物件上。
- **職位（position）** = *你屬於哪個群體*，用於分發共用授權。職位是 **扁平的**：沒有層級，因此不會自動從經理向總監上捲。
- **共用規則** = *例外* —— 「EU 區域的每個人都能編輯 EU 客戶」「服務總監能看到每個緊急工單」。

兩者都必須允許：權限設定檔決定你 *是否* 能讀商機，共用決定你能讀 *誰的*。

關於職位 + 共用這一面，參見 [共用與安全](/zh-Hant/docs/administration/sharing-and-security)。

## 給管理員的提示

- ✅ **新物件需要授權。** 在某個權限集點名它之前，它對任何人都不可讀 —— 缺失的授權看起來像介面壞了，而不像權限錯誤。
- ✅ **從內建權限設定檔開始** —— 除非必要，否則不要自訂。
- ✅ 拿不準時，**複製** 而非修改。
- ✅ **每季稽核權限設定檔** —— 當人們換職位時，他們的權限設定檔往往沒變。
- ✅ 將 System Administrator 限制在 **最多 2–3 人**。

## 給使用者的提示

如果你無法做某件你認為自己應該能做的事：

1. 檢查你的權限設定檔（右上角 → 你的名字 → 權限設定檔）。
2. 詢問管理員該權限設定檔是否授予了這個物件。
3. 如果權限設定檔正確但缺少某條具體 *記錄*，那是[共用](/zh-Hant/docs/administration/sharing-and-security)問題，而非權限設定檔問題。
