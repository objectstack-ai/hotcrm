# 潛在客戶

**潛在客戶**是一次入站詢問——某人表現出了興趣，但尚未被確認為真正的銷售商機。在你決定值得跟進之前，潛在客戶會與你真正的客戶和聯絡人分開存放。

## 何時該用潛在客戶（而非聯絡人）

| 情境 | 使用…… |
| --- | --- |
| 有人填寫了網頁表單 | 潛在客戶 |
| 展會名單上的一個名字 | 潛在客戶 |
| 你購買了一份行銷名單 | 潛在客戶 |
| 現有客戶的新採購方加入 | 聯絡人（歸在現有客戶之下） |
| 真實客戶處已確認的決策者 | 聯絡人 |

關鍵是把未經審核的雜訊擋在你真正的客戶資料庫之外。

## 5 種潛在客戶狀態

每筆潛在客戶都會經歷這些狀態。銷售代表一次只能推進一步——系統會攔截無效的跳轉。

| 狀態 | 含義 | 你通常接下來做什麼 |
| --- | --- | --- |
| **新建** | 剛到達，還沒人聯絡 | 在 SLA 內進行首次聯絡 |
| **已聯絡** | 銷售代表已透過電話/郵件聯絡 | 套用 BANT 資格審核 |
| **已審核** | 通過 BANT——值得跟進 | **轉換**為客戶、聯絡人和商機 |
| **不合格** | 不匹配（產業不對、沒有預算等） | 如情況變化可稍後重新開啟 |
| **已轉換** | 已成為真正的客戶和聯絡人 | （潛在客戶現已鎖定） |

如果情況發生變化（預算釋放、新專案啟動），你還可以將一筆不合格潛在客戶**重新開啟**回*新建*。

## 每筆潛在客戶記錄儲存的內容

潛在客戶詳情介面有 9 個可摺疊區塊。只展開你需要的：

| 區塊 | 其中內容 |
| --- | --- |
| **身份** | 稱謂、名/姓、全名 |
| **公司資訊** | 公司名稱、職位、產業、年營收、員工人數、網站 |
| **聯絡資訊** | 郵箱、電話、手機 |
| **資格審核** | 狀態、評級（0-5 星）、評分（0-100）、預算、時間線 |
| **指派** | 負責人、下次跟進日期、潛在客戶來源 |
| **地址** | 郵寄地址 |
| **附加資訊** | 描述、標籤 |
| **溝通偏好** | 郵件退訂、請勿致電 |
| **轉換** | 潛在客戶轉換後自動填充 |

可選**產業**包括 Technology、Software/SaaS、Finance、Healthcare、Retail、Manufacturing、Education、Real Estate、Media、Logistics、Hospitality、Energy、Government、Non-profit 和 Other。

可選**潛在客戶來源**包括 Web、Referral、Event、Trade Show、Webinar、Partner、Advertisement、Cold Call 和 Other。

## 潛在客戶評分——評分的含義

每筆潛在客戶都會自動獲得一個 **0 到 100 的評分**，每當潛在客戶被建立或更新時都會重新計算。評分會考慮：

- **公司規模**——公司營收和人數越大 → 評分越高。
- **產業匹配度**——預設情況下 Technology、Finance 和 Healthcare 評分最高。
- **職位資歷**——VP 和 C 級頭銜會加分。
- **互動訊號**——近期網頁造訪、網路研討會出席等。

你還可以設定手動**星級評級（0-5）**作為人工覆蓋：

- ⭐⭐⭐⭐ 或更高 → 系統會將該潛在客戶標記為**熱門**並將下次跟進設為今天。
- ⭐⭐⭐⭐⭐ → 立即向負責人發送郵件。

> 管理員可以調整評分權重——參見 [Administration › Automation](/zh-Hant/docs/administration/automation)。

## 重複的潛在客戶

同一個人再次詢問是正常現象，不是錯誤。老客戶再次填寫網站表單，或者你匯入的展會名單與既有名單有重疊，都會產生**第二筆潛在客戶**——HotCRM 會記錄這層關係，而不是拒絕這筆記錄。

當新記錄的電子郵件在系統中已經存在時，儲存時會帶上：

- **重複狀態 = 疑似重複**——這只是系統的猜測，尚未下任何結論。
- **重複於**——它疑似重複的那筆記錄：如果這個人已經是**聯絡人**，就指向該聯絡人；否則指向使用同一電子郵件、**最早的未結案潛在客戶**。每次重複提交都指向同一筆原始記錄，因此一組重複記錄是一份清單，而不是一條鏈。

在潛在客戶頁籤的**疑似重複線索**視圖裡處理它們。打開這兩筆記錄逐一比對，然後二選一：

- **是老客戶的新詢問**——清空重複狀態，按正常流程推進。預算重新到位的老客戶是真實商機。
- **是同一次詢問重複輸入**——把記錄設為*不合格*，原因選**重複**。此時表單會要求你指明存活的那筆記錄，並把重複狀態設為**已確認重複**。不指明存活記錄就無法以重複為由作廢，所以作廢分析裡的每一筆都能點開。

> 匿名 Web-to-Lead 提交永遠會被接受。公開表單刻意不具備讀取 CRM 資料的權限，如果它無法查詢既有記錄，記錄會以未標記的狀態寫入——請在常規佇列中複核。

## 轉換一筆已審核的潛在客戶

當一筆潛在客戶通過資格審核後，點擊**轉換**。會彈出一個小表單詢問：

- 我們是否也要建立一個商機？
- 如果是——商機名稱和金額是多少？

然後系統會一步完成：

1. 根據潛在客戶的公司資訊建立一個**客戶**——若已有同名客戶，則直接重用。比對時忽略大小寫與多餘空格，因此公司名為 `ACME  Corp` 的潛在客戶會落到你既有的 `Acme Corp` 上，而不是再建一個客戶。這不是模糊比對：`Acme Corp` 與 `Acme Corporation` 仍然是兩家不同的公司。
2. 根據潛在客戶的個人資訊建立一個**聯絡人**，附加到該客戶上，並標記為主要聯絡人。
3. *（可選）* 在*開發期*階段建立一個**商機**，成交日期設為 90 天後。
4. 將潛在客戶標記為**已轉換**並鎖定它。
5. 向你發送一封確認郵件，總結所建立的內容。

轉換後，潛在客戶變為唯讀——所有後續活動都發生在新的客戶、聯絡人和商機上。

## AI Copilot 如何提供協助

當你打開一筆潛在客戶時，Sales Copilot 會出現在側邊面板。試著提問：

- *"Qualify this lead"*——執行 BANT，給你一個評分以及每個維度的一行理由。
- *"Is this a hot lead?"*——快速是/否加上推理。
- *"Draft an intro email"*——撰寫一封個人化的首次外聯郵件。

Copilot 會推薦下一步行動（例如，安排通話、發送跟進、取消資格）。

## 標準列表視圖

潛在客戶列表沒有裁剪過的頁籤，所以切換器裡列出的就是全部已儲存視圖——一共八個，順序如下。視圖名依產品介面中的中文名稱寫成，所以用的是「線索」，指的就是本頁行文中的「潛在客戶」：

| 視圖 | 展示什麼 |
| --- | --- |
| **全部線索**（預設打開） | 所有線索，最新的在前；姓名是進入記錄的連結，同列還有公司、郵箱、狀態、評分、來源和負責人。每頁 25 列，可匯出 CSV / XLSX，勾選後可批次**加入行銷活動**。組織裡還沒有線索時它會直說——*還沒有線索 · 建立第一條線索，從這裡開始*。 |
| **我的線索** | 你負責的線索，評分高的在前，同評分內最新的在前。側邊欄的**我的工作 › 我的線索**進的也是它。 |
| **🔥 高熱度線索** | 仍處於**新建**或**已聯絡**、且評分高過 4.5 星的線索。評分只按整星記（打分鉤子四捨五入到整星，星級控件也只讓你點整星），所以實際上這就是**五星**佇列；四星的線索沒有丟，它在**高優先級**裡。按**下次跟進日期**由近及遠排序，列上帶電話和郵箱，從上往下打就行。 |
| **高優先級** | 更寬的一刀：**四星及以上**，同樣只看新建和已聯絡。列按評分著色——五星綠色，四星橙色。 |
| **疑似重複線索** | 上文說的複核佇列：**重複狀態**為*疑似重複*的線索，最早被懷疑的排在最前，重複關聯欄位就在列上。處理一條少一條——確認或清除之後它就掉出佇列。沒有待複核的時候它會寫明：*沒有疑似重複 · 無需複核——每個重複錄入的郵箱都已檢查過。* |
| **線索流水線** | 看板視圖，一個狀態一欄，每欄彙總**年營收**。點開卡片是從側邊滑出的抽屜，不會把你帶離看板。 |
| **線索日曆** | 線索按進入系統的日期落在月曆上，標題是公司名，按狀態著色——看的是流入的形狀。 |
| **線索卡片** | 卡片牆，一條線索一張卡，以公司名為標題，卡面上是姓名、郵箱、電話、狀態和評分。 |

## 給銷售代表的提示

- ✅ 讓**下次跟進日期**保持真實——**🔥 高熱度線索**就是按它排序的，日期放著不更新，會把一條活著的線索壓到佇列底部。新線索會自動拿到一個（四星及以上是明天，其餘是三天後），**安排跟進**動作則會用你剛建的那個任務的到期日重新蓋章。
- ✅ 如果你有強烈的直覺判斷，就使用星級評級——評分並不能捕捉一切。
- ✅ 不要過早轉換——已轉換的潛在客戶無法還原。在確認期間使用*已審核*狀態。
- ❌ 不要永遠把雜訊留在*新建*中——3 次聯絡失敗後就取消其資格。

## 給管理員的提示

- 評分公式位於潛在客戶的自動化中。要重新設定權重，請編輯 `src/objects/lead.hook.ts`（綁定到 `crm_lead`）。參見 [Customization](/zh-Hant/docs/customization/extending-objects)。
- 透過授予訪客入口網站設定檔對潛在客戶物件的*僅插入*權限，可以啟用 Web-to-Lead——參見 [Administration › Profiles](/zh-Hant/docs/administration/profiles)。
- 要新增的產業或潛在客戶來源，請編輯潛在客戶物件的選擇列表——參見 [Customization](/zh-Hant/docs/customization/extending-objects)。
