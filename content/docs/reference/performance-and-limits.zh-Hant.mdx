# 效能與限制

以下限制為**預設企業版方案**。其他方案有所不同；自託管沒有平台施加的上限，但瓶頸會轉移到你的基礎設施上。

## 資料量

| 項目 | 限制 | 備註 |
| --- | --- | --- |
| 每個物件的記錄數 | **1 億** | 實際值；透過歸檔可以更高 |
| 自訂物件 | 每個租戶 **1,000** 個 | |
| 每個物件的自訂欄位 | **800** | 標準 + 自訂合計 |
| 每個欄位的選擇清單值 | **2,000** | |
| 每個物件的關係 | **40** 個 lookup / **2** 個 master-detail | |
| 每個物件的驗證規則 | **500** | |
| 每個物件的工作流規則 | **500** | |
| 每個物件的流程 | 無限制 | 每個流程都有自己的複雜度限制 |
| 每個物件的頁面版面 | **200** | |
| 每個物件的記錄類型 | **200** | |

## 檔案儲存

| 項目 | 限制 |
| --- | --- |
| 單檔案上傳 | **2 GB** |
| 每筆記錄的附件 | 無限制 |
| 總檔案儲存 | 按方案（通常為每個租戶 TB 級） |
| 圖片預覽格式 | jpg、png、gif、webp、svg |
| 文件預覽格式 | pdf、docx、xlsx、pptx |

超過 100 MB 的檔案透過分段上傳；平台負責分塊處理。

## API 限制

| 限制 | 預設值 |
| --- | --- |
| 每分鐘請求數（每使用者） | **6,000** |
| 每分鐘請求數（每租戶） | **60,000** |
| 並行連線數（每使用者） | **25** |
| 請求體大小 | **20 MB** |
| 回應大小（單筆記錄） | **10 MB** |
| 每次查詢的最大記錄數 | **2,000**（更多請使用游標分頁） |

速率限制回應使用 HTTP **429** 及 `Retry-After` 標頭。請始終實作指數退避。

## 如何保持在限制範圍內

### 分頁

當擷取 >2,000 筆記錄時：

```http
GET /api/v1/opportunities?limit=200&cursor=eyJpZCI6...
```

請始終分頁；切勿一次性載入所有記錄。

### 退避

當你遇到 429 時：

```js
async function callApi(fn, retries = 5) {
  try { return await fn(); }
  catch (e) {
    if (e.status === 429 && retries > 0) {
      await sleep(Math.min(60000, 1000 * Math.pow(2, 5 - retries)));
      return callApi(fn, retries - 1);
    }
    throw e;
  }
}
```

或使用自動處理退避的平台 SDK。

### 批量操作

對於 >100 筆記錄，使用**批量 API**而非 100 次單獨呼叫。

### AI 呼叫批次處理

在分流大量記錄時，使用**批量技能**呼叫 —— 它在底層進行批次處理並計為 N 次呼叫（因此仍遵守每使用者配額），但使用連線池實現約 10× 的加速。

### 欄位索引

對於你頻繁查詢的自訂欄位，將其標記為**索引** —— 加快清單篩選和報表執行。

### 歸檔舊資料

超出你營運視窗的記錄（例如，關閉超過 2 年的案例）可以被**歸檔**：

- 從熱儲存中移除；仍可透過**歸檔 API** 查詢。
- 釋放索引並提升效能。
- 可按物件設定自動歸檔策略。

## 監控你的使用情況

每個租戶在 **Setup → Usage** 處都有一個**使用情況儀表板**：

- 按使用者劃分的每分鐘 / 每天 / 每月 API 呼叫。
- 按技能劃分的 AI 技能呼叫。
- 儲存增長。
- 按記錄建立 / API 消耗排名的頂級使用者。
- 異常告警。

企業版租戶可與客戶團隊進行季度**使用情況評審**。

## 當你超出這些限制時

- **縱向** —— Enterprise+ 方案擴展大多數配額。
- **分片** —— 用於 >10 億筆記錄的多區域部署。
- **自託管** —— 消除平台上限；瓶頸變為基礎設施。

請聯絡你的客戶團隊或在 [GitHub](https://github.com/objectstack-ai/hotcrm/issues) 上提交問題。
