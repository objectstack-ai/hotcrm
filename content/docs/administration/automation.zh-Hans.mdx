# 自动化

自动化让 HotCRM *为你完成工作* —— 发送通知、更新字段、创建任务、升级案例，全程无需任何人点击按钮。提供五种自动化，每一种都适用于不同的工作。

> **HotCRM 如何实现它们：** 验证与字段逻辑以 **对象钩子**（`beforeInsert` / `beforeUpdate`）运行；所有多步骤、定时或审批类逻辑以 **流程** 运行；审批则是 **流程中的 `approval` 节点**（ADR-0019），而非独立的审批流程类型。平台同样支持独立的工作流规则与审批流程元数据 —— 下文一并列出以供参考。

## 五种类型

| 类型 | 触发时机 | 最适合 |
| --- | --- | --- |
| **验证规则** | 保存前 | 拦截不良数据 |
| **工作流规则** | 保存后 | 字段更新、简单的电子邮件提醒 |
| **流程** | 屏幕、记录变更或按计划 | 多步骤逻辑、分支、循环、等待、审批 |
| **计划作业** | 按计划 | 每日清扫、每周报表 |
| **审批流程** | 流程中（approval 节点） | 带记录锁定的多步骤签核 |

## 验证规则

最简单的类型。当某个条件为真时，它们会阻止保存。

**内置示例**：

- *“结束日期必须晚于开始日期”*（用于合同）。
- *“标价必须大于零”*（用于产品）。
- *“活动成员必须有一个潜在客户或一个联系人，但不能两者都有”*（用于活动成员）。
- *“折扣百分比必须介于 0 和 100 之间”*（用于报价行项目）。

要添加一条：

1. **设置 → 对象 → 验证规则 → 新建**。
2. 编写条件（*失败* 条件）。
3. 编写向用户显示的错误信息。
4. 激活。

## 工作流规则

当记录在保存后匹配某个条件时触发。每条规则可以执行一项或多项 **操作**。

**操作类型**：

- **字段更新** —— 更改同一条记录或父记录上的字段。
- **电子邮件提醒** —— 向特定收件人发送模板化邮件。
- **创建任务** —— 为记录所有者或其他用户创建。
- **出站消息** —— 触发一个 webhook。

**内置示例**：

- *评级为 Hot 的潜在客户创建* → 向销售经理发邮件 + 创建一个 *“24 小时内确认资格”* 任务。
- *商机赢单，金额 ≥ $100K* → 向团队发送庆祝邮件，在 #wins 频道发帖。
- *案例优先级变更为 Critical* → 通知值班工程师。

## 流程（多步骤）

当单纯的字段更新不够用时 —— 分支、循环、等待、跨对象写入、审批 —— 使用 **流程**。流程是一张可视化的节点图：获取数据 → 判断 → 创建/更新记录 → 通知 → 等待 → 调用子流程。

流程有三种触发方式，由起始节点决定：

- **屏幕（Screen）** —— 从按钮/操作手动启动，在屏幕上收集输入。
- **记录变更（Record change）** —— 在记录插入/更新时触发（`record-after-create` / `record-after-update`）。
- **计划（Schedule）** —— 按 cron 计划运行。

> **自动触发需要 `triggers` 能力。** 记录变更与计划类流程，只有当 stack 的 `requires` 列表包含 `triggers` 时才会触发 —— 它会安装记录变更与计划触发器提供方（计划触发器还依赖 job 服务）。屏幕类流程始终为手动启动。

**HotCRM 中的内置流程**（10 个）：

| 流程 | 触发 | 它做什么 |
| --- | --- | --- |
| **潜在客户转换** | 屏幕 | 将合格潜在客户转换为客户 + 联系人（+ 可选商机），然后通知 |
| **报价生成** | 屏幕 | 从商机生成报价，并将其推进到 *Proposal* |
| **潜在客户分配与路由** | 记录变更（插入） | 按评级写入跟进 SLA，并将新线索路由到销售经理队列 |
| **商机审批** | 记录变更 | 通过 approval 节点分级签核 —— 销售经理 > $100K，销售总监 > $500K |
| **案例升级** | 记录变更 | 当案例变为 *Critical* 时，重新分配给资深客服、通知、创建跟进任务 |
| **案例满意度回访** | 记录变更 + 等待 | 案例关闭后等待 1 天，再提醒负责人收集满意度评分 |
| **活动登记** | 计划（周一 9 点） | 批量将匹配的潜在客户登记进活动 |
| **合同续约提醒** | 计划（每日 8 点） | 为临近 `end_date` 的合同开出续约任务/商机 |
| **案例 SLA 监控** | 计划（每小时） | 标记并升级超过 SLA 到期时间的未结案例 |
| **停滞商机提醒** | 计划（每日 7:30） | 提醒负责人关注在某阶段停留过久的未结商机 |

流程内的通知由 **`notify` 节点** 投递（通过消息服务发送站内信 + 邮件）—— 而非旧的 `script`/邮件步骤（在 7.4 中已是空操作）。

如果你需要构建新的流程，请参见 [自定义 › 扩展对象](/zh-Hans/docs/customization/extending-objects)。

## 计划类自动化

基于时间的自动化以 **计划类流程** 实现 —— 即起始节点带 cron 计划的流程，见上表中四个 `计划` 行（活动登记、合同续约、SLA 监控、停滞商机提醒）。它们通过 job 服务运行，因此 `triggers` 能力需与 `job` 搭配（两者都在默认能力集中）。

无需编排的日期驱动字段逻辑 —— 例如为报价设置默认过期日、冻结已过期/已接受的报价、推导预测周期 —— 放在轻量的 **对象钩子**（`beforeInsert` / `beforeUpdate`）中，而非计划清扫。

## 审批

自 ObjectStack 7.4 起，审批被建模为 **流程中的 `approval` 节点**（ADR-0019），而非独立的审批流程类型。进入节点时会创建审批请求、在该步骤待批期间 **锁定记录**、将实时状态镜像到 `approval_status` 字段，并沿 *approve* / *reject* 分支继续。

HotCRM 内置的 **商机审批** 流程串联两个 approval 节点实现分级签核（经理 → 总监）。关于阈值、审批人所见以及审计轨迹，参见 [收入 › 审批](/zh-Hans/docs/revenue/approvals)。

## 操作顺序

当一条记录被保存时，顺序是固定的：

1. **系统** 运行自动计算（公式字段、自动编号）。
2. **验证规则** 运行 —— 如果有任何失败，保存被阻止。
3. **记录被保存** 到数据库。
4. **工作流规则** 触发。
5. **流程触发器** 触发。
6. 来自工作流 / 流程的 **字段更新** 可能级联 —— 重新评估工作流最多 5 次后停止。
7. **电子邮件提醒** 进入队列。

理解这个顺序有助于调试 *“为什么我的工作流没有触发？”* 这类问题。

## 电子邮件模板

大多数自动化操作会发送电子邮件。模板位于 **设置 → 电子邮件模板**，并支持：

- **合并字段** —— `{{Opportunity.Name}}`、`{{Account.Owner.Email}}`。
- **条件块** —— 仅在条件为真时显示。
- **HTML + 纯文本** 版本。
- **附件** —— 报价 PDF、合同 PDF。

内置模板涵盖潜在客户路由、商机赢单、案例确认、合同激活、续约提醒。

## 在哪里监控自动化

- **设置 → 流程监控器** —— 过去 24 小时的自动化运行及其成功/失败。
- **设置 → 工作流队列** —— 待处理的电子邮件提醒和字段更新。
- **设置 → 计划作业 → 历史** —— 每个计划作业的过往运行。
- **对象 → 审计日志** —— 记录上发生了什么变化，谁/什么进行了变更。

## 给管理员的提示

- ✅ **验证规则** 是强制数据质量最廉价的方式 —— 放开手用。
- ✅ **每个条件一个工作流** 比有 10 个分支的超级工作流更易于维护。
- ✅ 对于任何超过 2 个操作的复杂逻辑，**使用流程** —— 调试起来容易得多。
- ✅ 在生产中激活前 **在沙箱中测试** —— 糟糕的自动化会快速级联。
- ✅ 在描述字段中 **记录每条规则的作用** —— 未来的你会感谢现在的你。

## 给用户的提示

如果一条记录的行为不符合预期：

1. 检查 **审计日志** —— 该字段是被工作流更新的吗？
2. 检查 **任务列表** —— 工作流是否自动创建了一个你错过的任务？
3. 请管理员检查该记录的 **流程监控器**。
