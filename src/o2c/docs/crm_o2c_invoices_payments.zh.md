# 发票与回款——由谁录入，什么算逾期

写给销售，也写给财务（**应收会计**岗位）。发票和回款是财务在自己系统中开具和收到的记录。财务录入或导入它们；销售只查看、从不录入，所以销售看到的每个数字都是财务写的。

发票和回款属于**客户**。订单和合同都可填可不填：针对一张订单的发票填这张订单；一张发票对应多个订单，或暂时对应不上任何发票的预收款，只需填客户。

应收会计岗位在所有客户上录入和导入它们。这个岗位能查看所有客户，但不能编辑任何客户：能查看客户，就足以写入它的发票和回款。

## 界面上看不出的规则

- **客户、订单与合同。** 选择订单或合同会带出它的客户。在回款上，选择发票或回款计划也会带出它的客户；回款没填合同时，发票还会带出它的合同。保存时填了或改了回款的发票、而这张发票计入某个回款计划时，回款取这个节点，替换回款上填的节点：节点的**已收**统计的是指向它的回款，付了这张发票的回款必须计入发票所在的节点。只有发票没有节点，或回款没填发票（预收款）时，回款才保留自己的节点。选择另一个客户的订单或合同会被拒绝，并写明是哪一个。归在合同下的订单会带出它的合同：填了另一份合同会被拒绝，订单和合同属于不同客户也会被拒绝。发票只填了回款计划、没填订单或合同，或回款只填了发票或回款计划、都没填时，会从它带出订单和合同，这样订单和合同上的汇总与节点、发票统计的是同一批记录。
- **订单的合同带到它的发票和回款上。** 订单在发票和回款保存之后才有了合同（点了**起草合同**，或选了订单的**关联合同**），其中没填合同的会带上这份合同，合同的汇总随即把它们算进去。把订单改到另一份合同下时，原来跟着旧合同的发票和回款一起改到新合同；清空订单的合同时，它们的合同也一起清空，订单下一次有了合同再把它们补上。填了其他合同的保持不变。不管是谁改的订单都会这样：销售改订单会连带改掉财务的发票和回款上的**合同**，此外什么都不改。每条记录的历史里都能看到这次修改。
- **发票的回款计划必须属于它的客户。** 在发票上选择回款计划会带出它的客户。发票表单会列出所有客户的回款计划；选了另一个客户的，保存会被拒绝。提示写明是哪个节点；发票上还留着节点带出的订单或合同时，写明的是那个订单或合同。
- **到期日。** 留空时，保存时自动填写：**开票日期**加上合同的**付款条款**；没有合同或合同没填付款条款时，取订单的**付款条款**（Net 15、30、60 或 90 天；Due on Receipt 即开票当天）。财务填写的日期会保留。两者都没有的发票没有付款条款可用，请手工填写到期日。
- 发票的**未付**是**金额**减去**已付**，最低为零，每当针对它的回款保存时随之更新。**已作废**的发票未付为零，并退出所有统计。
- **多付。** 超过未付金额的回款照样接受，无论是手工录入还是导入。发票按已付清处理（**未付**为零），超出的部分显示在**多付**里。它不会冲抵其他发票，任何**应收余额**也不会因此变成负数。
- **逾期。** 「订单与回款」应用的**跟进 → 逾期发票**列出状态为**已开具**、**到期日**早于今天且仍有**未付**金额的发票。
- **每张发票一笔回款。** 一笔收款支付多张发票时，每张发票记录一笔回款；没有分摊。
- **回款的发票和回款计划必须属于它的客户。** 回款表单会列出所有客户的发票和回款计划；选了另一个客户的，保存会被拒绝，并写明是哪一个。发票属于回款的客户、但它的节点属于另一个客户时，按发票拒绝（节点是发票带出的）：请更正这张发票的回款计划，或选择另一张发票。

## 导入

财务使用 **Invoice Import (CSV)** 和 **Payment Import (CSV)** 导入。**ERP 编号**列是唯一键：编号已在某条记录上的行会更新这条记录，而不是新增一条。每条导入的记录**来源**为**导入**，并带有**同步时间**（导入的时刻）。客户用客户名称指定，订单用订单编号（SO-0001）或它的**外部编号**，合同用合同编号（CTR-0001），发票用发票号码，回款计划用节点名称。每行需要客户、订单或合同：订单或合同（回款还可以是发票）能带出客户时，**Account** 列可以留空。

**多份合同上有同名节点时，该行导入失败**（「匹配到多条记录」）：导入会在所有合同里查找这个名称。这时在该列填写节点的记录 ID，即节点页面地址的末尾。多个客户同名时，同样会失败。
