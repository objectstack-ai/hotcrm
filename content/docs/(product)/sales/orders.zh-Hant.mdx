# 訂單

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**訂單**記錄客戶這一次買了什麼：哪些產品或服務、多少、什麼價格。它是一筆交易最終落地的記錄。**合同**記錄雙方約定了什麼，是可選的：訂單可以掛在一份框架合同下，但大多數訂單沒有合同。

| | 訂單 | 合同 |
| --- | --- | --- |
| 記錄 | 這一次買了什麼 | 雙方約定了什麼 |
| 明細 | 有；小計是各訂單行之和 | 沒有明細 |
| 日期 | 下單日期、發貨日期 | 開始、結束、期限、續約 |
| 適用 | 一次銷售 | 訂閱、項目服務、框架協議、保密協議 |

一張訂單最多屬於一份合同；一份合同可以有多張訂單，也可以沒有。

這份合同必須屬於訂單自己的所屬客戶。訂單表單的 **關聯合同** 只列出該客戶的合同，更換所屬客戶時會清空 **關聯合同**。如果某次儲存仍然指定了另一個客戶的合同（例如透過 API），儲存會被拒絕，提示顯示在 **關聯合同** 上：請選擇該客戶的合同，或清空 **關聯合同**。在這條規則生效前已經儲存了其他客戶合同的訂單，下次編輯時也會被拒絕，直到改正它的關聯合同或所屬客戶。

## 在哪裡找到訂單

- 銷售應用 **銷售** 分組中的 **訂單**。
- 客戶頁面上的 **訂單** 列表，以及訂單所掛合同的頁面上的 **訂單** 列表。
- 訂單與回款應用中的 **訂單、合同與客戶**，財務在這裡查看訂單。

訂單只展示給使用報價單的人：銷售代表、銷售經理、銷售管理層和管理員，以及唯讀查看的財務（應收會計和財務總監）。服務和行銷人員看不到訂單。

## 接受報價時自動建立訂單

報價被**接受**時，它的訂單會自動出現：一張**草稿**訂單，帶著報價的名稱、所屬客戶、聯絡人、關聯商機和負責人，它的折扣、稅額、運費和付款條款，地址和描述，以及逐行複製的全部報價明細。合計與報價相同。訂單的**來源報價單**指向這份報價，訂單也會列在報價的頁面上。每份被接受的報價只有一張訂單，不論它的狀態被儲存了多少次。

除此之外不會建立任何東西：接受報價不再起草合同。如果這次銷售需要合同，從訂單起草（見下文）。

**來源報價單**由系統填寫，不能手動修改。它隨「報價與產品」模組一起提供：管理員關閉該模組後，報價以及這個欄位都不存在，訂單只能手動錄入。

## 從訂單起草合同

訂閱或項目通常需要合同，產品銷售通常不需要。在訂單頁面點擊**起草合同**即可起草：一份*草稿*合同，合同類型為*訂閱合同*，期限 12 個月、從今天起算，金額為訂單的總金額，名稱與訂單相同（從報價產生的訂單沿用報價的名稱），帶著訂單的所屬客戶、聯絡人、關聯商機、負責人和付款條款。這就是以往接受報價時產生的那份起始草稿；打開它補全期限、日期和類型。隨後訂單的**關聯合同**會指向這份合同，你也會收到一條帶連結的**合同已起草**通知。

- 只有當訂單還沒有關聯合同時才會提供**起草合同**。掛在現有框架合同下的訂單，其**關聯合同**已經指向那份合同，不會再提供第二份。
- **已取消**的訂單不提供**起草合同**，也不會為它起草任何東西。
- 訂單需要填寫**聯絡人**：合同必須有主要聯絡人。沒有聯絡人時不會起草任何東西，系統會提示你先填寫聯絡人。
- 銷售代表也可以執行它，儘管銷售代表不能親手新建合同：草稿由系統寫入。

## 本版本之前：每份被接受的報價都會起草合同

在本版本之前，接受報價會起草一份合同，但不會建立訂單。現在接受報價會建立訂單，需要合同時再從訂單起草。這兩項自動化都是管理員可以開關的流程，位於 Studio（控制台首頁的 **New in Studio** → **HotCRM Revenue** → **Customize** → **Automations**；步驟見[系統管理 › 自動化](/zh-Hant/docs/administration/automation#switching-a-packaged-flow)）：

| 流程 | 出廠狀態 | 作用 |
| --- | --- | --- |
| **已接受的報價單創建訂單** | 開啟 | 建立上文所述的草稿訂單 |
| **已接受的報價單起草合同** | 關閉 | 像本版本之前一樣，為每份被接受的報價起草合同 |

如果要保留原來的行為，開啟**已接受的報價單起草合同**。此後每份被接受的報價都會像以前一樣起草合同，報價的訂單也會指向這份合同。如果完全不需要訂單，再關閉**已接受的報價單創建訂單**。這項選擇在重啟和升級後都會保留。見[系統管理 › 自動化](/zh-Hant/docs/administration/automation#switching-a-packaged-flow)。

## 訂單狀態

| 狀態 | 含義 |
| --- | --- |
| ⚪ **草稿** | 正在整理 *（新訂單的預設狀態）* |
| 🔵 **已確認** | 已與客戶確認；訂單行和金額被鎖定 |
| 🟢 **已完成** | 已交付完畢 |
| ⚫ **已取消** | 不再執行 |

訂單按 **草稿 → 已確認 → 已完成** 推進。**已確認** 可以退回 **草稿**，**草稿** 或 **已確認** 可以改為 **已取消**。**已完成** 和 **已取消** 是最終狀態；其他任何狀態變更都會被拒絕，並提示允許的變更。

用訂單頁面上的按鈕推進訂單（訂單列表每一列的選單裡也有）：*草稿*訂單點擊 **Confirm Order**，*已確認*的訂單點擊 **Complete Order**，兩者都可以點擊 **Cancel Order**。只會提供訂單從目前狀態能做的變更。每個按鈕都會先詢問，並說明這次變更的後果：確認會鎖定訂單行，完成或取消是最終的。如果點擊時這次變更已不再允許（例如有人剛剛取消了這張訂單），它會被拒絕並顯示那條提示，訂單不會有任何變化。

目前仍可以在訂單表單上修改 **狀態**，同樣只能沿上面的路線變更。*已確認*的訂單就是這樣退回*草稿*的：這一步沒有按鈕。

## 訂單記錄儲存的內容

| 分組 | 欄位 |
| --- | --- |
| **訂單資訊** | 訂單編號、訂單名稱、訂單負責人、所屬客戶、聯絡人、關聯商機、狀態、下單日期、關聯合同、客戶採購單號、描述 |
| **價格** | 小計、折扣 (%)、折扣金額、稅額、運費及手續費、總金額、付款條款 |
| **發貨** | 發貨狀態、發貨日期 |
| **地址** | 帳單地址、收貨地址 |
| **系統** | 外部編號 |

**客戶採購單號** 是客戶自己採購單上的編號。**外部編號** 是這張訂單在其他系統（例如它來自的訂單系統）中的編號；兩張訂單不能使用同一個外部編號。

## 訂單行

每一行包括產品、產品標題、描述、數量、標價、銷售單價、行折扣，以及這一行的小計和總計，與報價單明細相同。

- **選擇產品**：這一行以產品名稱作為標題、帶出產品的標價，銷售單價預設等於標價，可以改成別的價格。
- **沒有產品？** 填寫這一行的 **產品標題** 和 **銷售單價**。目錄裡沒有的東西就這樣錄入；報價與產品模組關閉時（其產品選擇器為空），訂單行也這樣錄入。
- 訂單行的標價取自產品本身，而不是價格表。

## 合計如何計算

```
小計       = Σ 訂單行（數量 × 銷售單價 × (1 − 行折扣 %)）
折扣金額   = 小計 × 訂單折扣 %
總金額     = 小計 − 折扣金額 + 稅額 + 運費及手續費
```

每次新增、修改或刪除訂單行，小計都會重新計算；小計、折扣、稅額或運費任一變化時，折扣金額和總金額隨之更新。有訂單行的訂單不能手動填寫小計：儲存時如果把它改成不等於各訂單行之和的數，會被拒絕，請改為修改訂單行。沒有訂單行的訂單保留你填寫的小計。

## 已確認訂單的訂單行和金額被鎖定 [#a-confirmed-orders-lines-and-amount-are-locked]

訂單離開 **草稿** 後，訂單行不能再新增、修改或刪除，**訂單行** 列表上也不再顯示 **新建**。它的 **小計**、**折扣 (%)**、**稅額** 和 **運費及手續費** 也不能再修改，因此 **總金額** 保持確認時的數：訂單合同、收款計畫和框架合同的額度都讀取它。要修改已確認訂單的訂單行或金額，請先在表單上把 **狀態** 改回 **草稿** 並儲存，改完後再點擊 **Confirm Order**；之後合同和收款計畫會像訂單在草稿時的任何修改一樣跟隨新的總金額。退回草稿期間，訂單不計入框架合同的訂單金額。已完成或已取消訂單的訂單行和金額保持不變：差額請另開一張新訂單。訂單的其他欄位（例如發貨欄位）仍可編輯。導入和系統自身的更新不受這條規則限制。

## 發貨

**發貨狀態**（*未發貨*、*部分發貨*、*已發貨*）和 **發貨日期** 表示訂單發貨到了哪一步。它們由人手動填寫或由匯入填寫；HotCRM 中沒有別的功能會改動它們，背後也沒有庫存或發貨單。
