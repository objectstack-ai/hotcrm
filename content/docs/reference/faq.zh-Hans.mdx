# 常见问题

## 🔒 访问与可见性

### 为什么我看不到一条我确定存在的记录？

最有可能是某条[共享规则](/zh-Hans/docs/administration/sharing-and-security)没有授予你访问权限。按以下顺序检查：

1. 你是**所有者**吗？如果不是……
2. 这条记录是否**从你能看到的父记录派生**（你客户下的联系人、你报价上的行项）？如果不是……
3. 是否有**共享规则**同时匹配该记录和你的某个**岗位**（例如，地区、层级）？如果不是……
4. 这条记录是否被**手工共享**给了你？如果不是……
5. 你的简档是否拥有 **View All**？如果不是……

→ 你将看不到它。请所有者把记录共享给你，或请管理员扩展共享规则。

注意：共享一个**客户**只会带上它的联系人；该客户下的报价、合同、任务、工单和商机仍归各自的所有人。

### 为什么某个字段是灰色 / 只读的？

三种可能：

- **字段级安全**限制了你简档的编辑权限 → 请管理员处理。
- 该记录**在审批流程中被锁定** → 等待或撤回。
- 某条**验证规则**阻止了更改 → 查找内联错误消息。

### 我在另一个租户中拥有管理员权限 —— 为什么这里没有？

简档和权限是**按租户**划分的。你需要管理员在此租户中授予你*系统管理员*简档。

### 为什么 AI Copilot 说"我找不到那条记录"？

Copilot 遵守你的共享设置 —— 如果你看不到它，它也看不到。请确认记录存在并检查共享设置。

## 📈 记录与数据

### 我创建了一条线索，但它被分配给了别人 —— 为什么？

是自动分配跑了。**不存在“Setup → Lead Settings”这个屏幕，也没有任何分配规则可查** —— 一条到达时没有所有者的线索，会在插入时交给持有 `sales_rep` 岗位的人中未结线索最少的那一位（`src/objects/lead.hook.ts`）。它做的是负载均衡，不匹配地区或区域。所以你看到的所有者是负载最轻的销售代表，而不是离得最近的那一位。

### 我的商机无法移动到 Closed Won。

三个阻碍因素，按顺序：

1. **必填字段**缺失（Close Date、Amount、Won Reason）。
2. **需要审批** —— 金额 > $500K 会触发[折扣审批](/zh-Hans/docs/revenue/approvals)；必须先获得批准。
3. **验证规则** —— 例如，*"必须有一个主要联系人角色"*。

### 为什么我的商机跳回到了上一个阶段？

很可能是审批被拒绝了。检查商机上的**审批历史**部分。

### 删除的记录去了哪里？

哪里也没去 —— **删除是立即且永久的。** 没有回收站可供恢复，设置里也没有对应入口：平台根本没有软删除运行时。`@objectstack/spec` 已经把当年承诺回收站的那个开关退役，并把理由写得很直白 —— *“每一次删除从来都是硬删除，一个默认为真、承诺回收站的开关是一种虚假的能力暗示”*。请把每一次删除都当作不可逆。**Setup → Audit Logs** 里的审计日志会记录谁在何时删了什么；但它无法把记录找回来。

### 我的导入显示"导入 0 行" —— 为什么？

常见原因：

- **External ID** 列未设为匹配键，但冲突模式为*仅更新*。
- CSV 中的**选择列表值**与定义的值不匹配。
- **必填字段**缺失。
- **所有者邮箱**与任何用户都不匹配。

试运行报告会告诉你哪一行失败以及原因。请始终先试运行。

## ⚙️ 自动化

### 我的流程没有触发 —— 为什么？

按顺序检查：

1. 该流程是否**已激活**？
2. 在保存时记录是否真的**符合起始条件**？
3. 是否有**验证规则**在流程触发前阻止了保存？
4. 是否有**先前的流程**更改了记录，导致条件不再匹配？
5. 这条流程是否在**上一次运行尚未结束时又因同一条记录被重入**？引擎的重入守卫会跳过这次运行并记一条警告日志。没有可对照的重新评估次数 —— 守卫是兜底，不是停止条件。参见[管理 › 自动化](/zh-Hans/docs/administration/automation)。

**Studio → Developer → Flow Runs**（中文界面：开发者 → 流程运行记录）显示某条流程最近的运行及其状态 —— 先选中你预期应当触发的那条流程。

### 我的 SLA 计时器没有运行。

本应用里没有任何东西在倒计时 —— 不存在可以盯着看的实时 SLA 计时器。真实存在的是：给每一张工单打上的一个截止时间，加上一个每小时跑一次、事后标记违约的扫描。检查：

- 工单处于**打开状态**（不是 Resolved / Closed）—— 每小时的 `case_sla_monitor` 扫描按 `status: { $nin: ['resolved', 'closed'] }` 过滤，所以已解决的工单永远不会被捞进来。
- 工单**根本有没有 SLA 截止时间**。现在每个优先级都会被自动打上，取自 `src/objects/case.hook.ts` 里的一张优先级 × 客户层级矩阵 —— 但矩阵里没有对应行的优先级仍然会留空，而截止时间为空的工单永远进不了扫描的候选集，所以无论它开着多久，**SLA Violated** 都保持 `false`。（手工填一个截止时间是有效的 —— 之后扫描会像对待其他工单一样对待它。）
- 那个截止时间**已经过去**，并且此后已经跑过一次扫描。扫描每小时一次，且只标记已经超期的工单，所以一个超期但在下一次扫描之前就被解决的工单，根本不会被标记。

**没有营业时间设置可查** —— 本应用里没有工作日日历，没有节假日清单，也不存在“设置 → 营业时间”这个屏幕。矩阵里的每一个数字都是挂钟小时，夜间、周末与节假日一律照算。**同样不存在“SLA 定义”这个界面**：矩阵写死在钩子里而不是配出来的，你在界面上能设的只有账户的**客户层级**，它决定走哪一列。参见 [SLA 与升级](/zh-Hans/docs/service/sla-and-escalation)。

### 自动编号跳号了（例如，从 #1234 跳到 #1267）。

正常现象。为提升性能，序列会成批预留编号；当记录被删除、保存尝试后验证失败或批次被放弃时会出现间隙。该序列是**单调递增**的，而非连续的。

## 🤖 AI Copilot

### Copilot 的回答错误 / 过时。

三个原因：

- **知识陈旧** —— 没有索引可以刷新：Copilot 直接查询已发布的**知识文章**记录，所以保存即刻生效。设置里没有 *AI* 分组，没有 *Knowledge Bases* 界面，也没有任何重新索引的动作；答案过时就说明文章过时，请到 **服务 → 知识库** 里直接改那篇文章。
- **源文档过时** —— 被引用的文章需要更新。
- **提示词可以更精准** —— 对于自定义技能，优化提示词；对于内置技能，通过点踩按钮提交反馈报告。

### Copilot 不回答关于某个特定客户的问题。

两种可能：

- **共享** —— 你看不到该客户的记录。
- **AI 脱敏规则** —— 管理员可以阻止 Copilot 引用被标记的客户（例如 VIP、诉讼中）。Copilot 会明确说明这一点。

### 为什么今天 AI 响应很慢？

**没有 AI 仪表盘，也没有 AI 健康页面。** 设置里根本没有 *AI* 分组 —— 那是 **Studio → AI** 的，下面是 Agents / Tools / Skills，与健康无关 —— 设置里也没有任何地方报告模型延迟。最接近的真实界面是 **设置 → 配置 → AI 与 Embedder**，它配置提供商、模型与 Embedder，并带有 *Test connection* 与 *Test embedder* 两个按钮：那是一次性探测，不是监控面板。变慢基本都在上游 —— LLM 提供商本身，或者它的速率限制。重新索引永远不是原因，因为根本没有重新索引这回事。

## 📊 报表与仪表盘

### 我的报表显示的记录比预期少。

共享问题。报表遵守记录可见性 —— 你只能看到你能看到的内容。运行公司管道报表的销售代表只能看到自己的商机。

### 仪表盘磁贴是空的。

检查：

- 磁贴的**筛选器** —— 是否过于严格？
- 底层的**分析刷新** —— 编译后的 cube 由分析服务刷新，HotCRM 没有声明任何刷新计划，所以磁贴不新鲜要去问你自己的部署。
- 你对源对象的**简档权限**。

### 我更改了某条记录上的某个字段 —— 仪表盘何时更新？

每块仪表盘按自己声明的间隔重新查询：Customer Service 每 **60 秒**、Sales Performance 每 **180 秒**、CRM Overview / Sales Activity / Executive Overview 每 **300 秒**（`src/dashboards/`）。底下那个 cube 多久由分析服务重新编译一次，是部署侧的问题 —— 本应用自己不配置任何刷新计划。HotCRM 的仪表盘元数据也没有声明任何手动刷新控件，所以你的控制台上若有刷新按钮，它来自平台而不是本应用。

### 为什么我无法将自定义字段添加到报表？

该字段必须在字段定义中为**报表**启用。请管理员打开 *Available in Reports* 开关。

## 🔌 集成

### 我的邮件未被记录。

没有任何东西在记录它，在收件箱连接器落地之前也不会有。HotCRM 不含 Gmail 或 Outlook 连接器——`src/` 里没有连接器元数据，已安装的平台包也没有提供——所以一封邮件不会仅仅因为到了你的收件箱就出现在某条记录上，无论它是否匹配某个联系人的地址；也没有什么排除列表在把邮件拦在外面。这个产品里也不存在 `Settings` 应用，所以 `Settings → Email` 指向的是一个不存在的界面。真正落地的是出站那一半：联系人上的**发送邮件**会把邮件写成一条记录，并在该联系人的**活动**时间线上留下一条条目。如果那里什么都没有，就是没有人发过——而对勾选了*拒绝邮件*的联系人，这个操作压根就是隐藏的。已经发出的邮件是否真的送得出去是另一个问题，它取决于你的部署配置了什么邮件传输方式。参见[邮件与日历](/zh-Hans/docs/guides/email-and-calendar)与[集成](/zh-Hans/docs/guides/integrations)。

### 我的 DocuSign 信封没有更新合同。

没有人发出那个信封，也没有任何东西在等它。HotCRM 不含 DocuSign 连接器——`src/` 里没有连接器元数据，已安装的平台包也没有提供——所以既没有集成日志可开，也没有 Webhook 投递会重试。**设置 → 集成** 确实是一个真实的分组，但就本应用发出的形态而言，它下面只有平台自己贡献的两个条目——*连接智能体* 与 *数据源*——没有任何厂商往那里挂东西。[集成](/zh-Hans/docs/guides/integrations)页面上的 DocuSign 一行是设计意图，不是一个可以打开的开关。在它落地之前，报价或合同的状态是一个由人手工设置的字段，签署完的文件是由人上传的附件——参见[合同](/zh-Hans/docs/revenue/contracts)。

### Stripe 说客户 X 存在；HotCRM 说没有。

两边不会建立任何关联，在 Stripe 连接器落地之前也不会。HotCRM 不附带任何打包的厂商连接器——`src/` 里没有连接器元数据，已安装的平台包也没有提供——所以 Stripe 的客户、订阅和发票都不会自行到达任何客户或合同记录，无论是按邮箱匹配、按 external ID 还是别的方式。[集成](/zh-Hans/docs/guides/integrations)页面上的 Stripe 一行是设计意图，不是一个可以打开的开关，也没有可执行的重新关联操作。在它落地之前，客户及其合同都是有人在 HotCRM 里创建的记录。

## 🚀 性能

### 页面加载缓慢。

检查：

- **网络** —— 你的 VPN 是否经过较慢的地区路由？
- **列表视图大小** —— 尝试筛选到 &lt;500 行。
- **自定义小部件** —— 临时禁用以隔离问题。
- **浏览器** —— 清除缓存；我们推荐最新版 Chrome / Edge / Safari / Firefox。

如果问题持续，检查**状态页面**是否有事故。

### 我触发了 API 速率限制。

参见[性能与限制](/zh-Hans/docs/reference/performance-and-limits)中的矩阵。常见原因：没有退避机制的紧凑集成循环。添加指数退避并遵守 `Retry-After` 标头。

## 👥 用户与许可证

### 我如何禁用一个用户？

**Setup → Users → [user] → Deactivate**。其记录会按停用向导重新分配。**不要删除**用户 —— 这会破坏历史记录。

### 一个用户可以有两个简档吗？

不可以。使用**权限集**在基础简档之上授予额外权限。

### 一个用户可以属于多个角色吗？

不可以 —— 每个用户一个角色。使用**公共组**进行横向共享。
