# 快速导览

带你导览你每天都会用到的屏幕。

## 1. 主页仪表盘

HotCRM 是三个应用（见第 2 节），每个应用打开时都落在你的侧边栏显示的第一个条目上，所以你落在哪里取决于你是谁。在 **Sales** 里，销售经理或管理员落在 **Home**，即两个固定条目中的第一个。销售代表的侧边栏里没有 **Home**：它从 **Sales Home**（销售代表自己的页面）开始，销售代表就落在那里。服务坐席与服务经理在 **Service** 里工作，它打开时落在 **Service Overview**。**Home** 打开的是 **Executive Overview** 仪表盘——9 个磁贴，讲收入、客户与管道：

| 磁贴 | 它显示什么 |
| --- | --- |
| **Total Revenue (YTD)** | 本年度已成交收入 |
| **Active Accounts** | 至少存在一项活跃关系的客户 |
| **Total Contacts** | 通讯录中的联系人 |
| **Open Leads** | 漏斗中尚未转化的线索 |
| **Revenue Trend** | 过去 12 个月的已成交收入 |
| **Revenue by Industry** | 本年度已成交收入按客户行业拆分 |
| **Pipeline by Stage** | 各销售阶段的进行中商机金额，每个阶段一根横条——是金额，不是商机条数 |
| **New Accounts** | 过去 6 个月的客户创建节奏 |
| **Accounts by Industry** | 各行业的年营收总额与客户数 |

上表用的是源码里的英文 label，也就是英文界面上看到的名字。简体中文界面下，它们显示为语言包里的译名——例如 **Open Leads** 显示为「未转化线索」、**Pipeline by Stage** 显示为「阶段管道分布」，仪表盘 **Executive Overview** 自己显示为「高管总览」。

磁贴上方是三个面板级控件：一个按预计成交日期的日期范围选择器（默认本季度）、一个 **Owner** 筛选器和一个 **Lead Source** 筛选器。开头 4 个 KPI 磁贴各自框定了自己的周期（本年度累计、"活跃"、"未转化"），不受日期选择器收窄，所以这几个数始终是完整的，而收入类图表跟着选择器走。

对销售经理与管理员来说，它就是每日开始工作的着陆页。

本节过去承诺的 4 样东西，这块盘上没有任何磁贴对应；另有一个名字，它属于另一块盘：

- **CRM Overview** 是一块真实存在的仪表盘，但它不是 **Home** 打开的那块。它挂在 **Insights** 分组下，在侧边栏靠下的位置——所以它要点一下才打开，不是"第一眼看到"的东西。**Open Deals (Selected Period)**（进行中商机的条数）、**Deals Won (Selected Period)** 与 **Pipeline by Owner** 是它的磁贴，不是这块盘的。
- *等待你响应的工单*：两块盘上都没有。**Executive Overview** 与 **CRM Overview** 都没有任何磁贴在数工单。**Open Cases**、**Critical Cases**、**Open Cases Past SLA** 在 **Service** 分组下的 **Service Overview** 上——参见 [Service](/zh-Hans/docs/service/index)。
- *按管道价值排名的顶级客户*：本应用里根本没有这样一个磁贴。**Accounts by Industry** 是按行业归组，不是给客户排名；全应用最接近的排名是 **CRM Overview** 上的 **Pipeline by Owner**，那是按销售代表排，不是按客户排。
- *近期活动（最近的通话、会议、邮件）*：也不在这里。**Interactions Logged**、**Meetings Booked** 与 **Customer Minutes** 在 **Activity** 分组下的 **Sales Activity** 上。
- *给经理看的团队级汇总*：这块盘不做这件事。每个磁贴对所有人跑的都是同一个查询，变的是你被允许读到哪些记录，而那由你的权限集决定。本应用的岗位是扁平的——没有可供可见性向上汇总的汇报线——而 **Sales Manager** 权限集直接授予 `viewAllRecords`，所以经理读到的是全组织的合计，而不是某个团队的切片。

## 2. 应用启动器

点击**应用启动器**（左上角网格图标）以在应用之间切换。HotCRM 按业务线分成多个应用，所以控制台打开时停在首页，首页的 *Your apps* 一栏列出你的启动器提供的应用，点一个即可进入：

- **Sales** —— 线索、客户、商机、报价与合同：销售团队的应用。
- **Service** —— 工单、知识库，以及它们所属的客户。
- **Marketing** —— 营销活动，以及它触达的线索、联系人与客户；营销模块启用时才有。
- **Admin** —— 面向系统管理员。

启动器只列出你的工作需要的应用：销售代表看到 **Sales**，服务坐席与服务经理看到 **Service**，市场人员看到 **Sales** 与 **Marketing**，销售经理与管理员三个都看得到。这决定的是启动器显示什么，而不是你能打开什么：启动器上没有的应用，用它的地址照样能打开；记录链接会在你当前所在的应用里打开。

在 Sales 内，左侧导航最上面是两个固定条目——**Home**，它打开的是 **Executive Overview** 仪表盘；**Sales Home**，销售代表自己的页面，汇总管道数字、线索、未结商机、未完成任务与即将到来的活动；其余内容分在 6 个分组里：

| 分组 | 内容 |
| --- | --- |
| **Sales** | Leads、Accounts、Contacts、Opportunities、Sales Performance、Contracts、Quotes、Products、Price Books、Product Catalog、Knowledge |
| **My Work** | My Tasks、My Deals、My Leads、My Calendar、Inbox |
| **Activity** | Events、Sales Activity |
| **Insights** | CRM Overview、Forecasts |
| **Reports** | Opportunities by Stage、Won Opportunities by Owner、Pipeline Coverage by Quarter、Opportunity Funnel by Owner、Lead Engagement by Month、Accounts by Industry and Type、Customer Churn Signals |
| **Help** | User Manual、Admin Manual、Revenue Manual |

上表用的是源码里的英文 label，也就是英文界面上看到的名字。简体中文界面下，它们显示为语言包里的译名——例如 **Inbox** 显示为「待我审批」、**Knowledge** 显示为「知识库」、**My Work** 显示为「我的工作」。

**Reports** 和 **Help** 这两个分组在应用加载时是折叠的——**Sales**、**My Work**、**Activity**、**Insights** 都会自动展开。先把 **Reports** 点开，再判断某份报表在不在这里。**Help** 打开应用内手册；**Admin Manual** 只对管理员显示。

建立在商机之上的条目——**Home**、**Sales Home**、**Sales Performance**、**CRM Overview**，以及 **Reports** 下的四张商机报表——不能读取商机的人在侧边栏里看不到；服务坐席与服务经理即使用地址打开 Sales 应用，也按岗位看不到它们：他们名下没有商机，**Opportunities** 与 **My Deals** 对他们总是空的，所以这两个条目也不对他们显示。其余报表对各自的数据也是同样的要求。销售代表也看不到 **Home**，所以销售代表的侧边栏从 **Sales Home** 开始。**Sales** 最后一项 **Knowledge** 是给销售代表的：它打开已发布的文章，只对销售代表显示。其他人在 **Service** 里找到 **Knowledge**。

一个去处只占一行，这是刻意的。同一个对象如果有多种查看方式，它们是该对象列表页顶部的标签页，而不是导航里另起一行——这样侧边栏才短到能一眼扫完。

本页过去列出的 5 个分组名，应用里根本不存在；另有几个条目名，真身并不在它说的位置：

- *Products*（产品）不是分组。产品目录是 **Sales** 分组下的 **Products** 条目——产品是收入侧的主数据，理应放在销售里——参见 [Products](/zh-Hans/docs/revenue/products)。
- *Approvals* 现在也不是分组了。它下面唯一的条目 **Inbox** 本质上是一个「等你处理」的个人队列，因此已并入 **My Work** 分组——参见 [Approvals](/zh-Hans/docs/revenue/approvals)。
- 本页过去列出的 4 个条目名已经不在侧边栏了，但功能一个都没少——它们各自成了所属列表页上的一个标签页：*Pipeline* 是 **Opportunities** 页面上的 Sales Pipeline 标签页；*Calendar* 与 *Interaction History* 是 **Events** 页面上的 Event Calendar 与 ✅ Interaction History 标签页；*All Tasks* 则是 **My Tasks** 打开的那个页面的第一个标签页。
- *Activities* 不是分组，真实的分组叫 **Activity**，而且任务不在里面。`crm_task` 在侧边栏上就是 **My Work** 分组下的 **My Tasks** 一项。
- *Analytics* 不是分组。跨职能的仪表盘 **CRM Overview** 在 **Insights** 分组下，应用自带的每一张报表都在 **Reports** 分组下，上表已按各自的名字列出。没有任何条目叫 *Dashboards*。
- *AI* 不是分组，也没有叫 *Copilot* 或 *Knowledge Bases* 的侧边栏条目。Copilot 是每个页面右侧的聊天面板（见下文第 6 节），知识文章则是 **Service** 里 **Service** 分组下的 **Knowledge**。
- *Knowledge Base* 不是 HotCRM 使用的 label。在 **Service** 里，这个条目叫 **Knowledge**，应用打开时落在的仪表盘叫 **Service Overview**——参见 [Service](/zh-Hans/docs/service/index)。
- *Campaign Members* 不是侧边栏条目。营销活动成员要从营销活动详情页或全局搜索进入——参见 [Campaign Members](/zh-Hans/docs/marketing/campaign-members)。
- *Approval Requests* 与 *Action History* 也都不是条目：本应用在审批侧只有 **Inbox** 这一个入口。审批的操作留痕本身是真实数据，由审批插件以 `sys_approval_action` 存储，但本应用里没有任何导航条目能打开它。

在 Service 内，左侧导航最上面是 **Service Overview**，即服务团队的仪表盘；其余内容分在 5 个分组里：

| 分组 | 内容 |
| --- | --- |
| **Service** | Cases、Knowledge |
| **Customers** | Accounts、Contacts |
| **My Work** | My Cases、Inbox、My Tasks、My Calendar |
| **Reports** | Cases by Status and Priority、SLA on Closed Cases、Cases Opened by Day、Customer Churn Signals |
| **Help** | Service Manual |

**Reports** 和 **Help** 这两个分组在应用加载时是折叠的——**Service**、**Customers**、**My Work** 都会自动展开。不能读取工单的人看不到 **Service Overview** 和那三张工单报表；销售代表即使用地址打开这个应用，也看不到任何工单条目。

在 Marketing 内，左侧导航最上面是 **Campaigns**；其余内容分在 4 个分组里：

| 分组 | 内容 |
| --- | --- |
| **Audience** | Leads、Contacts、Accounts |
| **My Work** | Inbox、My Tasks |
| **Reports** | Lead Engagement by Month |
| **Help** | Marketing Manual |

**Reports** 和 **Help** 这两个分组在应用加载时是折叠的——**Audience**、**My Work** 都会自动展开。**Lead Engagement by Month** 与 **Customer Churn Signals** 各出现在两个应用里；两处条目打开的是同一份报表。

## 3. 你的第一条线索

**线索**是已表达兴趣但尚未通过资格审查的人。

1. 点击 **Sales → Leads → New**。
2. 填写 **Name**、**Company**、**Email**。
3. 保存。线索会自动分配给你。
4. 在线索详情页上请助手 *"判定此线索资格"* —— [线索资格判定技能](/zh-Hans/docs/ai-copilot/sales-copilot) 会按 BANT 给出 0–100 的评分并建议下一步操作。
5. 准备就绪后，点击 **转化线索** 一步将线索转化为 Account + Contact + Opportunity。

➜ 了解更多：[线索](/zh-Hans/docs/sales/leads)

## 4. 你的第一个商机

**商机**是你正在处理的真实交易。

1. 由线索转化自动创建，或 **Sales → Opportunities → New**。
2. 设置 **Account**、**Amount**、**Close Date**、**Stage**。
3. 随着交易推进，将其在各阶段间移动：*Prospecting → Qualification → Proposal → Negotiation → Closed Won*。
4. 系统会强制执行[状态机](/zh-Hans/docs/administration/state-machines) —— 你不能随意跳过阶段。
5. 点击 **✍️ Draft Email** 让 AI Copilot 起草一封符合上下文的跟进邮件。
6. 通过将阶段设置为 *Closed Won* 来赢单 —— 系统会自动创建合同并通知团队。

➜ 了解更多：[商机](/zh-Hans/docs/sales/opportunities)

## 5. 一个工单

**工单**是一个客户问题。

1. 工单通过邮件、Web 表单、电话、聊天或门户到达。
2. 新工单进入队列 —— 坐席接手。
3. 在新工单上请助手 *"分流此工单"* —— [工单分流技能](/zh-Hans/docs/ai-copilot/service-copilot) 会建议优先级、分类以及匹配的知识库文章。
4. SLA 计时器开始 —— 在工单页面查看响应时间 / 解决时间倒计时。
5. 回复客户；解决后关闭工单。

➜ 了解更多：[工单](/zh-Hans/docs/service/cases)

## 6. AI Copilot

Copilot 位于每个页面的**右侧聊天面板**。问它：

- *"本周我的管道里有什么风险？"*
- *"给我 [客户名称] 的客户 360。"*
- *"为这条线索起草一封发现跟进邮件。"*
- *"我本季度的预测是多少？"*

它从你的 CRM 数据中读取并遵守你的共享 —— 你无法让它泄露你本就看不到的记录。

➜ 了解更多：[AI Copilot](/zh-Hans/docs/ai-copilot/index)
