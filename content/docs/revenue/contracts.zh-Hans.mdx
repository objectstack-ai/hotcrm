# 合同

**合同**是你公司与客户之间的法律协议——他们购买什么、为期多久、价格如何、付款条款是什么。在 HotCRM 中，合同是**活跃客户关系的记录系统**：一旦激活，它就会解锁账户上的 *Customer* 状态。

## 5 种状态

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| ⚪ **Draft** | 灰色 | 正在谈判，尚未签署 |
| 🔵 **In Approval** | 蓝色 | 已发送进行内部签批 |
| 🟢 **Activated** | 绿色 | 已签署并生效 |
| 🟠 **Expired** | 橙色 | 结束日期已过 |
| 🔴 **Terminated** | 红色 | 提前取消 |

激活是关键转换——它会触发账户被提升为 *Customer*。

## 6 种合同类型

| 类型 | 用于 |
| --- | --- |
| **Subscription** | 经常性访问——SaaS、软件订阅 |
| **Service** | 有时限的服务——咨询、培训 |
| **License** | 永久软件许可 |
| **Partnership** | 经销商、推荐、渠道合作伙伴协议 |
| **NDA** | 保密协议（零价值） |
| **MSA** | 主服务协议——多个 SOW 的总框架 |

## 合同记录存储的内容

合同记录把自己的字段声明为 **6 个区块**。合同表单只把其中一部分挑进各个标签页，所以下表是一份合同携带的字段全集，而不是逐屏对照表：

| 区块 | 其中内容 |
| --- | --- |
| **合同信息** | 合同编号 *(自动编号 `CTR-0001`)*、合同类型、合同文档、描述 |
| **签约方** | 合同负责人、所属客户、主要联系人、关联商机——联系人和商机的选择器都按你先选定的客户过滤 |
| **条款与日期** | 合同期限（月）、开始日期、结束日期、特殊条款 |
| **合同金额** | 合同金额、计费周期、付款条款、账单地址 |
| **状态与审批** | 状态、签署日期、签署人 |
| **续约** | 自动续约、续约通知（天） |

所属客户、主要联系人、合同期限、开始日期、结束日期、合同金额和状态都是**必填**的——缺一项合同就存不下来。

有三个字段名读者会去找，但它们并不存在：

- **激活日期**。没有这个字段，也没有别的字段记录激活的那一刻。激活时系统盖的是**签署日期**（见下文*合同激活时*），所以"什么时候生效的"这类报表只能读它。
- **续约条款**。续约就是上面那两个字段。自由文本的续约说明写进**特殊条款**——它跟着合同一起走。
- **客户经理**。所有权只有**合同负责人**这一个查找字段，合同上没有第二个负责人字段。

**合同文档**是一个**链接**，不是上传——它存的是指向文档实际所在位置的 URL。已签署的 PDF 本身是作为**附件**挂在记录上的；Contract 对象启用了文件，这才使它成为可能。也没有单独的*订单表*字段。

## 计费周期

客户被开票的频率——一共四个值，新合同不改就是**按月**：

- **按月** *(默认)*
- **按季度**
- **按年**
- **一次性**

没有*自定义*计费周期。不属于这四种的节奏只能写进**特殊条款**，选项列表里放不下它。

## 付款条款

客户何时付款——一共五个值，与报价上的那五个是同一套，所以两条记录说的是同一种话：

- **15 天账期**——开票后 15 天内
- **30 天账期** *(默认)*——30 天内
- **60 天账期**
- **90 天账期**
- **货到付款**——立即

没有 *Net 45*，也没有*预付*。预先付款是写进**特殊条款**的约定，不是这里能选的一个条款值。

## 续约

两个字段驱动续约：

- **自动续约**——默认关闭，要你自己打开。打开后，每日续约扫描会替你开出续约商机；关着的时候，扫描照样提醒你，但不会建任何商机。
- **续约通知（天）**——在结束日期前多少天触发提醒。默认 30 天，而且每份合同各带各的。

没有*续约条款*字段。"续约时上调 5%，除非客户选择退出"这类说明写进**特殊条款**——合同自己身上的那个自由文本字段。

当合同进入其续约窗口时，系统会建一条跟进任务并向合同负责人发邮件——它到底建了些什么，见下文*每日——续约提醒*。

## 系统自动做的事

### 合同激活时
把合同状态**改成** *Activated* 会触发两次写入，也只有这两次：

1. 在合同上盖 **签署日期**——写入当天日期，且仅当合同上还没有签署日期时才盖。如果你在激活的同一次编辑里一并填了签署日期，系统保留你填的值。
2. **账户类型 → Customer**——凡是还不是 *Customer* 的账户都会被提升，所以除了潜在客户，合作伙伴和前客户也同样会被改成正式客户。

不会发出任何东西，也不会通知任何人。激活既不给合同所有者发通知，也不给账户所有者发通知，主要联系人那边更是什么都收不到——这里没有面向客户的外发邮件，也没有哪个开关能打开它。账户上同样没有 *Customer Since* 字段：账户本身不记录自己何时成为客户，做同期群分析只能读合同的签署日期或开始日期。

这两次写入都在保存**之后**执行，失败只记日志、不向上抛，所以即使账户提升失败，合同也已经是激活状态。它们还只挂在**更新**上——创建时就已经是 *Activated* 的合同（数据导入、种子数据、一次性写入整条记录的集成）两次都不会触发，其账户仍然停留在潜在客户。

### 每日——到期扫描
每晚午夜，系统会查找结束日期已过的 *Activated* 合同，并对每一份做两件事，也只有这两件：

1. **状态 → Expired**。
2. 向**合同负责人**发送**通知**——站内消息加邮件，链接指向这份合同。

别的人一概不会被告知。这里没有第二条通知：合同到期时，客户负责人、主要联系人以及客户团队的其他人什么都收不到，所以如果合同负责人之外还有人需要知道，得由管理员另行配置。这次扫描也只看 *Activated* 的合同——过了结束日期却还停在 *Draft* 或 *In Approval* 的合同不会被动——而且每次运行最多处理 500 份合同。

### 每日——续约提醒
每天上午 8 点，系统会查找结束日期落在这份合同自己的*续约通知（天）*窗口内的 *Activated* 合同，并按以下顺序对每一份：

1. **给合同负责人建一条续约任务**——*"Renewal due: contract CTR-0042"*，一条高优先级的跟进任务，到期日就是合同的结束日期，归属在该客户名下。
2. **通知合同负责人**——站内消息加邮件。通知里的链接指向合同记录，也仅此而已：上面没有任何一键操作，点开它不会创建任何东西。
3. **开一笔续约商机**——但仅当*自动续约*打开时。在同一个客户下开一笔 *Existing Customer - Renewal* 商机，阶段为 *Proposal*，金额从合同金额复制，关闭日期取合同的结束日期，负责人从合同复制，下一步写 *"Confirm renewal terms with customer"*。如果该客户下已经有一笔在途的续约商机，这一步会被跳过。

所以续约商机从来不是你点出来的。*自动续约*开着时，你读到提醒的时候它已经在管道里了；关着时，没有人替你开，提醒和那条任务就是全部。

那条任务同时也是扫描不重复自己的原因：续约窗口内的每天早上，同一份合同都会被匹配上，而只要它还挂着一条未完成的 *Renewal due* 任务，这一天就算已经处理过了——不会有第二条任务、第二条通知、第二笔商机。把这条任务标记完成，只要合同仍在窗口内，第二天早上的扫描就会再建一条新的。

两个值得知道的边界：扫描最多往前看 120 天，所以续约通知天数设得比 120 更长时，它也要等到 120 天这个点上才开始触发；每次运行最多处理 500 份合同。

### 手动终止
终止一份合同，就是把状态改成 *Terminated*。关于这个动作，有两件常被默认成立的事，其实都不成立。

**能不能改，取决于 profile，不取决于所有权。** 合同的编辑权是对象级的权限，不会因为你是所有者就延伸过来：**Sales Manager** 与 **System Administrator** 持有它，**Sales Rep** 没有。而这道缺口恰好落在最常见的那种情形上——报价被接受后起草出来的那份合同，把报价的负责人一并抄了过来，所以做成这笔生意的销售代表，最后拿到的是一份自己读得到、却动不了的合同。终止它是别人的动作——该找的人是他的 **Sales Manager**，不管合同挂在谁名下，经理都够得到。

**终止之后，也没有任何东西把门插上。** *Terminated* 确实被声明成终点，但它和整条状态推进一样是**警告**级：把一份已终止的合同改回 *Activated*，只会写进服务端日志，**保存照样通过**——见下文*状态推进是建议，不是闸门*。所以「一次性动作」是约定俗成——是这个状态的含义，也是下游所有人对它的读法——而不是强制。真要强制，得由管理员自己配置。

**状态**是合同上两个记录变更历史的字段之一，所以审计日志确实记下了谁在何时改的——包括把它救活的那一次。

## 内置规则

有三条规则会直接拒绝保存：

- **结束日期必须晚于开始日期**——对象上唯一一条会把合同挡回去的校验规则。
- **期限必须与日期区间对得上**——合同 hook 会算**开始日期**到**结束日期**之间有多少个月，与**合同期限（月）**相差超过 **1 个月**就拒绝：*"Contract term (12 months) does not match date range (6 months from … to …)."* 改期限就要一起改日期，否则存不下去。
- **已激活的合同，结束日期不能往前改**——合同一旦是「已激活」，把**结束日期**改早的编辑会被拒绝（*"Cannot shrink end_date … after activation"*）。往后延没问题；把一份生效中的协议提前收尾，那是终止或修订，不是编辑。

另有两件事常被当成规则，其实不是：

- **合同金额不能为负**——那是字段自己的最小值 0，不是校验规则，所以 $0 的保密协议照样能存。**合同期限（月）**同理，最小值是 1。
- **状态推进是建议，不是闸门。** 声明的路线是「草稿」→「审批中」→「已激活」→「已过期」或「已终止」；「审批中」可以退回「草稿」，三种在途状态都能直接走到「已终止」，而「已过期」与「已终止」都是终点。但它是以**警告**级别声明的：非法的跳转——「草稿」直接跳「已激活」，或者把「已过期」的合同救活——只会写进服务端日志，**保存照样通过**。表单上没有任何东西拦住它，也不会通知任何人。而**新建**时就直接是「已激活」的合同根本不受检查，正是上文那条会跳过激活写入的导入路径。

还有一条读者以为存在、其实没有的规则：**没有任何东西阻止删除一份已激活的合同。** 合同对象上既没有删除 hook，也没有任何按状态的检查——谁能删合同完全由他的 profile 决定，而 profile 从不看状态。**System Administrator** 能删任何一份合同，包括已激活的；**Sales Manager** 和 **Sales Rep** 一份都删不了，连草稿也删不了。如果你的组织要求已签署的协议不可删除，得由管理员自己配置——应用本身不替你做这件事。

## 共享

合同是 **私有** 的，也没有任何共享规则放开它。合同的可见性 **不** 跟随账户：

- **合同所有者** 读取自己的合同——而所有权买到的就只有「读」。能不能编辑，是更前面一层决定的，由你 profile 上的对象级权限说了算：**Sales Rep** 对合同只有只读权，所以挂在销售代表自己名下的合同，他读得到、却改不了。记录级共享放宽的是你能触及*哪些记录*，从来不是你握有*哪些操作*，所以任何共享规则、任何记录共享，都不会把这个「读」变成「编辑」。
- **Sales Manager** 与 **System Administrator** 能读取全部合同（对该对象持有 *查看所有*），也是仅有的两个对合同持有编辑权的 profile。两者同样**能写**全部合同，而不只是自己名下的那些——在私有对象上，这需要编辑权之外的第二道授权，因为写入这道门要问记录归谁：经理的 profile 在合同上带着组织级的写深度，管理员则带着 *修改所有*。报价起草出来的那份合同恰恰依赖这个区分：它落在**销售代表**名下，所以如果经理的触及范围只到自己名下的记录，他就恰好动不了那份最常被找上门的合同。
- **其他所有人** —— 包括通过区域或团队共享规则拿到该账户的销售代表 —— 只能看到自己拥有的合同。因此哪怕账户本身完全可读，账户上的 *Contracts* 相关列表也可能是空的。

如果你的组织希望合同跟随账户，需要管理员显式配置——而今天可走的两条路，没有一条真的交付了「跟随账户」：在 Contract 上新增共享规则，放开的是这条规则匹配到的那些记录，而且是对该对象的每一个持有者放开；把它的 OWD 改成“由父级控制”，在本版本中派生出来的是组织范围——父级链接并不会按调用者去查。两种做法都是一次宽口径的放开，而不是一次按账户收窄的放开——参见[共享与安全](/zh-Hans/docs/administration/sharing-and-security)，*“由父级控制”在实践中*。

## 标准列表视图

合同只存了**一份**列表——**全部合同**，你有权看到的每一份合同，上面没有任何过滤条件——而列表顶上的标签行改的是同一批记录**怎么画**，不是里面有哪些记录。一共四个标签，没有别的：

| 标签 | 它怎么画同一批合同 |
| --- | --- |
| **全部合同** *(落地标签)* | 网格：合同编号（钉在最左，也是进入记录的链接）、所属客户、关联商机、状态、合同金额（带列合计）、合同期限（月）、开始日期、结束日期、自动续约、合同负责人。按**结束日期**升序，所以最快到期的排在最上面。每页 25 行。 |
| **续约日历** | 同一批合同摆在月历上，落点是各自的**结束日期**，标题取合同编号，按状态着色。 |
| **合同条款** | 每份合同一根甘特条，从开始日期画到结束日期，好让相互重叠的期限彼此对齐着看。 |
| **合同时间线** | 同样是开始到结束的跨度，按季度刻度铺开，按所属客户分组、按状态着色。 |

四个标签都不做任何过滤，所以**你能看到的每一份合同在四个标签里都在**，切标签只是换一种画法。这里没有保存好的*我的活跃合同*、*60 天内到期*、*待续约*、*本月已过期*或*待激活*——要把列表收窄到自己的合同或某一个状态，得自己去排序和过滤网格的列。真正替你盯着续约日期的是上文那条每日续约提醒，不是某个列表视图。

## 给合同所有者的提示

- ✅ **激活时附上已签署的 PDF**——审计人员会感谢你。
- ✅ **为企业级交易把「续约通知（天）」设为 90**——给你整整一个季度去谈判，而且扫描往前看得足够远，撑得住这个设置。
- ✅ **把谈定的续约约定写进特殊条款**——"价格锁定 3 年；续约时上调 5%"。没有*续约条款*字段，而提醒到达时，特殊条款仍然写在这份合同上。

## 给销售代表的提示

- ✅ **合同不是你填出来的——接受报价才是起草它的动作。** 对 Sales Rep 来说合同是只读的：你既建不了也改不了。你真正握在手里的是报价，把它标记为**已接受**，系统就会替你起草合同——一份「草稿」状态的合同，带着报价上的所属客户、主要联系人、关联商机、负责人和总价，期限 12 个月、从今天起算，合同类型为「订阅合同」。
- ✅ **商机链接是从报价上抄过来的，不是你在表单上被预填了一格**——所以没有什么"保留它"可言。人工那条路也不预填：当 Sales Manager 或管理员手工建合同时，商机是一个个挑出来的，选择器唯一帮上忙的地方是它只列出合同上已选定客户名下的商机。今天也没有任何东西为了报表去读这个链接——HotCRM 根本没有随附任何合同报表或仪表盘。
- ✅ **自己的合同你读，别的事去找人。** 你的报价接受后起草出来的那份合同挂在你名下，所以你读得到；别人名下的合同你看不见。改期限、改日期、改金额、改状态都是 **Sales Manager** 或 **System Administrator** 的事，修订也一样——修订是一份新合同，只有他们能建。挂在你名下的那份合同，你的经理不需要先转移所有权就能改，所以开口问就是全部要做的事。

## 给管理员的提示

- 合同激活是一个**对象 hook**（`src/objects/contract.hook.ts`），不是 flow——盖签署日期和提升账户都写在那里，流程列表里找不到它。到期扫描和续约提醒**才是**定时 flow。参见 [管理 › 自动化](/zh-Hans/docs/administration/automation)。
- 合同类型和计费周期选项列表是可扩展的。
