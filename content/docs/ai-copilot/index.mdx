# AI and Agents

**HotCRM is built for agents, and it does not ship one.** It provides three things an agent works with: the **objects** (every account, deal, order, contract, invoice, project, expense and case), the **actions** a person runs from a button, and eight **skills** that teach an agent the CRM. The agent itself is yours: one you connect over MCP, or the assistant the platform provides.

## Why it is built this way

Reading a receipt, checking an expense against a travel policy, drafting a reply, chasing an overdue invoice: each is work an agent does better every month, and none of it needs to be built into a CRM. HotCRM keeps what an agent cannot invent — the records, the rules that guard them, and who may do what — and leaves the reasoning to the agent.

So you will not find a built-in receipt scanner, policy engine or chat assistant in HotCRM. You will find:

| Every object, over MCP, under the caller's permissions | [Connect Your Agent](/docs/ai-copilot/connect-your-agent) |

| Fields an agent can write its findings into, such as **Review Notes** on an expense report or a travel request | [Expenses](/docs/expenses) |

## The one rule: an agent is a person

An agent connects **as someone** — with a sign-in or that person's API key — and acts as them. It reads what they may read, writes what they may write, and is refused where they would be refused, with the same message. Records it writes carry that person's name. There is no agent account with wider access, and no switch that gives one.

So the question "what may my agent do?" has the same answer as "what may this person do?": their permission sets, their positions and the sharing rules. See [Sharing and Security](/docs/administration/sharing-and-security).

## What the platform's assistant adds

ObjectStack environments can run a platform assistant (`ask`). HotCRM authors no agent for it; its eight skills attach to that assistant and teach it to qualify a lead, draft an email, forecast revenue, build a customer 360°, triage a case, and file and check expenses. A local community-edition boot runs no assistant (`GET /api/v1/ai/agents` answers an empty list): there, the agent is the one you connect.

> **No app-owned agents.** HotCRM used to define two agents of its own — a "Sales
> Copilot" and a "Service Copilot". They were retired, and their capability moved into
> skills that attach to the platform assistant.
