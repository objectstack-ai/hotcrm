# 知识库

知识库是 AI 助手在起草回复、建议解决方案或分流工单时所读取的**支持内容库**。一个维护良好的知识库正是让 Copilot 变得有用的关键——它决定了 AI 是输出含糊空洞的废话，还是准确、契合品牌的客户答复。

## 知识库里有什么

知识库就是一个对象——**知识文章**——每篇文章都是你在**服务 → 知识**下创建的普通记录。它背后没有另一套索引，也没有文件库：列表视图里能看到的，就是 Copilot 能读到的。

每篇文章归入一个**分类**，而这七个分类就是全部词汇表：

| 分类 | 该放什么 |
| --- | --- |
| **入门指南** | 首次配置、上手引导、"我该从哪开始" |
| **操作指南** | 分步骤的任务说明 |
| **故障排查** | 症状 → 成因 → 修复、错误码、已知绕行方案 |
| **账务与价格** | 账单、套餐变更、退款、价格问题 |
| **API 与集成** | 接口、Webhook、连接器配置 |
| **版本说明** | 什么变了、什么时候变的 |
| **政策制度** | 支持时间、SLA 承诺、数据处理，以及一切你写下来就要兑现的承诺 |

除分类外，每篇文章还带有**标签**（身份认证、单点登录、移动端、邮件、报表、性能、数据导入、Webhook）、**状态**（草稿 → 审核中 → 已发布 → 已归档）、**受众**（公开或仅内部）和**语言**。**文章编号**（`KA-0001`）自动生成，Copilot 引用的就是这个编号。

## 怎么找文章

**知识**列表自带四个页签：

- **全部文章**——按分类分组，发布时间最新的在前。
- **已发布**——只看已发布的文章，浏览数最高的在前。
- **我的草稿**——你自己的草稿与审核中的文章。
- **复核队列 · 最久未复核在前**——已发布文章按最久未复核在前排序，所以列表顶部就是最可能过时的内容。

对象声明的检索字段是**标题**、**摘要**和**文章编号**，全局搜索与查找选择器读的正是这三个字段——同事会拿来搜索的那些词，应该写在这里，而不是埋在正文里。

## AI 助手如何使用它

读文章的技能只有一个：**Customer 360°**。向它要一位客户的全貌，它在客户、联系人、进行中商机和工单之外，还会按刚读到的那些工单的**分类或标签**去查询**已发布**的文章，并按编号（`KA-0007`）逐条标注出处。

有两件事值得说准，因为它们过去都被写反了：

- **工单分流不会检索文章。** 它只声明了 `describe_object` 与 `get_record` 两个工具，完全没有检索类工具。它返回的是一个优先级、判定它的那一条理由，以及指向"升级"或"关闭"的指引——没有文章清单。
- **邮件撰写不会引用文章。** 草稿的依据是这个技能读到的记录——联系人，以及请求点名时的相关客户或商机——它的指令里没有任何一步去取文章。当回复确实需要引用某篇文章时，把 Customer 360° 匹配出来的那篇拿来粘贴进去。

匹配靠的是分类与标签，不是语义。归错分类的文章，正文答得再好也浮不出来——所以知识管理员最有杠杆的动作是分类，而不是润色文字。

## 维护知识库

知识库的**好坏取决于你放进去的内容**。一个典型的内容维护工作流：

### 1. 捕获有效的内容

当客服用一个出色的答复解决了一个棘手工单时，把该答复整理成一篇新文章。**来源案例**字段会把它链回它出自的那个工单，下一个读者能顺着看到真实的对话。

### 2. 分流来访问题

每周查看最常见的工单主题。排名前 10 的问题值得设立专门的文章——如果 30 个客户问了同一件事，第 31 个就应该由一篇文章来回答。

### 3. 淘汰过时内容

如果产品发生变化，对应的文章需要更新。**复核队列**按"多久没人动过"给已发布文章排序，从顶部往下处理即可。发布只在第一次盖上发布时间，之后每次编辑都会刷新复核时间，所以这个排序反映的是真实的关注度。

### 4. 关注被引用和被阅读的内容

每篇已发布的文章上都有**有用**和**没用**两个按钮。按下其中一个会记录你的**文章反馈**（Article Feedback）——每位读者每篇文章一条记录——文章上的**有用**／**没用**计数会立即按这些记录重新统计。改变主意就按另一个按钮：你自己那条评价会改写，而不是新增一条，所以这两个数字表示的是*有多少人*，而不是点了多少次。反馈记录本身会列在文章上，作者可以看到谁认为这个答复没用，以及对方留下的备注。

反复被投"没用"的文章正在造成伤害，应当重写而不是放着不管。

<Callout type="info">
  **浏览数已不再统计。** 文章上原本有一个*浏览数*字段，但产品里没有任何东西能够增加它——它永远停留在演示数据给的那个值。与其留下一个看起来像度量、实际不是的数字，不如把这个字段删掉。等真正的文章浏览入口存在、能够写入它的那天，它会回来。衡量知识库是否真正起作用的指标，见[知识库转移率](/zh-Hans/docs/service/#service-overview)。
</Callout>

## 给服务经理的提示

- ✅ 将知识库更新纳入每周团队会议——"本周我们需要哪 3 篇新文章？"
- ✅ 奖励贡献知识库内容的客服；这能放大他们的专业能力。
- ✅ 审计 **Customer 360°** 引用的文章——每周随机抽取 10 篇，检查它们是否真的配得上被匹配到的那些工单。

## 给管理员的提示

- **不发布等于不存在。** Copilot 只查询已发布的文章，草稿对它是不可见的。
- **认真设置受众。** 公开文章是写给客户看的，仅内部的文章只给客服看。注意：客户门户今天并不提供文章——按设计，访客权限集完全读不到这个对象——所以*公开*表达的是意图，不是一个发布渠道。
- **分类属于元数据。** 增加第八个分类是改对象，不是改设置——参见 [定制 › 扩展对象](/zh-Hans/docs/customization/extending-objects)。
- HotCRM 不附带任何独立的销售、产品或竞争情报知识库可供接入；有的就是这一个对象和它的分类。Copilot 拿它能做什么、不能做什么，详见 [AI Copilot › 知识库](/zh-Hans/docs/ai-copilot/knowledge-bases)。
