# 出差申請

出差申請在出差之前提出：去哪裡、什麼時候、為什麼、大約花多少錢。你的上級在花錢之前批准或駁回；為項目出差時，由項目的項目經理審批。它在 **Expenses** 應用的 **Travel Requests** 下。

出差申請不是必需的。沒有申請也可以錄入和提交費用。

## 填寫申請

打開 **My Travel Requests**，點 **New**：

| 欄位 | 填寫什麼 |
| --- | --- |
| **Purpose** | 為什麼去（必填） |
| **Destination** | 去哪裡（必填） |
| **Start Date** 和 **End Date** | 出差的第一天和最後一天（必填）。**Days** 首尾兩天都算 |
| **Estimated Amount** | 整次出差的一個總數，使用貴公司的本位幣，不論每一部分由誰支付（必填） |
| **Account** | 為哪個客戶出差，可選 |
| **Project** | 為哪個項目出差，可選（啟用 Project Delivery 時才有）。不提供 Closed 或 Cancelled 的項目 |
| **Itinerary** | 用你自己的話寫的計劃 |
| **Notes** | 其他內容 |

在 **Files** 分頁上傳檔案。**Source** 說明這筆記錄從哪裡來，**Review Notes** 是助手或規則寫給審批人看的發現。兩者都不影響任何判斷：助手可以以你的身分透過介面起草申請、估算金額或檢查，決定仍由審批人做出。

## 行程明細

一次出差有好幾程時，可以在申請頁面的 **Itinerary Lines** 下逐程列出。每一程點一次 **New**：

| 欄位 | 填寫什麼 |
| --- | --- |
| **Kind** | Flight、Train、Car、Hotel 或 Other（必填） |
| **From** 和 **To** | 這一程從哪裡出發、到哪裡；酒店的 **To** 填酒店所在地（**To** 必填） |
| **Start Date** 和 **End Date** | 這一程的日期（必填），酒店另填退房日期 |
| **Details** | 座位、想住的酒店或其他要求 |
| **Booking Reference** | 訂好之後的確認號 |

各程按出行順序列出。行程明細不帶金額：申請上的 **Estimated Amount** 是唯一的總數。行程明細是可選的，沒有明細的申請也是完整的。

## 提交和審批

| 狀態 | 含義 |
| --- | --- |
| **Draft** | 還在填寫 |
| **Submitted** | 已交給審批人，等待期間鎖定 |
| **Approved** | 同意。計劃不再改動 |
| **Rejected** | 被退回。改回 Draft，修改計劃後重新提交 |
| **Cancelled** | 批准後不去了。最終狀態 |
| **Closed** | 出差已結束。最終狀態 |

點 **Submit** 即送審。由誰決定取決於 **Project**：

- **有項目**：由項目的**項目經理**決定。項目經理也審批這個項目上的費用，所以出差和它的花費交給同一個人。項目沒有項目經理，或者是項目經理自己出差，則由管理員決定。
- **沒有項目**：由**你的上級**（你使用者記錄上的 **Manager**）決定；沒有上級時，改由 **Finance Controllers** 決定。

無論哪種，都只有一個人在 **Inbox** 中決定，不會兩人都審。只有一級：財務在之後的費用上把關，不審批出差申請。**Requests to Approve** 列出等待你審批的申請。不能審批自己的申請，也沒有人能手動設定 **Approved** 或 **Rejected**。

**等待期間改主意了？**在 Inbox 中撤回，申請回到 **Draft**。

**只有一個人的組織。** 沒有人能審批自己提交的申請，管理員也一樣，所以出差申請需要另一位能審批它的使用者：你的上級、一位 **Finance Controller** 或一位管理員；項目上的出差申請則是項目的項目經理或一位管理員。在這個人加入之前，提交的申請停在 **Submitted**，沒有人能決定它：請在 Inbox 中撤回，等這個人加入後再次提交。

**只有 Draft 狀態的申請可以刪除。**申請一經提交就保留在記錄中，連同它的審批和報銷單。要取消已批准的出差，請選擇 **Cancel Trip**；被駁回的申請要先退回 **Draft**。

## 批准之後

批准針對的是這份計劃，所以已批准申請的 **Purpose**、**Destination**、日期、**Estimated Amount** 和 **Project** 都不再改動。從提交那一刻起，各程也一樣被鎖定：類型、地點、日期和要求都不再改動，也不能再新增或刪除行程。要改計劃，請點 **Cancel Trip**，再重新申請。出差結束後，點 **Close**。

每一程的 **Booking Reference** 都可以填寫，只有申請等待審批期間除外：這時每一程都被鎖定，Booking Reference 也不例外，改動會被拒絕，直到審批有了結果。訂好之後，由你本人、以你的身分透過介面辦事的助手、你的審批人或代訂人把確認號寫在這裡，批准之後也可以。

## 報銷這次出差

用 **Submit for a Trip** 提交這次出差的費用，並選這張申請（見[費用](/zh-Hant/docs/expenses#expenses-of-a-trip)）。之後申請會對照預計金額顯示花費：

| 欄位 | 顯示什麼 |
| --- | --- |
| **Reported Amount** | 引用本申請、已提交、已批准或已付款的報銷單合計。草稿或被駁回的報銷單，重新提交後才計入 |
| **Difference from Estimate** | 已申報減去預計：大於零就是超出預計 |
| **Over the Estimate** | 已申報超出預計時打勾 |

申請頁面上列出它的報銷單，每張報銷單也給審批人看同樣的數字。超出預計只是提醒審批人，不會攔住。

財務把一張報銷單標記為已付款時，如果這張申請下沒有其他報銷單還處於草稿、已提交或已批准，申請會自動 **Closed**。已取消或已關閉的申請不能再報銷。

## 誰能看到

你能看到自己的申請及其行程明細，以及請你審批的申請。財務能在 **All Travel Requests** 裡看到所有申請，銷售經理和銷售領導也一樣；他們都不能修改別人的申請。出差申請不出現在 Sales、Service、Marketing 應用裡，也不出現在客戶頁面上。

啟用 Project Delivery 時，項目人員在 **Project Delivery** 應用的 **My Expenses** 旁邊也能找到 **My Travel Requests**，項目頁面的 **Related** 分頁列出這個項目的出差申請（每個人看到的範圍同上）。出差申請不計入項目成本：成本隨費用而來。不啟用 Project Delivery 時，沒有 **Project** 欄位，所有申請都交給出差人的上級。
