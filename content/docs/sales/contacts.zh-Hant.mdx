# 聯絡人

**聯絡人**是某個客戶處的個人——通常是決策者、影響者或最終使用者。每個聯絡人都屬於一個客戶。

## 聯絡人記錄儲存的內容

聯絡人詳情介面有 6 個可摺疊區塊：

| 區塊 | 欄位 |
| --- | --- |
| **身份資訊** | 稱謂、名、姓、全名、頭像 |
| **客戶與職務** | 聯絡人負責人、所屬客戶、職位、部門、直屬上級 |
| **聯絡方式** | 郵箱、電話、手機 |
| **郵寄地址** | 郵寄地址、郵寄城市、郵寄省份、郵政編碼、郵寄國家（五個獨立欄位） |
| **附加資訊** | 生日、線索來源、描述、最近聯絡時間 |
| **溝通偏好** | 主要聯絡人、禁止致電、拒絕郵件 |

## 主要聯絡人

每個客戶有**一個主要聯絡人**——通常是主要決策者或業務發起人。將某個聯絡人設為主要會自動清除前一個聯絡人上的標誌，因此你絕不會出現兩個的情況。

主要聯絡人會被自動建議為以下情境的預設值：

- 商機（主要聯絡人欄位）
- 報價（聯絡人欄位）
- 合約（主要聯絡人欄位）

這能省去大量點擊。

## 客戶處的組織架構圖

使用**直屬上級**來建模客戶內部的組織結構：

```
CEO
├── VP Sales
│   └── Sales Director
└── VP Engineering
```

客戶詳情頁將其渲染為一棵可點擊的樹，因此你能一眼看出誰向誰匯報。AI Copilot 在總結客戶時會用到它——它能告訴你哪些人是決策者、哪些是影響者。

## 溝通偏好（GDPR / CCPA）

兩個退訂標誌用於記錄此人不希望被聯絡。它們都是聯絡人記錄**溝通偏好**區塊裡的核取方塊，區別在於產品對它們的落實程度：

| 標誌 | 目前真正會發生什麼 |
| --- | --- |
| **拒絕郵件** | **已強制執行。** 對已退訂的聯絡人，**發送郵件**動作會被隱藏——記錄頁標題列和列表行上都不再出現；建立這樣的聯絡人時，也不會給負責人推送「去打個招呼」的提醒。 |
| **禁止致電** | **對「安排」強制執行，對「記錄」不攔截。** HotCRM 會拒絕為帶此標記的聯絡人*安排*電話觸達：未完成的**電話**任務、以及狀態為**已計劃**的*電話*行事曆事件，儲存時一律被拒——無論寫入來自「安排跟進」畫面、手動新建任務、資料匯入還是 API。記錄已經發生的通話則刻意保持可用：**記錄通話**動作，以及狀態為**已完成**的*電話*任務，永遠不會被攔截，因為拒絕它們只會掩蓋通話的證據，而不能阻止通話發生。該標記只針對電話——郵件由**拒絕郵件**管轄，會議和示範不受限制。 |

兩者都是普通的可編輯核取方塊：任何能編輯該聯絡人的人都能勾選或取消。沒有任何欄位級規則把它們保留給管理員，因此請把它們當作對本人意願的記錄、需要團隊自覺遵守，而不是一把鎖。

## 內建規則

- **郵箱地址在你所屬的組織內必須唯一**。同一個地址不能同時用於兩個聯絡人，即使這兩個聯絡人隸屬於不同的客戶——第二次儲存會被拒絕，並提示 *"Another contact … with email … already exists."*。同一平台上的其他組織可以有自己使用該地址的聯絡人——這條規則只作用於你自己的資料，而不是整個平台。郵箱在儲存與比較前會統一轉為小寫，因此 `Ada@Example.com` 與 `ada@example.com` 視為同一個地址。因此，若同一個人同時在兩家公司與你往來，兩筆聯絡人記錄需要各自使用不同的郵箱地址。
- **新聯絡人提醒**——建立聯絡人時，系統會通知這筆記錄的**負責人**，站內收件匣和郵件各一份：*"… was added as a contact. Reach out to welcome them."*。聯絡人本人收不到任何東西：*contact_welcome* 是這條流程的名字和它的通知主題，不是郵件範本，HotCRM 也沒有發給客戶的歡迎郵件。有兩種情況一條提醒都不會有——聯絡人**沒有負責人**（種子資料或整合寫入的記錄就沒有），以及聯絡人勾選了**拒絕郵件**。

## 共享——誰能看到哪個聯絡人

聯絡人可見性**繼承自父級客戶**。如果你能看到該客戶，就能看到它的所有聯絡人。沒有需要管理的單獨聯絡人共享模型。

這讓安全機制變得簡單：把客戶共享設定正確，聯絡人就會隨之而來。

## 標準列表視圖

聯絡人列表預設打開**全部聯絡人**，切換器裡就是下面這三個已儲存視圖——只有這三個：

| 視圖 | 展示什麼 |
| --- | --- |
| **全部聯絡人**（預設打開） | 所有聯絡人，**按所屬客戶分組，分組預設摺疊**：你展開正在跟的那個客戶，而不是從一張平鋪的大名單裡翻。組內按姓氏 A→Z 排序，列上是頭像、所屬客戶、職位、部門、郵箱、電話和負責人。每頁 50 列，可匯出 CSV / XLSX。 |
| **聯絡人目錄** | 同一批人以照片卡片呈現，卡片正面就是聯絡人頭像——開會前把人和臉對上最快的一屏。卡片上有姓名、職位、部門、郵箱、電話和所屬客戶。 |
| **主要聯絡人** | 只列被標記為**主要聯絡人**的人（每個客戶一個，見上文），按所屬客戶排列。發報價或群發郵件之前值得過一遍這張表，因為各處的預設聯絡人正是從這一批裡取的。 |

沒有「我的聯絡人」這類按負責人過濾的視圖；就可見性而言也不需要：聯絡人不單獨共享，而是繼承所屬客戶的共享（見上文）。想看「自己的人」，從[客戶](./accounts)列表的**我的客戶**進入客戶記錄，或者在**全部聯絡人**裡展開自己那幾個客戶的分組。

## AI Copilot 如何使用聯絡人

當你讓 AI 助手起草一封郵件時，它會使用：

- 聯絡人的名和職位（用於個人化）。
- 客戶名稱和產業（用於上下文）。
- 產品目錄（用於相關談話要點）。
- 聯絡人的溝通偏好（以跳過退訂項）。

因此 *"Draft a follow-up to Jane"* 能在幾秒內給你一封個人化的、符合品牌調性的郵件。

## 給銷售代表的提示

- ✅ 始終設定職位和部門——它會被報告和 Copilot 使用。
- ✅ 使用直屬上級欄位——它讓客戶會議的準備工作容易得多。
- ✅ 每個客戶恰好標記一個主要聯絡人。

## 給管理員的提示

- 部門列表（Sales、Marketing、Engineering、Finance、IT、Operations、HR、Legal、Executive、Other）可按選擇列表值設定。參見 [Customization › Extending Objects](/zh-Hant/docs/customization/extending-objects)。
- 新聯絡人提醒是一條流程，不是範本：要改措辭、通知管道或通知給誰，編輯 `src/flows/contact-welcome.flow.ts`。它背後沒有任何郵件範本設定。
- 來自客戶的共享繼承意味著你通常永遠不需要針對特定客戶的聯絡人共享規則。
