# 订单

**订单**记录客户这一次买了什么：哪些产品或服务、多少、什么价格。它是一笔交易最终落地的记录。**合同**记录双方约定了什么，是可选的：订单可以挂在一份框架合同下，但大多数订单没有合同。

| | 订单 | 合同 |
| --- | --- | --- |
| 记录 | 这一次买了什么 | 双方约定了什么 |
| 明细 | 有；小计是各订单行之和 | 没有明细 |
| 日期 | 下单日期、发货日期 | 开始、结束、期限、续约 |
| 适用 | 一次销售 | 订阅、项目服务、框架协议、保密协议 |

一张订单最多属于一份合同；一份合同可以有多张订单，也可以没有。

这份合同必须属于订单自己的所属客户。订单表单的 **关联合同** 只列出该客户的合同，更换所属客户时会清空 **关联合同**。如果某次保存仍然指定了另一个客户的合同（例如通过 API），保存会被拒绝，提示显示在 **关联合同** 上：请选择该客户的合同，或清空 **关联合同**。在这条规则生效前已经保存了其他客户合同的订单，下次编辑时也会被拒绝，直到改正它的关联合同或所属客户。

## 在哪里找到订单

- 销售应用 **销售** 分组中的 **订单**。
- 客户页面上的 **订单** 列表，以及订单所挂合同的页面上的 **订单** 列表。
- 订单与回款应用中的 **订单、合同与客户**，财务在这里查看订单。

订单只展示给使用报价单的人：销售代表、销售经理、销售管理层和管理员，以及只读查看的财务（应收会计和财务总监）。服务和市场人员看不到订单。

## 接受报价时自动创建订单

报价被**接受**时，它的订单会自动出现：一张**草稿**订单，带着报价的名称、所属客户、联系人、关联商机和负责人，它的折扣、税额、运费和付款条款，地址和描述，以及逐行复制的全部报价明细。合计与报价相同。订单的**来源报价单**指向这份报价，订单也会列在报价的页面上。每份被接受的报价只有一张订单，不论它的状态被保存了多少次。

除此之外不会创建任何东西：接受报价不再起草合同。如果这次销售需要合同，从订单起草（见下文）。

**来源报价单**由系统填写，不能手动修改。它随"报价与产品"模块一起提供：管理员关闭该模块后，报价以及这个字段都不存在，订单只能手动录入。

## 从订单起草合同

订阅或项目通常需要合同，产品销售通常不需要。在订单页面点击**起草合同**即可起草：一份*草稿*合同，合同类型为*订阅合同*，期限 12 个月、从今天起算，金额为订单的总金额，名称与订单相同（从报价生成的订单沿用报价的名称），带着订单的所属客户、联系人、关联商机、负责人和付款条款。这就是以往接受报价时生成的那份起始草稿；打开它补全期限、日期和类型。随后订单的**关联合同**会指向这份合同，你也会收到一条带链接的**合同已起草**通知。

- 只有当订单还没有关联合同时才会提供**起草合同**。挂在现有框架合同下的订单，其**关联合同**已经指向那份合同，不会再提供第二份。
- **已取消**的订单不提供**起草合同**，也不会为它起草任何东西。
- 订单需要填写**联系人**：合同必须有主要联系人。没有联系人时不会起草任何东西，系统会提示你先填写联系人。
- 销售代表也可以运行它，尽管销售代表不能亲手新建合同：草稿由系统写入。

## 本版本之前：每份被接受的报价都会起草合同

在本版本之前，接受报价会起草一份合同，但不会创建订单。现在接受报价会创建订单，需要合同时再从订单起草。这两项自动化都是管理员可以开关的流程，位于 Studio（控制台首页的 **在 Studio 中新建** → **HotCRM Revenue** → **定制** → **自动化**；步骤见[系统管理 › 自动化](/zh-Hans/docs/administration/automation#switching-a-packaged-flow)）：

| 流程 | 出厂状态 | 作用 |
| --- | --- | --- |
| **已接受的报价单创建订单** | 开启 | 创建上文所述的草稿订单 |
| **已接受的报价单起草合同** | 关闭 | 像本版本之前一样，为每份被接受的报价起草合同 |

如果要保留原来的行为，开启**已接受的报价单起草合同**。此后每份被接受的报价都会像以前一样起草合同，报价的订单也会指向这份合同。如果完全不需要订单，再关闭**已接受的报价单创建订单**。这项选择在重启和升级后都会保留。见[系统管理 › 自动化](/zh-Hans/docs/administration/automation#switching-a-packaged-flow)。

## 订单状态

| 状态 | 含义 |
| --- | --- |
| ⚪ **草稿** | 正在整理 *（新订单的默认状态）* |
| 🔵 **已确认** | 已与客户确认；订单行和金额被锁定 |
| 🟢 **已完成** | 已交付完毕 |
| ⚫ **已取消** | 不再执行 |

订单按 **草稿 → 已确认 → 已完成** 推进。**已确认** 可以退回 **草稿**，**草稿** 或 **已确认** 可以改为 **已取消**。**已完成** 和 **已取消** 是最终状态；其他任何状态变更都会被拒绝，并提示允许的变更。

用订单页面上的按钮推进订单（订单列表每一行的菜单里也有）：*草稿*订单点击**确认订单**，*已确认*的订单点击**完成订单**，两者都可以点击**取消订单**。只会提供订单从当前状态能做的变更。每个按钮都会先询问，并说明这次变更的后果：确认会锁定订单行，完成或取消是最终的。如果点击时这次变更已不再允许（例如有人刚刚取消了这张订单），它会被拒绝并显示那条提示，订单不会有任何变化。

目前仍可以在订单表单上修改**状态**，同样只能沿上面的路线变更。*已确认*的订单就是这样退回*草稿*的：这一步没有按钮。

## 订单记录保存的内容

| 分组 | 字段 |
| --- | --- |
| **订单信息** | 订单编号、订单名称、订单负责人、所属客户、联系人、关联商机、状态、下单日期、关联合同、客户采购单号、描述 |
| **价格** | 小计、折扣 (%)、折扣金额、税额、运费及手续费、总金额、付款条款 |
| **发货** | 发货状态、发货日期 |
| **地址** | 账单地址、收货地址 |
| **系统** | 外部编号 |

**客户采购单号** 是客户自己采购单上的编号。**外部编号** 是这张订单在其他系统（例如它来自的订单系统）中的编号；两张订单不能使用同一个外部编号。

## 订单行

每一行包括产品、产品标题、描述、数量、标价、销售单价、行折扣，以及这一行的小计和总计，与报价单明细相同。

- **选择产品**：这一行以产品名称作为标题、带出产品的标价，销售单价默认等于标价，可以改成别的价格。
- **没有产品？** 填写这一行的 **产品标题** 和 **销售单价**。目录里没有的东西就这样录入；报价与产品模块关闭时（其产品选择器为空），订单行也这样录入。
- 订单行的标价取自产品本身，而不是价格表。

## 合计如何计算

```
小计       = Σ 订单行（数量 × 销售单价 × (1 − 行折扣 %)）
折扣金额   = 小计 × 订单折扣 %
总金额     = 小计 − 折扣金额 + 税额 + 运费及手续费
```

每次添加、修改或删除订单行，小计都会重新计算；小计、折扣、税额或运费任一变化时，折扣金额和总金额随之更新。有订单行的订单不能手工填写小计：保存时如果把它改成不等于各订单行之和的数，会被拒绝，请改为修改订单行。没有订单行的订单保留你填写的小计。

## 已确认订单的订单行和金额被锁定 [#a-confirmed-orders-lines-and-amount-are-locked]

订单离开 **草稿** 后，订单行不能再添加、修改或删除，**订单行** 列表上也不再显示 **新建**。它的 **小计**、**折扣 (%)**、**税额** 和 **运费及手续费** 也不能再修改，因此 **总金额** 保持确认时的数：订单合同、收款计划和框架合同的额度都读取它。要修改已确认订单的订单行或金额，请先在表单上把 **状态** 改回 **草稿** 并保存，改完后再点击 **确认订单**；之后合同和收款计划会像订单在草稿时的任何修改一样跟随新的总金额。退回草稿期间，订单不计入框架合同的订单金额。已完成或已取消订单的订单行和金额保持不变：差额请另开一张新订单。订单的其他字段（例如发货字段）仍可编辑。导入和系统自身的更新不受这条规则限制。

## 发货

**发货状态**（*未发货*、*部分发货*、*已发货*）和 **发货日期** 表示订单发货到了哪一步。它们由人手动填写或由导入填写；HotCRM 中没有别的功能会改动它们，背后也没有库存或发货单。
