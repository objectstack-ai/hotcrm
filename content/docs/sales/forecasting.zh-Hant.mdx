# 預測

**預測**是某一時刻銷售管道的凍結快照。每個負責人每個週期一筆記錄——通常是每位銷售代表每季度或每月一筆。你透過堆疊快照來構建趨勢（「我們的 Q3 數字逐週是如何變化的？」），而不是透過重新讀取即時商機資料。

本頁講的是儲存這些快照的**預測物件**。關於*生成*預測敘述的 AI 對話，請參見 **AI Copilot → 營收預測**。

## 預測記錄上儲存的內容

| 區塊 | 欄位 |
| --- | --- |
| **週期** | 負責人、週期（`month` / `quarter`）、週期開始。週期結束和友好標籤（例如 **Q3 2026**）是衍生的。 |
| **數字** | 配額、銷售管道金額、最佳情況金額、承諾金額、已成交金額。 |
| **衍生** | **預期金額**、**達成率（%）** 和 **覆蓋倍數**——由上面這些數字逐筆算出的公式欄位。沒有人需要錄入它們。 |
| **來源** | `scheduled`（每晚作業）、`ai`（Copilot 生成）、`manual`（銷售代表錄入）。 |
| **敘述** | 可選的評述——發生了什麼變化、什麼有風險、下次一對一要問什麼。 |

銷售管道、最佳情況、承諾和已成交是相互獨立的桶——它們回答不同的問題：

- **銷售管道**——本週期內的每一筆開放交易，無論信心如何。
- **最佳情況**——銷售代表認為透過衝刺努力可以贏下的交易。
- **承諾**——銷售代表願意以自己名義擔保的交易（按慣例 ≥ 80% 機率）。
- **已成交**——已經贏得；無法移動。

## 週期是如何衍生的

你輸入 `period` 和 `period_start`；系統計算其餘部分。對於一個從 2026-07-01 開始的季度預測：

- `period_end` → 2026-09-30
- `period_label` → **Q3 2026**

因此你絕不會看到一筆標記為「2026-07-01 至 ???」的記錄——只有人類可讀的標籤。列表視圖和儀表板會直接按 `period_label` 分組。

## 預測是如何建立的

有三種來源，記錄在 `source` 欄位中：

1. **Scheduled**——**Forecast Snapshot** 流程每晚 3 點執行，為每一位手上至少還有一筆進行中交易的銷售代表拍下**當前季度**的快照。這是歷史趨勢的脊柱。重跑一次只會刷新同一筆，所以數字既會上升也會下降；它從不寫入**配額**，配額始終保持經理設定的值。
2. **AI**——Copilot 技能根據當前銷售管道 + 近期階段移動 + 類似的過往交易生成預測。對話記錄會與該記錄一併儲存。
3. **Manual**——經理直接錄入一個數字。用於調整和覆蓋。

你可以為同一個負責人/週期擁有全部三種——它們在趨勢圖中並排顯示，因此分歧是可見的。

**當前季度只有一個自動寫入方。** 當前季度的資料列由每晚的定時快照打開，此外沒有任何東西會去打開它——新組織附帶的示範資料刻意停在這個視窗的邊緣，只播種已結束的季度和當前月份，因此絕不會與定時快照寫入的資料列相撞。在一個剛播種的組織上，由此帶來兩個後果，它們都是預期行為，而不是故障：

- **當前季度的資料列，在凌晨 3 點的定時快照首次跑完之前並不存在。** 在那之前，任何限定在*本季*的東西——尤其是銷售儀表板的 *Quota Attainment by Rep* 表格——空著才是對的。已結束的季度和當前月份則從一開始就有資料。
- **定時快照打開的每一筆，配額都是空的，並且一直空到有人手動填上為止。** 沒有任何自動化會寫配額。配額是達成率那個靠人工維護的分母，一個每晚重設它的作業只會抹掉銷售代表真正要負責的那個數字。

## 你用它們來做什麼

- **彙總儀表板**——銷售儀表板的 *Quota Attainment by Rep* 表格顯示每位銷售代表**當前季度**的配額、已成交收入與達成率。它讀的正是這些快照，所以在定時快照打開當前季度之前它是空的；而如果還沒有人給某位銷售代表設配額，他那一筆仍然會出現，只是沒有達成率——資料集的比值度量遇到缺失的配額時不會去做除法，而是直接不給值。
- **趨勢**——選擇一個負責人和一個週期，按每個快照的 `created_at` 繪製 `commit_amount` 的圖表。突然的下降會觸發*「為什麼這週承諾下降了 ¥800k？」*的對話。
- **達成率**——**有**專門的欄位，不需要你在報表層重建它。**達成率（%）**（`attainment_pct`）是每筆快照上的一個公式欄位——`closed_amount ÷ quota × 100`，只讀這一筆自己的兩個欄——並且它是三個預測列表視圖上都有的一欄，記錄表單上也有。零值是有保護的：配額為 0、或者還沒有配額時，它讀作 **0.00** 而不是報錯，所以一個沒設好的分母永遠不會把視圖弄壞。**覆蓋倍數**（`coverage_ratio`）就在它旁邊，形狀完全一樣——`銷售管道金額 ÷（配額 − 已成交）`，配額已經被覆蓋時讀作 0.00。
- **AI 依據**——AI 代理讀取近期快照，將其敘述建立在真實的進展之上，而非憑空想像的交易。

**一個團隊的達成率，不是各位銷售代表達成率的平均值。** 上面那個逐筆計算的**達成率（%）**，和你在儀表板上看到的彙總值，是刻意區分開的兩個數字。`attainment_pct` 是逐筆的，用 0 到 100 的百分數表示，所以 `106.00` 表示 106%。而 `forecast_metrics` 資料集的 **Attainment** 度量——*Quota Attainment by Rep* 表格以及任何建立在該資料集上的小工具用的都是它——是**先把兩邊分別求和、再相除**得到的 0–1 比值。這正是它的用意：先求和再相除，會按每位銷售代表所背的配額大小給出權重，而對各筆的百分數取平均，會讓背 20 萬配額的人和背 200 萬配額的人說話一樣響。按負責人或按週期分組，資料集就會算對；自己去平均那一欄欄位則不會。配額缺失時兩者也會分道揚鑣——欄位的保護讀作 0.00，資料集度量則乾脆不給值。

## 誰能編輯

預測繼承標準的 CRM 權限模型：

- **銷售代表**檢視並編輯自己的預測。
- **銷售經理**檢視並編輯其轄區內所有人的預測（透過角色層級）。
- **銷售營運**檢視所有預測，並可以覆蓋任何數字。
- 所有編輯都會在平台稽核日誌中被追蹤——每次承諾更改都會被歸因並加上時間戳。

## 常見問題

**我應該每週拍快照還是只在季末拍？**
每週。預測的全部價值在於趨勢，季末的單個快照什麼也告訴不了你。

**如果銷售代表在兩次快照之間移動了一筆交易會怎樣？**
兩個快照都會被保留。下次儀表板重新整理顯示新數字；趨勢圖將舊數字顯示為一個歷史點。

**預測能自動從商機彙總嗎？**
對當前季度來說，它已經在這麼做了——每晚的 **Forecast Snapshot** 流程做的正是這件事：銷售管道、最佳情況、承諾和已成交每晚都會從即時商機重新求和，寫回同一筆。**配額**是它唯一不會替你算的數字。物件*不*會做的，是在你讀取時重新計算已儲存的金額：一筆已結束週期的快照會保留寫入當時的值，這是有意為之。衍生欄位則正好相反——**達成率（%）** 和**覆蓋倍數**每次讀取時都從該筆自己已儲存的欄算出來，所以在一筆舊快照上把配額改對，不用重跑任何東西，那一筆的達成率就會跟著重新算出。

**這與已儲存的報告有何不同？**
報告針對*當前*資料執行。預測是一個*凍結*的數字——即使六個月後，檢視上季度的承諾也會給你銷售代表當時所擔保的數字，而不是從此後已經變動的記錄重新計算出的數字。
