# 共享与安全

共享回答这个问题：*“这个用户能查看和编辑哪些记录？”* 在 HotCRM 中，四个层级叠加在一起为你给出答案：

1. **组织范围默认值 (OWD)** —— 基线（“默认情况下，商机是私有的”）。
2. **角色层级** —— 经理自动看到其团队的记录。
3. **共享规则** —— 例外和开放（“EU 团队可以看到 EU 客户”）。
4. **客户团队** —— 记录级的“你和我一起在跟进这个客户”。

外加用于隐藏敏感字段的 **字段级安全**。

## 第 1 层 —— 组织范围默认值

OWD 是每个对象的 *最严格* 设置。其他一切要么放宽，要么维持访问权限。

| 对象 | 默认 OWD | 原因 |
| --- | --- | --- |
| Lead | 私有 | 代表跟进自己的潜在客户 |
| Account | 私有 | 客户所有权很重要 |
| Contact | 由父级控制（Account） | 可见性随客户而定 |
| Opportunity | 私有 | 敏感的交易数据 |
| Quote | 由父级控制（Opportunity） | 随交易而定 |
| Contract | 私有 | 敏感的商业条款 |
| Product | 公开只读 | 每个人都能看到目录 |
| Case | 公开读/写 | 服务团队中的任何人都可接手 |
| Campaign | 公开只读 | 营销创建，销售查看 |
| Campaign Member | 由父级控制（Campaign） | 随活动而定 |
| Task / Event | 私有 | 个人活动项 |

**OWD 的选项**：私有 / 公开只读 / 公开读/写 / 由父级控制。

⚠️ 出于安全考虑，**降低 OWD 是一道单向门** —— 从私有 → 公开很容易；要退回去可能需要清理共享规则。

## 第 2 层 —— 角色层级

角色层级是用于可见性的 **组织架构图**。经理自动看到其下属拥有的一切。

HotCRM 自带一个 10 角色的默认配置，可以干净地映射到一个典型的销售 / 服务 / 营销组织，在一个高管父级之下：

```
Executive
 ├── Sales Director
 │    └── Sales Manager
 │         └── Sales Representative
 ├── Service Director
 │    └── Service Manager
 │         └── Service Agent
 └── Marketing Director
      └── Marketing Manager
           └── Marketing User
```

一个 *Sales Director* 自动看到其下任何人拥有的每一个商机。他们看不到服务或营销记录（那些是同级，不是子级）。要将一个区域拆分为多个团队（例如 *Sales Manager — East* 和 *Sales Manager — West*），请克隆 **Sales Manager** 节点。

在 **设置 → 角色** 中配置角色。

## 第 3 层 —— 共享规则

共享规则在 OWD + 层级之外 **开放** 访问。它们处理这样的情况：

- *“所有北美代表都能看到所有北美客户，即便在其层级之外。”*
- *“客户成功团队可以读取所有活跃的客户账户。”*
- *“财务可以读取所有赢单的商机。”*

### 两种形式

| 类型 | 共享给谁 | 示例 |
| --- | --- | --- |
| **基于条件** | 任何匹配记录筛选条件的人 | *“Region = EU 的客户”* → 与 EU 公开组共享 |
| **基于所有者** | 某个组中用户拥有的所有记录 | *“SDR 拥有的所有记录”* → 与 AE 组共享 |

### 内置共享规则

HotCRM 开箱即带这些：

- **VIP 客户** —— 等级为 *Platinum* 的客户与所有高管以只读方式共享。
- **活跃合同** —— *Activated* 的合同与客户成功团队以只读方式共享。
- **赢单商机** —— *Closed Won* 的商机与财务团队以只读方式共享。
- **公开产品** —— 产品对所有用户只读。

在 **设置 → 共享设置** 中创建新规则。

## 第 4 层 —— 客户团队

对于由一个 **小组**（AE + SDR + SE + CSM）跟进的客户，**客户团队** 是一个针对每条记录的共享列表。每个成员可以对客户及其子记录拥有 **读取** 或 **读/写** 权限。

在 **设置 → 客户团队** 中配置团队模板，这样添加一个新的“企业小组”客户时会自动分配团队。

## 这些层级如何组合

如果以下任一条件为真，用户就能看到记录：

1. 他们 **拥有** 该记录。
2. 他们的 **权限档案** 在该对象上授予 *查看所有*。
3. **OWD** 为公开（或更高）。
4. **共享规则** 授予他们访问权限。
5. 他们在角色层级中 **高于** 所有者。
6. 他们在 **客户团队** 中（针对客户/商机/合同/案例）。
7. 该记录被 **手动共享** 给他们。

如果都不适用 → 无访问权限。（而且如果无访问权限，记录是不可见的 —— 不是“你没有权限”，而是从搜索和列表中直接 *消失*。）

## 字段级安全 (FLS)

FLS 控制一条记录内某个权限档案能查看和编辑 **哪些字段**。

常见用途：

- 对代表隐藏 **佣金 %**（只有经理才能看到）。
- 对非 HR 用户隐藏 **生日**。
- 让 **收入区间** 对除财务以外的所有人只读。

在 **设置 → 对象 → 字段 → 字段级安全** 中配置。

FLS 在 **任何地方** 都强制执行 —— 列表视图、报表、API、AI Copilot。如果一个字段被隐藏，Copilot 也无法引用它。

## AI Copilot 的共享

Copilot 代表用户行事 —— 它看到的恰好是用户看到的，不多不少。这意味着：

- 共享规则自动适用。
- FLS 自动适用。
- 运行 Copilot 的管理员会比代表看到更多 —— 这是设计使然。

不存在“AI 绕过” —— Copilot 无法泄露用户尚不能看到的数据。

## 给管理员的提示

- ✅ **从严格开始** —— 对 Lead/Account/Opportunity 使用私有 OWD。按需通过共享规则放开。
- ✅ **每季度审计共享规则** —— 它们会积累；修剪掉不再需要的。
- ✅ 使用 **公开组** 让共享规则易于管理（“与 EU 团队共享”而非“与这 47 个用户共享”）。
- ✅ 不要在权限档案中过度使用 **查看所有** —— 它是绕过每条共享规则的大锤。

## 给用户的提示

如果你认为自己应该能看到某条记录却看不到：

1. 检查 **谁拥有它**（在聊天中询问）。
2. 检查 **你是否在客户团队中**（打开客户 → 团队选项卡）。
3. 询问管理员是否应该添加一条 **共享规则**。

通常最干净的修复方式是把你加入客户团队，而非为所有人扩展一条共享规则。
