# HotCRM Documentation

**HotCRM** is a production CRM application built on top of [`@objectstack/runtime`](https://github.com/objectstack-ai/framework). Everything — objects, hooks, pages, flows, agents — is declared as **TypeScript metadata** and executed by the platform.

This is the documentation for the **current baseline** (v0.1). The baseline ships **10 core sales-cloud objects**, 10 server-side hooks, 12 pages, 5 automation flows and 2 AI agents. Iterations add capabilities incrementally — see [What's New](/docs/whats-new).

## What's in the Box (v0.1 Baseline)

| Layer | Items |
|---|---|
| **Objects** | account, contact, lead, opportunity, opportunity_line_item, product, quote, quote_line_item, contract, campaign, campaign_member, case, task |
| **Hooks** | 10 — field validation, status normalization, deletion protection |
| **Pages** | Home, App Launcher, Utility Bar, Account / Lead / Opportunity detail, Action Modals |
| **Views** | 10 — one list view per core object |
| **Flows** | 5 — automation pipelines |
| **Agents** | 2 — AI assistants |
| **Sharing** | 4 sharing rules + role hierarchy |
| **Seed Data** | ~90 records across 9 tables (verified on first sign-up) |

## Why HotCRM

- **Code-as-source-of-truth** — every field, hook, page, and flow is checked into git as TypeScript. No clicks-not-code drift between dev and prod.
- **AI-extensible** — agents and skills are first-class metadata; the same record can be operated by a human at `/_console/` or an LLM via the agent runtime.
- **Self-hosted** — runs on SQLite for dev and Postgres / MongoDB / Turso for production. No vendor lock-in.
- **Incremental** — iterations add 1 verified feature at a time. See [What's New](/docs/whats-new) for the changelog.
