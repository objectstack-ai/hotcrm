# 上线清单——配置 HotCRM

写给负责让 HotCRM 上线的管理员。请按顺序完成各步：每一步都依赖前一步。每一步背后的规则（谁能看到什么、每个门槛在哪里）写在本手册的其他页面里；这一页讲的是按什么顺序应用它们。

## 1. 决定如何处理演示数据

一个新的 HotCRM 组织在第一次启动时会被填入一家演示公司：客户、联系人、线索、商机、工单、报价单等等，让仪表盘有内容可看。这些演示记录归第一位管理员所有。设置里没有控制它的开关，由构建方式决定：

- 标准构建会把演示公司写入组织；
- 多组织构建只给每个新组织写入产品目录，别的都不写。

在标准构建上，请在导入你自己的数据**之前**清理掉不需要的演示记录：导入会把每一行匹配到已有的记录上，所以一个与演示客户同名的真实客户会更新那条演示记录，而不是新建你的客户。见[导入数据](./crm_admin_data_import.md)。

## 2. 把人加进来

在**设置 → 人员与组织 → 用户**里创建同事，或者在**邀请**里邀请他们。新用户在接下来两步给他权限之前没有任何 HotCRM 访问权；在那之前，HotCRM 会把他引到平台的访问申请页，而不是给他一个空的应用。

## 3. 给每个人分配岗位

岗位决定了一个人能做的大部分事情，也驱动着自动化。打开**设置 → 访问控制 → 岗位**，打开一个岗位，添加它的任职人。一个人可以同时担任多个岗位。担任一个岗位，就获得这个岗位的权限集；没有权限集的岗位只会扩大任职人能看到的记录范围。

有三个岗位是分配池，没有人担任时，相关的自动化起不了作用：

- **销售代表**——没有负责人的新线索（例如来自网页表单的线索）会分给手上未结线索最少的任职人。
- **客服专员**——没有负责人的新工单会分给手上未关闭工单最少的任职人。没有人担任时，新工单保持未分配。
- **服务经理**——升级的工单会分给手上未关闭工单最少的任职人。

还有两个岗位承担审批：**销售经理**审批新客户、线索转化和大额商机，**销售总监**还要签批最大的商机。另外，把各区域的销售代表加入**北美销售团队**或**欧洲销售团队**，他们才能编辑自己区域内的客户。每个岗位打开了哪些访问权，见[访问权限](./crm_admin_access.md)。

## 4. 检查权限集

日常使用的权限集由岗位分发。有两个权限集值得在**设置 → 访问控制 → 权限集**里手动检查：

- **系统管理员**——分配给负责运维 HotCRM 的人。它打开这本手册，并授予列表导出权限，而平台自带的管理员权限不包含导出。
- **CRM 用户**——HotCRM 给每个成员的底线权限：自己的线索、客户、商机、任务和活动，以及对产品、营销活动和知识库的读取权限。没有担任任何岗位的人，至少需要这个权限集才能在 HotCRM 里工作。

## 5. 开启计划任务

每天和每小时的扫描（停滞商机、报价单和合同过期、SLA 违约、续约和任务提醒）在部署开启计划任务之前都不会运行。在那之前，什么都不会过期，也不会发出任何提醒。如何开启，以及它启动的每个计划，见[自动化](./crm_admin_automation.md)。

## 6. 导入你的数据

先导入客户，再导入联系人，最后导入线索。顺序、匹配规则和可能遇到的拒绝，见[导入数据](./crm_admin_data_import.md)。

## 7. 以用户身份检查

**设置 → 人员与组织 → 用户**的行菜单里可以模拟某个用户登录。每种岗位各挑一个人登录，检查 HotCRM 是否打开在[快速上手](./crm_getting_started.md)所说的位置，以及侧边栏是否显示了他需要的内容。某人缺了某个入口，几乎总是第 3 步或第 4 步漏了一个岗位或权限集。
