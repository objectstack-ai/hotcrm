# 简介

**HotCRM 是一套客户与营收软件，面向任何销售产品、项目服务或订阅的公司。** 它把工作从第一次营销触达一路串到回款：线索与商机，报价、订单与合同，合同的回款计划以及财务据此记录的发票和回款，交付所售内容的项目，途中员工花出去的费用，以及之后的服务工单。它运行在其下的平台 [**ObjectStack**](https://github.com/objectstack-ai/objectstack) 之上。

## 六个应用

每条业务线都有自己的应用。应用启动器按每个人的工作提供他需要的应用。

| 应用 | 谁在里面工作 | 涵盖什么 |
| --- | --- | --- |
| [**销售**](/zh-Hans/docs/sales/index) | 销售代表、销售经理、销售管理层 | 线索、客户、联系人、商机、报价单、订单、合同、产品与价格表、预测、回款计划 |
| [**服务**](/zh-Hans/docs/service/index) | 服务坐席、服务经理 | 工单、SLA 与升级、知识库 |
| [**营销**](/zh-Hans/docs/marketing/index) | 营销人员 | 营销活动，以及它触达的线索、联系人和客户 |
| [**订单与回款**](/zh-Hans/docs/order-to-cash) | 应收会计、财务控制 | 每个客户的回款计划，以及发票和回款，有没有合同都可以 |
| [**项目交付**](/zh-Hans/docs/projects) | 项目经理、项目成员、财务控制 | 项目、按费率卡配置人员、预算、工时单，以及每个项目的成本 |
| [**费用报销**](/zh-Hans/docs/expenses) | 每一位员工 | 附带票据的费用、报销单及其审批与付款、出差申请 |

服务、营销、订单与回款、项目交付和费用报销是模块，产品与报价也是：管理员可以关掉其中一个，它的应用和条目随之消失，直到重新打开 —— 参见[启用和停用模块](/zh-Hans/docs/administration/modules)。产品、价格表、报价单和大额商机审批在[销售](/zh-Hans/docs/sales/index)下说明；仪表盘和报表在[分析](/zh-Hans/docs/analytics/index)下说明。

这些记录是**串联在一起**的：线索转化为客户、联系人和商机；接受报价单即赢下商机并创建订单，需要时再从订单起草合同；合同带着它的回款计划、发票和回款；项目写明它交付的商机、合同或订单；工单能看到客户的完整历史。

## HotCRM 面向谁

下面的角色，就是管理员在 **Setup → Position Holders** 中给人分配的岗位。

- **销售代表、销售经理、销售总监和高管** —— 线索、商机、报价、订单、合同和预测。
- **服务坐席、服务经理和服务总监** —— 按时解决客户工单。
- **营销人员、营销经理和营销总监** —— 开展营销活动，触达受众。
- **财务** —— 应收会计记录发票和回款；财务控制审批大项目、预算追加和报销单；两者都可以把已批准的报销单标记为已付款。
- **项目经理、项目成员、项目总监和 PMO** —— 交付项目、填报工时并审批。
- **每一位员工** —— 记录费用、提交报销单、出差前先申请。
- **管理员** —— 按业务配置系统。

## 它有何不同

### 1. 从第一次触达到回款，是同一套记录

销售、财务、交付和服务在同一批客户、合同和订单上工作，没有人需要把一笔交易再录进第二套系统，才能做回款计划或给项目配人。

### 2. 为智能体而建

HotCRM 提供对象、动作和技能；识别票据、核对制度、起草回复这类自动化，是**你的智能体**的工作，它通过 MCP 接入。智能体以它所接入的那个人的身份行事，权限与共享规则都和这个人一样。HotCRM 不自带助手：助手是平台的，HotCRM 用八项技能教会它。参见 [AI 与智能体](/zh-Hans/docs/ai-copilot/index)。

### 3. 流程开箱即配好

大额商机、项目、预算追加、工时单、报销单和出差申请的审批，SLA 升级，以及合同续约提醒都已内置（其中定时运行的那些，要管理员打开定时任务后才会运行）。按需调整即可，不必从头搭建。

### 4. 建立在元数据优先的平台上

每个对象、字段、规则、页面和流程都是 Git 仓库里的元数据，运行在 ObjectStack 上。如果你是开发者，参见[开发者](/zh-Hans/docs/developers/index)，了解这在实践中意味着什么。

## 开箱即带什么

- **38 个业务对象**，覆盖销售、服务、营销、营收、订单与回款、项目交付和费用报销，带有各自的字段、选项列表和校验。
- **18 个岗位** —— 按业务线分发记录访问权的扁平分组。岗位之间不向上汇总，所以每个需要某条记录的岗位，都由它自己的共享规则点名。
- **55 个流程** —— 审批、线索分配、赢单与合同通知、续约与到期巡检、SLA 升级、项目与费用审批，以及两个计费交接事件。
- **标准列表视图、仪表盘和报表**，每个应用都有。
- **八项 AI 技能**，供平台智能体使用 —— 实时数据、线索资格判定、邮件撰写、营收预测、客户 360°、工单分流、费用代填和费用检查 —— 以及九个对智能体开放的动作：线索上的**转化线索**和**安排跟进**，以及**提交报销**等七个费用和出差申请的步骤。
- **一个知识文章库**，用于支持内容：一个对象、七个分类，智能体像读其它记录一样读取它。
