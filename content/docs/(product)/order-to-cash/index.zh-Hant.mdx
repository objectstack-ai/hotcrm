# 訂單與回款

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

合約簽訂後，業務最關心三個問題：**開票了嗎？回款了嗎？有沒有逾期？**「訂單與回款」回答的就是這三個問題。它是 HotCRM 的一個模組，位於側邊欄的 **Order to Cash** 下。

## 是窗口，不是帳本 [#a-window-not-a-book]

每張發票、每筆回款都保存在財務記帳的地方：ERP、會計軟體，或財務自己的紀錄。「訂單與回款」是業務**查看**它們的窗口。財務在紀錄頁面上輸入，或批次匯入；ERP 也可以透過同一個匯入編號寫入。數字從不在 HotCRM 裡更正：在源頭更正後，再以同樣的方式進來。

因此這個模組不做任何記帳。它不開立、不審核發票，不分攤收款，不與銀行對帳，不催收，也不認列收入。[與財務軟體的邊界](/zh-Hant/docs/sales/billing-handoff)一頁介紹了在贏單和合約生效時仍會通知計費系統的兩個事件。

業務在這裡維護的只有一樣東西：自己的**回款計劃**。

## 包含什麼 [#what-is-in-it]

| 紀錄 | 是什麼 | 由誰輸入 |
| --- | --- | --- |
| **Payment Plan** | 按訂單或合約制定的回款計劃中的一步：預付款、上線、驗收、保留款，或一個訂閱週期 | 客戶的業務團隊 |
| **Invoice** | 財務開給客戶的一張發票，可以針對訂單或合約，也可以都不針對 | 財務 |
| **Payment** | 客戶付來的款項：對應回款計劃、訂單、合約，或暫時都不對應 | 財務 |

三者都屬於**客戶**。回款計劃寫明它按哪張訂單或哪份合約制定；發票和回款只在有訂單或合約時才填。發票和回款**並行**：回款不填發票，收了多少看回款計劃和訂單，不逐張看發票。所以一張發票對應多個訂單，或暫時對應不上任何東西的預收款，都只記在客戶上。客戶的 **Payment Plans**、**Invoices** 和 **Payments** 分頁列出它的全部紀錄；訂單和合約的分頁列出填了它的紀錄。歸在合約下的訂單，它的紀錄兩者都填，所以合約的分頁和彙總包括它所有訂單下的紀錄。

## 在哪裡找到它 [#where-to-find-it]

| 誰 | 在哪裡 |
| --- | --- |
| 財務（應收會計） | **Order to Cash** 應用：**Receivables** 下的 **Invoices**、**Payments** 和 **Payment Plans**，**Follow-up** 下的 **Overdue Payment Plans** 和 **Planned This Month**，以及這些紀錄所屬的 **Contracts** 和 **Accounts**。這是財務啟動器上唯一的應用。 |
| 銷售代表和銷售經理 | **Sales** 應用 **Collection Plan** 群組下的 **Payment Plans**，以及每張訂單和每份合約上的 **Payment Plans**、**Invoices**、**Payments** 分頁。銷售代表的啟動器上沒有 Order to Cash 應用。 |
| 銷售經理和管理員 | 兩處都有：他們的啟動器提供全部四個應用。 |

啟動器決定的是提供哪些應用，而不是能打開哪些：啟動器上沒有的應用，用位址照樣能打開；每筆紀錄的存取權限仍由它的共用規則決定。

## 誰能做什麼 [#who-can-do-what]

| 人員 | 回款計劃 | 發票與回款 |
| --- | --- | --- |
| 業務代表 | 在自己能查看的客戶上新增、編輯、刪除回款計劃 | 唯讀 |
| 業務經理 | 在自己能查看的客戶上新增、編輯、刪除回款計劃 | 唯讀 |
| Accounts Receivable（財務） | 唯讀 | 在所有客戶上輸入、編輯、刪除和匯入 |
| 管理員 | 全部 | 全部 |

能查看客戶，就足以按上表寫入它的回款計劃、發票和回款：業務代表不用編輯客戶或合約就能維護回款計劃，財務在只能查看的客戶上輸入發票和回款。不能查看客戶的人，這三類紀錄都寫不了。

其他能查看客戶的人，在其角色本身能查看這些紀錄的範圍內，也能隨客戶一起查看它的回款計劃、發票和回款：這三類紀錄跟隨客戶的共用設定。財務的權限來自 **Accounts Receivable** 職位，由管理員在 **Setup → Position Holders** 中指派。

業務從不輸入回款。業務看到的數字永遠是財務輸入的，所以按回款計算的獎金方案不會讀到業務自己填寫的數字。

## 不是每個客戶都要用 [#not-every-customer-uses-it]

不需要「訂單與回款」的公司，由管理員停用這個模組。它的應用、Sales 應用裡的選單項目、紀錄，以及訂單、合約和客戶頁面上的相關分頁和彙總數字都會隨之消失；訂單本身照常可用。

## 訂單、合約和客戶上的彙總 [#totals]

訂單、合約和客戶上各有本模組的彙總數字，業務不用打開分頁就能看到（介面名稱依 zh-CN 語言包的繁體寫法）：

| 欄位 | 所在紀錄 | 統計什麼 |
| --- | --- | --- |
| **計劃回款** | 訂單、合約 | 回款計劃各節點的計劃金額合計 |
| **已開票** | 訂單、合約、客戶 | 狀態為**已開具**的發票金額合計；已作廢的發票不計入 |
| **已回款** | 訂單、合約、客戶 | 回款金額合計 |
| **未回款** | 訂單、合約、客戶 | 訂單上是 **Total Price** 減去**已回款**；合約上有 Confirmed 或 Completed 的訂單時是 **Order Amount**（這些訂單的金額）減去**已回款**，否則是 **Contract Value** 減去**已回款**；都不低於零。客戶上是它已簽下的每筆交易的未回款之和（見下文） |
| **未開票** | 訂單、合約、客戶 | 同上，用**已開票**代替**已回款** |

客戶的**已開票**和**已回款**涵蓋該客戶的所有發票和回款，包括沒填訂單或合約的；訂單和合約的彙總涵蓋填了它的紀錄。客戶的**未回款**和**未開票**把每筆已簽下的交易算一次：每張 **Confirmed** 或 **Completed** 的訂單，以及每份沒有訂單的 **Activated** 或 **Expired** 合約。有訂單的合約透過訂單統計，所以框架合約的上限金額永遠不會算成欠款；草稿和已取消的訂單、尚未簽訂的合約都不計入；只填了客戶的預收款計入**已回款**，但在財務填上它付的是什麼之前，不會減少任何一筆交易的未回款。這些數字都不是手動填寫的：儲存回款計劃、發票、回款、訂單或合約時隨之更新。在訂單上，它們顯示在「價格」區段；在合約上，顯示在「合約金額」區段；在客戶上，顯示在「財務資訊」區段。交易業績只按訂單自己的合計統計，從不統計這些數字。能查看訂單或合約的人都能看到它上面的彙總。客戶上的彙總要有和客戶款項打交道的角色才能看到：業務、財務、行銷、服務、項目經理和管理員都能看到；只有每個成員都有的 **CRM User** 權限集的人，以及參與項目的顧問，能查看客戶，但看不到這些彙總。沒有人能編輯。

**訂單上的紀錄跟著訂單的合約走。** 訂單的回款計劃、發票和回款已經儲存之後，訂單才有了合約（點了**起草合同**，或選了訂單的**關聯合同**），這些紀錄裡沒填合約的會帶上訂單的合約，合約的彙總隨即把它們算進去，不需要逐筆重新儲存。把訂單改到另一份合約下時，原來跟著舊合約的紀錄一起改到新合約：舊合約的彙總減少，新合約的彙總增加。清空訂單的合約時，這些紀錄的合約也一起清空，訂單下一次有了合約（例如點了**起草合同**）再把它們補上。填了其他合約的紀錄保持不變。這一改動替修改訂單的人完成，所以業務改訂單會連帶改掉財務的發票和回款上的合約，此外什麼都不改；每筆紀錄的歷史裡都能看到這次修改。
