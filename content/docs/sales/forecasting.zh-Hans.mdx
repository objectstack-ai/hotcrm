# 预测

**预测**是某一时刻销售管道的冻结快照。每个负责人每个周期一条记录——通常是每位销售代表每季度或每月一条。你通过堆叠快照来构建趋势（"我们的 Q3 数字逐周是如何变化的？"），而不是通过重新读取实时商机数据。

本页讲的是存储这些快照的**预测对象**。关于*生成*预测叙述的 AI 对话，请参见 **AI Copilot → 营收预测**。

## 预测记录上存储的内容

| 区块 | 字段 |
| --- | --- |
| **周期** | 负责人、周期（`month` / `quarter`）、周期开始。周期结束和友好标签（例如 **Q3 2026**）是派生的。 |
| **数字** | 配额、销售管道金额、最佳情况金额、承诺金额、已成交金额。 |
| **派生** | **预期金额**、**达成率（%）** 和 **覆盖倍数**——由上面这些数字逐行算出的公式字段。没有人需要录入它们。 |
| **来源** | `scheduled`（每晚作业）、`ai`（Copilot 生成）、`manual`（销售代表录入）。 |
| **叙述** | 可选的评述——发生了什么变化、什么有风险、下次一对一要问什么。 |

销售管道、最佳情况、承诺和已成交是相互独立的桶——它们回答不同的问题：

- **销售管道**——本周期内的每一笔开放交易，无论信心如何。
- **最佳情况**——销售代表认为通过冲刺努力可以赢下的交易。
- **承诺**——销售代表愿意以自己名义担保的交易（按惯例 ≥ 80% 概率）。
- **已成交**——已经赢得；无法移动。

## 周期是如何派生的

你输入 `period` 和 `period_start`；系统计算其余部分。对于一个从 2026-07-01 开始的季度预测：

- `period_end` → 2026-09-30
- `period_label` → **Q3 2026**

因此你绝不会看到一条标记为"2026-07-01 至 ???"的记录——只有人类可读的标签。列表视图和仪表盘会直接按 `period_label` 分组。

## 预测是如何创建的

有三种来源，记录在 `source` 字段中：

1. **Scheduled**——**Forecast Snapshot** 流程每晚 3 点运行，为每一位手上至少还有一笔进行中交易的销售代表拍下**当前季度**的快照。这是历史趋势的脊柱。重跑一次只会刷新同一行，所以数字既会上升也会下降；它从不写入**配额**，配额始终保持经理设定的值。
2. **AI**——HotCRM 里没有任何东西会写入这个值。**营收预测**（Revenue Forecasting）Copilot 技能是只读的：它组合 `describe_object`、`aggregate_data`、`query_records` 和 `visualize_data` 读取实时商机数据，并**在对话里**作答——加权销售管道、有风险的交易，以及在图比文字更能说明问题时给出一张图。它不会开出任何一条预测记录，对话内容也没有地方可放：**Notes** 是唯一的叙述性列，而且要由人手工填写。这个值是留给你自己的 agent 或集成所写入的快照的；Copilot 对话永远不会产出一条。
3. **Manual**——经理直接录入一个数字。用于调整和覆盖。

你可以为同一个负责人/周期拥有全部三种——它们在趋势图中并排显示，因此分歧是可见的。

**当前季度只有一个自动写入方。** 当前季度的行由每晚的定时快照打开，此外没有任何东西会去打开它——新组织附带的演示数据刻意停在这个窗口的边缘，只播种已结束的季度和当前月份，因此绝不会与定时快照写入的行相撞。在一个刚播种的组织上，由此带来两个后果，它们都是预期行为，而不是故障：

- **当前季度的行，在凌晨 3 点的定时快照首次跑完之前并不存在。** 在那之前，任何限定在*本季度*的东西——尤其是销售仪表盘的 *Quota Attainment by Rep* 表格——空着才是对的。已结束的季度和当前月份则从一开始就有数据。
- **定时快照打开的每一行，配额都是空的，并且一直空到有人手工填上为止。** 没有任何自动化会写配额。配额是达成率那个靠人工维护的分母，一个每晚重置它的作业只会抹掉销售代表真正要负责的那个数字。

## 你用它们来做什么

- **汇总仪表盘**——销售仪表盘的 *Quota Attainment by Rep* 表格显示每位销售代表**当前季度**的配额、已成交收入与达成率。它读的正是这些快照，所以在定时快照打开当前季度之前它是空的；而如果还没有人给某位销售代表设配额，他那一行仍然会出现，只是没有达成率——数据集的比值度量遇到缺失的配额时不会去做除法，而是直接不给值。
- **趋势**——选择一个负责人和一个周期，按每个快照的 `created_at` 绘制 `commit_amount` 的图表。突然的下降会触发*"为什么这周承诺下降了 ¥800k？"*的对话。
- **达成率**——**有**专门的字段，不需要你在报表层重建它。**达成率（%）**（`attainment_pct`）是每条快照上的一个公式字段——`closed_amount ÷ quota × 100`，只读这一行自己的两个列——并且它是三个预测列表视图上都有的一列，记录表单上也有。零值是有保护的：配额为 0、或者还没有配额时，它读作 **0.00** 而不是报错，所以一个没设好的分母永远不会把视图弄坏。**覆盖倍数**（`coverage_ratio`）就在它旁边，形状完全一样——`管道金额 ÷（配额 − 已成交）`，配额已经被覆盖时读作 0.00。
- **AI 依据**——AI 代理读取近期快照，将其叙述建立在真实的进展之上，而非凭空想象的交易。

**一个团队的达成率，不是各位销售代表达成率的平均值。** 上面那个逐行计算的**达成率（%）**，和你在仪表盘上看到的汇总值，是刻意区分开的两个数字。`attainment_pct` 是逐行的，用 0 到 100 的百分数表示，所以 `106.00` 表示 106%。而 `forecast_metrics` 数据集的 **Attainment** 度量——*Quota Attainment by Rep* 表格以及任何建立在该数据集上的小部件用的都是它——是**先把两边分别求和、再相除**得到的 0–1 比值。这正是它的用意：先求和再相除，会按每位销售代表所背的配额大小给出权重，而对各行的百分数取平均，会让背 20 万配额的人和背 200 万配额的人说话一样响。按负责人或按周期分组，数据集就会算对；自己去平均那一列字段则不会。配额缺失时两者也会分道扬镳——字段的保护读作 0.00，数据集度量则干脆不给值。

## 谁能编辑

预测继承标准的 CRM 权限模型：

- **销售代表**查看并编辑自己的预测。
- **销售经理**查看并编辑其辖区内所有人的预测（通过角色层级）。
- **销售运营**查看所有预测，并可以覆盖任何数字。
- 所有编辑都会在平台审计日志中被跟踪——每次承诺更改都会被归因并加上时间戳。

## 常见问题

**我应该每周拍快照还是只在季末拍？**
每周。预测的全部价值在于趋势，季末的单个快照什么也告诉不了你。

**如果销售代表在两次快照之间移动了一笔交易会怎样？**
两个快照都会被保留。下次仪表盘刷新显示新数字；趋势图将旧数字显示为一个历史点。

**预测能自动从商机汇总吗？**
对当前季度来说，它已经在这么做了——每晚的 **Forecast Snapshot** 流程做的正是这件事：销售管道、最佳情况、承诺和已成交每晚都会从实时商机重新求和，写回同一行。**配额**是它唯一不会替你算的数字。对象*不*会做的，是在你读取时重新计算已存储的金额：一条已结束周期的快照会保留写入当时的值，这是有意为之。派生字段则正好相反——**达成率（%）** 和**覆盖倍数**每次读取时都从该行自己已存储的列算出来，所以在一条旧快照上把配额改对，不用重跑任何东西，那一行的达成率就会跟着重新算出。

**这与已保存的报告有何不同？**
报告针对*当前*数据运行。预测是一个*冻结*的数字——即使六个月后，查看上季度的承诺也会给你销售代表当时所担保的数字，而不是从此后已经变动的记录重新计算出的数字。
