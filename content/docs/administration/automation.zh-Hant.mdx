# 自動化

自動化讓 HotCRM *為你完成工作* —— 傳送通知、更新欄位、建立任務、升級案例，全程無需任何人點擊按鈕。提供五種自動化，每一種都適用於不同的工作。

> **HotCRM 如何實作它們：** 驗證與欄位邏輯以 **物件鉤子**（`beforeInsert` / `beforeUpdate`）執行；所有多步驟、排程或審批類邏輯以 **流程** 執行；審批則是 **流程中的 `approval` 節點**（ADR-0019），而非獨立的審批流程類型。平台同樣支援獨立的工作流規則與審批流程中繼資料 —— 下文一併列出以供參考。

## 五種類型

| 類型 | 觸發時機 | 最適合 |
| --- | --- | --- |
| **驗證規則** | 儲存前 | 攔截不良資料 |
| **工作流規則** | 儲存後 | 欄位更新、簡單的電子郵件提醒 |
| **流程** | 螢幕、記錄變更或按排程 | 多步驟邏輯、分支、迴圈、等待、審批 |
| **排程作業** | 按排程 | 每日清掃、每週報表 |
| **審批流程** | 流程中（approval 節點） | 帶記錄鎖定的多步驟簽核 |

## 驗證規則

最簡單的類型。當某個條件為真時，它們會阻止儲存。

**內建範例**：

- *「結束日期必須晚於開始日期」*（用於合約）。
- *「標價必須大於零」*（用於產品）。
- *「行銷活動成員必須有一個潛在客戶或一個聯絡人，但不能兩者都有」*（用於行銷活動成員）。
- *「折扣百分比必須介於 0 和 100 之間」*（用於報價行項目）。

要新增一條：

1. **設定 → 物件 → 驗證規則 → 新增**。
2. 撰寫條件（*失敗* 條件）。
3. 撰寫向使用者顯示的錯誤訊息。
4. 啟用。

## 工作流規則

當記錄在儲存後匹配某個條件時觸發。每條規則可以執行一項或多項 **操作**。

**操作類型**：

- **欄位更新** —— 變更同一條記錄或父記錄上的欄位。
- **電子郵件提醒** —— 向特定收件人傳送範本化郵件。
- **建立任務** —— 為記錄所有者或其他使用者建立。
- **出站訊息** —— 觸發一個 webhook。

**內建範例**：

- *評級為 Hot 的潛在客戶建立* → 向銷售經理發郵件 + 建立一個 *「24 小時內確認資格」* 任務。
- *商機贏單，金額 ≥ $100K* → 向團隊傳送慶祝郵件，在 #wins 頻道發文。
- *案例優先級變更為 Critical* → 通知值班工程師。

## 流程（多步驟）

當單純的欄位更新不夠用時 —— 分支、迴圈、等待、跨物件寫入、審批 —— 使用 **流程**。流程是一張視覺化的節點圖：取得資料 → 判斷 → 建立/更新記錄 → 通知 → 等待 → 呼叫子流程。

流程有三種觸發方式，由起始節點決定：

- **螢幕（Screen）** —— 從按鈕/操作手動啟動，在螢幕上收集輸入。
- **記錄變更（Record change）** —— 在記錄插入/更新時觸發（`record-after-create` / `record-after-update`）。
- **排程（Schedule）** —— 按 cron 排程執行。

> **自動觸發需要 `triggers` 能力。** 記錄變更與排程類流程，只有當 stack 的 `requires` 列表包含 `triggers` 時才會觸發 —— 它會安裝記錄變更與排程觸發器提供方（排程觸發器還依賴 job 服務）。螢幕類流程始終為手動啟動。

**HotCRM 中的內建流程**（10 個）：

| 流程 | 觸發 | 它做什麼 |
| --- | --- | --- |
| **潛在客戶轉換** | 螢幕 | 將合格潛在客戶轉換為客戶 + 聯絡人（+ 可選商機），然後通知 |
| **報價生成** | 螢幕 | 從商機生成報價，並將其推進到 *Proposal* |
| **潛在客戶指派與路由** | 記錄變更（插入） | 按評級寫入跟進 SLA，並將新線索路由到銷售經理佇列 |
| **商機審批** | 記錄變更 | 透過 approval 節點分級簽核 —— 銷售經理 > $100K，銷售總監 > $500K |
| **案例升級** | 記錄變更 | 當案例變為 *Critical* 時，重新指派給資深客服、通知、建立跟進任務 |
| **案例滿意度回訪** | 記錄變更 + 等待 | 案例關閉後等待 1 天，再提醒負責人收集滿意度評分 |
| **活動登記** | 排程（週一 9 點） | 批次將匹配的潛在客戶登記進活動 |
| **合約續約提醒** | 排程（每日 8 點） | 為臨近 `end_date` 的合約開出續約任務/商機 |
| **案例 SLA 監控** | 排程（每小時） | 標記並升級超過 SLA 到期時間的未結案例 |
| **停滯商機提醒** | 排程（每日 7:30） | 提醒負責人關注在某階段停留過久的未結商機 |

流程內的通知由 **`notify` 節點** 投遞（透過訊息服務傳送站內信 + 郵件）—— 而非舊的 `script`/郵件步驟（在 7.4 中已是空操作）。

如果你需要建構新的流程，請參見 [自訂 › 擴充物件](/zh-Hant/docs/customization/extending-objects)。

## 排程類自動化

基於時間的自動化以 **排程類流程** 實作 —— 即起始節點帶 cron 排程的流程，見上表中四個 `排程` 行（活動登記、合約續約、SLA 監控、停滯商機提醒）。它們透過 job 服務執行，因此 `triggers` 能力需與 `job` 搭配（兩者都在預設能力集中）。

無需編排的日期驅動欄位邏輯 —— 例如為報價設定預設過期日、凍結已過期/已接受的報價、推導預測週期 —— 放在輕量的 **物件鉤子**（`beforeInsert` / `beforeUpdate`）中，而非排程清掃。

## 審批

自 ObjectStack 7.4 起，審批被建模為 **流程中的 `approval` 節點**（ADR-0019），而非獨立的審批流程類型。進入節點時會建立審批請求、在該步驟待批期間 **鎖定記錄**、將即時狀態鏡像到 `approval_status` 欄位，並沿 *approve* / *reject* 分支繼續。

HotCRM 內建的 **商機審批** 流程串聯兩個 approval 節點實作分級簽核（經理 → 總監）。關於閾值、審批人所見以及稽核軌跡，參見 [收入 › 審批](/zh-Hant/docs/revenue/approvals)。

## 操作順序

當一條記錄被儲存時，順序是固定的：

1. **系統** 執行自動計算（公式欄位、自動編號）。
2. **驗證規則** 執行 —— 如果有任何失敗，儲存被阻止。
3. **記錄被儲存** 到資料庫。
4. **工作流規則** 觸發。
5. **流程觸發器** 觸發。
6. 來自工作流 / 流程的 **欄位更新** 可能級聯 —— 重新評估工作流最多 5 次後停止。
7. **電子郵件提醒** 進入佇列。

理解這個順序有助於除錯 *「為什麼我的工作流沒有觸發？」* 這類問題。

## 電子郵件範本

大多數自動化操作會傳送電子郵件。範本位於 **設定 → 電子郵件範本**，並支援：

- **合併欄位** —— `{{Opportunity.Name}}`、`{{Account.Owner.Email}}`。
- **條件區塊** —— 僅在條件為真時顯示。
- **HTML + 純文字** 版本。
- **附件** —— 報價 PDF、合約 PDF。

內建範本涵蓋潛在客戶路由、商機贏單、案例確認、合約啟用、續約提醒。

## 在哪裡監控自動化

- **設定 → 流程監控器** —— 過去 24 小時的自動化執行及其成功/失敗。
- **設定 → 工作流佇列** —— 待處理的電子郵件提醒和欄位更新。
- **設定 → 排程作業 → 歷史** —— 每個排程作業的過往執行。
- **物件 → 稽核日誌** —— 記錄上發生了什麼變化，誰/什麼進行了變更。

## 給管理員的提示

- ✅ **驗證規則** 是強制資料品質最廉價的方式 —— 放開手用。
- ✅ **每個條件一個工作流** 比有 10 個分支的超級工作流更易於維護。
- ✅ 對於任何超過 2 個操作的複雜邏輯，**使用流程** —— 除錯起來容易得多。
- ✅ 在生產中啟用前 **在沙箱中測試** —— 糟糕的自動化會快速級聯。
- ✅ 在描述欄位中 **記錄每條規則的作用** —— 未來的你會感謝現在的你。

## 給使用者的提示

如果一條記錄的行為不符合預期：

1. 檢查 **稽核日誌** —— 該欄位是被工作流更新的嗎？
2. 檢查 **任務清單** —— 工作流是否自動建立了一個你錯過的任務？
3. 請管理員檢查該記錄的 **流程監控器**。
