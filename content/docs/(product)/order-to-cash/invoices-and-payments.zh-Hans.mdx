# 发票与回款

这里的**发票**，是财务在自己系统中开具的一张发票的记录；**回款**，是收到款项的记录。两者都由财务录入或导入。销售在客户、订单、合同和**订单与回款**下的列表中查看它们。

两者都属于**客户**，而且**并行**：回款不填发票。发票填它开给的订单或合同；回款填它收的回款计划，或它付的订单或合同。一张发票对应多个订单，或暂时对应不上任何东西的预收款，只需填客户。客户还欠多少看订单、合同和客户上的**未回款**，什么逾期看回款计划，不逐张看发票。

**应收会计**岗位在所有客户上录入和导入它们。这个岗位能查看所有客户，但不能编辑任何客户：能查看客户，就足以写入它的发票和回款。

## 发票 [#invoices]

| 字段 | 内容 |
| --- | --- |
| **发票号码** | 财务开具的发票上的号码 |
| **客户** | 这张发票开给的客户。必填；选择订单或合同时自动带出 |
| **订单** | 这张发票针对的订单（如有）。选择订单会带出它的客户，归在合同下的订单还会带出这份合同；另一个客户的订单会被拒绝 |
| **合同** | 这张发票针对的合同（如有） |
| **开票日期** | 开具的日期 |
| **到期日** | 应付款的日期（见下文） |
| **金额** | 开票金额，含税 |
| **状态** | **已开具**或**已作废** |
| **发票文件** | 发票文件（如已附上） |

**到期日。** **到期日**留空时，保存时会自动填写：**开票日期**加上合同的**付款条款**；没有合同或合同没填付款条款时，取订单的**付款条款**（Net 15、30、60 或 90 天；Due on Receipt 即开票当天）。填写了日期则按填写的保存。既没有订单也没有合同的发票没有付款条款可用，请手工填写到期日。

**已作废的发票。** 在源头作废或全额红冲的发票，在这里设为**已作废**。它随即退出所有统计：订单、合同和客户的**已开票**不再计入它，**未开票**相应增加。

## 未回款与未开票 [#unpaid-and-uninvoiced]

| 数字 | 订单上 | 合同上 |
| --- | --- | --- |
| **未回款** | **总金额**减去**已回款** | 有已确认或已完成的订单时**订单金额**减去**已回款**，否则**合同金额**减去**已回款** |
| **未开票** | **总金额**减去**已开票** | 有已确认或已完成的订单时**订单金额**减去**已开票**，否则**合同金额**减去**已开票** |

有订单的合同按实际下单的金额计算，不按合同金额：一份 1,000,000 的框架合同，下单 600,000、已开票 100,000 时，未开票是 500,000。实际下单的金额只算**已确认**和**已完成**的订单：草稿和已取消的订单不计入，订单全是草稿或已取消的合同按合同金额计算。草稿订单确认后即计入。在订单上录入的发票和回款会带上订单的合同，所以合同的**已开票**和**已回款**会算进它们，每条只算一次。

两者都不低于零：超过应收的回款照样接受，无论是手工录入还是导入，因为这笔钱确实收到了，未回款到零为止。客户上的**未回款**和**未开票**把它已签下的每笔交易各自的数加起来，每笔只算一次：每张**已确认**或**已完成**的订单，以及每份没有订单的**已激活**或**已过期**合同。哪些计入，见[订单、合同和客户上的汇总](/zh-Hans/docs/order-to-cash#totals)。

**什么算逾期**看的是回款计划：过了**计划日期**仍有未回款金额的节点，在「订单与回款」应用的**跟进 → 逾期回款计划**里。见[回款计划](./collection-plan)。

## 回款 [#payments]

| 字段 | 内容 |
| --- | --- |
| **回款编号** | 自动编号：PAY-00001、PAY-00002…… |
| **客户** | 付款的客户。必填；选择订单、合同或回款计划时自动带出 |
| **订单** | 这笔款项针对的订单（如有）。留空时从回款计划带出 |
| **合同** | 这笔款项针对的合同（如有）。留空时从订单带出，没有订单时从回款计划带出 |
| **回款计划** | 这笔款项计入的节点（如有）。选择后带出它的客户；另一个客户的会被拒绝 |
| **回款日期** | 收到款项的日期 |
| **金额** | 收到多少 |
| **方式** | **银行转账**或**其他** |

**每个节点一行。** 一笔收款结清了多个节点或多张订单时，按财务已有的拆分，每个节点或每张订单记录一笔回款。HotCRM 中没有分摊这一步。

**预付款。** 把回款记录到回款计划或订单上；还没有任何东西对应时，只记在客户上。之后开具发票时不用再填什么：发票和回款不做匹配。

**针对其他客户的回款计划的回款会被拒绝**，提示会写明是哪一个。表单会列出所有客户的回款计划，所以这项检查在保存时进行。

**发票或回款上选择另一个客户的订单或合同会被拒绝**，提示会写明是哪一个。填了订单之外的另一份合同，或订单和合同属于不同客户，同样会被拒绝。导入时 **Account** 留空，就由订单或合同带出。

## 导入 [#importing]

财务可以用**Invoice Import (CSV)** 和 **Payment Import (CSV)** 两个导入映射，从电子表格、财务软件或 ERP 的导出文件批量导入发票和回款。带有正确列标题的模板是 `assets/import-templates/` 下的 `invoices.csv` 和 `payments.csv`。

| 列 | 发票 | 回款 |
| --- | --- | --- |
| ERP Reference | ✓ 唯一编号 | ✓ 唯一编号 |
| Account | ✓ 客户名称；填了订单或合同时可留空 | ✓ 填了订单、合同或节点时可留空 |
| Order | ✓ 订单编号，例如 SO-0001，或订单的**外部编号**；可选 | ✓ 可选 |
| Contract | ✓ 合同编号，例如 CTR-0001；可选 | ✓ 可选 |
| Invoice Number | ✓ | — |
| Billing Milestone | — | ✓ 节点名称 |
| Issue Date、Due Date、Amount、Status | ✓ | — |
| Payment Date、Amount、Method | — | ✓ |

- **ERP 编号是唯一键。** 导入一行时，如果它的 **ERP 编号**已在某张发票上，就更新这张发票，而不会再添加一张。因此财务修改文件后可以再次导入。ERP 通过接口写入时使用同一个编号。
- **每一条导入的记录都有标记。** 它的**来源**为**导入**，**同步时间**为导入的时刻，读者可以看出数字从哪里来、有多新。手工录入的记录，来源为**手工录入**。
- **引用按名称匹配。** 客户名称、订单编号或外部编号、合同编号或节点名称匹配不到任何记录时，该行导入失败，导入报告会写明原因。客户、订单和合同都没填（回款还可以是节点）的行同样失败：客户是必填的。
- **多份合同上有同名节点时，该行导入失败。** 节点常常同名（「预付 30%」「第二年」），而导入会在所有合同里查找这个名称，不只在该行的合同里查找，所以导入报告会写「匹配到多条记录」。这时在 **Payment Plan** 列填写节点的记录 ID，它在节点页面地址的末尾。两个客户同名时，**Account** 列也会这样失败。
- **一笔收款分到两张订单时是两行回款**，各需要自己的 **ERP 编号**，而它是唯一的。请和生成文件的一方约定编号规则，例如收款编号加订单编号。

金额使用公司的币种，与 HotCRM 中所有金额一样。请在导入前完成换算。
