# 实时模式——会自我改写的 CRM

大多数"AI CRM"是在一个静态模式之上外挂一个聊天机器人。一旦管理员添加了一个自定义字段，机器人就会出错：它依据的是上周训练时的模式，而非你今天发布的模式。

HotCRM 与众不同。**模式即系统提示词。**

每次销售 Copilot 回答数据问题时，它都会针对 `@objectstack/runtime` 的元数据服务调用 `describe_object`——该服务会重新读取实时注册表。在 10:00:00 添加一个字段，下一位用户在 10:00:05 提问时就能看到它。

## 30 秒演示

```bash
# 1. Admin adds a field — no migration, no deploy.
curl -X POST $HOTCRM/api/v1/ai/tools/add_field/invoke \
  -d '{
    "objectName": "crm_account",
    "name": "health_score",
    "label": "Health Score",
    "type": "number"
  }'

# 2. Sales rep asks Copilot — five seconds later.
curl -X POST $HOTCRM/api/v1/ai/chat \
  -d '{
    "agent": "sales_copilot",
    "messages": [{ "role": "user",
      "content": "Top 5 accounts by health_score — cite IDs." }]
  }'
```

Copilot 的工具调用轨迹：

1. `describe_object('crm_account')` → 看到 `health_score`（number）。
2. `query_records('crm_account', orderBy: [{ field: 'health_score', order: 'desc' }], limit: 5)`。
3. 返回带有记录 ID 的排序列表。

总耗时：不到 30 秒。无需重新训练。无需重启。无需部署任何东西。

## 为什么这能成立

| 层级            | 它的作用                                                                   |
|------------------|--------------------------------------------------------------------------------|
| 元数据服务 | 对象 + 字段的单一事实来源。每次写入时热重载。       |
| `describe_object`| 内置 AI 工具。每次调用都重新读取元数据。从不缓存。               |
| 实时数据技能  | 捆绑 `describe_object` + `query_records`，并促使智能体先行检查。 |
| 销售 Copilot    | 始终在回答前检查模式。自动呈现未知字段。 |

运行完整演示：

```bash
./scripts/wow1-live-schema.sh
```

## 这带来了什么

* 字段由运营而非工程添加。
* 每租户的模式扩展，AI 会自动呈现。
* 字段弃用，AI 在它们被移除的那一刻就停止引用。
* 迭代速度以秒计，而非以冲刺周期计。
