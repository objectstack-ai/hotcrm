# 簡介

本應用未隨附繁體中文語言包，因此本頁出現的介面名詞依固定順序取用：zh-CN 語言包已收錄者，採其用詞的繁體寫法；未收錄者，保留產品內的英文原名，不另造譯名。

**HotCRM 是一套客戶與營收軟體，面向任何銷售產品、項目服務或訂閱的公司。** 它把工作從第一次行銷觸達一路串到回款：線索與商機，報價、訂單與合約，合約的回款計畫以及財務據此記錄的發票和回款，交付所售內容的項目，途中員工花出去的費用，以及之後的服務工單。它運行在其下的平台 [**ObjectStack**](https://github.com/objectstack-ai/objectstack) 之上。

## 六個應用

每條業務線都有自己的應用。應用啟動器按每個人的工作提供他需要的應用。

| 應用 | 誰在裡面工作 | 涵蓋什麼 |
| --- | --- | --- |
| [**Sales**](/zh-Hant/docs/sales/index)（銷售） | 銷售代表、銷售經理、銷售管理層 | 線索、客戶、聯絡人、商機、報價單、訂單、合約、產品與價格表、預測、回款計畫 |
| [**Service**](/zh-Hant/docs/service/index)（服務） | 服務專員、服務經理 | 工單、SLA 與升級、知識庫 |
| [**Marketing**](/zh-Hant/docs/marketing/index)（營銷） | 行銷人員 | 行銷活動，以及它觸達的線索、聯絡人和客戶 |
| [**Order to Cash**](/zh-Hant/docs/order-to-cash)（訂單與回款） | 應收會計、財務控制 | 每個客戶的回款計畫，以及發票和回款，有沒有合約都可以 |
| [**Project Delivery**](/zh-Hant/docs/projects)（項目交付） | 項目經理、項目成員、財務控制 | 項目、按費率卡配置人員、預算、工時單，以及每個項目的成本 |
| [**Expenses**](/zh-Hant/docs/expenses)（費用報銷） | 每一位員工 | 附帶票據的費用、報銷單及其審批與付款、出差申請 |

Service、Marketing、Order to Cash、Project Delivery 和 Expenses 是模組，產品與報價也是：管理員可以關掉其中一個，它的應用和條目隨之消失，直到重新打開 —— 參見[啟用和停用模組](/zh-Hant/docs/administration/modules)。產品、價格表、報價單和大額商機審批在 [Sales](/zh-Hant/docs/sales/index) 下說明；儀表板和報表在[分析](/zh-Hant/docs/analytics/index)下說明。

這些紀錄是**串聯在一起**的：線索轉化為客戶、聯絡人和商機；接受報價單即贏下商機並建立訂單，需要時再從訂單起草合約；合約帶著它的回款計畫、發票和回款；項目寫明它交付的商機、合約或訂單；工單能看到客戶的完整歷史。

## HotCRM 面向誰

下面的角色，就是管理員在 **Setup → Position Holders** 中給人分配的職位。

- **銷售代表、銷售經理、銷售總監和高階主管** —— 線索、商機、報價、訂單、合約和預測。
- **服務專員、服務經理和服務總監** —— 按時解決客戶工單。
- **行銷人員、行銷經理和行銷總監** —— 開展行銷活動，觸達受眾。
- **財務** —— 應收會計記錄發票和回款；財務控制審批大項目、預算追加和報銷單；兩者都可以把已核准的報銷單標記為已付款。
- **項目經理、項目成員、項目總監和 PMO** —— 交付項目、填報工時並審批。
- **每一位員工** —— 記錄費用、提交報銷單、出差前先申請。
- **管理員** —— 按業務設定系統。

## 它有何不同

### 1. 從第一次觸達到回款，是同一套紀錄

銷售、財務、交付和服務在同一批客戶、合約和訂單上工作，沒有人需要把一筆交易再錄進第二套系統，才能做回款計畫或給項目配人。

### 2. 為智能體而建

HotCRM 提供物件、動作和技能；辨識票據、核對制度、起草回覆這類自動化，是**你的智能體**的工作，它透過 MCP 接入。智能體以它所接入的那個人的身分行事，權限與共用規則都和這個人一樣。HotCRM 不自帶助手：助手是平台的，HotCRM 用八項技能教會它。參見 [AI 與智能體](/zh-Hant/docs/ai-copilot/index)。

### 3. 流程開箱即設定好

大額商機、項目、預算追加、工時單、報銷單和出差申請的審批，SLA 升級，以及合約續約提醒都已內建（其中排程執行的那些，要管理員開啟排程工作後才會執行）。按需調整即可，不必從頭搭建。

### 4. 建立在元資料優先的平台上

每個物件、欄位、規則、頁面和流程都是 Git 儲存庫裡的元資料，運行在 ObjectStack 上。如果你是開發者，參見[開發者](/zh-Hant/docs/developers/index)，了解這在實務中意味著什麼。

## 開箱即附什麼

- **38 個業務物件**，涵蓋銷售、服務、行銷、營收、訂單與回款、項目交付和費用報銷，具備各自的欄位、選擇清單和驗證。
- **18 個職位** —— 按業務線分發紀錄存取權限的扁平群組。職位之間不向上彙總，所以每個需要某條紀錄的職位，都由它自己的共用規則點名。
- **55 個流程** —— 審批、線索分配、贏單與合約通知、續約與到期巡檢、SLA 升級、項目與費用審批，以及兩個計費交接事件。
- **標準清單檢視、儀表板和報表**，每個應用都有。
- **八項 AI 技能**，供平台智能體使用 —— 即時資料、線索資格審查、郵件起草、營收預測、客戶 360°、工單分流、費用代填和費用檢查 —— 以及九個對智能體開放的動作：線索上的 **Convert Lead**（轉化線索）和 **Schedule Follow-up**（安排跟進），以及 **Submit for Reimbursement**（提交報銷）等七個費用和出差申請的步驟。
- **一個知識文章庫**，用於支援內容：一個物件、七個分類，智能體像讀其它紀錄一樣讀取它。
