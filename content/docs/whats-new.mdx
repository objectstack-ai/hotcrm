# What's New

## v0.1.0 — Baseline (May 2026)

**Hard reset.** Previous iterations attempted a 17-package monorepo covering 146 objects across CRM/HR/Healthcare/Education/Real Estate/Financial Services/Community. That codebase shipped with disabled hooks, 30 % seed-insert rate, and an unbuildable browser experience. It is preserved on the `legacy-archive` git branch for reference only.

This release re-bases HotCRM on `framework/examples/app-crm` — a verified, runnable reference implementation maintained inside the ObjectStack framework monorepo. From here, every new feature is added one PR at a time with explicit acceptance criteria.

### Included

- **10 core sales-cloud objects**: account, contact, lead, opportunity (+ line items), product, quote (+ line items), contract, campaign (+ members), case, task.
- **10 hooks** covering field validation (e.g. website format), value normalization (uppercased account numbers), and deletion protection (customer accounts with open opportunities).
- **2 state machines** (lead, opportunity) with transition guards.
- **12 pages** including Home, App Launcher, Account / Lead / Opportunity details, Action Modals, Utility Bar.
- **10 list views** (one per core object).
- **5 automation flows**, **2 AI agents**, **2 skills**, **1 approval process**.
- **4 sharing rules** + 10-level role hierarchy.
- **Seed dataset**: ~90 records authored with `defineDataset()` (compile-time field-name checking). Verified to insert successfully on first sign-up.
- **`/_console/`, `/_studio/`, `/_account/`** UIs wired and serving 200.

### Architecture changes from legacy

| Aspect | Legacy | v0.1 |
|---|---|---|
| Layout | 17 packages × workspace | Flat `src/`, single package |
| Workspace scope | `packages/*` + `apps/*` | `apps/*` only (docs site) |
| Build | Per-package `tsc` + aggregator | Single `objectstack build` |
| Object count | 146 (mostly unverified) | 13 (all wired end-to-end) |
| Hooks | 107 (all disabled — sandbox-incompatible) | 10 (running) |
| Seed insert rate | ~30 % | 100 % |

### Removed

- `packages/{crm,finance,hr,marketing,products,support,analytics,integration,community,healthcare,real-estate,education,financial-services,ai,core,server}`
- `objectstack.aggregator.ts` (no longer needed)
- The "146 objects / 6 clouds" marketing surface — docs now describe only what runs.

### Migration

- If you forked the legacy hotcrm, check out `legacy-archive` for the prior tree.
- If you want a specific schema (e.g. `patient.object.ts` from healthcare), port it manually into `src/objects/` and re-verify hooks against the QuickJS sandbox.

## Roadmap

See [GitHub Issues](https://github.com/objectstack-ai/hotcrm/issues) for the active iteration backlog.

Iteration policy:

1. **One PR = one feature**, ≤ 500 lines of diff.
2. **No unverified code** — every hook must run in the sandbox; every seed must insert; every page must render.
3. **No batch generation** — features are added one object at a time so each ships with tests and docs.
4. **Acceptance criteria are public** — listed in the issue before code is written.
