# 知识库

HotCRM 的知识只有**一个**去处：**知识文章**对象（`crm_knowledge_article`），从导航的**服务 → 知识**进入。Copilot 读它用的，是它读客户、工单、商机时的同一批记录工具。它下面没有另一套检索子系统，也没有多个按团队划分的库让你挑。

## 并不存在四个知识库

这一页过去描述过四个内置知识库——**销售知识**、**产品信息**、**支持知识**和**竞争情报**。HotCRM 一个都不附带，也从未附带过：没有任何元数据以这些名字声明过知识库，没有任何技能绑定到其中之一，Setup 里也没有可供填充种子内容的地方。如果你照着旧版页面去找过，那就是你什么也没找到的原因。

真正存在的，是一个文章对象加一个**分类**选项集。四条承诺各自的实际落点是：

| 旧名字 | 今天的实情 |
| --- | --- |
| **销售知识**——销售剧本、异议处理、资格判定框架 | 在现有选项集里无处安放。七个分类是为产品与支持内容写的，没有销售剧本这一类。把剧本归到**操作指南**或**政策制度**下也能用，但那是你自己的约定，不是产品自带的约定。 |
| **产品信息**——数据表、规格、版本说明 | 归入**版本说明**、**API 与集成**或**账务与价格**的文章。产品自己的**规格书**仍旧只是产品记录上的一个文件——见下文。 |
| **支持知识**——故障排查、操作手册、FAQ | 归入**故障排查**、**入门指南**或**操作指南**的文章。选项集本来就是为这类内容写的，也是四条承诺里唯一大体兑现的一条。 |
| **竞争情报**——竞争对手画像、对战卡 | 没有落点。HotCRM 没有竞争对手对象：仅供演示的 `crm_competitor` 模块已被删除，这一行是活得比它久的文字（#790 从共享与权限页面清掉的是同一批残留）。应用里仅有的竞争对手数据，是商机上"输给竞争对手"这一条丢单原因，以及它旁边的自由文本**丢单详情**——商机上原有的**竞争对手**选项集只有无人读取的占位选项，已由 #1061 退役。 |

## 一篇文章是什么

一条记录，加上几个真正决定检索结果的字段：

| 字段 | 作用 |
| --- | --- |
| **文章编号** | `KA-0001`，自动生成——Copilot 引用的就是它。 |
| **标题**与**摘要** | 两者都可检索。摘要是一段话的要点，显示在搜索结果和 AI 引用里。 |
| **正文** | 文章本身，Markdown 格式。 |
| **分类** | 入门指南 · 操作指南 · 故障排查 · 账务与价格 · API 与集成 · 版本说明 · 政策制度。 |
| **标签** | 身份认证 · 单点登录 · 移动端 · 邮件 · 报表 · 性能 · 数据导入 · Webhook。 |
| **状态** | 草稿 → 审核中 → 已发布 → 已归档。 |
| **受众** | 公开或仅内部。 |
| **语言** | 英语 · 简体中文 · 西班牙语 · 日语。 |

分类与标签是 Copilot 用来匹配的那套固定词汇，因此这两个字段决定一篇文章能不能被找到。客服如何撰写、复核、下架文章，参见 [服务 › 知识库](/zh-Hans/docs/service/knowledge-base)。

## Copilot 如何取到一篇文章

靠查询这个对象——和它查询工单的方式一模一样：

1. 读取眼前的工单，取它们的**分类**和**标签**。
2. 在 `crm_knowledge_article` 上查询与之匹配的**已发布**文章。
3. 按文章编号（`KA-0007`）标注用了哪几篇，你可以打开记录核对。

这是一次带过滤条件的记录查询，不是语义检索。匹配依据是人工设置的分类与标签，所以一篇归错分类的文章，正文答得再好，对 Copilot 也是不可见的。

### 到底哪些技能会读文章

| 技能 | 会读文章吗？ |
| --- | --- |
| 🔭 **Customer 360°** | **会**——它的指令第 3 步会按刚读到的工单的分类或标签去查询已发布文章。也只有它会。 |
| 🚦 **工单分流** | 不会。它声明了 `describe_object` 与 `get_record` 两个工具，完全没有检索类工具——它检索不了任何东西，文章也不例外。 |
| ✍️ **邮件撰写** | 不会。它*本可以*——它带着 `query_records`——但它的指令里没有任何一步去取文章，因此没有哪份草稿会引用文章。 |
| 🎯 **线索资格判定** · 📈 **收入预测** · 🔄 **实时数据** | 不会。它们都没有取知识的步骤。 |

所以"问 Copilot，它会找到那篇文章"具体指的是 **Customer 360°**。向工单分流要匹配文章，你只会拿到一个优先级。

### 为什么没有语义检索

平台确实提供了一个知识检索工具，但它检索的是一个*已声明的知识来源*，而知识来源只能声明在 agent 上。HotCRM 交付的是技能而不是 agent，因此没有地方去声明它——那个工具即便挂上也只会解析成功、返回为空。直接查询对象，是同一件事的诚实版本，也正是这些技能在做的事。

## 不存在的东西

明确列出来，因为旧版页面把这些全都承诺过：

- **没有文档摄取。** 没有任何东西会把 PDF、Word 或 Markdown 上传进一个知识索引。一篇文章就是有人敲进去或粘贴进去的一条记录。
- **没有 `/knowledge/...` 目录。** 应用里不存在这样一个 Markdown 文件目录，也没有任何东西在监听它。
- **没有嵌入、分块、检索阈值和缓存**，因此也没有所谓"高于质量阈值的最相关的 5 个片段"。查询返回的是匹配的记录。
- **没有夜间重新索引，也没有手动重建索引的按钮。** 一篇已发布文章在保存的那一刻就可被查询到，因为它是一条记录。
- **没有连接器**去接 Confluence、Notion、Google Drive 或 SharePoint。
- **没有按技能绑定知识的机制**，因此也无法新增一个知识库（比如一个合规库）再把它接到某个技能上。给文章对象加一个**分类**，才是产品自带的划分新内容域的方式，而那是一次元数据变更。

产品的**规格书**字段最像例外：它确实是产品记录上的一个真实文件字段，可放不超过 20 MB 的 PDF。但没有任何东西读取该文件的内容——没有技能，也没有索引。它在那里是给人下载的。

## 给管理员的提示

- ✅ **分类和标签就是检索面。** 一篇没人找得到的文章，通常是归错了，而不是写差了。重写正文之前先审一遍分类。
- ✅ **发布它，否则它不存在。** 查询只过滤已发布的文章；草稿和已归档文章对 Copilot 不可见。
- ✅ **内部文章要标成仅内部。** 受众是人工设置的字段，而面向客户的答复不该引用一份内部操作手册。

## 给知识管理员的提示

- ✅ 文章要**短、可扫读**，并把具体症状（"Error 503"、"无法登录"）写进**标题**和**摘要**——检索读的就是这两个字段加文章编号。
- ✅ **一篇文章只回答一个问题。** 分类匹配是粗粒度的，一篇同时回答三个不相关问题的文章，总会在错误的那个问题上被匹配出来。
- ✅ 当 **Customer 360°** 按某个工单的分类或标签匹配不到任何文章时，那就是一个值得记下来的知识空缺。

各技能分别读什么、写什么，参见 [技能](/zh-Hans/docs/ai-copilot/skills)；自己写一个技能，参见 [定制 › 添加 AI 技能](/zh-Hans/docs/customization/ai-skills)。
