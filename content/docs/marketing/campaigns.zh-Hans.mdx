# 营销活动

**营销活动**是任何市场营销举措——一次邮件群发、一场网络研讨会、一个展会展位、一次内容下载、一个付费社交广告活动。每个营销活动都有预算、目标受众、持续时间和可衡量的结果（收入、线索、商机）。

## 4 种营销活动状态

| 状态 | 含义 |
| --- | --- |
| ⚪ **Planning** | 设计中——受众、预算、内容 *(默认)* |
| 🟠 **In Progress** | 进行中——成员已加入，正在跟踪互动 |
| 🟢 **Completed** | 已完成——活动本身已结束，指标仍在实时更新 |
| 🔴 **Aborted** | 完成前已取消 |

系统会在营销活动结束日期的次日自动将其从 *In Progress* 移至 *Completed*——这样你就不必记着了。

## 8 种营销活动类型

| 类型 | 用途 |
| --- | --- |
| **Email** *(默认)* | 通讯、滴灌计划、广播邮件 |
| **Webinar** | 带注册和出席跟踪的虚拟活动 |
| **Trade Show** | 在行业活动上的线下展位展示 |
| **Conference** | 演讲席位、赞助 |
| **Direct Mail** | 实体信件、礼品、包裹 |
| **Social Media** | 付费或自然社交营销活动 |
| **Content Marketing** | 博客文章、电子书、白皮书、门控内容 |
| **Partner Marketing** | 与渠道合作伙伴的联合营销活动 |

以及 5 个主要渠道：**Digital · Social · Email · Events · Partner**。选择最能描述营销活动如何触达受众的渠道——它被渠道组合报表使用。

## 营销活动记录存储什么

详情屏幕有几个部分：

| 部分 | 字段 |
| --- | --- |
| **Basic** | 营销活动代码、名称、描述、类型、渠道、状态 |
| **Schedule** | 开始日期、结束日期 |
| **Budget** | 预算成本、实际成本、预期收入、实际收入 *(汇总)* |
| **Audience** | 目标规模、发送数量 |
| **Engagement** *(汇总)* | 打开、点击、响应、转化 |
| **Attribution** *(汇总)* | 生成的线索、创建的商机、成交赢单收入 |

**Campaign Code** 是自动生成的（例如 CAMP-000123），因此每个营销活动都有一个唯一的简短引用，用于邮件主题行和跟踪 URL。

## 内置规则

- **结束日期必须在开始日期当天或之后** — 基本的合理性检查。
- **超预算警告** — 如果实际成本超过预算成本，记录上会显示警告。它不会阻止保存，但会标记该营销活动以供财务审查。

## 自动发生的事

- **自动完成** — 每天凌晨 2 点，任何超过结束日期的 *In Progress* 营销活动都会被标记为 *Completed*。这次扫描只翻转状态，也只翻转状态——在它运行之前，各项数字就已经是最新的了。
- **实时指标** — 指标块（发送、响应、转化、ROI）会在成员加入、成员响应、其线索转化、商机归因到该营销活动时随之重新计算。正在进行中的营销活动报的就是真实数字；不必等它结束才能读。
- **成员加入** — 当营销活动进入 *In Progress* 时，Campaign Enrollment flow 每周一早上 9 点运行并添加新的匹配受众成员。
- **ROI 计算** — 营销活动的实际收入是相关成交赢单商机金额的汇总总和。ROI =（实际收入 − 实际成本）÷ 实际成本。

## 营销活动加入流程

当你启动一个营销活动（状态 → *In Progress*）时，系统会将你的目标受众批量加入为 [营销活动成员](/zh-Hans/docs/marketing/campaign-members)。

该流程按计划运行（默认周一早上 9 点）并：

1. 读取营销活动的目标受众条件（例如"所有评级 ≥ 3 的 Technology 行业线索"）。
2. 查找匹配的线索和联系人。
3. 为每个人创建一条状态 = *Sent* 的营销活动成员记录。
4. 可选地触发营销活动的发送操作（邮件发送、邮件派发等）。

对于实时营销活动（例如带注册表单的网络研讨会），你也可以从营销活动详情页**手动**添加成员，或通过任何线索/联系人上的 **Add to Campaign** 操作添加。

## 衡量营销活动

营销活动详情页的右侧面板显示：

- **Sent** — 加入的成员数量。
- **Open rate** — 状态 ≥ Opened 的成员百分比。
- **Click rate** — 状态 ≥ Clicked 的成员百分比。
- **Response rate** — 状态 ≥ Responded 的成员百分比。
- **Conversion rate** — 状态 = Converted 的成员百分比（即成为商机）。
- **Opportunities generated** — 以该营销活动为来源的商机数量。
- **Pipeline value** — 这些商机金额的总和。
- **Closed-won revenue** — 这些商机中阶段 = closed_won 的金额总和。
- **ROI** —（成交赢单收入 − 实际成本）÷ 实际成本。

## 归因：从营销活动到收入

连接点是商机上的 **Source Campaign** 查找字段。当销售代表转化一个来自营销活动的线索时——或在商机上手动设置来源营销活动时——系统会将收入归功于该营销活动。

对于受多个营销活动影响的交易（多触点），惯例是记录**末次触点**营销活动（最接近转化的那个）。要实现完整的多触点归因，可考虑使用营销活动影响联接对象扩展模型——请参阅 [自定义](/zh-Hans/docs/customization/extending-objects)。

## 标准列表视图

营销活动一共保存了**四个**视图（`src/views/campaign.view.ts`），列表上方的标签行改的是同一批营销活动**怎么画**，而不是里面有哪些营销活动。一个视图一个标签，标签上写的就是视图自己的名字：

| 视图 | 它展示什么 |
| --- | --- |
| **全部营销活动** | 表格：名称（固定在左侧，也是进入记录的链接）、渠道、状态、开始与结束日期、预算成本和预期营收——后两列带列合计。按**开始日期**升序排列，每页 25 行。 |
| **活动排期** | 每个营销活动一根甘特条，从开始日期到结束日期，以名称为标题，让相互重叠的档期对齐排布。 |
| **活动日历** | 同一批营销活动排在月历上，落在各自的**开始日期**，按渠道着色。 |
| **营销时间线** | 同样的起止跨度画在月度刻度上，按渠道分组、按状态着色。 |

四个视图都没有任何过滤条件，所以**你能看到的每个营销活动在四个标签里都在**，切换标签只是换一种画法。不存在名为 *Active Campaigns*、*Upcoming Campaigns*、*Completed This Quarter*、*Over Budget*、*By Type* 或 *Best ROI* 的已保存视图：要把列表收窄到某个状态，请自己对表格的列排序和过滤。**ROI** 并不在这些列里——它在营销活动记录的*成本*区块上，以及市场仪表盘里。

## 共享——营销活动默认公开

营销活动对整个组织**公开只读**。销售中的任何人都可以看到市场营销正在运行什么，并在客户对话中使用该背景。编辑权限保留给市场营销用户。

## 给营销人员的提示

- ✅ 在启动时**设置预期收入**——这是财务预测营销活动贡献的依据。
- ✅ **一旦知道就记录实际成本**——如果字段为空，超预算警告就无济于事。
- ✅ 如果你提前结束，请**将营销活动状态更新为 *Completed***；不要等待自动完成。
- ✅ 在描述中**记录有效的做法**——未来的你和未来的同事会感谢你。

## 给销售代表的提示

- ✅ 当一个线索到来时，检查他们是否在某个营销活动中——它会告诉你他们已经看过什么。
- ✅ 在你成交的商机上设置 **Source Campaign**——没有它市场营销就无法衡量 ROI。

## 给管理员的提示

- 自动完成 cron（每天凌晨 2 点）和加入 cron（周一早上 9 点）是可配置的。请参阅 [Administration › Automation](/zh-Hans/docs/administration/automation)。
- 要添加新的营销活动类型或渠道，请编辑营销活动对象的选项列表。请参阅 [自定义 › 扩展对象](/zh-Hans/docs/customization/extending-objects)。
- 对于多触点归因，请参阅自定义指南。
