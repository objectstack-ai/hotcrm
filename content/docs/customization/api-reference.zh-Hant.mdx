# API 參考

HotCRM 透過 **REST + ObjectQL** API 公開其完整的資料平面。Web UI、行動應用、AI Copilot 以及任何外部整合都使用同一套端點。

> 如需逐個端點的完整參考（由 OpenAPI 規範自動產生），請查看位於 `your-hotcrm-url/api/explorer` 的 **API Explorer**。

## 認證

### OAuth 2.0（建議用於應用）

標準的授權碼流程：

```http
GET /oauth/authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://your-app/callback
  &scope=read:opportunity write:opportunity
```

用授權碼換取權杖：

```http
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=...
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET
&redirect_uri=https://your-app/callback
```

在後續請求中使用 **存取權杖**：

```http
GET /api/v1/opportunities
Authorization: Bearer <access_token>
```

權杖有效期為 **1 小時**；使用重新整理權杖進行重新整理。

### 個人存取權杖（用於指令稿）

對於伺服器對伺服器的指令稿，請在 **Settings → Developer → Personal Access Tokens** 中產生一個 PAT。將其作為 Bearer 權杖使用。

⚠️ PAT 會繼承你使用者的權限。請將其視為機密。

### API 金鑰（用於整合）

對於具名整合（Stripe、DocuSign、你自己的）：

1. **Setup → Integrations → API Keys → New**。
2. 選擇作用域。
3. 複製金鑰（僅顯示一次）。

API 金鑰可以限定到特定的物件 + 動作，並擁有各自獨立的速率限制。

## 物件端點

每個物件都公開一套統一的端點。以 `crm_opportunity` 為例：

| 方法 | 端點 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/opportunities` | 帶篩選 / 排序 / 分頁的清單 |
| `GET` | `/api/v1/opportunities/{id}` | 依 ID 取得單筆記錄 |
| `POST` | `/api/v1/opportunities` | 建立 |
| `PATCH` | `/api/v1/opportunities/{id}` | 部分更新 |
| `PUT` | `/api/v1/opportunities/{id}` | 完整取代 |
| `DELETE` | `/api/v1/opportunities/{id}` | 軟刪除（資源回收筒） |
| `POST` | `/api/v1/opportunities/{id}/restore` | 從資源回收筒還原 |
| `POST` | `/api/v1/opportunities/bulk` | 以最多 10,000 筆為一批進行建立 / 更新 |
| `POST` | `/api/v1/opportunities/query` | ObjectQL 查詢 |

替換為物件名稱（清單使用 snake_case 複數形式）—— `accounts`、`contacts`、`leads`、`cases`、`contracts`、`products`、`quotes`、`campaigns`、`tasks`、`events` 等。

## ObjectQL

對於任何超出簡單欄位相等的查詢，請透過 `POST /api/v1/{object}/query` 使用 ObjectQL：

```json
POST /api/v1/opportunities/query
{
  "filters": [
    ["stage", "in", ["proposal", "negotiation"]],
    ["amount", ">", 100000],
    ["close_date", "between", "2026-01-01", "2026-03-31"]
  ],
  "sort": [{ "field": "amount", "direction": "desc" }],
  "limit": 200,
  "cursor": "...",
  "fields": ["id", "name", "amount", "stage", "account.name", "owner.name"],
  "expand": ["crm_account", "owner", "crm_opportunity_line_item"]
}
```

### 受支援的運算子

`=`、`!=`、`>`、`>=`、`<`、`<=`、`in`、`not_in`、`between`、`contains`、`starts_with`、`ends_with`、`is_null`、`is_not_null`、`in_role_subordinates`、`in_group`。

### 分頁

基於游標。每個回應都包含 `next_cursor`。將其回傳以取得下一頁。

```json
{
  "results": [...],
  "next_cursor": "eyJpZCI6...",
  "has_more": true
}
```

切勿對大型資料集使用基於位移量的分頁 —— 它是 O(n) 的。

### 聯結相關記錄

使用 `expand` 內聯展開 lookup 目標：

```json
{
  "fields": ["id", "name", "account.name", "account.industry"],
  "expand": ["crm_account"]
}
```

支援多層聯結（例如 `opportunity.account.parent_account`），最深可達 3 層。

## 彙總

```json
POST /api/v1/opportunities/aggregate
{
  "filters": [["stage", "=", "closed_won"], ["close_date", "in_year", 2026]],
  "group_by": ["owner", "month(close_date)"],
  "metrics": [
    { "field": "amount", "op": "sum",   "as": "total_bookings" },
    { "field": "amount", "op": "avg",   "as": "avg_deal_size" },
    { "field": "id",     "op": "count", "as": "deal_count" }
  ]
}
```

## Webhook

### 訂閱

```json
POST /api/v1/webhooks
{
  "name": "stripe-sync-on-contract-active",
  "object": "crm_contract",
  "events": ["updated"],
  "filter": [["status", "=", "activated"]],
  "url": "https://your-app/webhooks/contract-activated",
  "secret": "shhh",
  "auth": { "type": "hmac_sha256", "header": "X-Signature" }
}
```

### 載荷

```json
{
  "event": "contract.updated",
  "occurred_at": "2026-03-12T14:23:11Z",
  "tenant_id": "ten_abc",
  "record_id": "ctr_xyz",
  "before": { ... },
  "after":  { ... },
  "user_id": "usr_alex"
}
```

在處理之前，請驗證 `X-Signature` 標頭。

## 事件匯流排（串流）

對於高輸送量的整合，請訂閱事件匯流排（Kafka / EventBridge / Pub/Sub），而非 HTTP Webhook：

```ts
import { EventBus } from '@hotcrm/sdk';

const bus = new EventBus({ token: process.env.HOTCRM_TOKEN });

bus.subscribe('opportunity.closed_won', async (event) => {
  await provisionCustomer(event.record);
});
```

## SDK

官方 SDK：

- **TypeScript / Node** —— `@hotcrm/sdk`
- **Python** —— `hotcrm-sdk`
- **Go** —— `github.com/hotcrm/hotcrm-go`

所有 SDK 都會：

- 處理認證、重試、退避、分頁。
- 提供帶型別的物件（根據你租戶的 schema 產生）。
- 從事件匯流排串流接收事件。

```ts
import { Hotcrm } from '@hotcrm/sdk';

const crm = new Hotcrm({ token: process.env.HOTCRM_TOKEN });

const opps = await crm.opportunity.query({
  filters: [['stage', '=', 'closed_won']],
  limit: 200,
});

for await (const opp of crm.opportunity.queryAll({ filters: [...] })) {
  console.log(opp.name);
}

await crm.opportunity.update('opp_123', { amount: 50000 });
```

## AI 技能 API

呼叫該使用者有權存取的任何 AI 技能：

```http
POST /api/v1/ai/skills/email_drafting/invoke
{
  "input": {
    "record_id": "opp_123",
    "goal": "discovery follow-up after demo"
  }
}
```

回應包含結構化輸出 + 引用。

對於串流回應（打字機式體驗）：

```http
POST /api/v1/ai/skills/{skill}/stream
```

回傳 server-sent events。

## 速率限制

請參閱 [效能與限制](/zh-Hant/docs/reference/performance-and-limits)。在收到 429 回應時，請遵守 `Retry-After` 標頭。

## 錯誤

標準 HTTP 狀態碼。內文：

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Amount is required when moving to Negotiation",
    "field": "amount",
    "request_id": "req_abc123"
  }
}
```

提交問題時請附帶 `request_id`。

## 版本管理

- **URL 版本化**：`/api/v1/...`
- **破壞性變更** 發佈在 `/api/v2/...` 中 —— 在 `v2` GA 之後，`v1` 仍受支援 24 個月。
- **新增性變更**（新欄位、新端點）無需通知即發佈在 `v1` 中。
- **棄用** 會在移除前至少 6 個月出現在 `Sunset` 標頭中。

## 沙盒與測試

**測試模式** API 的基礎 URL 為 `your-sandbox-url/api/v1/`。端點完全相同，資料相互隔離。

對於本機開發，開源開發執行階段會在 `localhost:3000/api/v1/` 公開完整的 API。

## 提示

- ✅ 使用 **SDK** —— 手寫 HTTP 既繁瑣又容易出錯。
- ✅ 始終實作 **退避** —— 即使你認為自己未超出限制。
- ✅ 使用 **游標分頁**，絕不要用位移量。
- ✅ 優先使用 **事件匯流排** 而非輪詢。
- ✅ **驗證 Webhook 簽章** —— 切勿僅憑來源 IP 就信任。
- ✅ 在生產之前針對 **沙盒** 進行測試。
