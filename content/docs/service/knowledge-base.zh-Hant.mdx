# 知識庫

知識庫是 AI 服務 Copilot 在起草回覆、建議解決方案或分流工單時所讀取的**支援內容庫**。一個維護良好的知識庫正是讓 Copilot 變得有用的關鍵——它決定了 AI 是輸出含糊空洞的廢話，還是準確、契合品牌的客戶答覆。

## 知識庫裡有什麼

知識庫就是一個物件——**知識文章**——每篇文章都是你在**服務 → 知識**下建立的普通記錄。它背後沒有另一套索引，也沒有檔案庫：列表檢視裡能看到的，就是 Copilot 能讀到的。

每篇文章歸入一個**分類**，而這七個分類就是全部詞彙表：

| 分類 | 該放什麼 |
| --- | --- |
| **入門指南** | 首次設定、上手引導、"我該從哪開始" |
| **操作指南** | 分步驟的任務說明 |
| **故障排查** | 症狀 → 成因 → 修復、錯誤碼、已知繞行方案 |
| **帳務與價格** | 帳單、方案變更、退款、價格問題 |
| **API 與整合** | 介面、Webhook、連接器設定 |
| **版本說明** | 什麼變了、什麼時候變的 |
| **政策制度** | 支援時間、SLA 承諾、資料處理，以及一切你寫下來就要兌現的承諾 |

除分類外，每篇文章還帶有**標籤**（身分認證、單一登入、行動端、郵件、報表、效能、資料匯入、Webhook）、**狀態**（草稿 → 審核中 → 已發布 → 已歸檔）、**受眾**（公開或僅內部）和**語言**。**文章編號**（`KA-0001`）自動產生，Copilot 引用的就是這個編號。

## 怎麼找文章

**知識**列表自帶四個頁籤：

- **全部**——按分類分組，發布時間最新的在前。
- **已發布**——只看已發布的文章，瀏覽數最高的在前。
- **我的草稿**——你自己的草稿與審核中的文章。
- **複核佇列**——已發布文章按最久未複核在前排序，所以列表頂部就是最可能過時的內容。

物件宣告的檢索欄位是**標題**、**摘要**和**文章編號**，全域搜尋與查找選擇器讀的正是這三個欄位——同事會拿來搜尋的那些詞，應該寫在這裡，而不是埋在正文裡。

## Service Copilot 如何使用它

讀文章的技能只有一個：**Customer 360°**。向它要一位客戶的全貌，它在客戶、聯絡人、進行中商機和工單之外，還會按剛讀到的那些工單的**分類或標籤**去查詢**已發布**的文章，並按編號（`KA-0007`）逐條標注出處。

有兩件事值得說準，因為它們過去都被寫反了：

- **工單分流不會檢索文章。** 它只宣告了 `describe_object` 與 `get_record` 兩個工具，完全沒有檢索類工具。它返回的是一個優先級、判定它的那一條理由，以及指向"升級"或"關閉"的指引——沒有文章清單。
- **郵件撰寫不會引用文章。** 草稿的依據是這個技能讀到的記錄——聯絡人，以及請求點名時的相關客戶或商機——它的指令裡沒有任何一步去取文章。當回覆確實需要引用某篇文章時，把 Customer 360° 匹配出來的那篇拿來貼上。

匹配靠的是分類與標籤，不是語義。歸錯分類的文章，正文答得再好也浮不出來——所以知識管理員最有槓桿的動作是分類，而不是潤色文字。

## 維護知識庫

知識庫的**好壞取決於你放進去的內容**。一個典型的內容維護工作流：

### 1. 捕獲有效的內容

當客服用一個出色的答覆解決了一個棘手工單時，把該答覆整理成一篇新文章。**來源案例**欄位會把它連回它出自的那個工單，下一個讀者能順著看到真實的對話。

### 2. 分流來訪問題

每週查看最常見的工單主題。排名前 10 的問題值得設立專門的文章——如果 30 個客戶問了同一件事，第 31 個就應該由一篇文章來回答。

### 3. 淘汰過時內容

如果產品發生變化，對應的文章需要更新。**複核佇列**按"多久沒人動過"給已發布文章排序，從頂部往下處理即可。發布只在第一次蓋上發布時間，之後每次編輯都會重新整理複核時間，所以這個排序反映的是真實的關注度。

### 4. 關注被引用和被閱讀的內容

每篇文章上都有**瀏覽數**、**有用**和**沒用**。被大量閱讀卻被投"沒用"的文章正在造成傷害；從來沒人讀的那篇，可能只是歸進了沒人瀏覽的分類。

## 給服務經理的提示

- ✅ 將知識庫更新納入每週團隊會議——"本週我們需要哪 3 篇新文章？"
- ✅ 獎勵貢獻知識庫內容的客服；這能放大他們的專業能力。
- ✅ 稽核 **Customer 360°** 引用的文章——每週隨機抽取 10 篇，檢查它們是否真的配得上被匹配到的那些工單。

## 給管理員的提示

- **不發布等於不存在。** Copilot 只查詢已發布的文章，草稿對它是不可見的。
- **認真設定受眾。** 公開文章是寫給客戶看的，僅內部的文章只給客服看。注意：客戶入口今天並不提供文章——按設計，訪客權限集完全讀不到這個物件——所以*公開*表達的是意圖，不是一個發布通道。
- **分類屬於元資料。** 增加第八個分類是改物件，不是改設定——參見 [定制 › 擴展物件](/zh-Hant/docs/customization/extending-objects)。
- HotCRM 不附帶任何獨立的銷售、產品或競爭情報知識庫可供接入；有的就是這一個物件和它的分類。Copilot 拿它能做什麼、不能做什麼，詳見 [AI Copilot › 知識庫](/zh-Hant/docs/ai-copilot/knowledge-bases)。
