# 营销活动成员

**营销活动成员**是 [营销活动](/zh-Hans/docs/marketing/campaigns) 与某个人（一个 [线索](/zh-Hans/docs/sales/leads) 或一个 [联系人](/zh-Hans/docs/sales/contacts)）之间的联系。它记录营销活动已经触达该人，以及后来发生了什么：他们是否响应、其线索是否转化、还是要求不再收到联系。

## 成员如何加入

三种方式：

1. **通过营销活动流程批量加入** — 当营销活动进入 *In Progress* 时，[Campaign Enrollment flow](/zh-Hans/docs/marketing/campaigns) 运行并添加所有匹配受众条件的人。
2. **从线索列表或联系人列表加入** — **Add to Campaign**（加入营销活动）两边都有。在列表里勾选需要的记录后批量运行，或在列表视图行的 ⋮ 菜单里对单条运行；两种方式都由记录选择器来选定营销活动。它在两个对象上都是列表操作，所以打开一条线索或一个联系人并不会提供它。已经在该活动里的人会被跳过，所以重复运行不会把一次触达算成两次——跳过检查按关系各查各的，因此同一个人以线索身份加入一次、又以联系人身份加入一次，是刻意保留的两条成员记录，而不是一次重复。营销活动上仍然没有一个 *Add Members* 选人器供你从线索和联系人列表视图中挑人。
3. **在营销活动上逐条新建** — 打开营销活动，在 *Related*（相关）选项卡里找到 **Campaign Members** 面板，用面板上的 **New**（新建）按钮手工填写一条成员记录。

一个人随着时间推移可以加入多个营销活动，但每个营销活动只能加入一次（每人每个营销活动一个成员身份）。

## 4 种成员状态

成员状态就是响应生命周期，其中每一个取值在应用里都有真实的写入方：

| 状态 | 含义 | 由谁写入 |
| --- | --- | --- |
| ⚪ **已发送** | 营销活动已触达他们 *(新成员的默认状态，无论以哪种方式创建)* | 加入 |
| 🟢 **已响应** | 他们作出了回应——回复、注册、下载 | 成员上的 **Mark Responded**（标记为已响应） |
| 🟣 **已转化** | 其线索后来成为了客户 | 该线索转化时自动写入 |
| 🔴 **已退订** | 他们要求不再收到联系 | 销售代表在成员记录上设置，或来自一次退订请求 |

这四个取值并不是一部只升不降的阶梯。大多数成员停在*已发送*；作出回应的移到*已响应*；仍处于*已发送*或*已响应*、其线索后来转化的成员会被自动提升为*已转化*。把成员改回去——纠正一次误点，或为了重发而重置回*已发送*——会连同响应时间戳一起清除。*已退订*的成员永远不会被那次转化扫描提升：退订不会被一个营销结果覆盖掉。

## 为什么同时支持线索和联系人？

营销活动成员可以关联到一个**线索**（尚未合格的人）或一个**联系人**（现有客户处的人）——但不能同时关联两者。这由一条内置规则强制执行：`crm_lead` 或 `crm_contact` 必须且只能设置其一。

这种双重支持意味着：

- 市场营销可以针对**潜在客户**（线索）开展漏斗顶端营销活动。
- 市场营销可以针对**现有客户**（联系人）开展追加销售、交叉销售或续约营销活动。

如果一个线索后来被转化为联系人，现有的营销活动成员身份仍与该线索关联，而新的营销活动可以将同一个人作为联系人重新定位。

## 成员记录存储什么

| 字段 | 用途 |
| --- | --- |
| Member Number | 这条成员记录自己的编号（CM-00001），保存时自动生成 |
| Campaign | 营销活动——必填 |
| Lead | 线索：该人加入时身份为线索的，记录在此 |
| Contact | 联系人：该人是已有联系人的，记录在此 |
| Added Date | 该人加入的时间——由加入它的那一方写入，之后只读 |
| Status | 该人走到了哪一步（见上文四种状态） |
| Response Date | 他们响应的时间，在首次进入已响应状态时打上 |
| Has Responded | 是/否的快捷标识，由系统与*状态*保持一致——*已转化*同样算作已响应 |

## 什么被跟踪，什么没有

> **本应用不跟踪打开、点击或退信。** 平台的邮件服务负责发信，并记录这条消息的去向——*Queued → Sent*（已排队 → 已发送），或者 *Failed*（失败）——但它不带跟踪像素、没有点击回调、也没有退信数据源。任何依赖它们的成员状态都只会永远停在默认值上，所以产品里没有这样的状态。应用真正能观察到的，是一个人作出了回应、以及一条线索发生了转化——这正是这四种状态所讲述的内容。

每一种状态都有真实的写入方：

- **已发送** — 在成员记录被创建时写入，上文的每一条加入路径都会写。
- **已响应** — 成员记录上的 **Mark Responded**（标记为已响应）按钮。它只在成员仍处于*已发送*时出现：已响应、已转化或已退订的成员没有什么可记录的，而已退订的人更不该被一次误点重新拉回漏斗。它会连同状态一起打上*响应时间*与*已响应*标识。
- **已转化** — 自动写入。当某个成员的线索被转化时，该线索所加入的每一个营销活动都会提升自己的成员记录并重算指标。转化是这个应用唯一能自行观察到的营销活动结果。
- **已退订** — 由销售代表在成员记录上设置，或来自一次退订请求。设置它的同时会勾上此人线索或联系人上的 **Email Opt Out**（拒收邮件），这才是让他们不再进入后续活动的机制：加入流程会跳过已退订的人。它只朝一个方向走——把一个人标记为退订，并不会改写他已有的成员记录，因为那些记录的是当时发生的事实。

## 指标如何汇总

营销活动详情页会汇总其成员：

```
Sent          = 该营销活动的全部成员
Responses     = 处于 Responded 或 Converted 的成员
Response rate = Responses ÷ Sent，以百分比表示
```

转化以营销活动上的「已转化线索数」抵达该页面；商机一旦带上营销活动，就会进入同一页面的商机与 ROI 数字。退订不是营销活动上的计数：你在成员记录上看到它，也在此人的 **Email Opt Out**（拒收邮件）上看到它。

这些数字会在每一次成员变化时重算——有人加入、有人被标记为已响应、有人被移除——所以正在进行中的营销活动报的就是真实数字，不必等一个夜间作业。把一个成员标记为*已响应*，营销活动的响应率随之变动。

## 成员在哪里查看

在营销活动详情页的 **Related**（相关）选项卡下，一个标题为 **Campaign Members** 的面板里。该面板列出这个活动的每一位成员，五列——**Lead**（线索）、**Contact**（联系人）、**Added Date**（加入日期）、**Status**（状态）和 **Response Date**（响应日期）——并带着上面提到的 **New**（新建）按钮。列的顺序就是这行记录发生的顺序：谁被加入、什么时候加入、后来怎么响应。

读者常带着两个预期过来，它们真正的落点是：

- **没有 *Members* 选项卡。** 成员面板只是活动在共用的 *Related* 选项卡上的关联记录面板之一。
- **没有任何成员列表视图** —— *All Members*、*Responded*、*Unsubscribed*、*Converted to Opportunity* 都不存在。Campaign Member 对象一个列表视图都没有；即便有，关联列表面板也不读子对象的列表视图：面板的列是在活动关联字段上直接定好的，从来不来自视图。产品里没有任何东西能把这个面板按状态筛选，也没有面向 Campaign Member 的报表，所以「所有响应过的人」是活动上的一个**数字**而不是一份可以打开的名单——见上文《指标如何汇总》一节，那里的响应率由成员状态实时算出。

## 给营销人员的提示

- ✅ **盯住退订**——每一次退订都会同时把这个人从邮件里排除，于是他会自动退出后续的每一次加入。退订数上升，是该换内容的信号，而不是该换名单的信号。
- ✅ **用*已响应*和*已转化*来评判一个营销活动**——它们是这个应用真正能观察到的两个结果。
- ✅ **在商机上标记营销活动来源**——没有它，转化就无法汇总。

## 给销售代表的提示

- ✅ 当你打开一个线索时，查看侧边栏中的 **Campaign Memberships**——它会告诉你他们被投放过哪些营销活动、以及他们怎么回应的。
- ✅ 用营销活动作为对话开场白——*"我看到你参加了我们最近关于……的网络研讨会。"*

## 给管理员的提示

- 没有什么打开/点击跟踪可供开启，也没有哪个连接器能加上它。如果某个营销活动的响应数字偏低，先确认销售代表是否在用 **Mark Responded**（标记为已响应）——那个按钮，以及线索发生转化，是仅有的能把成员移出*已发送*的两件事。
- "*Lead* 或 *Contact* 必须且只能设置其一"这条规则存在于 campaign_member 对象的验证规则中。
