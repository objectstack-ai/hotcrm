# Quick Start

This guide assumes `pnpm dev` is running per the [installation guide](/docs/getting-started/installation).

## 1. Sign Up

Open [http://localhost:3000/_account/sign-up](http://localhost:3000/_account/sign-up) and create an account. Or via curl:

```bash
curl -X POST http://localhost:3000/api/v1/auth/sign-up/email \
  -H 'Content-Type: application/json' \
  -d '{"email":"sales@acme.com","password":"admin123","name":"Sales Rep"}'
```

The response includes an auth token. Save it; you'll use it for API calls.

## 2. Browse the Seeded Data

Open [http://localhost:3000/_console/](http://localhost:3000/_console/). You'll land on the Home page. The left sidebar lists every object the user can see — Accounts, Contacts, Leads, Opportunities, Quotes, Contracts, Campaigns, Cases, Tasks, Products.

Click **Accounts** — you'll see 5 demo records (Acme Corporation, Global Tech Inc, etc.) with industry, revenue, employee count, tier, segment, and health score.

Click any account to open the **Account Detail** page (`src/pages/account_detail.page.ts`). It shows fields, related contacts, related opportunities, and quick actions.

## 3. Create a Record (UI)

From the Accounts list view, click **New**. Fill in:

- **Name**: `Stark Industries`
- **Type**: `customer`
- **Industry**: `manufacturing`
- **Annual Revenue**: `9000000000`
- **Website**: `https://stark.example.com`

Click **Save**. The `account_protection` hook (`src/objects/account.hook.ts`) runs server-side:

- Validates the website starts with `http://` or `https://`
- Rejects negative annual revenue
- Normalises `account_number` to uppercase

Try saving with `website: stark.example.com` (no protocol) — you'll get a server error: *"Website must start with http:// or https://"*. This is the hook in action.

## 4. Create a Record (API)

```bash
TOKEN="<your token from step 1>"

curl -X POST http://localhost:3000/api/v1/objectql \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "operation": "create",
    "object": "lead",
    "data": {
      "first_name": "Tony",
      "last_name": "Stark",
      "company": "Stark Industries",
      "email": "tony@stark.example.com",
      "status": "open",
      "rating": "hot"
    }
  }'
```

Query it back:

```bash
curl -X POST http://localhost:3000/api/v1/objectql \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "operation": "find",
    "object": "lead",
    "filters": [["company", "=", "Stark Industries"]]
  }'
```

## 5. Try the State Machine

Leads have a state machine declared in `src/objects/lead.state.ts`:

```
open → working → qualified → converted
                          → unqualified
```

Each transition is guarded. Try transitioning a `converted` lead back to `open` via the UI — you'll be blocked. Try converting an `open` lead directly to `converted` — also blocked. Transitions must follow the declared graph.

## 6. Trigger an Approval

Open an opportunity → create a quote → apply a discount > 20 %. The quote enters the **Quote Discount Approval** process (`src/approvals/`). It will appear under the Approvals tab for the assigned approver.

## What Just Happened

Every interaction you just performed was driven by metadata in `src/`:

| You did | File that drove it |
|---|---|
| Saw the account list | `src/views/account.view.ts` |
| Opened the account detail | `src/pages/account_detail.page.ts` |
| Got blocked by website validation | `src/objects/account.hook.ts` |
| Transitioned a lead | `src/objects/lead.state.ts` |
| Sent a quote for approval | `src/approvals/index.ts` |
| Got 90 seed records on sign-up | `src/data/index.ts` |

There is no admin UI to change behaviour — edit the file, restart `pnpm dev`, and the change is live.
