# SLA 与升级

SLA（服务级别协议）系统根据每个工单的优先级为其赋予一个**截止时间**，实时呈现**违约**，并自动将卡住的工单**升级**给资深员工。

## SLA 目标如何计算

每个工单在创建的那一刻就会获得一个 **SLA 截止日期**。该目标基于优先级：

| 优先级 | 默认 SLA 目标 | "违约"是什么样子 |
| --- | --- | --- |
| **Critical** | 4 小时 | 工单详情上的红色横幅、向支持经理发出警报 |
| **High** | 8 小时 | 列表视图中的红色徽章 |
| **Medium** | 2 个工作日 | 琥珀色徽章 |
| **Low** | 7 个工作日 | 灰色徽章 |

SLA 目标可按优先级配置——参见下方的*给管理员的提示*部分。

> **营业时间**——系统可以配置为只计算营业时间（例如周一至周五 9-5），而非日历时间。参见 [管理 › 设置](/zh-Hans/docs/administration/setup)。

## SLA 如何被跟踪

每个工单上有两个字段：

- **SLA 截止日期**——工单必须在何时之前解决。
- **SLA 已违约？**——当解决时间超过目标时为 `true`。

违约标记对客服是**只读的**——他们无法篡改。它由系统自动计算。

工单详情页在页眉中显示实时 SLA 倒计时：

- ⏱ *剩余 2h 14m*——正常
- ⚠️ *剩余 24m*——警告区
- 🚨 *已违约 – 超时 1h 32m*——升级范畴

## SLA 表现报表

**SLA 表现**报表显示在 SLA 目标内解决的工单百分比，并按以下维度细分：

- 客服（谁达成了他们的 SLA？）
- 优先级（哪个优先级桶在漏单？）
- 账户等级（客户是否被比潜在客户更差地对待？）
- 月份（表现是趋升还是趋降？）

这份报表是支持团队最常用的 KPI。

## 工单升级

工单升级流程会自动将卡住或紧急的工单重新分配给资深员工。

### 何时触发升级

升级流程在工单满足以下任一条件的那一刻运行：

- 工单被设为 **Critical** 优先级，或
- 工单为 **High** 优先级**且**关联账户为 **Customer**（非潜在客户）

### 升级会做什么

被触发时，流程按顺序执行以下步骤：

1. 将工单**重新分配**给当前客服的**经理**。
2. **将 `Escalated` 标记设为** true 并标记升级日期。
3. **将状态更改为** *Escalated*。
4. **在原客服上创建一个跟进任务**，明天到期（让他们保持参与并从中学习）。
5. **向原客服、其经理以及更广泛的 `support-team@example.com` 列表发送邮件**，附上工单编号、优先级和账户名称。

结果是：客户的问题在几分钟内就到了资深客服手中，支持团队也立即看到升级警报。

### 必需项：升级原因

你不能在未填写**升级原因**的情况下升级一个工单——这是一个简短的文本字段，解释升级*为何*发生。它会成为工单审计跟踪的一部分，并为 QBR 报表提供素材。

## 其他工单自动化

| 自动化 | 触发时机 | 作用 |
| --- | --- | --- |
| **紧急时通知** | 优先级设为 Critical | 向 `support_manager@example.com` 发邮件 |
| **升级时通知** | `Escalated` 标记翻转为 true | 向 `escalation_team@example.com` 发邮件 |
| **计算解决时间** | 工单关闭 | 计算从创建 → 关闭的小时数 |
| **设置关闭标记** | 状态变更 | `is_closed = (status == "closed")` |
| **设置关闭日期** | 状态变更为 *Closed* | 将关闭日期标记为 NOW |
| **更新账户最后活动** | 工单更新 | 将 `account.last_activity_date` 刷新为今天 |

## 共享——升级的工单获得团队可见性

默认情况下工单是**私有的**。但**紧急未结工单**会通过 *Escalated Cases* 共享规则自动共享（读 + 写）给所有服务经理及其下属。因此当某事爆发时，领导层无需主动申请访问权限。

## AI Copilot 如何使用 SLA

[Service Copilot 的工单分流技能](/zh-Hans/docs/ai-copilot/skills#case-triage)在推荐优先级时会考虑 SLA：

- 一个客户等级的账户即使主题含糊，仍会因客户关系而获得 **High**。
- 一个描述中含 *"production is down"* 的潜在客户会获得 **Critical**，尽管它不是付费客户。
- Copilot 使用[支持知识库](/zh-Hans/docs/service/knowledge-base)与过往的相似工单进行模式匹配。

如果优先级解析为 **Critical**，Copilot 会立即推荐升级并起草内部通知消息。

## 推荐节奏

| 角色 | 查看什么 | 何时 |
| --- | --- | --- |
| **客服** | My Open Cases（按 SLA 截止日期排序） | 当班期间每小时 |
| **服务经理** | Breached SLA + Critical Cases | 每天一早 |
| **服务总监** | SLA 表现报表 | 每周 |
| **高管** | 服务仪表盘 | 每周 |

## 给服务客服的提示

- ✅ 关注你的 SLA 倒计时——当你看到琥珀色区域时，请求帮助。
- ✅ 当你确实被阻塞时使用 **Waiting on Customer**——取决于你的配置，这可以暂停 SLA 计时。
- ✅ 不要人为降低优先级来延长你的 SLA——经理可以看到优先级变更历史。

## 给服务经理的提示

- ✅ 每天早上运行 **Breached SLA** 列表视图。
- ✅ 使用 **Service Board** 看板进行每日站会。
- ✅ 辅导那些违约率趋升的客服——在它形成模式之前于 1:1 中提出。

## 给管理员的提示

- 每个优先级的 SLA 目标通过工单对象的自动化（一个 SLA 计算钩子）设置。要调整，请编辑 `src/objects/case.hook.ts`（绑定到 `crm_case`）或更改底层配置——参见 [管理 › 自动化](/zh-Hans/docs/administration/automation)。
- 营业时间与日历时间的行为由你租户的营业时间设置控制。参见 [管理 › 设置](/zh-Hans/docs/administration/setup)。
- 升级触发条件（Critical，或 High+Customer）存在于 [工单升级流程定义](/zh-Hans/docs/administration/automation)中。在那里调整条件即可更改升级何时触发。
- *紧急时通知*和*升级时通知*的收件人列表可在工单工作流规则中配置。
