# 文件与评论

有两样东西只属于记录本身：**证明双方约定了什么的文档**，以及**围绕它的讨论**。
HotCRM 把两者都放在记录上 —— 合同在客户那里，"我们当初为什么给这个折扣？"
的讨论在商机那里，而不是散落在某个人的邮箱里。

## 📎 附件

打开任意客户、联系人、商机、报价单、合同或工单，在记录详情下方就能看到
**附件（Attachments）** 面板。

| 对象 | 常见附件 |
| --- | --- |
| **客户** | 已签署的主服务协议、组织架构图、安全问卷 |
| **联系人** | 已签署的保密协议、名片、会议纪要 |
| **商机** | 方案书、修订稿、已签署的订单 |
| **报价单** | 生成的报价 PDF、客户回签件 |
| **合同** | 已执行的合同正本 |
| **工单** | 截图、日志包、复现步骤 |

### 上传

1. 打开记录。
2. 在附件面板中点击 **Upload**（或把文件拖放到面板上）。
3. 文件会出现在列表中，并显示名称、大小和类型。

每一行都带有**下载**和**删除**操作。

### 谁能看到、能做什么

附件没有自己的权限 —— **它们继承所在记录的权限**。这一条规则回答了所有问题：

- **上传**需要对该记录有*编辑*权限。你不能编辑这个商机，就不能往上面传文件。
- **查看和下载**需要对该记录有*读取*权限。能打开这笔生意的同事就能看到它的文件；
  不能打开的人则看不到 —— 文件列表对他们直接返回空，而不是显示一行打不开的记录。
- **删除**仅限上传者本人，以及能编辑该记录的人。
- **匿名访客什么也拿不到。** 通过公开的 Web-to-Lead / Web-to-Case 表单进来的访客，
  即使拿到直链也无法获取文件。

因为访问权跟随记录，所以按区域、按客户团队共享记录，或者变更负责人时，
附件会自动一起带过去。不需要再记第二套权限。

### 潜在客户有意不支持附件

未验证的潜在客户往往从表单和名单里批量涌入，在它们上面开放附件面板基本上只会
收集垃圾。潜在客户一旦转化，生成的客户、联系人和商机都支持上传文件。如果你的团队
确实需要在验证之前就往潜在客户上传文件，请联系管理员 —— 这只是一个开关。

> 记录上的文件**字段**（例如产品数据表）和附件不是一回事：字段只能放一个文件，
> 并且属于记录的数据本身；而附件面板可以在旁边放任意多个文件。

## 💬 评论

每条记录都带有 **Discussion（讨论）** 信息流：一个评论框，加上这条记录的动态，
最新的在最下方。

- 在框内输入内容，按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>（Mac：<kbd>⌘</kbd>+<kbd>Enter</kbd>）发布。
- 支持基础格式 —— **粗体**、*斜体*、列表和代码。
- 输入 <kbd>@</kbd> 提及同事，对方会收到通知。
- 可以用表情回应某条评论，或回复以开启一个话题串。

系统条目（阶段变更、负责人变更）也出现在同一个信息流里，讨论和记录历史因此
读起来是同一个故事。

### 评论里该写什么

- ✅ *"采购要求 Net-60；财务已批准，详见附件中的 MSA。"*
- ✅ *"内部支持者已离职 —— 新联系人是 Dana，正在重新验证需求。"*
- ❌ 任何你不希望整个营收团队读到的内容。评论对同事可见，请把它当作共享工作的
  内部备注，而不是私信。

## 小技巧

- ✅ 在文档**签署的那一刻**就把它附上 —— 六个月后，所有人只会去记录上找它。
- ✅ 把**决策**写进评论，而不只是把结果填进字段。`阶段 = 谈判中` 说明了"是什么"，
  评论才说明"为什么"。
- ✅ @ 提及你需要对方配合的那个人。没有 @ 任何人的评论只是日记。
- ✅ 文件命名要能在列表里读懂 —— `apex-msa-2026-signed.pdf` 胜过 `scan_0043.pdf`。
