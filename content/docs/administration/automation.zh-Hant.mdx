# 自動化

自動化讓 HotCRM *為你完成工作* —— 傳送通知、更新欄位、建立任務、升級案例，全程無需任何人點擊按鈕。提供五種自動化，每一種都適用於不同的工作。

## 五種類型

| 類型 | 觸發時機 | 最適合 |
| --- | --- | --- |
| **驗證規則** | 儲存前 | 攔截不良資料 |
| **工作流規則** | 儲存後 | 欄位更新、簡單的電子郵件提醒 |
| **流程** | 儲存後（或按排程） | 多步驟邏輯、分支、迴圈 |
| **排程作業** | 按排程 | 每日清掃、每週報表 |
| **審批流程** | 提交時 | 多步驟簽核 |

## 驗證規則

最簡單的類型。當某個條件為真時，它們會阻止儲存。

**內建範例**：

- *「結束日期必須晚於開始日期」*（用於合約）。
- *「標價必須大於零」*（用於產品）。
- *「活動成員必須有一個潛在客戶或一個聯絡人，但不能兩者都有」*（用於活動成員）。
- *「折扣百分比必須介於 0 和 100 之間」*（用於報價行項目）。

要新增一條：

1. **設定 → 物件 → 驗證規則 → 新增**。
2. 撰寫條件（*失敗* 條件）。
3. 撰寫向使用者顯示的錯誤訊息。
4. 啟用。

## 工作流規則

當記錄在儲存後匹配某個條件時觸發。每條規則可以執行一項或多項 **操作**。

**操作類型**：

- **欄位更新** —— 變更同一條記錄或父記錄上的欄位。
- **電子郵件提醒** —— 向特定收件人傳送範本化郵件。
- **建立任務** —— 為記錄所有者或其他使用者建立。
- **出站訊息** —— 觸發一個 webhook。

**內建範例**：

- *評級為 Hot 的潛在客戶建立* → 向銷售經理發郵件 + 建立一個 *「24 小時內確認資格」* 任務。
- *商機贏單，金額 ≥ $100K* → 向團隊傳送慶祝郵件，在 #wins 頻道發文。
- *案例優先級變更為 Critical* → 通知值班工程師。

## 流程（多步驟）

當工作流規則不夠用時 —— 分支、迴圈、多物件 —— 使用 **流程**。

流程是一個視覺化的步驟序列：取得資料 → 檢查條件 → 更新記錄 → 呼叫子流程 → 等待 → 重複。

**HotCRM 中的內建流程**：

| 流程 | 它做什麼 |
| --- | --- |
| **潛在客戶轉換** | 當 *Status = Qualified* 時，建立客戶 + 聯絡人 + 商機，將它們關聯，轉移活動 |
| **商機贏單** | 當 *Closed Won* 時，建立合約（如有關聯產品），通知團隊，可選地建立續約任務 |
| **報價過期** | 每日 —— 查找超過過期日期的報價，將狀態設為 *Expired*，通知所有者 |
| **活動登記** | 當活動轉入 *In Progress* 時，將匹配的潛在客戶/聯絡人登記為成員 |
| **案例升級** | 由 SLA 監控器執行 —— 重新指派、通知經理，可選地建立父案例 |

如果你需要建構新的流程，請參見 [自訂 › 擴充物件](/zh-Hant/docs/customization/extending-objects)。

## 排程作業

按時鐘（cron）執行。它們驅動著保持你資料新鮮的每日/每週清掃。

**內建排程作業**：

| 作業 | 排程 | 它做什麼 |
| --- | --- | --- |
| **報價過期清掃** | 每日凌晨 1 點 | 讓超過過期日期的報價過期 |
| **活動自動完成** | 每日凌晨 2 點 | 將超過結束日期的活動移至 *Completed* |
| **活動自動登記** | 每週一上午 9 點 | 重新評估活動中的活動並新增新匹配的成員 |
| **合約過期** | 每日午夜 | 將已過期的 *Activated* 合約移至 *Expired* |
| **合約續約提醒** | 每日上午 8 點 | 當處於續約通知視窗內時通知合約所有者 |
| **SLA 違約監控** | 每 5 分鐘 | 檢查未結案例的 SLA 風險/違約，觸發提醒 |

你可以在 **設定 → 排程作業** 中新增自訂排程作業。

## 審批流程

審批流程是一種專門的自動化 —— 帶鎖定的多步驟簽核。關於內建的折扣審批以及如何設定新的審批，參見 [收入 › 審批](/zh-Hant/docs/revenue/approvals)。

## 操作順序

當一條記錄被儲存時，順序是固定的：

1. **系統** 執行自動計算（公式欄位、自動編號）。
2. **驗證規則** 執行 —— 如果有任何失敗，儲存被阻止。
3. **記錄被儲存** 到資料庫。
4. **工作流規則** 觸發。
5. **流程觸發器** 觸發。
6. 來自工作流 / 流程的 **欄位更新** 可能級聯 —— 重新評估工作流最多 5 次後停止。
7. **電子郵件提醒** 進入佇列。

理解這個順序有助於除錯 *「為什麼我的工作流沒有觸發？」* 這類問題。

## 電子郵件範本

大多數自動化操作會傳送電子郵件。範本位於 **設定 → 電子郵件範本**，並支援：

- **合併欄位** —— `{{Opportunity.Name}}`、`{{Account.Owner.Email}}`。
- **條件區塊** —— 僅在條件為真時顯示。
- **HTML + 純文字** 版本。
- **附件** —— 報價 PDF、合約 PDF。

內建範本涵蓋潛在客戶路由、商機贏單、案例確認、合約啟用、續約提醒。

## 在哪裡監控自動化

- **設定 → 流程監控器** —— 過去 24 小時的自動化執行及其成功/失敗。
- **設定 → 工作流佇列** —— 待處理的電子郵件提醒和欄位更新。
- **設定 → 排程作業 → 歷史** —— 每個排程作業的過往執行。
- **物件 → 稽核日誌** —— 記錄上發生了什麼變化，誰/什麼進行了變更。

## 給管理員的提示

- ✅ **驗證規則** 是強制資料品質最廉價的方式 —— 放開手用。
- ✅ **每個條件一個工作流** 比有 10 個分支的超級工作流更易於維護。
- ✅ 對於任何超過 2 個操作的複雜邏輯，**使用流程** —— 除錯起來容易得多。
- ✅ 在生產中啟用前 **在沙箱中測試** —— 糟糕的自動化會快速級聯。
- ✅ 在描述欄位中 **記錄每條規則的作用** —— 未來的你會感謝現在的你。

## 給使用者的提示

如果一條記錄的行為不符合預期：

1. 檢查 **稽核日誌** —— 該欄位是被工作流更新的嗎？
2. 檢查 **任務清單** —— 工作流是否自動建立了一個你錯過的任務？
3. 請管理員檢查該記錄的 **流程監控器**。
